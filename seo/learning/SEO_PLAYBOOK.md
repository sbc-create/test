## Процедуры (не паттерны — они не требуют доказательства эффекта)

### Публикация страницы нового тайтла
1. Проверить hard gates `NEW_RELEASE_PRIORITY_MODEL.hard_gates`. Не прошёл хоть один — draft.
2. Проверить distinct value против существующих URL своего и чужих tenant.
3. Опубликовать; сразу обновить внутренние ссылки и sitemap lastmod.
4. Перекрауз — только в пределах прочитанной из API квоты и только для приоритетных URL.
5. Через 48 ч проверить статус, canonical, рендер и наличие в индексе.
6. Оценивать не раньше зрелости данных.

### Реакция на падение
1. Отличить внешнее от своего: сравнить с портфелем, релизами и окнами обновлений.
2. Если падение локально и совпадает с изменением — откатить последний обратимый пакет **этого сайта**.
3. Не откатывать несвязанные сайты.
4. Зафиксировать в FAILED_PATTERNS то, что не сработало.

### Каннибализация
1. Определять по кластеру интента, а не по URL.
2. Primary выбирать по полезности, а не по позиции.
3. Межтенантный конфликт не решается canonical — это редакционное решение о разделении интентов.

## Антипаттерны (запрещены по построению)

- Массовая генерация страниц ради покрытия запросов.
- Автосинонимизация текста ради «уникальности».
- Один и тот же текст, подборка или раскладка главной на нескольких сайтах.
- Оценка эксперимента до зрелости данных.
- Раскатка на портфель по одному успешному наблюдению.
- Любая имитация пользовательской активности.
