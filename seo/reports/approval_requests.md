# Запросы на решение владельца

Один агрегированный пакет. Оператор не спрашивает повторно об одном и том же
неизменившемся блокере и не останавливает из-за них независимые задачи.

## Блокирует работу с реальными данными

1. **Передать репозиторий/ветку development-контура и принятый base commit.**
   Сейчас репозиторий пуст — discovery портфеля выполнять не над чем.
2. **Инвентарь 15–20 сайтов** без секретов: site_id, домен, окружение, владелец, канал алертов.
3. **Доступы (только ссылки на secret store, не значения):**
   `secret://gsc/service-account`, `secret://yandex/webmaster-oauth`,
   `secret://yandex/metrika-oauth`, `secret://cms/seo-operator`, `secret://logs/reader`.
4. **Каталог CDNVideoHub/VK на чтение + модель rights_ref** — без него редакционный
   discovery невозможен.

## Требует решения, а не данных

5. **Стартовый `seo_autonomy_tier` на каждый сайт.** Рекомендация: начать с 0
   (только чтение и отчёты), поднять до 1 после первой недели наблюдений.
6. **Разрешить ли публичные редакционные ответы** (`disclosed_editorial_reply_enabled`).
   По умолчанию выключено.
7. **Как разводить интенты между сайтами портфеля.** Технического решения нет:
   два своих сайта на одном запросе конкурируют друг с другом.
8. **Позиционирование каждого сайта** (аудитория, рубрики, tone of voice, отличия).
   Без этого межсайтовый гейт дублей будет блокировать публикации.

## Для перехода к production-автономии

9. Подписанная production policy: `production_authorized: true` в manifest сайта.
10. Проверенный backup/restore.

Полный контекст: `seo/UNKNOWNS.md`.
