# Подготовка к canary-выкладке

## Выкладка НЕ выполнялась и не разрешена

`PRODUCTION_MUTATIONS=0`. Задание прямо запрещает production до отдельного
явного принятия preview владельцем.

## Что должно произойти до выкладки

1. Владелец открывает оба preview и выносит решение по каждому семейству
   отдельно. Непринятое семейство не выкладывается.
2. Для Animedia визуальная готовность и готовность ДАННЫХ — разные статусы.
   `ANIMEDIA_DATA_READINESS=FAIL`: каталог аниме источником не передан, и пока
   это так, витрину нельзя объявлять полностью production-ready, даже если её
   оформление принято.

## Команда владельца — выполнять только после принятия

Артефакт витрины собирается из текущего файла шаблона; отпечаток кандидата на
момент сдачи — в `preview-manifest.json`. Команда приводится как образец
порядка, а не как готовая к запуску строка: `--expect-sha256` обязан быть взят
из СОБРАННОГО артефакта на момент выкладки, а не скопирован отсюда.

```
sudo -n python3 automation/host/lords-zona-canary-run.py \
  --artifact  automation/host/lords-frontend.py \
  --expect-sha256 <sha256 собранного артефакта> \
  --commit <commit> --build-id <build-id> --design-version 1.2.0 \
  --sites <zona-01ИЛИanimedia-01: только принятое семейство> \
  --profiles <профиль ровно принятых витрин> \
  --out artifacts/evidence/templates-zona-animedia-visual-parity-006/canary-run
```

`--sites` содержит только принятое семейство. `lords-01` в команде не
появляется ни при каких условиях.

## Единственное изменение вне шаблонов, которое потребуется отдельно

Same-origin доставка постеров (`N-01` в `data-vs-template-defects.json`).
Механизм в проекте есть, но включён только в vhost `lords-01`. Нужно добавить
тот же снимок в vhost `zona-01` и `animedia-01` и лишь затем включить
`LORDS_POSTER_SAME_ORIGIN=1`. Правка nginx в эту задачу не входила.
