# Правило новинок 1.1.1 — материалы приёмки

Проверялись **отображаемые карточки**, а не результат отдельной функции.

## Как воспроизвести

```bash
python3 seed_mix.py <каталог-данных> lords-90 mix-1   # представительная смесь
bash family_sweep.sh      # четыре семейства общего рантайма
bash profile_sweep.sh     # семь профилей Lords
bash rework_sweep.sh      # переработанные раскладки 1.2 zona и animedia
python3 check_preview.py  # один экземпляр по адресу
```

## Смесь

252 записи: 120 архивных (1955–2014, загружены сегодня), 40 свежих, 20
сериалов (10 старых продолжающихся, 10 новых), 8 будущих премьер, 12 без года
выхода, 20 мультфильмов, 20 аниме, 12 дорам.

Доли взяты с боевого снимка, где архив в окне по дате загрузки составлял
большинство. Если правило сломается, это видно сразу: на полке появятся
карточки с годом из прошлого века.

## Чего проверка не покрыла

**Animedia в переработанной раскладке 1.2.** Витрина не отдаёт ни одной
карточки ни на главной, ни в каталоге, ни в разделе новинок — ей нужен снимок
своей формы, которую общая смесь не даёт. Проверено, что это НЕ регрессия: на
коммите до правки (`bee0486^`) та же раскладка на той же смеси отдавала столько
же — ноль. Правило новинок в её коде присутствует, потому что код общий;
подтвердить его на отображаемых карточках этой раскладки нельзя без снимка
формата Animedia.

**Стек `payload-next-multisite`.** Отбор новинок перенесён в запрос
(`lib/newness.ts`, `freshOnly`), но поднять его здесь нельзя: нужны
установленные зависимости Node и база Payload, которых в обязательном прогоне
нет. Закреплено разбором исходного текста
(`tests/unit/test_newness_rule_everywhere.py`) — запрет на сортировку новинок
по дате правки и обязательный `freshOnly` у блока главной.

## Разница до и после

Тот же `check_preview.py` на коммите до правки, семейство lords:

```
на главной нет архива                 FAIL  61 чужая карточка из 84
в разделе новинок только вышедшее     FAIL  45 из 48
вторая страница подчиняется правилу   FAIL  44 из 48
на карточках нет годов старше окна    FAIL  42 из 47, вплоть до 1955
```

После правки — ноль в каждом блоке, при том что архив остался в каталоге и
находится поиском.

Кэш хранит слаги и разрешает их в ПЕРЕДАННОМ наборе; отфильтрованный архив в наборе отсутствует и выпадает |
| Повторный импорт | `test_lords_newness_rule.py::test_повторный_импорт_не_возвращает_архив_в_новинки` | дата загрузки обновилась, год прежний — не новинка |

Пустой блок — допустимый исход. Добивать его архивом запрещено, и проверка
это различает: с общей смесью раздел новинок обязан быть НЕ пуст, с архивом
только — обязан быть пуст.
