# Перенос изменений Animedia в каноническую линию без подделки манифеста

Стадия: `ANIMEDIA-BLOCKWISE-PARITY-03`, поручение владельца
`OPTION_A_FINISH_PARITY03_FIRST`.
Решение-первопричина: `knowledge/DECISIONS.md` D140.
Блокер: `BLOCKERS.json` B-OWNERSHIP-01.

`config/TEMPLATE-BASELINE-MANIFEST.json` **не изменялся**:
`BASELINE_MANIFEST_MUTATED=0`. Ни один дайджест не подгонялся.

## Что на самом деле происходит

Решение владельца `TEMPLATE-POSTDEPLOY-REMEDIATION-03A` назначило канонического
writer'а шаблонного релиза: PR #76, ветка `claude/fleet-tpl-baseline-001`.
Управляемых файлов два:

- `automation/host/lords-frontend.py`
- `factory/lords/collection_contract.py`

Измерено 2026-09-21:

| Точка | `lords-frontend.py` | `collection_contract.py` |
| --- | --- | --- |
| Запись в манифесте | `1668f71b…` | `58b78601…` |
| `canonical_head_sha` манифеста (`ca805888`, 16.09) | `746be110…` | `58b78601…` |
| **Вершина канонической ветки `b398ca2` (18.09)** | **`1668f71b…` — совпадает** | **`58b78601…` — совпадает** |
| Animedia `START_HEAD` `03b3908` | `19146d6d…` | `1de55d9d…` |
| Animedia сейчас | `76cb52a0…` | `1de55d9d…` |

Из этого следуют три факта, и ни один из них не был очевиден заранее:

1. **Манифест точен.** Его дайджесты совпадают с вершиной канонической ветки
   побайтово. Гейт не «устарел» — он работает.
2. **Поле `canonical_head_sha` отстало.** Оно указывает на `ca805888` от 16.09,
   тогда как дайджесты соответствуют `b398ca2` от 18.09. Это отдельная мелкая
   неточность записи, не влияющая на гейт.
3. **Расходится именно линия Animedia**, и по обоим файлам. `collection_contract.py`
   разошёлся ещё до стадии восстановления и этой работой не трогался.

## Почему перенос безопасен: конфликта содержимого нет

| Величина | Значение |
| --- | --- |
| Общее основание | `bc97871` (16.09) |
| Коммитов на линии Animedia от основания | 120 |
| Коммитов на канонической линии от основания | 4 |
| Из них трогают `lords-frontend.py` | **0** |
| Из них трогают `collection_contract.py` | **0** |
| Коммитов Animedia, трогающих `lords-frontend.py` | 43 (+4861 / −772) |
| Коммитов Animedia, трогающих `collection_contract.py` | 5 (+169 / −7) |

Каноническая ветка после общего основания **ни разу** не правила ни один из
управляемых файлов. Значит их перенос — не слияние встречных правок, а
однонаправленное продвижение.

## Репетиция, а не предположение

Проверено в одноразовом отсоединённом рабочем дереве на вершине `b398ca2`.
Ни одна ветка не затронута, `push` и `merge` не выполнялись.

```
git worktree add --detach <tmp>/canon-rehearsal b398ca2
git diff bc97871..<animedia HEAD> -- \
    automation/host/lords-frontend.py factory/lords/collection_contract.py > owned-files-transfer.patch
git -C <tmp>/canon-rehearsal apply --check --verbose owned-files-transfer.patch
```

Результат:

```
patch bytes: 413454
apply --check exit: 0        ← конфликтов ноль
apply exit: 0
automation/host/lords-frontend.py      after == animedia HEAD   (побайтово)
factory/lords/collection_contract.py   after == animedia HEAD   (побайтово)
```

То есть патч ложится на каноническую вершину чисто и воспроизводит версии
Animedia бит в бит.

## Побочная находка, исправленная здесь же

В репетиционном дереве гейт `test_контракт_коллекций_ровно_один` **проходил**, а
на ветке Animedia падал. Причина найдена: `automation/host/collection_contract.py`
добавила линия Animedia коммитом `f772c02` (19.09). Его нет ни на канонической
вершине, ни в общем основании, ни в `origin/main`, и он побайтово равен
`factory/lords/collection_contract.py`.

Копия была не нужна: deploy кладёт контракт спутником артефакта **из
канонического пути** —
`install … ${RUNTIME_REPO}/factory/lords/collection_contract.py → <frontend>/`
(`deploy-nova-family.sh:51`, `deploy-nova-lords.sh:55`), а
`apply-nova-closed-update.py` лишь снимает копию для откáта из уже выложенного
каталога. Отслеживаемый дубликат давал второй источник правды, который мог
разъехаться незаметно: локальный запуск брал бы копию, а production —
канонический файл.

Дубликат удалён. Импорт в артефакте теперь сначала берёт канонический пакет, а
спутник рядом с артефактом остаётся вторым путём для выложенной раскладки, где
пакета нет. Гейт «контракт коллекций ровно один» стал зелёным, и это уменьшило
объём переноса, а не увеличило его.

Ранее в `BLOCKERS.json` этот дубликат был отнесён к Core. Атрибуция исправлена:
он принадлежит линии Animedia.

## Порядок переноса — действия владельца канонической линии

Ни один шаг ниже не выполнен: все требуют прав на каноническую ветку и
разрешения на `push`/`merge`, которых у этой сессии нет.

1. Владелец PR #76 берёт ветку `claude/animedia-template-finalization-01` на
   вершине `<FINAL_HEAD>` и убеждается, что рабочее дерево чисто.
2. Продвигает каноническую линию: слияние ветки Animedia в
   `claude/fleet-tpl-baseline-001` либо перенос патча управляемых файлов.
   Конфликтов по управляемым файлам не будет — доказано репетицией выше.
3. **Регенерирует** `config/TEMPLATE-BASELINE-MANIFEST.json` на канонической
   линии: это законное обновление, потому что его делает владелец записи, а не
   потребитель. Предлагаемые значения, посчитанные с перенесённого дерева:

   ```
   automation/host/lords-frontend.py
     было : 1668f71bb514a5a2c81247131183bd6dfc2a503481421ced7f48a3b67c7699bd
     станет: 76cb52a00c183283039e222844808c4380c97ffffa8ec7f3af040a259a05cb19

   factory/lords/collection_contract.py
     было : 58b786017fba0dc360017188b3473074dfd18b4d552cd70a9c63a412b1d96c71
     станет: 1de55d9d4ee44d5f586bf97b6513d8f18aabc0c946b9efca40603b0ec194d948
   ```

   Значение `lords-frontend.py` действительно для `FINAL_HEAD` этой стадии;
   при любом дальнейшем коммите в файл его нужно пересчитать заново. Поэтому
   дайджест регенерируется **после** переноса, а не заранее.
4. Заодно поправляет отставшее `canonical_head_sha`: сейчас `ca805888`, а
   дайджесты соответствуют `b398ca2`.
5. Прогоняет `tests/unit/test_template_ownership_gate.py` — все семь проверок
   должны стать зелёными.

## Чего делать нельзя

- Подгонять дайджест в манифесте со стороны Animedia. Это выдало бы
  соответствие решению владельца, которого нет, и обнулило бы смысл гейта:
  он существует ровно для того, чтобы поймать правку общего файла мимо
  канонической линии.
- Ослаблять или удалять `test_дайджесты_владения_совпадают_с_файлами`.
- Считать перенос выполненным без прогона гейта на канонической линии.

## Уборка

Репетиционное рабочее дерево удалено после проверки; патч
`owned-files-transfer.patch` был временным и в репозиторий не коммитился —
он воспроизводится одной командой `git diff` из плана выше.
