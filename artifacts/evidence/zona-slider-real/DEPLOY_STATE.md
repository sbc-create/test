## Почему так вышло

| Время (UTC) | Событие | Источник |
| --- | --- | --- |
| 2026-09-21 17:37:22 | установлен артефакт `bbd6467…` — код с настоящим слайдером | mtime `zona-01-frontend.py` |
| 2026-09-21 17:37:50 | манифест витрины переписан, `design_version` стал `1.3.0` | mtime `template-manifest-zona-01.json` |
| 2026-09-22 04:11:55 | служба перезапущена (не этой сессией) | старт PID 1568687 |

Артефакт `bbd6467…` знает только версии оформления `1.1.0`, `1.2.0`, `1.2.1`.
Версия `1.3.0` ему неизвестна. Незнакомая версия не отвергалась — она молча
выключала новое оформление, и витрина проваливалась в прежний статический
релиз. До перезапуска в 04:11 в памяти жил прежний манифест, поэтому подмены
не было видно; перезапуск её проявил.

## Доказательство на самих установленных байтах

Установленный файл поднят дважды с одним и тем же снимком и разными
манифестами (`sha256` файла — `bbd6467f7ee9012694020f2cb102e04e5a458bbc5b7c4759662b830987194ff5`):

| `design_version` | `/` | `/catalog/` | `/title/tancuy-chtoby-zhit/` |
| --- | --- | --- | --- |
| `1.3.0` — как в боевом манифесте | 200, H1 **0**, слайдов 0, карточек 0 | карточек 0 | **404** |
| `1.2.0` | 200, H1 1, слайдов **8**, карточек **36** | карточек 28 | **200** |

То есть установленный артефакт исправен и несёт настоящий слайдер. Ломает не
код, а расхождение объявленной версии с тем, что код умеет исполнять.

| Что | Значение |

| исполняется процессом | `/srv/lords/.frontend/zona-01-frontend.py` (из cmdline PID 1568687) |
| `ExecStart` в файле юнита | `/srv/lords/.frontend/lords-frontend.py` — **диспетчер**, а не рантайм |
| куда ведёт диспетчер | `sites/zona-01/current` → `releases/zona-slider-2650fad6` |
| что лежит в этом релизе | `7ccf094a…` — цель отката, БЕЗ настоящего слайдера |

Отсюда предупреждение, которое важнее самой починки:

> **`systemctl daemon-reload` перед перезапуском переведёт Zona на релиз
> `7ccf094a…` — на код без настоящего слайдера.** Загруженный в память юнит и
> файл юнита на диске расходятся, и перезагрузка юнитов молча выберет второй.

Файл юнита не правился: это вне области ночной работы.

## Что исправлено в ветке (но НЕ выложено)

`claude/zona-real-slider-01` содержит исправление причины: версия `1.3.0`
зарегистрирована как версия оформления Zona, а незнакомая версия больше не
проваливает витрину молча — Zona с незнакомой версией не поднимается вовсе,
и отказ виден в журнале юнита. Артефакт из ветки не собирался и не
устанавливался: выкладка — операция владельца.

## Два пути владельца

### Путь A — восстановление одной правкой, без нового артефакта

Возвращает объявленную версию к той, которую установленный и уже одобренный
артефакт умеет исполнять. Восстанавливает витрину с настоящим слайдером.

```
sudo -u lords python3 -c "import json,pathlib; p=pathlib.Path('/srv/lords/.frontend/template-manifest-zona-01.json'); m=json.loads(p.read_text()); m['design_version']='1.2.0'; p.write_text(json.dumps(m, ensure_ascii=False, indent=2))" && sudo systemctl restart nova-zona-01.service
```

**Без `daemon-reload`.** После перезапуска `/` обязана отдать один H1, восемь
слайдов и карточки, а `/title/tancuy-chtoby-zhit/` — 200.

### Путь B — выкладка артефакта из этой ветки

Даёт то же самое плюс ночные исправления (точки слайдера на 320px, оценки на
карточке) и делает манифест `1.3.0` законным. Требует обычной процедуры
сборки и установки артефакта с отпечатком — то есть решения владельца, а не
одной команды.

Путь A быстрее и возвращает ровно то состояние, которое уже проходило приёмку.
Путь B закрывает причину на будущее.
