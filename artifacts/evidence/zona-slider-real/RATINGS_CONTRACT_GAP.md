# Оценки Zona: что сделано и какого контракта не хватает

## Что показывает Zona сегодня

Оценки берутся из СОБСТВЕННОГО бокового файла витрины
`/srv/lords/.frontend/zona-01-details.json`, поле `ratings_by_source`. Это
данные Zona, а не чужой сервис, поэтому показывать их можно и нужно.

Покрытие, посчитанное по выборке в 8000 записей боевого снимка:

| Поле | Записей | Доля |
| --- | --- | --- |
| `imdb_rating` | 6733 | 84% |
| `kinopoisk_rating` | 3058 | 38% |
| `ratings_by_source` | 3322 | 41% |
| в нём `imdb` | 2660 | 33% |
| в нём `shikimori` | 662 | 8% |

Каждая запись источника несёт происхождение: `provider`, `retrieved_at`,
`match_state`, `votes`, `scale`. Ничего не достраивается витриной.

## Что исправлено этой ночью

До правки карточка читала `kinopoisk_rating` и `imdb_rating` напрямую, мимо
разбора `ratings_by_source`. Следствия, измеренные на стенде:

* Shikimori не показывался на карточке вовсе, хотя показан на странице
  произведения. На боевом снимке это тысячи карточек.
* Число печаталось в двух видах: «IMDb 7.8» и «IMDb 7.8 из 10».
* «Оценки нет» и «оценка потеряна вёрсткой» выглядели одинаково.

Теперь карточка зовёт `оценки_по_источникам` — тот же разбор, что и страница
произведения. Правила соблюдены и закреплены тестами:

| Требование | Как соблюдено |
| --- | --- |
| шкала 1–10 | шкала приходит из данных (`scale`), по умолчанию 10.0; печатается вслух |
| не подставлять случайные значения | значение только из `ratings_by_source` или прежних полей |
| отсутствие ≠ 0 | `_число_оценки` отбрасывает `0`, `null` и нечисла; состояние `data-rating="none"` |
| не смешивать с комментариями | модуль комментариев не вызывается |
| не писать оценки от имени пользователей | записи нет вовсе |
| страница живёт при сбое | исключение разбора ловится, состояние `data-rating="unavailable"`, каталог отдаётся |
| одинаковый формат | одно место разбора на карточку и страницу |
| экранирование | значения проходят `html.escape`, число собирается форматтером |
| кэш не путает тайтлы | оценка читается по слагу записи в момент отрисовки, общего кэша оценок нет |
| structured data не меняется | `schema_тайтла` не трогалась |

## Чего не хватает: контракт чтения общего модуля

Общий модуль сообщества — `/srv/lords/.frontend/community_ratings_overlay.py`.
Его публичная функция:

```python
merge_into_detail(detail: dict, *, space: str = "animedia") -> dict
```

Ограничения, прочитанные в самом модуле и в его флагах:

* `space` понимает только `"animedia"` и `"yummy"`;
* флаг доступа выбирается как `RATINGS_PUBLIC_READ_ANIMEDIA` либо
  `RATINGS_PUBLIC_READ_YUMMY` — ключа для Zona нет;
* `community-ratings-flags.json` содержит `allowlist` c ключами `animedia` и
  `yummy`; ключа `zona` нет, `RATINGS_PUBLIC_READ_ZONA` нет;
* проекция `community-ratings-projection.json` индексирована по субъектам тех
  же двух пространств.

Значит, включение оценок сообщества на Zona требует правки ЧУЖОГО общего
модуля: нового пространства, нового флага и записи в allowlist. Ночное задание
это прямо запрещает, и правка не сделана.

## Готовый адаптер

Место подключения в витрине уже есть и изолировано: `ВидЗона._оценки_плитки`
и `разметка_оценок` работают со списком, который возвращает
`оценки_по_источникам(деталь)`. Модуль сообщества возвращает деталь с
дополненным `ratings_by_source` — то есть форма совпадает, и подключение
сводится к одному вызову перед разбором:

```python
# Вызывать ТОЛЬКО после того, как контракт ниже подтверждён владельцем.
деталь = community_ratings_overlay.merge_into_detail(деталь, space="zona")
```

Ключ `amd` в `ИСТОЧНИКИ_ОЦЕНОК` уже помечен как оценка зрителей витрины
(`пользовательская=True`) и выводится отдельной группой — то есть смешать
мнение зрителей с оценкой агрегатора разметка не даст.

## Что должен решить владелец

1. Появляется ли пространство `zona` в общем модуле оценок.
2. Значение флага `RATINGS_PUBLIC_READ_ZONA` и состав allowlist.
3. Наполняется ли проекция субъектами Zona и по какому ключу сопоставления
   (у Zona есть `external_ids.imdb` / `kinopoisk`, у проекции — свои субъекты).
4. Остаётся ли `aggregate_rating_schema_org` выключенным (сейчас модуль
   выставляет `False`, и structured data оценок не объявляет).

До этих решений Zona показывает свои оценки и ничего не выдумывает.
