# VISUAL_MATRIX — что снято и чем это измерено

## Два уровня evidence

| Уровень | Что | Где |
| --- | --- | --- |
| Кандидат | 15 маршрутов × 6 ширин (320/390/768/1024/1440/1920), два независимых прогона | `run1/`, `run2/` |
| Шаблоны | 6 шаблонов × 2 маршрута × 2 ширины (390 и 1440) | `templates/<шаблон>/` |
| Контактный лист | все шаблоны рядом, снимок открывается в полном размере | `templates/index.html` |

Маршруты кандидата: главная, каталог, новинки (премьеры и добавленные),
фильмы, сериалы, анимация, подборки, поиск с результатом, пустой поиск,
страница фильма, страница сериала, сезон, эпизод, несуществующий адрес.

## Что измеряется автоматически

Измеритель — `automation/host/zona-visual-audit.py`. На каждой паре
«страница × ширина» снимается:

| Измерение | Как получено |
| --- | --- |
| горизонтальное переполнение | `scrollWidth - innerWidth` документа |
| элементы шире экрана | обход видимых элементов вне объявленных прокруток |
| обрезанный текст | `scrollWidth > clientWidth` у листьев без `data-clamp-allowed` |
| карточки без названия | пустой или невидимый `.zt__t` |
| неоткликаемые карточки | `elementFromPoint` в центре карточки внутри экрана |
| битые картинки | `complete && naturalWidth === 0` |
| невидимые и перекрытые органы | размер, стиль и попадание указателя |
| мелкие цели | меньше 24×24 |
| мёртвая полоса | высота секции минус габарит её видимого содержимого |
| сдвиг раскладки | `PerformanceObserver` по `layout-shift` |
| высота первого экрана | высота героя против высоты окна |
| заполненность сетки | число карточек в `.zg` |
| число H1 | `document.querySelectorAll('h1')` |
| дубли DOM-id | пересчёт всех `[id]` |
| смена состояния слайдера | сверка ID, заголовка, картинки и адреса CTA после действия |
| видимость фокуса | `:focus-visible` после клавиши Tab |

## Слайдер: проверяется состояние, а не наличие кнопки

На каждой ширине выполняется девять шагов, и после каждого сверяются четыре
поля активного слайда:

1. нажатие «вперёд»; 2. ещё раз «вперёд»; 3. «назад» — обязан вернуть на
предыдущий; 4. нажатие на точку — обязано привести ровно на свой слайд;
5. `ArrowRight`; 6. `ArrowLeft`; 7. свайп указателем мимо органов управления;
8. цикл вперёд с последнего слайда на первый; 9. цикл назад.

Плюс серия из десяти быстрых нажатий подряд: точка обязана оказаться там, где
предсказано арифметикой, а не «где-то рядом».

## Оговорки, без которых снимки можно понять неверно

* **Постеры на снимках — заглушки.** Стенд работает без сети, и внешние
  картинки подменяются PNG той же пропорции с устойчивым цветом из адреса.
  Это сделано, чтобы «битыми» не оказались все постеры сразу и чтобы
  композиция читалась. Судить по снимкам о самих постерах нельзя — только о
  раскладке, плотности, ритме и типографике.
* **Снимок — первый экран**, а не вся страница: сравнивать шаблоны удобнее по
  одинаковому кадру.
* **Данные — выборка боевого снимка**, а не весь каталог: отбор
  детерминирован и описан в `zona-sample-snapshot.py`. В выборку намеренно
  включены записи без постера, без даты и без оценок.
* **Приёмка владельцем не проводилась.** Всё перечисленное — технические
  кандидаты.

## Две находки, которые оказались ошибкой измерителя

Записано, потому что «приёмка нашла дефект» и «приёмка ошиблась» должны
различаться:

1. 24 карточки «без названия» на главной при 390px. Это карточки двух
   закрытых вкладок недельного блока (по 12). Скрытое вкладкой — замысел;
   измеритель теперь их исключает и считает отдельно.
2. «Перекрытый» орган управления ниже сгиба. Точка попадания зажималась краем
   экрана, и проверка находила то, что попало в зажатую точку. Теперь
   элементы вне экрана помечаются непроверяемыми, а не перекрытыми.

Третья похожая: фокус проверялся программным `focus()`, на котором
`:focus-visible` не срабатывает. Теперь фокус ставится клавишей Tab.
