## Что произойдёт при запуске root-команды

Порядок из восьми шагов, только для `zona-01`:

1. базовые отпечатки `zonafilm.space` (сейчас `1.0.2`);
2. установка кандидата `1.1.0` штатным установщиком;
3. доказательство, что домен отдаёт именно новый артефакт;
4. обход маршрутов, сверка сущностей, границы серий;
5. учебный откат на `1.0.2`;
6. сверка восстановленного отпечатка — теперь по релизу И по измеренной структуре;
7. возврат кандидата вперёд на `1.1.0`;
8. три последовательные публичные проверки.

### При успехе

`zona-01` остаётся на `1.1.0`, вердикт `CANARY_ACTIVE_VERIFIED`, отчёт в
`canary-run/canary-run.json`, публичные адреса — в поле `public_urls`.

### При ошибке

На шагах 3–4 — немедленный откат и остановка. На шагах 5–6 витрина уже на
`1.0.2` и там остаётся. На шаге 7 срабатывает аварийный возврат самого
установщика. На шаге 8 порядок сам возвращает витрину на прежний релиз
(`rollback_after_final`) — на неподтверждённом кандидате витрина не остаётся.
Во всех случаях итог один: `zona-01` на здоровой `1.0.2`.

### Lords

В команде нет `lords-01`: ни в `--sites`, ни в профиле. Перезапускается ровно
один юнит — `nova-zona-01.service`. Манифест Lords не переписывается. Общий файл
`lords-frontend.py` записывается тем же содержимым, которое уже на диске
(см. `shared-artifact-write.json`).

## Оговорка про 210 серий

У Zona двухсот десятой серии в снимке источника нет: самый длинный сериал —
182 серии, и границы проверяются по фактическому пределу `1,2,99,100,101,181,182`.
Случай 210 серий закрыт на Lords (286 серий, границы `…,209,210`, за последней —
404). Выдумывать отсутствующую у источника серию нельзя.
