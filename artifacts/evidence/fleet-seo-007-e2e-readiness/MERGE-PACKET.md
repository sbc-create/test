# Пакет слияния: тег Метрики в канонический рендерер

## Зачем

Боевые витрины сейчас отдают тег Метрики. Канонический рендерер его **не
содержит**: ветка `claude/templates-zona-animedia-visual-parity-005`,
коммит `0a2658c`, переработала шаблоны Zona и Animedia (+830/−202 строки) и
вставку аналитики не перенесла.

Выложите `0a2658c` — тег исчезнет со всех четырёх витрин. Страницы будут
отдаваться как ни в чём не бывало; пропажу станет видно только по отчёту
Метрики через сутки.

## Что готово

Ветка `claude/fleet-seo-007-e2e-readiness`, коммит `ba69ad1`, ответвлена
**от вашей вершины `0a2658c`**. Она содержит ровно одно изменение рендерера:
вставку тега в `_отдать` — единственную точку, через которую уходят все
двадцать семь выходов обработчика.

Слияние конфликтов не даст: ваша работа взята целиком и не тронута.

## Почему не в шаблон

Тег стоял в шаблонах — в пяти местах. Ваша переработка добавила два новых
`<head>`, и про них надо было помнить. Это и есть причина пропажи: не
невнимательность, а место вставки. В отдаче ответа забывать нечего.

## Что проверено

* при пустом счётчике рендерер отдаёт **побайтово то же самое**, что ваш
  исходный, на всех пяти маршрутах — визуально не изменилось ничего;
* с заданным счётчиком — ровно один тег и одна инициализация на маршрут,
  на обоих ваших новых оформлениях (`lords-sheet` и `zona-rail`);
* повторная отдача второго тега не добавляет;
* 23 проверки ворот релиза: свой счётчик у каждого домена, чужой на страницу
  не попадает, негодное значение даёт страницу без тега.

## Что нужно от вас

Влить `ba69ad1` перед следующей выкладкой рендерера. Одна команда:

```
git merge claude/fleet-seo-007-e2e-readiness
```

После выкладки юниты витрин должны иметь переменную `LORDS_METRIKA_COUNTER`
(drop-in уже стоит на всех четырёх). Без неё код отработает штатно и отдаст
страницу без тега — молчащего тега не будет.
