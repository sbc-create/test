# Остаточные блокеры после visual-repair-cycle-3

`overall_score` остаётся 33.19/100 — до порога 80 далеко, и ни один из
оставшихся ниже пунктов не устраняется правкой `factory/lords/**`. Порядок —
по величине вклада в потерянный балл (вес компонента × доля потери).

## 1. `structure_order` (вес 30%, счёт 0.0/100 на всех 15 ячейках)

**Владелец: контракт `contracts/visual-scoring` (PR #81) и/или инструмент
замера эталона `tests/tools/measure_reference.js` / `docs/reference-packs/
amd-online`.** Не Lords/Core.

Причина установлена точно (см. `scoring-summary.json.structure_order_zero_root_cause`):
эталонный pack не содержит ни одного токена `block_order`/`required_block_*_present`
— инструмент замера эталона не умеет извлекать структурный порядок с живого
чужого сайта без пользовательских `data-visual-role` атрибутов, которых там
нет и быть не может. Кандидат структурно готов (75/75 токенов на 15 ячейках).
Правка требует решения владельца контракта (эквивалентный способ мерить
структурный порядок эталона) или явного исключения компонента с
перераспределением веса — оба выхода вне `factory/lords/**`.

## 2. `header_sticky` (часть `geometry`, кандидат `true` / эталон `false`, все 15 ячеек)

**Владелец: `blueprints/lords/profiles/animedia-portal.yaml`** (профильное
решение) **или новый запрос к владельцу `factory/lords/**`** на профильный
флаг `layout.header_sticky` (тогда это станет задачей Lords/Core, но только
после того, как владелец профиля попросит именно это).

Источник в общем слое — `factory/lords/theme.py:473`
(`.site-header{position:sticky}`) — общий для всех профилей, поведение
корректное и обычное; несовпадение — то, что `amd.online` НЕ держит шапку
прилипающей, а этот шаблон — держит везде. Менять поведение для всех
профилей ради одного эталона запрещено этим же циклом («не подгоняй число
под один кандидат»).

## 3. `type_h3_font_size` / `type_h3_font_weight` (часть `typography`)

**Владелец: дизайн-система Lords/Core (не эта сессия) либо профильный
override, если шаблон его для этого заведёт.**

Эталон 14px/500, кандидат `.card__title{font-size:.92rem;font-weight:600}`
(`factory/lords/theme.py:674`) — общий дизайн-токен, используемый всеми
профилями. Приводить его к 14/500 в общем слое означало бы тюнинговать общий
CSS под одну Animedia-референс-пару.

Побочное наблюдение (не исправлено, не входит в CORE-HANDOFF): `.card__title`
резолвится от `<html>` без явного `font-size` (implicit UA default), а не от
задекларированной базы `<body>{font-size:14px}` — см. cycle-2 README, раздел
«Побочное наблюдение». Требует отдельного решения владельца дизайн-системы,
не одностороннего решения этой ветки.

## 4. `cards_media` на `collection_hub` (tokens_missing=2 на всех 3 ширинах)

**Владелец: `tests/tools/measure_candidate_tokens.js`** (инструмент замера
кандидата, не тронут ни одним из трёх циклов ремонта PR #76).

Инструмент не публикует токены `cards_media` для поверхности `/collections/`,
хотя эталон их ожидает (contract не относит `collection_hub` к
`not_applicable` для `cards_media` — в отличие от `catalog`/`not_found`).
Не входит в CORE-HANDOFF и не является дефектом `factory/lords/**` — карточки
на `/collections/` рендерятся (`factory/lords/render.py::_collections_index`),
просто измеритель их не снимает. Отдельная задача для владельца инструмента
замера.
