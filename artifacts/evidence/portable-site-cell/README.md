# Доказательства PORTABLE-SITE-CELL-01

Содержимое каталога получено одним прогоном пилота. Ничего не заполнялось
вручную: файл, которого здесь нет, означает проверку, которая не запускалась.

| Файл | Что это |
| --- | --- |
| `pilot.json` | итог прогона: каждые ворота с исходом `PASS` / `FAIL` / `NOT_RUN` и подробностями |
| `pilot-AGENTS.md` | правила, которые получает сгенерированный проект сайта |
| `pilot-site-manifest.json` | паспорт сайта из сгенерированного проекта, включая владение полями |
| `pilot-ci-release.yml` | шаблон CI проекта сайта: группа параллелизма на сайт, отказ чужому `site_id`, отказ устаревшему выкату |
| `pilot-cell-*.release-manifest.json` | манифесты двух релизов пилота: digest, исходный коммит, закреплённые версии |

## Как воспроизвести

```bash
PYTHONPATH=. python3 tests/tools/cell_pilot.py \
  --root var/cells/pilot-run-05 --keep \
  --evidence artifacts/evidence/portable-site-cell/pilot.json
python3 -m pytest tests/integration/test_cell_pilot.py -q
```

Прогон без `--root` работает во временном каталоге и удаляет его за собой;
в отчёте это видно по полю `pilot_root_kept`.

## Что читать в `pilot.json`

`summary` даёт три числа. `not_run` — не «почти пройдено»: у каждого такого
ворота в `detail.reason` записано, чего именно не хватило. На момент прогона
непройденными остаются настоящий remote и CI, межсерверный перенос,
переключение домена, живой SEO-процесс и Topvisor — все пять по отсутствию
доступа, а не по результату проверки.

Два манифеста релиза здесь не случайно: пилот собирает второй релиз, чтобы
проверить точечный выкат, отказ устаревшему выкату и откат. Оба принадлежат
одному сайту — `source_repo` и `site_id` в них совпадают.

## Чего здесь нет

Данных сайта, дампов, секретов и снимков баз. Пакет доказательств — это отчёт о
проверках, а не резервная копия: собранный артефакт и данные переносятся
разными каналами, и смешивать их нельзя.
