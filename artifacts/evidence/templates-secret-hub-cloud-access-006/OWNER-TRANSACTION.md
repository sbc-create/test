## Что исправлено по шести замечаниям

### 1. Область: 13 из 13, а не 10 из 13

Прежняя редакция выводила три юнита Yami за область как «чужой продукт». Это
организационный критерий, применённый к технической границе: юнит, исполняющий
от root файл `0664 claude:claude`, держит границу открытой независимо от того,
чей он.

`out_of_scope` теперь пуст. Все 13 затронутых входят в транзакцию. Полная
таблица по **всем 27** root-юнитам хоста — `root-units-table.json`, колонки:
unit, ExecStart, интерпретатор, транзитивный код, владелец/права, доступно ли
на запись `claude`, доступ к credentials, затронут, включён, причина.

Последствие, которое нельзя замолчать: перенос скриптов Yami замораживает их —
новая выкладка продукта перестанет вступать в силу сама, продукту понадобится
перезакрепление на каждом релизе. Это записано в `manifest.json →
coordination_required` и требует согласования с владельцем Yami.

### 2. Один коммит вместо двух

Прежде код брался из `6fcd337`, а файлы транзакции жили в другом коммите — два
разных объекта без доказательства идентичности.

Манифест объявляет источник как `SELF`: тот самый коммит, в котором он лежит.
Хеша этого коммита во время сборки ещё не существует, поэтому провенанс
считается по рабочему дереву, а совпадение дерева с коммитом подтверждается
**после** фиксации сверкой sha256 каждого файла против объектов git
(`verify-self-reference.sh`). Без этой сверки самоссылка была бы обещанием.

Проверено на текущем коммите: 159 файлов совпали.

`SOURCE_COMMIT` = `TRANSACTION_COMMIT` = `INSTALLER_COMMIT` =
`PROVENANCE_COMMIT` = `MANIFEST_COMMIT` — по построению, а не по сверке.

### 3. Загрузчик усилен

`automation/hardening/bootstrap.sh`:

* абсолютные пути ко всем системным бинарникам, каждый проверяется на
  принадлежность root перед использованием;
* `set -euo pipefail`;
* **уникальный** root-owned staging на каждый запуск (`mktemp -d` в `/root`,
  режим 0700) — переиспользование каталога означало бы, что в нём может лежать
  что-то от прошлого раза;
* выгрузка из git идёт **от непривилегированного пользователя** через
  `setpriv --reuid --regid --clear-groups --no-new-privs`; при отсутствии
  `setpriv` транзакция отказывает, а не выгружает от root;
* отключены `replace`-объекты, grafts, alternates, системная и пользовательская
  конфигурация git (`GIT_NO_REPLACE_OBJECTS`, `GIT_GRAFT_FILE=/dev/null`,
  `GIT_ALTERNATE_OBJECT_DIRECTORIES=`, `GIT_CONFIG_*`, `HOME=/nonexistent`) —
  каждый из них способен подменить содержимое, которое git отдаёт по имени
  коммита, не меняя самого имени;
* sha256 **установщика, release.json, provenance.json и manifest.json**
  проверяются значениями из отчёта владельца **до первого исполнения**;
* совокупный отпечаток сверяется с **литералом из команды владельца**, а не с
  тем, что записано в `release.json`: файл, проверяющий сам себя, не проверяет
  ничего;
* подмена любого управляющего файла останавливает транзакцию **до** изменения
  системы.

### 4. Проверки хоста встроены, откат сравнивается с baseline

`host_checks.py` снимает состояние **до** первой мутации (`baseline.json`) и
**после** установки. Проверяется: эффективные определения юнитов, владельцы и
права всего закреплённого дерева, разрешение символических ссылок, отсутствие
кода агента во всей цепочке (глобально), `systemd-analyze verify`, активность
юнитов и таймеров, здоровье конвейера обновления каталога, здоровье витрин
Lords, **отпечаток отдаваемого витриной контента**, отсутствие следов значений
секретов в созданных файлах и в журнале.

Любой провал запускает откат; после отката состояние **сравнивается с
baseline**, и расхождение называется вслух. Без этого «вернулись как было»
означало бы «скрипт дошёл до конца без ошибки».

Аудит после установки теперь требует **глобального** нуля: любой оставшийся
root-юнит с кодом агента останавливает транзакцию, независимо от области.

## Доказательство до установки

`simulate_post_transaction.py` считает состояние границы после транзакции **без
единой мутации**: собирает эффективные определения юнитов так, как их увидит
systemd после drop-in'ов, и проверяет каждый путь к коду. Существующие пути
сверяются по фактическому владельцу и правам; пути внутри будущего
закреплённого каталога принимаются по построению — его создаёт и делает
root-owned сам установщик.

Текущий результат: **глобально чисто**, 27 root-юнитов охвачено, 13
закрепляется, ноль путей к коду на территории агента.

Это не заменяет пост-аудит внутри транзакции, а отвечает на тот же вопрос
заранее: отчёт операции о самой себе — слабейший вид доказательства, и получить
его можно только выполнив операцию.

## Что транзакция НЕ делает

Не публикует панель, не трогает nginx, не читает и не меняет значения
credentials, не трогает шаблоны, каталоги, контент, SEO, плеер, DNS и TLS. Ни
один `LoadCredential` не добавляется и не убирается. Меняются только пути, по
которым root берёт **код**; пути к данным (`FACTORY_REPO`,
`LORDS_ARTIFACT_ROOT`) остаются прежними намеренно.

## Что нужно для финальной пересборки

Один коммит от владеющей сессии с финальным состоянием набора:

```
automation/host/nova-daily-refresh.sh
automation/host/nova-catalog-publish.py
automation/host/nova-detail-backfill.py
```

После него: манифест переводится на этот коммит, провенанс пересчитывается,
самоссылка перепроверяется, симуляция прогоняется заново, и только тогда
выдаётся одна runnable-команда с актуальными хешами.
