# Ночная сессия: выделение сайтов в отдельные репозитории

## Общий блокер, установленный один раз

`sudo` и `systemctl` запрещены `.claude/settings.json → permissions.deny`
(правила `Bash(sudo *)`, `Bash(systemctl *)`). Это **общий** блокер: активация
невозможна ни для одного домена. Обходов не искал, по доменам не повторял.

Второй общий блокер: домены очереди отсутствуют в
`inventory/network-allowlist.yaml`, поэтому публичная проверка снаружи не
выполнялась ни для одного сайта.

## Что сделано

Написан `factory/cell/extract.py` — выделение **действующего** сайта в свой
репозиторий. Источник истины — наблюдаемое состояние хоста, а не профиль:
порт и юнит из реестра рантайма, переменные из самого юнита systemd,
исполняемые файлы из каталога релиза, происхождение из `RELEASE.json`.

Почему из юнита, а не из профиля: они расходились. У animedia-02 профиль нёс
счётчик и canonical соседнего сайта, а юнит — правильные пути. Переносить надо
то, что работает.

Где `RELEASE.json` не содержал путей (zona-01), файлы искались в исходном
коммите по имени и сверялись по sha256 — совпадение имени само по себе ничего
не значит. Это подняло происхождение zona-01 с нуля до 5 из 7 файлов.

## Найденные ограничения, которые отдельный репозиторий не снимает

1. **Yummy: общий read-model.** `YUMMY_READMODEL` — один SQLite на все три
   витрины в общем каталоге. Пока он общий, изоляция данных между
   yummyani.site/org/biz **не достигнута**, сколько бы репозиториев ни завели.
2. **Yummy: нет неизменяемого релиза.** Рантайм исполняется прямо из общего
   изменяемого `/srv/lords/.frontend`, без `RELEASE.json`.
3. **Yummy проксирует в контейнер Next.js** своего домена — отдельный запуск
   требует и контейнера.
4. **Lords: модуля комментариев нет.** В релизе lords-01 три файла, community
   среди них отсутствует — в отличие от Animedia.
5. **zona-01 без каталога данных**: `/srv/lords/zona-01/data` не существует,
   то есть хранилища комментариев у Zona ещё нет.
6. **Yummy вне реестра фабрики**: у витрин нет ни профиля, ни пакета, и
   `consistency_report` это показывает.

Ни один живой сайт не изменялся. Все службы работают на прежних релизах,
