# Обязательный короткий отчёт после каждого задания

## Структура отчёта (6–8 строк)

1. **Статус:** выполнено / частично / заблокировано
2. **Сделано:** конкретные изменения либо результаты диагностики
3. **Проверено:** фактический результат и способ проверки
4. **Не получилось:** точная ошибка; если ошибок нет — «нет»
5. **Осталось:** конкретная незавершённая часть
6. **Доказательства:** process_id и путь к журналу; для изменений — коммит или сохранённый diff
7. **Следующее действие:** что выполняешь дальше; нужна ли конкретная помощь владельца

## Правила проверки

- process_id копируй дословно из результата соответствующего run_command
- Статус running и exit_code=null не означают завершение
- При 404 проверь правильность ID, затем прочитай log_path именно исходного запуска
- Не называй ошибку инструмента статуса разрывом SSH
- Не повторяй изменяющую команду, пока неизвестен результат первого запуска
- Разделяй: файл записан, изменение выложено, результат проверен на сайте
- Непроверенное обозначай явно; не заполняй пробелы предположениями

## Примечание

Не заканчивай ответ только вызовами инструментов или фразой «сейчас продолжу».
Промежуточный отчёт не является поводом прервать оставшуюся разрешённую работу.
Полные команды и результаты сохраняй в журнале. В чат выводи краткий итог;
при ошибке добавляй проблемную команду и существенный stderr.
