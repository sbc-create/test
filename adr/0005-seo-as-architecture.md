# ADR-0005. SEO как часть архитектуры, а не финальная косметика

- Статус: принято, 2026-08-21

## Решение

`knowledge/SEO_INDEXABILITY_MATRIX.yaml` — **вход рендера**. Для каждого из 20 типов
страниц зафиксированы: назначение, URL-шаблон, допустимые статусы, index/follow,
правило canonical, участие в sitemap, источники title/H1/description/текста, допустимая
structured data, обязательные внутренние ссылки, правила пагинации, требования к
VK-видео и условия `BLOCKED_SEO`.

Тип страницы, которого нет в матрице, **не рендерится** — `factory/render.py::_policy`
поднимает `BlockedSeo`.

Проверки идут тремя слоями, и каждый доказан негативными тестами:

| Слой | Что доказывает | Инструмент |
|---|---|---|
| `seo-lint` | артефакты сборки: canonical, дубли, sitemap, JSON-LD, пагинация, orphan | статический разбор HTML |
| `seo-crawl` | живой HTTP: статусы, редиректы, доступность страницы N напрямую, связность | обход по обычным ссылкам |
| `seo-render` | отрендеренный DOM: мобильная раскладка, видимость плеера, консоль, a11y, лабораторные метрики | Chromium + axe-core |

## Провенанс правил

Официальные источники (Google Search Central, Яндекс Вебмастер, web.dev, W3C) закрыты
egress-политикой этой сессии — 403 на CONNECT. Правила перенесены из мастер-промпта
пользователя и помечены `verified_against_official_docs: false`. Тест
`test_seo_matrix.py::test_matrix_is_marked_unverified_against_blocked_sources`
не даёт снять этот признак незаметно.

## Последствия

- Новый тип страницы = сначала запись в матрице (через `/research-freeze`), потом шаблон.
- Полевые Core Web Vitals не подменяются лабораторными: `performance-budget` явно
  различает их в отчёте.
