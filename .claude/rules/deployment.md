# Деплой и конвейер

- Состояния: `RECEIVED → VALIDATING → READY → BUILDING → BUILT → STAGING_DEPLOY →
  STAGING_QA → AUTHORIZATION_CHECK → PRODUCTION_DEPLOY → PRODUCTION_SMOKE → MONITORING → DONE`.
- Ошибка — всегда точный статус из перечня, не общий `failed`.
- Один job обрабатывается ровно один раз семантически даже после restart. Lock на
  `site+environment` исключает параллельное изменение.
- Каждый шаг идемпотентен и имеет timeout. Retry только для явно временных ошибок:
  exponential backoff + jitter + конечный лимит. Ошибки конфигурации, лицензии, прав и
  авторизации не ретраятся.
- После исчерпания retry — quarantine с root cause и следующими действиями.
- `plan` и `--dry-run` не меняют инфраструктуру ни при каких условиях.
- `production_authorized: false` → `BLOCKED_AUTHORIZATION`, ноль мутаций.
- Успешный staging не является разрешением на production.
- Сбой модели, лимит API или недоступность переводят job в retry-состояние и никогда
  не вызывают повторную публикацию уже применённого релиза.

## Адресная установка пакета: контроль автоматических перезапусков

Повод измеренный, 23.10. Нужна была ОДНА библиотека для ОДНОЙ витрины-канарейки
(`python3-pil` для уменьшения обложек на `animedia.icu`). `apt-get install`
отработал как просили, но вызванный им `needrestart` перезапустил **41 службу**
— включая `nginx`, `postgresql@16-main`, `ssh`, несколько витрин и службы Site
Factory. Область действия вышла за канарейку. У `animedia.icu` перед успешным
`healthz` было четыре ответа 502.

Вреда не осталось (проверено: 25 домéнов 200, 25 `healthz` ok, postgresql
принимает подключения, ssh работает, фоновая запись возобновилась), но это
удача, а не свойство операции.

**Правило.** Адресная установка пакета на узле с живыми витринами выполняется с
управляемым перезапуском, а не с автоматическим:

1. **Проверенный режим для конкретной операции.** Установка идёт без
   автоматических перезапусков:
   ```bash
   sudo NEEDRESTART_MODE=l apt-get install -y <пакет>
   ```
   `NEEDRESTART_MODE=l` означает «только перечислить, что требует перезапуска».
   Перечень читается, и дальше перезапускается ТОЛЬКО то, что нужно операции.
2. **Управляемый перезапуск нужных служб.** Для библиотеки, которую читает одна
   витрина, это одна служба:
   ```bash
   sudo systemctl restart nova-animedia-icu.service
   curl -s https://animedia.icu/healthz | head -c 120
   ```
3. **Проверка результата — в окружении службы, а не сессии.** Проверяется не
   «установлен ли пакет», а РЕАЛЬНОЕ преобразование тем интерпретатором и той
   учётной записью, которыми идёт служба:
   ```bash
   python3 automation/local/service-image-support-check.py \
       --user animedia-icu --url https://<домен>/poster/<uuid>.webp \
       --expect-width 480
   ```
   Эта проверка стоит в ночном проходе (`night-surface-pass.py --only images`),
   потому что её отсутствие не видно ни по одному другому признаку: 23.10
   правка уменьшения обложек была выпущена и полдня не действовала.
4. **Если перезапуск всё же был массовым** — проверяется последствие, а не
   предположение: доступность всех домéнов, `healthz` каждой витрины, порты,
   база, ssh и возобновление фоновой записи. Образец такой проверки —
   `docs/RESTART_CONSEQUENCES_20261023.md`.

**Чего правило НЕ требует.** Отключать `needrestart` постоянно или откладывать
обновления безопасности не нужно: режим `l` ограничивает только ОДНУ операцию.
Решение о массовом перезапуске остаётся за владельцем — правило лишь требует,
чтобы он был выбран, а не случился.
