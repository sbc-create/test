# Подключение сайта к общему модулю комментариев

Правило одно: сайт ссылается на закреплённый артефакт и передаёт конфигурацию.
Исходников комментариев в шаблоне сайта нет. Ради этого модуль и существует —
четыре копии, расходящиеся по мелочам, и есть то состояние, которого мы
избегаем.

Машиночитаемый контракт:
`artifacts/evidence/community-comments-platform-01/01-contracts/INTEGRATION_CONTRACT.json`.

## Что закрепляет сайт

Строка в `config/comments-platform/sites.json`:

```json
{
  "tenant_id": "lords",
  "site_id": "lords-01",
  "hosts": ["lordfilm47.space"],
  "allowed_origins": ["https://lordfilm47.space"],
  "module_version": "0.1.0-mvp",
  "artifact_checksum": "6032fb3c…",
  "theme": "dark",
  "language": "ru",
  "moderation_mode": "pre",
  "read_enabled": 0,
  "write_enabled": 0,
  "publication_enabled": 0,
  "seo_mode": "user_initiated",
  "rollout_percent": 0,
  "max_depth": 3,
  "max_length": 4000,
  "max_links": 2
}
```

`module_version` — точное значение. `latest`, `main`, `HEAD`, `stable` и
пустая строка отклоняются при загрузке реестра, а не при выкате: плавающая
версия превращает вопрос «какой код сейчас на animedia» в такой, на который
после факта уже никто не ответит.

`artifact_checksum` — sha256 файлов виджета, считается
`scripts/comments_platform_artifact.py`. Версия говорит, что собирались
поставить; сумма говорит, что реально отдаётся. Без второго «lords на 0.1.0»
не проверить после неудачной копии или закешированного файла.

Домены и `site_id` берутся из `config/FLEET-REGISTRY.json` и ниоткуда больше.
Придуманное имя хоста в списке CORS — это дефект безопасности, а не опечатка.

## Разметка на странице

```html
<link rel="stylesheet" href="/static/comments/comments-widget.css">

<div id="comments"
     data-cp-comments
     data-cp-resource-type="title"
     data-cp-content-id="tt-0001"></div>

<script src="/static/comments/comments-widget.js"></script>
<script>
  SiteFactoryComments.mount("#comments", {
    apiBase: "",              // пустая строка — тот же origin
    resourceType: "title",
    canonicalContentId: "tt-0001",
    csrfToken: window.__csrf, // обязателен при куки-аутентификации
    theme: "dark",
    locale: "ru"
  });
</script>
```

Стиль обязан загружаться до первой отрисовки: он резервирует высоту точки
монтирования. Без резерва контейнер нулевой высоты, и появление виджета
толкает всю страницу вниз — измеренный CLS 0.45.

Что **нельзя** передавать в конфигурацию: `tenant_id`, `site_id`, `tenant`,
`site`. Запрос, несущий любое из этих полей, отклоняется целиком — не
игнорируется. Молча отбросить значение означало бы позволить вызывающему
думать, что подмена сработала. Арендатор определяется сервером по Host.

## Ключ обсуждения

```
tenant_id · site_id · resource_type · canonical_content_id
```

URL и slug не участвуют. Смена домена, slug или canonical не создаёт новую
ветку комментариев — именно это и случилось бы, будь ключом адрес.

`resource_type` — одно из `title`, `episode`, `collection`, `article`,
`person`. Список закрыт.

## Идентичность

Сайт передаёт провайдера идентичности — объект с одним методом:

```python
class SiteAuth:
    def authenticated_subject(self, request_context) -> str | None:
        # уже проверенная сессия -> непрозрачный идентификатор, иначе None
        ...
```

Модуль никогда не видит пароль, содержимое cookie или email. Публичный
идентификатор выводится HMAC на ключе арендатора, поэтому один человек на
`lords` и на `zona` даёт два несвязанных значения: без обоих ключей
сопоставление не вычисляется. Ник, репутация, mute и баны раздельны по сайтам.

Сайтам без авторизации подходит гостевой режим: случайный непрозрачный токен
в cookie `cp_guest`. Это не отпечаток устройства и не выводится из него —
отпечаток уничтожил бы всё свойство несвязанности.

## Режимы SEO

| Режим | Что отдаётся до JS | Когда |
| --- | --- | --- |
| `user_initiated` | точка монтирования | по умолчанию, пока владелец не решил иначе |
| `ssr_first_page` | первая страница опубликованных | сайту нужна индексация комментариев |
| `ssr_paginated` | страница по курсору | длинные ветки |

В SSR попадают только `published` и `restored`. Ни `pending`, ни `hidden` не
присутствуют ни в разметке, ни в скрытом DOM, ни в JSON-острове: комментарий,
попавший в отданные байты, опубликован, что бы ни говорил CSS.

SSR включается только вместе с публикацией: отрисовать комментарии в HTML,
который читает краулер, и есть публикация.

## Отказ модуля

Страница обязана выжить. Все точки входа виджета обёрнуты, ошибка не уходит в
JavaScript хозяйской страницы, отказ API вырождается в сообщение в одном
блоке. Ошибка при этом не глушится молча — она уходит в `console.warn` и в
телеметрию: не ронять страницу и не оставлять следа — разные цели, и ценна
только первая.

## Телеметрия

Колбэк `onEvent` получает только форму события: `event`, `version`, `phase`,
`ms`, `count`, `status`, `code`, `sort`. Разрешённый список, а не
запрещённый, — новая точка вызова, передавшая текст, просто теряет его.
Текста комментариев, идентификаторов субъектов и токенов в событиях нет.
