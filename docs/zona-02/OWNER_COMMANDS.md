# zonafilm.cc — что осталось владельцу

Витрина собрана, выложена из собственного репозитория и работает службой с
автозапуском. Осталось то, что приходит снаружи этой сессии.

## Состояние на 23.09.2026

**Служба установлена.** `zonafilm-cc-activate.sh --apply` выполнен: юнит
`nova-zona-02.service` стоит, включён в автозапуск, работает от пользователя
`lords` и исполняет релиз собственного репозитория. Временного процесса рядом
нет. Скрипт остановился на сертификате — записи A ещё нет — и юнит при этом не
откатил.

Осталось **одно действие**: создать запись DNS и запустить ту же команду
повторно. Всё остальное на хосте она доделает сама.

| Осталось | Что именно | Что открывает |
| --- | --- | --- |
| **Запись DNS** | A для `zonafilm.cc` и `www` в панели Cloudflare | сертификат, vhost, публичный HTTPS и публичная приёмка |
| Отдельно: доступ к секретам | учётная запись, читающая токен Метрики и каталог Topvisor | счётчик и проект |

Почему запись не создаётся отсюда: `inventory/dns-zones.yaml` пуст, учётных
данных Cloudflare стенду не передавалось. Пустой реестр — `BLOCKED_INPUT`, а не
«разрешено всё».

Почему секреты не читаются отсюда: токен Метрики лежит под `0600 root:root`,
каталог Topvisor — под `0440 root:ubuntu`, и сессия не входит в эту группу.
Так и задумано: их читает сервисная учётная запись. Привилегированное
исполнение самой сессии закрыто `deny`-списком настроек, а штатный обходной
путь фабрики — root-runner релиз-оркестратора — на хосте не развёрнут
(`/usr/local/bin/site-factory-release-runner` отсутствует,
`/var/lib/site-factory` не создан). Проверено по одному разу, повторных
попыток не делалось.

## Действие 1 — запись DNS (панель Cloudflare, зона `zonafilm.cc`)

```
A    zonafilm.cc       45.131.182.225   Proxy status: DNS only
A    www.zonafilm.cc   45.131.182.225   Proxy status: DNS only
```

`45.131.182.225` — не догадка: то же значение в `origin_ipv4`
(`config/directions/lords.json`) и в живой записи соседней витрины
`zonafilm.space`, которая резолвится в него же (измерено).

`DNS only` — не предпочтение: proxy-режим поставил бы поверх витрины кэш и
сертификат Cloudflare, и `X-Robots-Tag: noindex`, который отдаёт origin, начал
бы зависеть от политики кэширования CDN. Это ровно тот риск случайного
открытия индексации, который по заданию исключён.

Зона делегирована и активна, записей A и AAAA в ней сейчас нет вовсе — выкат
не затронет ничего чужого.

## Действие 2 — та же команда на хосте, повторно

```bash
sudo bash /home/claude/wt-zona-02-launch-01/automation/host/zonafilm-cc-activate.sh --preflight
sudo bash /home/claude/wt-zona-02-launch-01/automation/host/zonafilm-cc-activate.sh --apply
```

Первая ничего не меняет: проверяет ссылку на релиз, наличие юнита и vhost
внутри него, принадлежность порта 9123 именно этой витрине по живому реестру,
наличие снимка каталога и бокового файла плеера, состояние DNS и сертификата.

Вторая ставит службу, ждёт готовности, и дальше — сертификат, vhost, публичная
проверка. Первый запуск (23.09.2026) дошёл до службы и остановился на
сертификате: записи A не было. Юнит при этом не откатился — **служба не
заложник записи DNS**. Повторный запуск после появления записи продолжит с
сертификата, уже поднятую службу обновит и перезапустит, а не тронет
установку заново.

Проверяется не код возврата, а наблюдаемый признак: `systemctl enable`
возвращает 0 и для витрины, которая не поднялась, поэтому шаг считается
пройденным только при `200` на `/healthz` и совпавшем
`X-Site-Factory-Build-Id`. Публичный `200` без совпавшего build-id тоже
считается провалом: `200` может отдать соседняя витрина, поймавшая имя.

Временный проверочный процесс сессии на порту 9123 скрипт останавливает сам,
до включения юнита, и отказывается идти дальше, если порт не освободился.
Одновременной работы временного процесса и службы не будет.

Те же два файла лежат внутри релиза витрины
(`/srv/lords/.frontend/sites/zona-02/current/deploy/`) — ячейка ставится и без
доступа к каталогу фабрики.

## Действие 3 — интеграции, под учётной записью с доступом к секретам

```bash
sudo -u <учётная-запись> bash \
  /home/claude/wt-zona-02-launch-01/automation/host/zonafilm-cc-integrations.sh --preflight
sudo -u <учётная-запись> bash \
  /home/claude/wt-zona-02-launch-01/automation/host/zonafilm-cc-integrations.sh --metrika-apply
```

`--preflight` ничего не создаёт: показывает, читаются ли секреты, что Метрика
уже знает про домен и что уже есть в аккаунте Topvisor.

`--metrika-apply` создаёт счётчик **или переиспользует существующий**: домен
заведён в реестре аналитики (`config/analytics.json`, состояние `planned`,
счётчик `null`), а провайдер сначала ищет счётчик этого домена и берёт
найденный; при двух счётчиках на домен он останавливается, а не выбирает.
Второго счётчика эта команда не создаст.

Topvisor платный, поэтому команда его только планирует и печатает план.
Создание проекта — отдельное решение владельца. Проект `zonafilm.cc` описан в
манифесте (`factory/topvisor/manifest.py`): домен, название, группы запросов,
регион, съём позиций «вручную, после отдельного разрешения», технический аудит
«запланирован, не запускался». Планировщик сверяет аккаунт по домену и
отключает создание целиком, если хоть одну запись не удалось прочитать.

После создания счётчика витрина начнёт его отдавать не сразу: номер вписывается
в `config/runtime.json` проекта сайта, выпускается релиз и ставится. Пока номер
пуст, страница не содержит тега вовсе — ни скрипта, ни noscript-пикселя. Это
намеренно: молчащий тег неотличим от рабочего до первого отчёта.

## Откат

```bash
sudo bash /home/claude/wt-zona-02-launch-01/automation/host/zonafilm-cc-deactivate.sh
```

Снимает vhost и юнит — оба, и в этом порядке. Данные витрины не удаляются.

Откат релиза (не активации) — отдельная операция, проверенная исполнением:

```bash
SITE_ROOT=/srv/lords/.frontend/sites/zona-02 \
  /srv/lords/.frontend/sites/zona-02/current/deploy/rollback.sh
```

## Чего делать НЕ нужно

* **не открывать индексацию.** Витрина закрыта на двух уровнях: заголовок и
  разметка каждой страницы, `robots.txt` запрещает всё, карта сайта пуста
  (измерено). Открытие — отдельная команда после визуальной приёмки и после
  того, как `zona-02` получит собственный SEO-профиль: сейчас профиль
  оформления называется так же, как у `zona-01` (D134);
* **не перезапускать соседей.** Все шесть живых витрин проверены после работ:
  отвечают 200 своими релизами, файлы данных не изменялись;
* **не трогать зоны других доменов** в Cloudflare.
