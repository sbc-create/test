# zonafilm.cc — что осталось владельцу

Контур `zona-02` собран, выложен из собственного репозитория, запущен и
проверен на стенде. Не сделано ровно то, что не может быть сделано этой
сессией, и ни один из этих шагов не обходится:

| Операция | Почему заблокирована |
| --- | --- |
| Запись DNS | `inventory/dns-zones.yaml` пуст, учётных данных Cloudflare стенду не передано. Пустой реестр — `BLOCKED_INPUT`, а не «разрешено всё» |
| Юнит systemd, сертификат, vhost | требуют root; `sudo` и `systemctl` закрыты `deny`-списком `.claude/settings.json`, и полномочие владельца этого не снимает — `deny` сильнее любого разрешения |
| Счётчик Метрики | `BLOCKED_SECRET`: `/etc/site-factory/secrets/yandex_oauth_token` не читается сессией агента. Так задумано: токен читает сервисная учётная запись |
| Проект Topvisor | `BLOCKED_SECRET`: процесс не в группе, которой выдан `/etc/site-factory/secrets/topvisor/`. Плюс платная операция — тариф без решения владельца не трогается |
| Комментарии и оценки 1–10 | решение чужого терминала, см. `docs/zona-02/COMMENTS_RATINGS_HANDOFF.md` |

## Шаг 1. Запись DNS (панель Cloudflare, зона `zonafilm.cc`)

```
A    zonafilm.cc       45.131.182.225   Proxy status: DNS only
A    www.zonafilm.cc   45.131.182.225   Proxy status: DNS only
```

`45.131.182.225` — не догадка: то же значение в `origin_ipv4`
(`config/directions/lords.json`) и в живой записи соседней витрины
`zonafilm.space` (измерено, резолвится в него же).

`DNS only` — не предпочтение. Все домены направления объявлены `"mode":
"dns-only"`. Proxy-режим поставил бы поверх витрины кэш и сертификат
Cloudflare, и тогда `X-Robots-Tag: noindex`, который отдаёт origin, зависел бы
от политики кэширования CDN — ровно тот риск случайного открытия индексации,
который по заданию исключён.

Делегация уже подтверждена и менять её не нужно: серверы зоны `.cc` отдают
`paris.ns.cloudflare.com` и `piers.ns.cloudflare.com`, оба отвечают
авторитетно. Записей A и AAAA в зоне сейчас нет вовсе — измерено, `NODATA` на
apex и `NXDOMAIN` на `www`, то есть чужих записей выкат не затронет.

**Ожидаемый результат:** `dig +short zonafilm.cc` → `45.131.182.225`.

## Шаг 2. Одна команда

```bash
sudo bash /home/claude/wt-zona-02-launch-01/automation/host/zonafilm-cc-activate.sh --preflight
sudo bash /home/claude/wt-zona-02-launch-01/automation/host/zonafilm-cc-activate.sh --apply
```

Первая ничего не меняет и проверяет всё, что проверяется без изменений: ссылку
на релиз, наличие юнита и vhost внутри релиза, принадлежность порта 9123
именно этой витрине по живому реестру, наличие снимка каталога и бокового
файла плеера, состояние DNS и сертификата.

Вторая выполняет по порядку: юнит → ожидание готовности → сертификат → vhost →
публичная проверка. После каждого шага проверяется наблюдаемый признак, а не
код возврата: `systemctl enable` возвращает 0 и для витрины, которая не
поднялась, поэтому проверяется `200` на `/healthz` и совпадение заголовка
`X-Site-Factory-Build-Id` с тем, что объявляет релиз. Публичный `200` без
совпавшего build-id тоже считается провалом: `200` может отдать соседняя
витрина, поймавшая имя.

Любой непройденный шаг откатывает **только то, что успел сделать этот запуск**,
и завершается ненулевым кодом. Скрипт повторно запускаемый: уже поднятый юнит
и уже выпущенный сертификат он не трогает.

Первый ответ появляется не сразу. Старт читает снимок каталога 16 МиБ и боковой
файл подробностей 73 МиБ и строит указатели: измерено на этом стенде — от 105
до 290 с. `TimeoutStartSec` в юните намеренно не задан, скрипт ждёт до 420 с.

Те же два файла лежат и внутри релиза витрины
(`/srv/lords/.frontend/sites/zona-02/current/deploy/`) — ячейка ставится без
доступа к каталогу фабрики.

## Шаг 3. Откат, если что-то не так

```bash
sudo bash /home/claude/wt-zona-02-launch-01/automation/host/zonafilm-cc-deactivate.sh
```

Останов службы и снятие vhost — обязательная часть, а не рекомендация.
Репетиция предыдущего контура показала: после отвязки общий загрузчик на
освободившемся порту уходит не в отказ, а в `releases/legacy/current`, и
`zonafilm.cc` отдавал бы чужую легаси-витрину.

Данные витрины при откате не удаляются: они лежат вне каталога релиза
(`/srv/lords/.frontend/sites/zona-02/data`). Повторная активация занимает
секунды.

Откат **релиза** (не активации) — отдельная и уже проверенная операция:

```bash
SITE_ROOT=/srv/lords/.frontend/sites/zona-02 \
  /srv/lords/.frontend/sites/zona-02/current/deploy/rollback.sh
```

## Шаг 4. Метрика и Вебмастер — под сервисной учётной записью

```bash
sudo -u <учётная-запись-сервиса> \
  /srv/site-factory/repo/.venv/bin/python3 -m factory analytics plan --domain zonafilm.cc
sudo -u <учётная-запись-сервиса> \
  /srv/site-factory/repo/.venv/bin/python3 -m factory analytics apply --domain zonafilm.cc --confirm-writes
```

Без `--confirm-writes` команда только планирует. Счётчик соседней витрины
подставлен не будет ни при каком исходе: `config/site-profiles/zona-02.json`
объявляет `analytics_profile.counter_id = null` с причиной, а `run.py` при
пустом значении не передаёт витрине `LORDS_METRIKA_COUNTER` вовсе — вместо
чужого счётчика не отправляется ничего.

`config/analytics.json` руками не правится — он заполняется этой командой.
Домена `zonafilm.cc` в нём сейчас нет, и это честное состояние, а не пропуск.

## Шаг 5. Topvisor

Учётные данные лежат в `/etc/site-factory/secrets/topvisor/` под `0440
root:ubuntu`; сессия агента в эту группу не входит — проверено попыткой
чтения, ответ `BLOCKED_SECRET`. Создание проекта — платная операция, и тариф
без отдельного решения владельца не меняется. Команда выдаётся после того, как
владелец подтвердит тариф и выдаст доступ.

## Чего делать НЕ нужно

* **не открывать индексацию.** Витрина закрыта на двух уровнях: `X-Robots-Tag:
  noindex, nofollow` в заголовке и в разметке каждой страницы, `robots.txt`
  запрещает всё, карта сайта пуста (измерено). Открытие — отдельная команда
  после визуальной приёмки и после того, как `zona-02` получит собственный
  SEO-профиль: сейчас профиль оформления называется так же, как у `zona-01`
  (см. D134);
* **не перезапускать соседей.** `nova-zona-01`, Animedia, Yummy, Lords,
  gateway, ratings и comments к этому контуру отношения не имеют. Все шесть
  живых витрин проверены после всех работ: отвечают 200 своими релизами,
  файлы данных не изменялись
  (`artifacts/evidence/zona-02-launch-01/01-local/neighbours.json`);
* **не трогать зоны других доменов** в Cloudflare.
