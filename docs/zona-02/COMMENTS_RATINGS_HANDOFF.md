# zona-02 → терминал «КОММЕНТАРИИ И ОЦЕНКИ»: запрос на подключение

Заявка, а не изменение. Общий реестр `config/comments-platform/sites.json`
принадлежит терминалу платформы, и эта задача его не трогает: менять общую
службу одновременно с тем, кто её готовит, — способ получить состояние,
которого не планировал никто.

Контракт прочитан по `docs/comments_platform/INTEGRATION.md` ветки
`claude/community-comments-platform-01` (на момент чтения — коммит `8203c36`,
«комментарии дорощены до публичных: премодерация, ответы, правка, CSRF»).

## Что измерено на стороне zona-02

| Факт | Значение | Чем подтверждено |
| --- | --- | --- |
| Виджет комментариев в шаблоне | **отсутствует** | 0 вхождений `data-cp-comments`, `SiteFactoryComments`, `comments-widget` в закреплённом артефакте `7ccf094a…` |
| Приём записи | **нет ни одного маршрута** | `POST`, `PUT`, `DELETE` отвечают `501`; проверки `security.method_*_not_accepted` в приёмке |
| Оценки на странице | только **внешние**, с указанием источника | `разметка_оценок` строит ряд из `ratings_by_source`; компонент различает внешнюю оценку и оценку зрителей витрины, но формы выставления нет |
| Голосование 1–10 | **не реализовано** | формы нет, endpoint'а нет, хранилища нет |
| Запись zona-02 в реестре платформы | **отсутствует** | `config/comments-platform/sites.json` содержит lords-01..03, zona-01, animedia-01..02, yummyani-site/org/biz |

Вывод без смягчения: **комментарий обычного посетителя, модерация и
выставление оценки 1–10 на zonafilm.cc сегодня невозможны** — ни включить, ни
проверить. Отчёт, объявляющий их проверенными, был бы неправдой.

## Почему не «просто добавить строку в реестр»

Три независимых причины, и достаточно любой:

1. Реестр платформы — общая служба чужого терминала. Правка в момент его
   активной работы даёт конфликт на общем файле, а не подключение.
2. Stage 1 авторизован ровно для одного домена: в `gates.stage_1_authorisation`
   записано `AUTHORIZED_DOMAIN: animedia.icu`, `SECOND_DOMAIN_DEPLOY_ALLOWED:
   false`. zona-02 стал бы вторым доменом.
3. Даже с открытой записью показывать было бы нечем: в закреплённом шаблоне
   zona-02 нет точки монтирования виджета. Сначала артефакт, потом задвижка.

## Заявка

```json
{
  "tenant_id": "zona",
  "site_id": "zona-02",
  "hosts": ["zonafilm.cc"],
  "allowed_origins": ["https://zonafilm.cc"],
  "module_version": "0.1.0-mvp",
  "artifact_checksum": null,
  "theme": "auto",
  "language": "ru",
  "moderation_mode": "pre",
  "read_enabled": 0,
  "write_enabled": 0,
  "publication_enabled": 0,
  "seo_mode": "user_initiated",
  "rollout_percent": 0,
  "max_depth": 3,
  "max_length": 4000,
  "max_links": 2
}
```

`tenant_id` — поле `family` витрины (`zona`), как требует
`source_of_truth` реестра. Домен и `site_id` взяты из
`config/site-profiles/zona-02.json` и `lords-runtime-registry.json`, а не
придуманы.

`artifact_checksum` оставлен `null` намеренно. Сумма обязана совпадать с
**фактически выложенным** артефактом виджета, и считает её
`scripts/comments_platform_artifact.py` на стороне платформы. Скопировать сюда
значение из чужой строки реестра значило бы объявить проверенной сумму, которую
эта задача не считала, — ровно та ошибка, ради которой поле и введено.

Все задвижки — нули. Это не осторожность, а контракт: посайтовое значение
разрешает сайт, потолок когорты разрешает аудиторию, и открывать их — решение
владельца платформы.

## Ключ обсуждения

`tenant_id · site_id · resource_type · canonical_content_id`

`canonical_content_id` витрины — постоянный идентификатор записи каталога
(`detail.id`), а не slug и не адрес. Это существенно: slug у zona-02 меняется
при пересборке снимка (см. `tests/unit/test_zona_stale_slug_after_shrink.py`),
и веткой обсуждения, привязанной к адресу, стала бы новая ветка на каждую
пересборку. Изоляция от zona-01 обеспечивается парой `tenant_id · site_id`:
у соседа `site_id = zona-01`, и ни одна запись не пересекается даже при
одинаковом `canonical_content_id`.

## Что нужно от терминала платформы

1. Решение владельца о втором домене (`SECOND_DOMAIN_DEPLOY_ALLOWED`).
2. Строка выше в `config/comments-platform/sites.json` с посчитанной
   `artifact_checksum`.
3. Версия шаблона zona с точкой монтирования виджета — после её публикации
   `zonafilm.cc` переводится на неё сменой `design_version` в своём манифесте.

До выполнения всех трёх пунктов состояние zona-02 по комментариям и оценкам —
`NOT_RUN`, и никакой другой отметки оно не получает.
