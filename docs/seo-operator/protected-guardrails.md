# Защищённые действия (protected guardrails)

Единый источник правды — `seo_operator/guardrails.py`. Этот документ описывает
правила словами; при расхождении верен код, потому что именно он исполняется.
Один и тот же модуль используют и PreToolUse-hook, и Python-конвейер, поэтому
разойтись они не могут.

## Принцип

Классификатор **закрыт по умолчанию**. Действие, не совпавшее ни с одним
разрешающим правилом, отклоняется — не разрешается «на всякий случай».
Это проверено тестом `test_unknown_action_fails_closed`.

## Блокируется всегда

Ни авторизация production, ни режим `UNATTENDED_SAFE` их не открывают.
Проверено тестом `test_blocked_beats_production_authorization`.

| Категория | Примеры |
| --- | --- |
| Разрушительный SQL | `DROP TABLE/DATABASE`, `TRUNCATE`, `DELETE` без `WHERE`, `DROP COLUMN` |
| Удаление данных | удаление сайтов, доменов, бакетов, backups, `terraform destroy` |
| История git | force push, `--force`, удаление удалённых веток через refspec |
| Прямая запись в main | любой `git push`, называющий `main` или `master` |
| Секреты | вывод значений токенов, чтение `.env`, `credentials`, `*.pem` |
| Расширение прав | `iam attach/create`, `add-iam-policy-binding`, `chmod 777` |
| Отключение защиты | `--no-verify`, `--dangerously-skip-permissions`, удаление hooks, снятие тестов |
| DNS | смена nameservers, удаление и трансфер доменов |

DNS-операции внутри утверждённого manifest разрешены отдельной проверкой
`check_dns`, которая сверяет hostname со списком доменов из portfolio registry.
Суффиксная подмена (`notexample.com` против `example.com`) блокируется — есть
тест `test_suffix_confusion_blocked`.

## Разрешено без вопросов (UNATTENDED_SAFE)

Чтение проекта, поиск, локальный анализ, lint, тесты, build, crawl/render по
HTTP, работа в собственной ветке, запуск CLI оператора, запись файлов внутри
рабочего дерева. Полный список — в `ALLOWED_PATTERNS`.

Push собственной ветки `claude/*` разрешён; push, называющий `main`,
заблокирован жёстко.

## Требует авторизации

Мутации production (`kubectl apply`, `terraform apply`, deploy, write-методы
HTTP) переходят в состояние `ask` и требуют явного токена авторизации на
конкретное действие. Общего «да» на все случаи не существует.

## Данные против команд

Guard различает исполняемую команду и данные, которые она записывает. Тело
heredoc, направленного в файл (`cat > file <<EOF`), из классификации
исключается — иначе тест или документ, *упоминающий* опасную строку, считался
бы попыткой её выполнить. Heredoc, направленный в интерпретатор или в шелл,
телом не считается и проверяется полностью.

Это не теоретическая тонкость: при разработке этого контура guard заблокировал
запись собственного теста, содержавшего строку `DROP TABLE` внутри фикстуры.
Правило добавлено после этого случая и покрыто `tests/operator/test_heredoc_guard.py`.

## Почему не bypassPermissions

Постоянный `bypassPermissions` снимает защиту целиком и навсегда, включая те
случаи, ради которых она и существует. Вместо этого работает связка:
permission rules в `.claude/settings.json` + PreToolUse-hook + классификатор с
закрытым дефолтом. Безопасное проходит молча, опасное отклоняется, спорное
уходит человеку.
