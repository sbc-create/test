# Пути состояния служб SEO-оператора — к переносу в выпуск (MOD-198)

Измерено 26.10 по `seo_operator/*.py`. Каждый модуль, чей путь в таблице, строит
его от корня кода (`Path(__file__).parents[1]`). Если код запустить из каталога
выпуска, эти пути укажут внутрь выпуска. Тогда служба увидит застывшую копию
очередей и реестров, а запись уйдёт в выпуск, который откатывается ссылкой.

| Класс | Пути | Кто пишет | Что нужно при переносе |
|---|---|---|---|
| Состояние служб | `var/editor-runs/*`, `var/seo-regular/*`, `var/seo-tech/*`, `var/notify/*`, `var/analytics/*`, `var/topvisor/*`, `artifacts/analytics/*` | сами службы | постоянный каталог вне выпуска |
| Живые реестры (правят сессии через git, читают службы) | `config/seo-tech-queue.json`, `config/experiments.json`, `config/site-cells.json`, `config/analytics.json`, `config/editorial-sources.json`, `config/seo-module-defects.json`, `config/seo-changes.json`, `config/portfolio.json` | сессии, иногда службы | читать из рабочей копии или из отдельного каталога данных, **не** из выпуска |
| Настройки поведения | `config/editor-run.json` и задания `docs/editor/*`, `docs/seo-tech/*` | сессии | можно класть в выпуск: это часть поведения, откат по ссылке правильный |

Предложение (в этой ветке не реализовано, нужно согласие Архитектора по MOD-198):
- два корня с прежним значением по умолчанию:
  - `SEO_STATE_ROOT` — для `var/` и `artifacts/`;
  - `SEO_REGISTRY_ROOT` — для живых реестров;
- общий модуль `seo_operator/paths.py`; все места из таблицы читают пути через него;
- юнит выпуска задаёт обе переменные.

Без переменных поведение не меняется, поэтому правку можно выпускать до переноса.
