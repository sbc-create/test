# Таксономия запросов

Реализация — `seo_operator/priority.py::classify_query`.

| Класс | Что означает | Какая страница отвечает | Основная метрика |
| --- | --- | --- | --- |
| `title_exact` | точное название произведения | карточка произведения | позиция, CTR |
| `title_season` | название + сезон/серия/эпизод | страница сезона или списка серий | позиция, переходы к просмотру |
| `watch_intent` | «смотреть», «онлайн» | страница с работающим плеером | переходы к просмотру |
| `discovery` | подборки, «что посмотреть», «похожие» | подборка, рубрика | глубина, recirculation |
| `informational` | сюжет, актёры, дата выхода, рецензия | информационный блок карточки | возвращаемость |
| `navigational` | бренд сайта | главная страница | возвращаемость |
| `unclassified` | не удалось отнести | — | требует ручного разбора |

## Правила разбора

Порядок проверки важен и зафиксирован в коде: сначала брендовые термины сайта
(они перекрывают всё), затем сезонные маркеры, затем намерение смотреть, затем
discovery, затем информационные. Запрос без маркеров считается точным названием.

## Зачем это нужно

Класс запроса определяет, какая страница должна на него отвечать. Большая часть
каннибализации возникает, когда на один класс нацелены две страницы — например,
карточка произведения и страница сезона конкурируют за `title_season`. Проверка
`check_cannibalization` находит такие пересечения по индексируемым URL.

Несовпадение класса и типа страницы — самая частая причина, по которой
технически безупречная страница не ранжируется: карточка товара не отвечает на
информационный запрос, сколько её ни оптимизируй.

## Ограничение

Таксономия работает по маркерам в тексте запроса и не заменяет проверку выдачи.
Если по запросу фактически ранжируются подборки, значит поисковая система
отнесла его к `discovery`, независимо от того, что решил классификатор.
