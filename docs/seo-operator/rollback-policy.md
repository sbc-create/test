# Политика отката

## Правило

Изменение не применяется, если его нельзя отменить. Технически это обеспечено
конструктором `Change`: объект не создаётся без `before`, без причины и при
совпадении `before` и `after`. `rollback_payload` вычисляется из наблюдаемого
состояния «до», а не из предположения о нём.

## Состав rollback payload

| Поле | Назначение |
| --- | --- |
| `change_id` | какое изменение отменяем |
| `site_id`, `entity_id`, `field_name` | что именно правим |
| `restore_value` | что записать обратно |
| `expected_current_digest` | каким значение должно быть сейчас |
| `experiment_id` | к какому эксперименту относится |

## Защита ручной правки

Откат по умолчанию **строгий**: если текущее значение не совпадает с тем, что
оператор записал, откат прерывается с `ConflictError`. Правка живого редактора
всегда выигрывает у автоматического отката.

Нестрогий откат (`strict=False`) существует, но применяется только по явному
решению человека и фиксируется в audit log.

## Порядок

Изменения откатываются в обратном порядке применения — последнее применённое
отменяется первым. Проверено `test_rollback_payloads_are_reverse_order`.

## Когда откат обязателен

| Условие | Действие |
| --- | --- |
| Нарушен guardrail | немедленный откат, не дожидаясь окончания наблюдения |
| Первичная метрика упала на 3% и хуже | немедленный откат |
| Наблюдение завершено, эффект ниже +5% | откат: недоказанное изменение не остаётся |
| Выборка меньше 1000 показов | `insufficient_data` — откат, вердикт не выносится |

Последнее правило намеренно строгое. Оставленное «на всякий случай» изменение
без доказанного эффекта превращается в необъяснимый дрейф по всему портфелю.

## Проверка

`scripts/demo_canary.py` выполняет полный цикл и записывает результат в
[`demo-canary-rollback.md`](demo-canary-rollback.md): применение, попытку
выхода за пределы canary, ухудшение метрики, откат, сверку восстановленных
значений и отказ затереть ручную правку.
