## 6. Минимальное действие владельца: свежий срез

Одна команда от root на claude-control-01. Тот же сборщик, тот же секрет через LoadCredential,
что у службы. Два периода последовательно, с паузой против 429. Запись — в `var/analytics/`:

```
systemd-run --wait --collect --pipe --uid=claude --gid=claude -p WorkingDirectory=/home/claude/wt-portable-site-cell-01 -p LoadCredential=yandex_oauth:/etc/site-factory/secrets/yandex_oauth_token /bin/bash -c 'bin/seo-operator analytics-collect --json --date1 2026-10-01 --date2 2026-10-07 --out var/analytics/slice-20261015-w1.json; sleep 120; bin/seo-operator analytics-collect --json --date1 2026-10-08 --date2 2026-10-14 --out var/analytics/slice-20261015-w2.json'
```

Затем сессия строит отчёт из готовых файлов, без доступа к секрету:

```
python3 automation/local/metrika-slice-report.py --out artifacts/analytics/slice-20261015 --week1 var/analytics/slice-20261015-w1.json --week2 var/analytics/slice-20261015-w2.json --daily var/analytics/slice-20261015-w2.json --today var/analytics/slice-20261015-w2.json --history artifacts/analytics/analytics-2026-10-13.json artifacts/analytics/analytics-2026-10-14.json
```

Посуточное окно сборщика — `14daysAgo…yesterday`, то есть при запуске 15.10 это 01–14.10.
Если снова 429, в файлах будет причина у каждого показателя. Нулей не появится, и отчёт
покажет доступную часть.
