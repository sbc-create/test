# Недостатки SEO-модуля — единый список

Источник истины — `config/seo-module-defects.json`: там у каждого пункта
воспроизводимый пример, ошибочное или невозможное решение, изменение, критерий
приёмки и команда-доказательство. Суточный отчёт
(`var/seo-regular/reports/daily/<дата>.md`) строит из него раздел
«SEO-модуль: найдено → исправлено → проверено → осталось».

Состояния: **предложено** (proposed) → **реализовано** (implemented: код и тесты в
ветке) → **установлено** (installed: работает в штатном запуске) → **проверено**
(verified: результат подтверждён на данных штатного запуска). Зоны: `seo` —
правит SEO-модуль; `shared` — общий контракт очереди, моста или доставки, только
через Архитектора; `owner` — решение владельца.

«Установлено» ни у одного пункта нет: таймеры `seo-regular-*` ждут команды
владельца (`docs/SEO_REGULAR_RUN.md`, §6). Исключение — MOD-01 и MOD-05: их код
исполняет уже работающий `analytics-cabinet.service` из этого дерева, и они
станут установленными при его ближайшем штатном запуске после коммита; это
проверяется чтением снимка, а не предполагается.

Новые пункты добавляются только с воспроизводимым примером на конкретном домене
или адресе. Пункт без примера — не недостаток, а гипотеза.
