# Один блок команд владельца: перезапуск `site-factory-mcp` на `claude-control-01`

Запись от 2026-10-16, 17:10 UTC. Перезапуск **согласован** владельцем (пункт 3
решений от 16.10). Здесь — почему он не выполняется из сессии и один
проверенный блок, который выполняется вручную.

## Почему не из сессии

Служба — системный юнит root (`/etc/systemd/system/site-factory-mcp.service`,
`User=claude`, `Restart=on-failure`). Перезапуск системного юнита делается
`systemctl`, а `Bash(systemctl *)` стоит в списке ЗАПРЕТОВ проекта
(`.claude/settings.json`), как и `sudo`. Это запрет, а не отсутствие правила, и
обойти его другим способом нельзя:

* обёртка на Python, вызывающая тот же `systemctl`, — тот же запрещённый
  вызов, только спрятанный от проверки прав;
* `SIGKILL` процессу (сработал бы `Restart=on-failure`) — тот же результат
  через поломку: это не контролируемый перезапуск, а имитация сбоя.

Поэтому действие остаётся за владельцем. Согласие владельца у меня есть,
технической возможности выполнить его в рамках собственных прав — нет, и
самовольного исключения я не делаю.

## Окно безопасно сейчас, и это измерено

Перезапуск нельзя делать поверх активной редакционной публикации. Состояние
проверяется новым инструментом `automation/local/editor-run-state.py` (только
чтение):

```
состояние editor-run.sh: IDLE
  блокировка: блокировка свободна
  последний запуск: 20261016T163503Z 16:35:03Z → 16:52:04Z COMPLETE
  процессов обёртки: 0
  перезапуск site-factory-mcp: разрешён
```

Таймер зовёт обёртку каждые 5 минут, а модель запускается примерно раз в час
(последние запуски: 14:32, 15:35, 16:35). Поэтому первая команда блока — та же
проверка: если она скажет `RUNNING`, блок прерывается и повторяется позже.

**Проверка подтверждена на настоящем запуске, а не только на подставной
блокировке.** В 17:52 UTC начался очередной прогон (`run-20261016T173741Z`), и
все три признака сошлись сами:

```
состояние editor-run.sh: RUNNING
  блокировка: блокировка удерживается другим процессом
  процессов обёртки: 1
  каталогов без итоговых файлов: 2 (run-20261014T102003Z, run-20261016T173741Z)
  перезапуск site-factory-mcp: ждать
```

То есть окно теперь закрыто и откроется примерно через четверть часа — блок
сам это и покажет первым шагом. Прежняя проверка в этот момент не отличалась бы
от своего же ответа час назад.

## Блок команд

Сервер: **`claude-control-01`** (тот же узел, где работают витрины). Выполнять
от root; каждая строка — ожидаемый результат справа.

```bash
# 1. окно свободно? ожидается: "состояние editor-run.sh: IDLE", код 0
python3 /home/claude/wt-nova-publish-memory-02/automation/local/editor-run-state.py

# 2. перезапуск. врезки 10-write-mode.conf и 20-editorial-queue.conf
#    сохраняются: это отдельные файлы, перезапуск их не трогает
systemctl restart site-factory-mcp.service

# 3. служба поднялась? ожидается: "active"
systemctl is-active site-factory-mcp.service

# 4. режим и готовность? ожидается: "ready": true и "read_only": false
curl -sS -m 20 http://127.0.0.1:9000/healthz

# 5. правка авторства действительно в памяти службы?
#    ожидается: все три пункта "ок", в том числе
#    "служба запущена ПОСЛЕ правки файлов"
python3 /home/claude/wt-nova-publish-memory-02/automation/local/editorial-fix-installed.py
```

## Что проверка показывает СЕЙЧАС, до перезапуска

```
1. код правки на месте                     [ок ] (5 проверок)
2. живой файл читается перед публикацией    [ок ] (3 проверки)
3. служба перечитала код                   [НЕТ] правка 2026-10-12 22:57:59,
                                                 запуск 2026-10-12 17:42:04
ИТОГ: правка НЕ подтверждена — публикации возобновлять нельзя
```

То есть ровно один пункт из трёх, и ровно тот, который перезапуск и закрывает.
Код правки лежит на диске с 12.10 22:57, а в памяти службы работает сборка от
17:42 того же дня.
