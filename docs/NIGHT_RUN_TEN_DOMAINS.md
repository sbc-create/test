## Главный блокер: токен GitHub не видит НОВЫЕ репозитории

Доказано сравнением на одном и том же токене исполнителя (заявки `access-check`,

| Репозиторий | Когда | repo_read | actions_read |

`token_available: true` во всех трёх случаях. Значит токен действителен и права
чтения у него есть — он просто не включает репозитории, созданные позже. Это
подпись fine-grained токена со списком «Only select repositories»: список не
расширяется сам при создании новых репозиториев. Формулировку выдал сам
исполнитель в поле `required_input`.

Следствие: ни один из шести новых доменов нельзя выпустить штатным механизмом,
потому что происхождение коммита проверяется через GitHub Actions. Обход
запрещён и не делался.

**Действие владельца (не команда, а настройка доступа):** в настройках токена,
лежащего в `/etc/site-factory/gh-token`, добавить в список репозиториев
`site-zonafilm12-site`, `site-lordserials22-info`, `site-lordserials22-site`,
`site-lordserials22-space` (и `site-yummyani7-site`, `site-yummyani7-info`, когда
они появятся) с правами чтения Contents и Actions. Расширять права сверх чтения

записей NS для домена в реестре TLD нет вовсе. Это не «нет A-записи в
Cloudflare»: зоны не существует. Четыре остальных домена делегированы на
Cloudflare и разрешаются в 45.131.182.225.

фабрики нет, исправить записи самостоятельно нельзя.

### Разделение причин отказа GitHub (пункт 3 задания)

Проверен КАЖДЫЙ репозиторий штатным `access-check`, а не распространён вывод двух:

| Репозиторий | access-check | Рабочая копия знает origin | Вывод |

| site-zonafilm-cc | repo_read=true, actions_read=true | да | доступ есть |
| site-zonafilm12-site | 404 | **да**, `origin/release/zonafilm12-site` | репозиторий существует, имя верное — **нет доступа у токена** |

| site-lordserials22-space | 404 | **да** | то же |

Наличие remote-tracking ссылки — доказательство состоявшегося обмена именно с

успешно — значит недоступность относится именно к токену исполнителя в
`/etc/site-factory/gh-token`, а не к репозиториям.
