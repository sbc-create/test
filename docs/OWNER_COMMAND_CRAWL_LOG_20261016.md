# Один блок владельца: включить отдельный журнал обходчика и дать его читать

Запись от 2026-10-16, 19:50 UTC. Владелец разрешил диагностику источников
`HeadlessChrome` по журналам и запретил массовую блокировку по названию
браузера. Диагностику из этой сессии сделать нечем, и причина ровно одна —
доступ к файлу журнала, а не отсутствие инструмента.

## Что уже готово и проверено

* **Инструмент журнала подготовлен**: `var/staged-nginx-crawl/` — файлы витрин
  плюс одна строка на витрину:
  `access_log /var/log/nginx/crawl.log crawl if=$is_crawler;`. В `/etc/nginx`
  ничего не изменено;
* **состав блока сужен по измерению, а не по намерению.** Построчная сверка со
  живыми файлами: три файла Yummy (`biz`, `org`, `site`) отличаются ровно на
  +5 строк и ноль удалённых — их применять безопасно. Остальные четыре
  (`animedia-02`, `lords-01…03`) живого соответствия в `sites-enabled` и
  `conf.d` НЕ имеют: их применение создало бы новые файлы, поэтому в блок они
  не входят;
* **недостающий файл формата дописан и проверен на деле.** В подготовленном
  каталоге не было `00-crawl-log.conf`, то есть применение одних файлов витрин
  уронило бы `nginx -t` на неизвестной переменной `$is_crawler`. Файл написан,
  и проверен не только синтаксисом: в контейнере с nginx (отдельный процесс,
  живой конфигурации узла не касалась) запрос с браузером
  `Chrome/145.0.0.0 Safari/537.36` дал строку журнала
  `127.0.0.1 2026-10-16T19:49:13+00:00 "127.0.0.1" "GET /anime/test" 200 43
  0.000 "Chrome/145.0.0.0 Safari/537.36"` — то есть браузер в журнал попадает,
  а это и есть предмет диагностики;
* **признак `$is_crawler` равен единице всегда, и это намеренно**: ключ
  обходчика — адрес, а не браузер (строк `HeadlessChrome` в журналах ноль),
  поэтому журнал пишет всё по трём витринам, а разделение «обходчик/люди»
  делается разбором по адресам после;
* **состав сверен с живым** (это важно, потому что файлы лежат с 15.10, и
  устаревший файл мог бы вернуть закрытую индексацию): в подготовленном файле
  `yummyani.biz.conf` заголовок `X-Robots-Tag: noindex` стоит только в блоке
  HTTP и в блоке `www`-перенаправления — ровно как в живом; в блоке апекса
  HTTPS его нет ни там, ни там. То есть применение не меняет режим индексации;
* **ключ фильтрации уже установлен и это НЕ браузер**: в журналах строк
  `HeadlessChrome` ноль, обходчик представляется обычным
  `Chrome/145.0.0.0`; работают два диапазона адресов — `47.82.*` (297 адресов)
  и `43.119.*` (322), вместе 85,3 % запросов.

## Чего не хватает: прав на чтение

```
/var/log/nginx           drwxr-xr-x root adm
/var/log/nginx/access.log -rw-r----- www-data adm   ← 0640, группа adm
мои группы: sudo sfhub lords docker claude          ← adm нет
```

`sudo` и `systemctl` — в списке запретов проекта, обходить их нельзя. Поэтому
нужен один шаг владельца: применить подготовленный журнал и сделать ЭТОТ ОДИН
файл читаемым для учётной записи сессии.

## Блок команд

Сервер `claude-control-01`, от root:

```bash
S=/home/claude/wt-nova-publish-memory-02/var/staged-nginx-crawl

# 1. формат и признак (новый файл, ничего не перекрывает)
install -m 0644 "$S/00-crawl-log.conf" /etc/nginx/conf.d/00-crawl-log.conf

# 2. три файла витрин Yummy: копия живого ДО замены, затем замена.
#    Эти три отличаются от живых ровно на +5 строк (четыре строки пояснения и
#    одна строка access_log), удалённых строк ноль — сверено построчно.
for d in yummyani.biz yummyani.org yummyani.site; do
  cp -p "/etc/nginx/sites-enabled/$d.conf" \
        "/etc/nginx/sites-enabled/$d.conf.bak.$(date -u +%Y%m%dT%H%M%SZ)"
  install -m 0644 "$S/$d.conf" "/etc/nginx/sites-enabled/$d.conf"
done

# 2. проверка. ожидается "syntax is ok" и "test is successful"
nginx -t

# 3. применение без обрыва соединений
systemctl reload nginx

# 4. отдельный журнал появился и в нём только обходчик
ls -l /var/log/nginx/crawl.log
tail -2 /var/log/nginx/crawl.log

# 5. дать читать ровно этот файл сессии (группа claude, только чтение)
chgrp claude /var/log/nginx/crawl.log && chmod 0640 /var/log/nginx/crawl.log
# и чтобы право не терялось при ротации:
printf '/var/log/nginx/crawl.log {\n  daily\n  rotate 7\n  missingok\n  notifempty\n  compress\n  create 0640 www-data claude\n  sharedscripts\n  postrotate\n    systemctl reload nginx >/dev/null 2>&1 || true\n  endscript\n}\n' > /etc/logrotate.d/nginx-crawl
```

Откат: удалить `/etc/nginx/conf.d/00-crawl-log.conf`, вернуть файлы витрин из
`/etc/nginx/sites-enabled/*.conf.bak.*`, `nginx -t && systemctl reload nginx`,
удалить `/etc/logrotate.d/nginx-crawl`.
