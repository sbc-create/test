# Порядок блоков главной: что проверяется до правки

Правило заведено по поручению владельца 27.10 после того, как редакционные
блоки на `animedia.icu` встали первыми и отодвинули разделы с актуальными
сериями. Оно не про вкус, а про проверяемые признаки блока.

## Перед изменением главной проверяется четыре вещи

1. **Назначение блока.** Кому он нужен и что помогает выбрать. Ответ
   формулируется через сценарий посетителя, а не через источник данных:
   «постоянный посетитель ищет новую серию» и «новый посетитель выбирает, что
   посмотреть» — два разных сценария, и блок служит одному из них.
2. **Приоритет.** Чей сценарий обслуживает первый экран. Блок, который нужен
   возвращающемуся посетителю, стоит выше блока, который помогает выбирать
   впервые: возвращаются чаще, чем приходят.
3. **Пересечение с соседними разделами.** Измеряется числом — долей общих
   работ к меньшему из двух блоков. Порог для разговора — 30%, порог для
   дефекта — 80%: при таком пересечении второй блок не добавляет выбора, он
   повторяет первый другим заголовком.
4. **Поведение при реальном количестве элементов.** Не «сколько может быть», а
   сколько приходит сейчас. Четыре карточки в сетке по три — это ряд из трёх и
   ряд из одной: композиционная пустота появляется не из CSS, а из
   несовпадения числа элементов с числом колонок.

## Порядок задаётся профилем сайта, а не кодом главной

Сценарий аниме-витрины не переносится на кинотеатральные Zona и Lords
автоматически. У аниме-витрины сериал выходит по серии в неделю, и
возвращающийся посетитель ищет именно новую серию; у кинотеатральной витрины
такого недельного ритма нет. Поэтому слот редакционных блоков объявлен полем
профиля:

| поле | значение | что означает |
| --- | --- | --- |
| `home_editorial_slot` | `top` | редакционная лента и подборки первыми блоками |
| `home_editorial_slot` | `after_rated` | после «Лучшего по оценкам» |

Значение по умолчанию принадлежит профилю: в рантайме аниме-витрины это
`АНИМЕДИА_СЛОТ_РЕДАКЦИИ = "after_rated"`. Кинотеатральные витрины живут в
своём рантайме (`lords-frontend.py`), их порядок этой правкой не затронут, и
переносить его туда без такой же проверки четырёх признаков нельзя.

## Порядок главной Animedia на 27.10

1. «Аниме недели» — верхний блок, недельный утверждённый снимок;
2. «Новые серии» — то, за чем возвращается постоянный посетитель;
3. «Лучшее по оценкам» — порядок по сводной оценке;
4. «Аниме-сериалы, которые стоит посмотреть» — редакционная лента;
5. «Тематические подборки аниме» — четыре визитки, сетка 2×2;
6. «Аниме-сериалы» — общий раздел сериалов с доступными сериями;
7. ниже — «Аниме-фильмы», «Дунхуа», «Короткие сериалы», сетка каталога.

## Названия

* Название блока говорит посетителю, что он увидит, а не описывает фильтр.
  «Сериалы с сериями» описывало отбор — стало «Аниме-сериалы».
* «Сейчас выходит» допустимо только для работ, у которых доступных серий
  МЕНЬШЕ заявленных: это проверяемый факт из снимка (`avail < eps`), а не
  догадка о выходе. Блок `_блок_сейчас_выходит` отбирает именно так.
* Общий заголовок подборок называет, подборки чего это: «Тематические
  подборки аниме».
* Ссылка из блока подборок называется тем, куда ведёт: «Все подборки».

## Пустоты

Число карточек на главной согласуется с числом колонок. Добавлять случайную
подборку ради заполнения ряда запрещено, удалять полезную ради симметрии —
тоже. При росте числа подборок на главной показываются выбранные редакцией в
объявленном ею порядке, остальные достижимы по «Все подборки».

## Чем это закреплено

* `automation/host/apply-home-blocks-patch.py` — правка с якорями и `--check`;
* `tests/unit/test_home_blocks.py` — порядок, названия и сетка;
* `automation/local/home-blocks-survey.py` — измерение порядка и пересечений
  на живой главной.
