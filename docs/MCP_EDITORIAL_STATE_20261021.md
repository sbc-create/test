действует до перезапуска». То есть загружен код девятидневной давности.

## Мой правленый `editorial.py` в эту службу НЕ загружен — и не может быть

Проверено по тексту, а не по времени файлов:

```

0
$ grep -c BLOCKED_INPUT /home/claude/wt-nova-publish-memory-02/factory/qwen/editorial.py

```

Правка «невыполнимое замечание о годе снимка заменено отказом с настоящей
причиной» лежит в МОЕЙ рабочей копии, а служба читает ДРУГУЮ. Перезапуск сам по
себе её не принесёт: нужно, чтобы правка оказалась в
`/home/claude/wt-portable-site-cell-01`, то есть её должна забрать линия, которая
ведёт эту копию (из моей сессии доступ к её репозиторию отклоняется защитой).

## Ловушка перезапуска, которую надо назвать ДО перезапуска

В установленном unit-файле стоит:

```
ExecStart=/usr/bin/python3 -m factory.qwen.mcp --http 127.0.0.1:9000 --read-only
```

а живой процесс отвечает `read_only: false`. Файл unit-а датирован 3.10, процесс
запущен 12.10 — значит процесс поднят не этой строкой, а прежней, без
`--read-only`.

**Следствие: перезапуск по текущему unit-у переведёт службу в режим только для
чтения, и все 22 пишущих инструмента перестанут писать.** Если редакционный
путь должен продолжать публиковать, перед перезапуском надо решить, остаётся ли
`--read-only` в unit-е. Это не мой выбор: я его только называю.

## Почему новых материалов нет с 12.10

Материалов в хранилище 19, дошло до посетителя 18 (отдельная проверка,
`automation/local/editorial-reaches-visitor.py`). Самый свежий актор —
`editor/claude-auto/run-20261012T224004Z`, то есть 12.10 в 22:40Z, через пять
часов после запуска службы.

Среди установленных таймеров узла producer-а редакционных материалов НЕТ:
в `/etc/systemd/system` есть `analytics-cabinet`, `k2-catalog-*`,
`nova-*`, `site-cell-executor`, `site-factory-mcp`, `topvisor-*`,
`yummy-content-refresh` — и ни одного, который звал бы редакционный конвейер.

Отсюда вывод, который стоит записать прямо: **материалы появляются только когда
их запускает сессия вручную; расписания у них нет.** «Написано, но не
используется» — не наш случай: написанное опубликовано (18 из 19), а нового не
пишется, потому что некому запустить.

## Что из этого следует для роста аудитории

Редакционный путь исправен на всём протяжении, которое можно измерить, и
упирается в две вещи, обе внешние: нет расписания у producer-а и нет токена
доверия у клиента (без него роль `qwen` готовит только черновики). Поэтому
ночью я материалы не публикую: подготовка черновиков без принятия — работа,
которая не доходит до посетителя, а публикация без разрешённого источника
запрещена режимом CLOSED_WORLD.
