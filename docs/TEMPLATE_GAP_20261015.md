# Шаблоны витрин: что уже есть и чего действительно не хватает

Запись от 2026-10-15. Оценка сделана перечислением, а не на глаз: девять
профилей семейства `lords` разобраны по тем решениям, которые они задают.

Решения, которые уже заняты: четыре типа героя (`catalog`, `editorial`,

## Где каждое решение ЧИТАЕТСЯ — это важнее списка

Измерено поиском по репозиторию, а не предположено:

| решение профиля | кто читает | следствие |
| --- | --- | --- |
| `theme.tokens`, `layout.*` в `blueprints/lords/profiles/*.yaml` | `factory/lords/theme.py` — генератор CSS фабрики | работает для сайтов, которые собирает фабрика |
| дизайн ЯЧЕЙКИ (палитра, меню, лид, подвал, тексты разделов) | таблицы рантайма по полю `profile` из `config/template-manifest.json`: `ДИЗАЙН_ПО_ПРОФИЛЮ` → `ТОКЕНЫ_ПО_ДИЗАЙНУ` и соседние | **профиль ячейки читает рантайм, а не YAML** |
| `config/profile.yaml` внутри ячейки | никто | справочная копия; помечена заголовком 2026-10-15 |
| `layout.card_ratio` | `factory/lords/theme.py` (переменная `--card-ratio`) | в рантайме ячейки пропорция карточки задана литералами `aspect-ratio:2/3`, переменная не используется |

Отсюда два вывода, без которых «добавить шаблон» означает добавить мёртвые
данные:

1. **Новый профиль витрины-ячейки — это запись в ДВУХ местах**: YAML профиля
   (для генератора фабрики и как происхождение) и таблицы дизайна в рантайме
   семейства (`automation/host/lords-frontend.py`). Без второй записи рантайм
   возьмёт дизайн по умолчанию, и профиль не будет виден на сайте ничем.
2. **Широкая карточка (16/9) сегодня невыразима**: рантайм ячейки держит
   пропорцию литералами. Профиль с `card_ratio: 16 / 9` стал бы ровно теми
   «мёртвыми данными, выглядящими содержимым», которые проект запрещает.
   Чтобы такой вариант появился, сперва нужна правка рантайма (переменная
   вместо литералов) — и это отдельная работа с отдельной проверкой.

## Чего не хватает, а что уже есть

**Светлого варианта не хватать не может: он уже есть у каждого профиля.**
Измерено в рантайме: `_корень_темы` объявляет ОБЕ палитры переменными `:root`
(светлая — база, тёмная выводится из неё `_тёмные_для`), выбор делается
атрибутом `data-theme`, и в шапке стоит переключатель «Сменить оформление».
То есть «светлый каталог фильмов» — не новый шаблон, а уже доступное состояние
существующего. Добавлять профиль ради другого акцента значило бы делать работу
без нового решения, и в отчёте это честнее назвать, чем выдать за вариант.

**Чего действительно не хватает — порядка полок главной под сериальную
витрину, живущую обновлениями.** У `lords-serials` первый экран каталожный:
свежие серии и календарь идут после полок. У `lords-new` таймлайн и календарь
есть, но это профиль «нового в прокате», а не сериального каталога.

И вот цена, которую важно знать заранее: **порядок полок задаётся не
профилем.** Полки собираются ветвлением по `ДИЗАЙН_ID` внутри рантайма
семейства (`automation/host/lords-frontend.py`), а YAML профиля на это не
влияет. Значит нужный вариант — правка РАНТАЙМА, а не добавление шаблона:

| что потребуется | где |
| --- | --- |
| запись дизайна (палитра, меню, лид, подвал, тексты разделов) | таблицы рантайма: `ДИЗАЙН_ПО_ПРОФИЛЮ`, `ТОКЕНЫ_ПО_ДИЗАЙНУ`, `НАВ_ПО_ДИЗАЙНУ` и соседние |
| своя ветка полок главной (свежие серии и календарь выше полок) | ветвление по `ДИЗАЙН_ID` в сборке главной |
| профиль витрины | `blueprints/lords/profiles/lords-serials-fresh.yaml` |
| запись в пуле | `config/template-pool.json` — и здесь ещё одна находка: операции «добавить шаблон в пул» в `factory.cell.templates` НЕТ (есть `reserve`, `assign`, `release_reservation`), а править файл руками запрещает его же примечание. Значит пополнение пула — отдельная операция, которой пока не существует |
| проверка | `test_lords_theme.py` подхватит новый профиль сам и измерит контраст в обеих темах |

Предлагаемый состав варианта (чтобы решение можно было принять, не возвращаясь
к разбору): плотность `dense`, герой `timeline`, фасеты сверху, календарь
включён, порядок полок — свежие серии, календарь, недавно добавленное, сериалы
по типам, популярное за неделю, жанры; меню ведёт `/new/` («Новые серии»)
вторым пунктом после `/series/`.

**Вывод.** Готовых к добавлению шаблонов — ноль, и это ответ по измерению, а не
отказ от работы: один кандидат растворился (светлая тема уже есть у всех),
второй стоит правки общего рантайма и пополнения пула, то есть выходит за
«подготовить шаблон» и требует отдельного выпуска и операции владельца.
Завершение восьми витрин этим не задерживается — ни одна из них на новый
шаблон не рассчитывает.

## Чего эта запись НЕ утверждает

Что шаблоны готовы. Здесь только оценка и границы: что существует, где это
читается и какой ценой добавляется. Подготовка самих двух шаблонов — отдельная
работа, и она не должна задерживать завершение восьми витрин (условие задания).
Правка рантайма семейства при этом отправляется отдельным выпуском: тот же файл
исполняют семнадцать действующих витрин (решение D212а).
