# Восстановление на чистом хосте

Процедура ТЗ §13. Проверяется ежемесячно автоматически (`seo-restore-drill.timer`);
репетиция, которую не проводят, планом восстановления не является.

## RPO / RTO

| Показатель | Целевое значение | Как измеряется |
|---|---|---|
| RPO | 24 часа | возраст последнего бэкапа в момент репетиции (`rpo_hours` в evidence) |
| RTO | 2 часа | время от старта восстановления до успешного dry-run (`rto_seconds`) |

Фактические значения берутся из evidence-файлов `restore-drill-YYYYMMDD.json`, а не
из этой таблицы. Если репетиция не проводилась, RPO/RTO имеют статус `NOT_MEASURED`.

## Процедура

```bash
# 1. Новый хост, утверждённый commit — не «последний main»
deploy/install.sh --repo git@github.com:owner/repo.git --commit <SHA>

# 2. Подключить Secret Hub (значения секретов на диск не попадают)
export SEO_SECRET_HUB_URL=https://secrets.internal/v1

# 3. Восстановить данные и убедиться, что состояние рабочее
deploy/restore-drill.sh --target /var/lib/seo-operator --backup-dir /var/backups/seo-operator

# 4. Read-only сверка
seo portfolio validate --json
seo permissions test --json
seo audit verify --json
seo guardrails verify --json

# 5. Только после чтения evidence — включить расписание
systemctl enable --now seo-collect.timer seo-daily-report.timer seo-restore-drill.timer
```

`install.sh` намеренно **не включает** таймеры: планировщик, запущенный на
непроверенном хосте, начнёт писать раньше, чем человек посмотрит на результат.

## Что проверяет репетиция

1. Чистый target (никогда не рабочий каталог — есть явная защита от совпадения).
2. Наличие бэкапа и совпадение контрольной суммы.
3. Применимость миграций к восстановленному состоянию.
4. Целостность audit-цепочки (разрыв = данные подменены).
5. Наличие наблюдений: пустая база «восстановилась» формально, но бесполезна.
6. Успешный dry-run полного цикла.

Любой шаг завершается `RESTORE_DRILL=fail` с причиной. Успех фиксируется
evidence-файлом, содержащим только метрики восстановления — секретов там нет
по построению.

## Что не хранится в GitHub

OAuth и API-токены, персональные данные, поисковые строки пользователей,
production-дампы, htpasswd, приватные ключи, runtime-логи и бэкапы.
В репозитории — код, схемы, миграции, IaC, units, тесты, runbooks и шаблоны отчётов.
