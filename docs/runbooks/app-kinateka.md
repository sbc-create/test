# Приложение «Кинатека»: главная, подборки, оформление — установка и работа

Передачи 135/136 (`/srv/site-factory/coordination/v1/handoffs/`). Контракт для клиента — `kinateka-config/1`
(репозиторий `sbc-create/ott-app-sandbox`, `docs/APP_CONFIG_CONTRACT.md`). Решение владельца 2026-10-27:
управление — разделом этой админки.

## Из чего состоит

| Часть | Ветка | Что делает |
|---|---|---|
| Раздел админки + Control API | `claude/kinateka-admin-01` (от развёрнутого `e698e2ad`) | черновик канала, проверка, предпросмотр, публикация, откат, история; `/api/v1/apps/kinateka/...`, область `app:write`, выключатель `SITE_ENGINE_APP_CONFIG_WRITES` |
| Служба чтения | `claude/kinateka-read-config-01` (от `a1cc5b6a`, включает маршрут offers) | `GET /api/app/v1/config/{sandbox\|production}`; дополняет позиции из текущего снимка; перечитывает снимок после обновления витриной; `--rollback-release` |
| Хранилище | `/srv/site-factory/repo/var/app-config/animedia-01/` | `revisions/<n>.json` (неизменяемые), `published-<канал>.json` (указатель), `draft-<канал>.json`, `history.jsonl` |

Каналы раздельны: публикация в `sandbox` меняет только указатель `sandbox`. Перенос в `production` — кнопка
«Скопировать в черновик» на странице канала production и отдельная публикация там.

## Установка (root, Архитектор)

Порядок важен: сначала служба чтения, затем Control API — приложение до публикации получает `NO_CONFIG` и строит свою
главную, так что промежуточное состояние безопасно.

1. Служба чтения (из рабочего дерева ветки `claude/kinateka-read-config-01`):
   ```
   bash automation/host/install-app-read-api.sh --dry-run      # показать юнит и шаги
   sudo bash automation/host/install-app-read-api.sh
   ```
   Установщик создаёт каталог ревизий (`claude:claude`, до юнита), добавляет `--config-dir` и `ReadOnlyPaths`,
   сохраняет прежний код и юнит в `*.previous`, перезапускает службу. Ключ клиента не трогается.
   Проверка: `curl -s http://127.0.0.1:9180/healthz` → `configChannels: {"sandbox": null, "production": null}`;
   с ключом `GET /api/app/v1/config/sandbox` → `404 NO_CONFIG`.
2. Control API и админка:
   ```
   sudo bash automation/host/deploy-control-api.sh deploy <sha ветки claude/kinateka-admin-01> --dry-run
   sudo bash automation/host/deploy-control-api.sh deploy <sha>
   ```
   Ветка начата от развёрнутого `e698e2ad` и не меняет credentials/changeset/audit — поколение безопасности то же.
3. Окружение `/etc/site-factory/control-api.env` (значения токенов в чат, журналы и git не попадают):
   - `SITE_ENGINE_APP_CONFIG_WRITES=1` — запись раздела; общая `SITE_ENGINE_CONTROL_WRITES` не нужна и не включается;
   - в `SITE_ENGINE_CONTROL_TOKENS` добавить токен редактора: `<новый токен>=read,app:write`
     (сгенерировать, например, `python3 -c "import secrets;print(secrets.token_urlsafe(32))"` прямо в файл);
   - по желанию `SITE_ENGINE_APP_CATALOG_DIR_ANIMEDIA_01` (по умолчанию `/srv/animedia-icu/data`).
   Затем `sudo systemctl restart site-factory-control-api`.

## Вход в панель (редактор, владелец)

Панель слушает только петлю сервера; наружу не выведена.

1. Туннель с своего компьютера: `ssh -N -L 8790:127.0.0.1:8790 <пользователь>@<сервер фабрики>`.
2. Браузер: `http://127.0.0.1:8790/admin` → «Вход по токену Control API» → токен с областью `app:write`
   (выдаёт Архитектор/владелец; токен только `read` даёт просмотр без кнопок).
3. В шапке — «Приложение „Кинатека“». Обзор: каналы `sandbox` и `production`, действующие ревизии, история.

## Работа редактора

На странице канала, сверху вниз:
- **Состояние**: действующая ревизия; «черновик готов к публикации» или список того, что исправить; кнопка
  «Опубликовать» (с комментарием) активна только при чистой проверке.
- **Предпросмотр черновика**: блоки главной в порядке показа, постеры и названия из текущего каталога — так их
  получит приложение; скрытые блоки — бледные; «не показано: N» — позиции, которых нет в каталоге или с жанром не для
  общей главной.
- **Блоки главной**: порядок числами, заголовок, «виден», вид карточек ряда (постеры/кадры), обложка; добавить блок
  (подборка, баннер, жанр, «недавно добавлено», «продолжить просмотр»).
- **Подборки**: открыть подборку → название, подзаголовок, описание, источник, дата проверки, срок; состав — порядок
  числами, причина, источник, дата; «Убрать»; добавить строками `contentId | причина | источник`; поиск тайтла по
  названию (с пометкой «не для общей главной»).
- **Оформление**: акцент, баннер (кадр/постер), карточки рядов, увеличение в фокусе на TV (1.00–1.12).
- **История**: каждая публикация и откат; кнопка «Вернуть ревизию N» переводит канал на неё.
- **Документ целиком (JSON)** — для правок, которых нет в формах.

Приложение видит опубликованное при следующем запуске или возврате на главную (кэш маршрута — 60 с). Без сервера оно
показывает последнюю принятую ревизию; ревизию, которую не понимает, не применяет.

## Правила состава (проверяет публикация)

- Позиции — по `contentId` каталога; у каждой — причина (до 140 знаков), источник, дата проверки.
- Жанры `этти`, `хентай`, `эротика`, `гарем` на общую главную не попадают: публикация отказывает, служба чтения
  отдаёт такие позиции в `missing`, если жанр появился позже. Возрастной метки в каталоге нет — это единственный признак.
- Дата импорта — не премьера; оценка — не популярность; связь со студией — не доступность.
- До вставки в панель файл подборок проверяется `ott-app-sandbox/tools/editorial_check.py --posters`.

## Три возврата — три разных пути

| Что | Как | Затрагивает |
|---|---|---|
| Конфигурация главной | «Вернуть ревизию N» в истории канала (или `POST .../channels/{канал}/rollback`) | только указатель канала |
| Код службы чтения | `sudo bash automation/host/install-app-read-api.sh --rollback-release` | прежний код и юнит из `*.previous`; ревизии и ключ на месте |
| Код Control API/админки | `sudo bash automation/host/deploy-control-api.sh rollback` | ссылка `current` → `previous`; ревизии в `var/` на месте |
| APK | восстановительный выпуск вперёд (код прежней версии, новый `versionCode`, та же подпись) | приложение; данные пользователя сохраняются |
