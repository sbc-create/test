# Audit Ledger: обслуживание

## Что где лежит

| Что | Где | В Git |
|---|---|---|
| Код журнала | `factory/site_engine/audit/` | да |
| Контракты | `contracts/control-plane/` | да |
| Тесты | `tests/audit/` | да |
| Манифест службы моста | `automation/host/units/` | да |
| База журнала | `/srv/site-factory/audit-ledger/audit_ledger.sqlite3` | **нет** |
| Лента, курсоры, DLQ | там же | **нет** |
| Резервные копии | `/srv/site-factory/audit-ledger/backups/` | **нет** |
| Манифесты карантина | `/srv/site-factory/audit-ledger/evidence/` | **нет** |
| Токены служб | `/etc/site-factory/control-api.env` | **нет** |

Разделение не косметическое. История системы не версионируется вместе с
кодом: коммит описывает, как служба работает, а база — что произошло. Слить
их значило бы получить откат кода, уносящий вместе с собой события.

## Выкладка

```
automation/host/deploy-control-api.sh deploy <sha>
```

Скрипт собирает неизменяемый каталог релиза из `git archive` указанного
коммита, создаёт собственное окружение, проходит протокол запуска и только
после этого атомарно переключает ссылку `current`. Отпечаток релиза
(`digest_of`) считается по отсортированному списку файлов кода — он и есть
artifact SHA-256.

## Откат

```
automation/host/deploy-control-api.sh rollback           # к предыдущему
automation/host/deploy-control-api.sh rollback --to <sha>
```

Откат кода не трогает данные журнала: они общие для всех версий. Если откат
нужен ВМЕСТЕ с состоянием проекции, отдельно выполняется
`projection.переключить` на таблицу из `rollback_table`.

## Мост к реестру

```
systemctl status  site-factory-audit-bridge
systemctl restart site-factory-audit-bridge
python -m factory.site_engine.audit.registry_bridge reconcile
```

Мост держит эксклюзивный замок `registry-bridge.lock`: второй экземпляр
отказывается стартовать и выходит с кодом 3. Курсор долговременный, replay
дублей не создаёт, пропуски находит `reconcile`.

## Тесты

Только через изолированный прогон:

```
python tests/audit/run_tests.py
```

Скрипт поднимает отдельный экземпляр API поверх копии базы и сверяет число
событий в каноническом журнале до и после. Прямой вызов `pytest tests/audit/`
пишет в канонический журнал — так уже случилось однажды, и шестьдесят
тестовых событий остались в нём навсегда.

## Карантин ошибочных записей

Журнал только на добавление. Ошибочно записанное не удаляется, а объявляется
непригодным новым событием `audit.event_set.quarantined.v1` со ссылкой на
манифест. Рабочая проекция такие события исключает, сырая лента — показывает.
Отмена решения — событием `audit.event_set.quarantine_revoked.v1`.
