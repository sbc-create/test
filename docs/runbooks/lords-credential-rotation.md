# Ротация CDNVideoHub API Token направления Lords

Выполняется **после** транзакции закрепления root-юнитов и **до** ввода
credentials Zona и Animedia/AMD.

## Почему ротация нужна, хотя утечки не доказано

Факта утечки нет: ни в журналах, ни в git, ни в артефактах значение токена не
обнаружено, и никто не наблюдал его использования третьей стороной. Доказать
обратное — что значение точно никто не читал — тоже нельзя, и именно это здесь
решает.

Пять root-юнитов получали расшифрованные credentials Lords и исполняли код,
который учётная запись `claude` могла переписать. Граница секретности,
объявленная в `docs/SECRET_HUB.md` («сессия агента не может получить API
Token»), в течение этого времени не действовала. Ротация — не реакция на
доказанный инцидент, а возврат к состоянию, в котором утверждение «этот токен
видели только те, кому положено» снова опирается на что-то кроме отсутствия
доказательств обратного.

Ротация — не срочная операция. Срочной была бы остановка утечки, а её нет.

## Предусловия

| Условие | Как проверить |
| --- | --- |
| транзакция закрепления выполнена | `/opt/site-factory/runtime/current` существует |
| аудит границы зелёный | `python3 automation/hardening/audit_root_units.py` → код 0 |
| панель Secret Hub опубликована и отвечает по HTTPS | владелец открыл её в браузере |
| текущие витрины Lords отвечают 200 | `lordfilm47.space`, `lordserial33.biz`, `1lordserials1.online` |

Пока хотя бы одно не выполнено, ротация не начинается: новый токен, введённый
в непочиненный контур, окажется в том же положении, что и старый.

## Порядок

Старый токен остаётся действующим до последнего шага. Это и есть план отката:
пока он не отозван, возврат — это применение прежней версии, которая в
хранилище никуда не делась.

### 1. Получить новый токен

Владелец выпускает новый API Token в личном кабинете CDNVideoHub и вводит его
**только** в форму панели Secret Hub, в карточку `lords`.

Нельзя: вставлять значение в терминал, в prompt агента, в файл, в URL, в тикет
или в переписку. У панели нет операции, возвращающей значение, — и ни у кого
другого её тоже быть не должно.

Панель на этом шаге выполняет живую read-only проверку токена у провайдера и
сохраняет его **новой версией**. Прежняя версия остаётся `superseded` и
пригодна для отката.

### 2. Применить атомарно

Кнопка «Применить к сайтам» в карточке `lords`, либо:

```
python3 -m factory secrets apply --portfolio lords
```

Порядок внутри `apply` уже продиктован требованием отката: бэкап хранилища →
живая проверка → проверка целей → снимок прежних файлов → атомарная запись →
проверка прав → и только затем перезапуск unit'ов этого направления.

Отказ на втором потребителе возвращает и первого. Половина сайтов на новом
токене и половина на старом — состояние, которое никак не называется, и
`apply` его не создаёт.

### 3. Проверить до отзыва

Всё проверяется на новом токене, пока старый ещё действует:

| Что | Как |
| --- | --- |
| состояние направления | `python3 -m factory secrets status` — `configured`, `verified`, новая версия, новый отпечаток |
| граница не сломана | `python3 automation/hardening/audit_root_units.py` → код 0 |
| health витрин | `/healthz` на каждой из трёх витрин Lords |
| публичные маршруты | главная, карточка, страница сезона — код 200 и непустой каталог |
| привязки плеера | на странице с эпизодом присутствует элемент провайдера, состояние `playable`, а не `noaccess` |
| каталог не опустел | число записей не упало: пустой каталог при HTTP 200 — самый незаметный вид отказа |
| журнал | в `journalctl -u lords-01..03` нет значений — только имена и коды |

Если хоть одна проверка не прошла — **откат**: применить предыдущую версию
(`rotate` умеет вернуться, значение не удалено), убедиться, что витрины снова
отвечают, и разбираться. Старый токен на этом шаге ещё не отозван, поэтому
откат работает.

### 4. Отозвать старый токен

Только после того, как все проверки шага 3 прошли, и не раньше:

```
python3 -m factory secrets revoke --portfolio lords --version <прежняя>
```

и отзыв прежнего токена на стороне CDNVideoHub в личном кабинете.

После этого шага откат к прежнему значению перестаёт существовать. Это
единственная необратимая операция во всём процессе, и она выполняется
последней намеренно.

**Автоматически старый токен не отзывается ни при каких условиях.** Отзыв
инициирует владелец, вручную, после проверок.

## Publisher ID

Меняется **только если** контракт CDNVideoHub считает Publisher ID секретом и
поддерживает его безопасную замену. Замороженный контракт отвечает на это
прямо, и догадка не требуется — `knowledge/cdnvideohub/PLAYER_CONTRACT.yaml`,
раздел `secrets`:

```yaml
CDNVIDEOHUB_API_TOKEN:
  kind: server_side_secret
  never_in: [NEXT_PUBLIC_*, HTML, JS bundle, screenshot, log, error response,
             analytics, git, artifact]
CDNVIDEOHUB_PUBLISHER_ID:
  kind: configured_public_value
```

Publisher ID классифицирован как **настраиваемое публичное значение**, а не
секрет. Это согласуется с тем, как он используется: попадает в атрибут
`data-publisher-id` элемента плеера на публичной странице (там же, раздел
`attributes`), то есть виден любому посетителю.

Отсюда: **Publisher ID не ротируется.** Ротация значения, которое контракт
объявляет публичным, не является операцией безопасности; замена издателя — это
переезд витрины на другого издателя со всеми последствиями для каталога, и
делается по другому поводу и по другому решению.

Вводить его через защищённую форму при этом правильно: форма — способ доставки
настройки без появления её в git, argv и журнале, и к классификации значения
это отношения не имеет.

## После ротации

Только теперь разрешается вводить credentials Zona и Animedia/AMD: контур
починен, а токен Lords снова принадлежит только тем, кому положено.
