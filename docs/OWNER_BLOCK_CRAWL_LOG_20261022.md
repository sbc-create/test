# Владельцу: включить журнал обхода роботов — он дешевле Вебмастера

Семь домéнов сети не получают от Яндекса НИ ОДНОГО поискового визита. Причина
не установлена, и дальше без одного из двух доступов не пройти. **Этот блок —
про более дешёвый из двух.**

## Какой вопрос он закрывает

Сейчас нельзя различить два совершенно разных случая:

* **робот не ходит** — тогда дело в обнаружении, и лечится это картой,
  ссылками, зеркалами;
* **робот ходит, но не ранжирует** — тогда дело в содержании или в фильтрах, и
  карта не поможет вовсе.

Лечение у них противоположное, и выбирать между ними догадкой — значит с
вероятностью половина делать не ту работу на семи домéнах.

## Почему ответа нет прямо сейчас

| попытка | результат |
| --- | --- |
| общий `/var/log/nginx/access.log` | **не читается из сессии**: владелец `www-data`, группа `adm`; и даже с доступом он не годится — своего `log_format` у него нет, действует встроенный `combined`, а в нём НЕТ ни `$host`, ни `$server_name`, то есть домена в записи просто нет |
| журнал витрины (`/var/log/nginx/yummyani.biz.access.log`) | не читается из сессии по той же причине |
| журнал обхода `/var/log/nginx/crawl.log` | **файла нет**: конфигурация `00-crawl-log.conf` в `/etc/nginx/conf.d/` не установлена (там есть только `00-webmaster-verification-log.conf`) |
| Вебмастер | доступа нет (B023) |

Важное замечание о прежней команде: разложить обход по доменам из общего
журнала нельзя ни первым полем, ни любым другим — `awk '{print $1}'` считал бы
IP клиентов и выдавал бы это за счёт по доменам. Поэтому нужен отдельный формат,
а не чтение существующего файла.

## Что уже готово в репозитории

* `automation/host/nginx/00-crawl-log.conf` — объявляет `map $http_user_agent
  $is_crawler`, формат `crawl` с `$host`, и `access_log … if=$is_crawler` для
  блоков БЕЗ собственного журнала. Префикс `00-` не декоративный: `log_format`
  допустим только в http-контексте, и файл обязан разбираться раньше
  конфигураций витрин;
* `automation/local/stage-crawl-log.py` — дописывает строку журнала обхода тем
  **восьми** блокам, которые объявляют свой `access_log` и потому объявление из
  http-контекста НЕ наследуют. Без этого шага обход восьми витрин не попал бы в
  файл вовсе, и неполнота выглядела бы как «роботы не ходят» — то есть хуже
  отсутствия журнала;
* `--diff` показывает правку, ничего не меняя. Проверено 22.10: правка — ровно
  одна добавленная строка `access_log /var/log/nginx/crawl.log crawl
  if=$is_crawler;` рядом с существующей, а не замена. nginx пишет в оба файла,
  и собственный журнал витрины остаётся как был.

## Блок операций

Выполняется владельцем. После каждого шага — своя проверка.

### 1. Посмотреть правку, ничего не меняя

```bash
python3 /home/claude/wt-nova-publish-memory-02/automation/local/stage-crawl-log.py --diff
```

### 2. Поставить объявление формата

```bash
cp -p /home/claude/wt-nova-publish-memory-02/automation/host/nginx/00-crawl-log.conf \
      /etc/nginx/conf.d/00-crawl-log.conf
nginx -t
```

`nginx -t` обязателен ДО перезагрузки: `access_log`, ссылающийся на ещё не
объявленный формат, роняет проверку конфигурации целиком.

### 3. Дописать строку восьми блокам со своим журналом

Файлы готовит `stage-crawl-log.py` (без `--diff` он кладёт их в
`var/staged-nginx-crawl/`); установка — копирование владельцем, после чего снова
`nginx -t`.

### 4. Применить

```bash
systemctl reload nginx
```

Проверка — файл появился и в нём есть домены:

```bash
ls -l /var/log/nginx/crawl.log
```

### 5. Что ответит замер

Через сутки после включения по этому файлу различимы оба случая, и различимы
ПО ДОМЕНУ. Минимально нужное от владельца, если файл не станет читаемым
сессией: выгрузка вида «домен, робот, число обращений за сутки» — её достаточно,
сам журнал не нужен.

### 6. Откат

```bash
rm -f /etc/nginx/conf.d/00-crawl-log.conf
nginx -t
systemctl reload nginx
```

Откат безопасен: собственные журналы витрин правка не трогала, она только
добавляла второй `access_log`.

## Чего этот блок НЕ делает и не обещает

* **не заменяет Вебмастер.** Он отвечает «ходит ли робот», но не «что он
  думает о страницах»: ни состояния индекса, ни показов, ни позиций в журнале
  нет и быть не может;
* **не называет причину нуля.** Он сужает её до одной из двух половин, и это
  его цена — дальше работа разная;
* **не обещает, что робот обнаружится.** Пустой `crawl.log` по домену — тоже
  ответ, и ответ сильный;
* **не читает ничего из существующих журналов:** из сессии они недоступны, и
  обходить это я не пыталась.
