# Откат

## Когда откатывать

- провален production smoke;
- деградация мониторинга сразу после выката;
- обнаружена утечка данных другого сайта или неверный canonical/TLS/домен;
- решение оператора.

## Как

```bash
python3 -m factory status   --site <id> --json      # зафиксировать состояние ДО
python3 -m factory rollback --site <id> --environment <env>
python3 -m factory verify   --site <id>             # без verify откат не доказан
```

`rollback` переключает `current` на предыдущий релиз (атомарно) и обязательно выполняет
health-проверку. Если предыдущего релиза нет — `DeployFailed` с явной причиной, а не
молчаливый успех.

## Данные

Откат кода **не** откатывает базу данных. Если релиз содержал миграцию:

1. восстановить БД из бэкапа этого релиза (`backup.ref` в результате задания);
2. подтвердить восстановление сравнением, а не наличием файла;
3. только затем открывать трафик.

Политика фиксируется в пакете: `rollback_policy.database_rollback: from_backup |
not_applicable`.

## После

Статус задания — `ROLLED_BACK`. Оформи инцидент скиллом `/incident-report`:
что произошло, влияние, какие команды и с какими exit code выполнялись, root cause
(«повторный запуск помог» причиной не является), какой тест или гейт это предотвратит.
