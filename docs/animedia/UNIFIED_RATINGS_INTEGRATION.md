# Подключение единого модуля оценок к animedia.icu

Контракт для терминала «ШАБЛОН ANIMEDIA». Общий модуль ничего не знает о
шаблоне витрины, витрина ничего не знает о базе оценок; между ними —
два файла и один модуль-адаптер.

## Цепочка выкладки (проверено 2026-09-22)

```text
animedia.icu
  → /etc/nginx/lords/animedia-01.conf  (server_name animedia.icu)
  → proxy_pass http://127.0.0.1:9121
  → nova-animedia-01.service           («nova frontend: animedia-01 (animedia.icu)»)
  → PID 279780
  → /srv/lords/.frontend/releases/20260921T214937Z-fac5643-animedia-parity/animedia-frontend.py
```

`animedia-01.service` — **другой** юнит (`/srv/lords/animedia-01/current/serve.py`,
PID 474239) и порт 9121 не держит. Для animedia.icu значим
`nova-animedia-01.service`.

## Что делает общий модуль

Готовит два файла в `/srv/lords/.frontend/`:

| Файл | Содержимое |
| --- | --- |
| `unified-ratings-projection-animedia.json` | оценки по произведениям: внешние источники раздельно, сводная оценка, оценка зрителей, редакционная |
| `unified-ratings-flags-animedia.json` | `RATINGS_PUBLIC_READ_ANIMEDIA`, `RATINGS_PUBLIC_WRITE_ANIMEDIA`, `KILL_SWITCH`, когорта `allowlist` |

Файлы собираются командой общего модуля; витрина их только читает.

## Что нужно от витрины: три точки

Больше изменений не требуется. Разметку внешних оценок витрина уже умеет
рисовать из `ratings_by_source`.

**1. Импорт адаптера** (`automation/host/animedia-frontend.py`):

```python
from factory.animedia import unified_ratings_adapter
```

**2. Обогащение данных произведения** — там, где деталь уже собрана:

```python
деталь = unified_ratings_adapter.merge_into_detail(деталь)
```

Адаптер возвращает тот же объект, если файла проекции нет, флаг чтения
выключен, произведение вне когорты или файл повреждён. Страница в этих
случаях выглядит ровно как до подключения.

**3. Монтирование блока на странице произведения**:

```python
ctx = unified_ratings_adapter.widget_context(деталь)
# ctx is None → блок не монтируется вовсе
```

Шаблон — `factory/animedia/frontend/unified_rating_widget.html`,
статика — `unified_rating_widget.css` и `unified_rating_widget.js`.

## API, который ждёт виджет

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/unified-ratings/me?space=animedia&subject_id=<id>` | своя оценка и текущий агрегат |
| `PUT` | `/api/unified-ratings/vote` | поставить или изменить оценку 1–10 |
| `DELETE` | `/api/unified-ratings/vote` | отозвать оценку |

Требования: `Idempotency-Key` обязателен, `X-CSRF-Token` обязателен,
cookie — `same-origin`. Сервер не доверяет `score` из интерфейса и
проверяет его до записи. `title_id` клиент не передаёт: сервер определяет
его по паре (space, subject_id).

## Что виджет показывает

* «Сводная оценка» — только при двух и более источниках, с числом
  источников и раскрываемым списком;
* каждый внешний источник отдельной строкой со своим числом голосов;
* «Оценка зрителей» отдельно от внешних; при отсутствии голосов —
  «Пока нет оценок», а не ноль;
* «Наша оценка» отдельно, если редакция её поставила;
* контрол 1–10, текущая своя оценка, изменение и отзыв.

Доступность: шкала размечена как `radiogroup`, стрелки перемещают фокус,
в обход Tab попадает один элемент группы, фокус виден обводкой, статус
операции объявляется через `aria-live`. На ширине 320–480px шкала
раскладывается в две строки по пять — сжимать десять целей нажатия в
одну строку значит сделать их непопадаемыми.

Отказ API не убирает показанные оценки: контрол сообщает, что сохранить
не получилось, и всё остальное остаётся на месте.

## Первый этап раскатки

* `RATINGS_PUBLIC_READ_ANIMEDIA=1` — внешние и сводная оценки видны
  обычным посетителям;
* `RATINGS_PUBLIC_WRITE_ANIMEDIA=0` — голосование доступно только
  владельцу или явно заданной тестовой когорте;
* `PUBLIC_WRITE_ROLLOUT_PERCENT=0`;
* `KILL_SWITCH` выключает и чтение, и запись одним флагом.

Пустой `allowlist` означает «никому», а не «всем».

## Чего этот адаптер не делает

Не меняет robots, canonical и индексацию; не трогает плеер, каталог и
комментарии; не обращается к animedia.space и другим доменам; не пишет
в базу и не ходит в неё вовсе.
