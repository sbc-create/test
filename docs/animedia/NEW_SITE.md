# Новый сайт семейства Animedia: откуда берётся версия

Постоянный документ. Отвечает на один вопрос: **что нужно сделать, чтобы новый
сайт получил исправления, а не прежние блоки.**

Он существует потому, что ответ не выводится из кода. Сборщик читает версию из
дерева той ветки, на которой запущен, и ни в одном файле до этого не было
сказано, какая ветка каноническая. «Соберите из шаблона» без имени ветки — это
указание, которое каждый исполнит по-своему.

## Что закреплено

| | |
| --- | --- |
| репозиторий | `sbc-create/test` |

| коммит после интеграции | **`761262d201fae1ee11feaec7298c71a5cffef5a4`** (merge PR №90) |
| оформление | **1.2.11** |
| `template_id` | `animedia-nova` |
| модуль сообщества | 2.1, пин `da20a290`, sha256 `f82555e8…` |
| выбираемые профили | `animedia-space`, `animedia-icu` |

Машинная копия — `config/animedia/TEMPLATE_VERSION.json`, блок `canonical`.
Файл читает сам сборщик, поэтому версия и ветка лежат там, где их нельзя
разойтись с кодом незаметно.

## Проверенная команда

Проверено 27 сентября 2026: собрано из `761262d`, поднято на изолированном
экземпляре, все проверки зелёные (см. «Чем это подтверждено»).

```bash
# 1. каноническая ветка семейства
git clone https://github.com/sbc-create/test.git
cd test
git checkout claude/animedia-template-fix-01

# 2. релиз + манифест витрины ОДНОЙ сборкой
python3 automation/host/animedia_release_build.py \
        --out-dir      "$РЕЛИЗЫ" \
        --stage        "<СТАДИЯ>" \
        --profile      animedia-space \
        --emit-manifest "$ДАННЫЕ/template-manifest-<site_id>.json"

# 3. запуск витрины
ANIMEDIA_RUNTIME_ROOT="$ДАННЫЕ" \
ANIMEDIA_TEMPLATE_MANIFEST="$ДАННЫЕ/template-manifest-<site_id>.json" \
ANIMEDIA_CATALOG="$ДАННЫЕ/<site_id>-catalog.json" \
ANIMEDIA_DETAILS="$ДАННЫЕ/<site_id>-details.json" \
ANIMEDIA_SITE_DATA_DIR="$ДАННЫЕ/site-data" \
ANIMEDIA_SITE_NAME="<Имя витрины>" \
LORDS_PLAYER_CONFIG="$ДАННЫЕ/player-<site_id>.json" \
python3 "$РЕЛИЗЫ/<build_id>/animedia-frontend.py" --host 127.0.0.1 --port <ПОРТ>
```

`--emit-manifest` не необязателен. Манифест витрины, набранный руками,
отстаёт от пересборки молча: артефакт новый, `build_id` прежний, и витрина
называет выпуск, которого на диске уже нет. Проверить это можно одним полем:

```bash
curl -s http://127.0.0.1:<ПОРТ>/healthz | python3 -c \
  'import sys,json; d=json.load(sys.stdin); print(d["release_id"], d["identity_match"])'
```

`identity_match: true` означает, что паспорт релиза, манифест витрины и цифра
исполняемого файла говорят одно.

### Отказы сборщика — намеренные

| отказ | условие |
| --- | --- |
| `ветка вне контура` | ветка не начинается на `claude/animedia-` |
| `нет файла версии шаблона` | нет `config/animedia/TEMPLATE_VERSION.json` |
| `рантайм не объявляет версию X` | строки версии нет в исходнике рантайма |
| `дерево грязное` | сборка не из зафиксированного кода |
| `артефакт в дереве не совпадает с зафиксированным в git` | то же |
| `профиль не объявлен выбираемым` | `--profile` вне `variants` |

На `origin/main` сборщик не работает и работать не должен: файла версии там
нет. Отсутствие изменений в `main` неработоспособности НЕ доказывает —
источник сборки семейства это ветка `claude/animedia-*`.

## Что задаёт конкретный сайт

Шаблон один, различия сайта приезжают рядом с ним и в Git не хранятся.

| вход | откуда | если нет |
| --- | --- | --- |
| `<site_id>` | имя снимка `<site_id>-catalog.json` | витрина не поднимется |
| снимки каталога, подробностей, топа | отдельная доставка | пустая витрина |
| `player-<site_id>.json` с `publisher_id` | Secret Hub | плеер молчит, страницы работают |
| `ANIMEDIA_SITE_DATA_DIR` | каталог данных сайта | голоса и комментарии некуда писать |
| профиль | `animedia-space` или `animedia-icu` | сборщик откажет |
| домен, TLS, nginx, порт | инфраструктура | вне шаблона |

**Чужой `publisher_id` умолчанием не становится.** Имя файла плеера выводится
из имени снимка каталога, поэтому у нового сайта витрина ищет свой
`player-<site_id>.json` и, не найдя, остаётся без плеера. Подставить соседний
ключ значило бы отправить просмотры и права нового домена в чужой кабинет —
и снаружи это выглядело бы как работающая страница. Закреплено проверкой
`test_новый_домен_не_получает_издателя_соседа`.

## Что требуется подключить (передача архитектору)

Автоматического выбора шаблона у фабрики на этой линии **нет**. Сайт получает
версию через ветку, из которой собран релиз; `config/TEMPLATE-BASELINE-MANIFEST.json`
— производный снимок УЖЕ существующих сайтов, а не место выбора, и руками не
правится. `factory/templates_cp` наблюдает за развёрнутыми витринами и тоже
ничего не выбирает.

Поэтому передача такая:

> Для нового сайта семейства Animedia собирайте из ветки
> `claude/animedia-template-fix-01`, коммит `761262d` и новее, оформление
> 1.2.11, командой из раздела «Проверенная команда» выше.

Пока эта строка не попала в инструмент создания сайта, выбор версии остаётся
действием человека. Считать это подключённым нельзя: подготовленная передача
и фактическое подключение — разные состояния, и второе здесь не выполнено.

## Чего эта версия не делает

Действующие сайты на 1.2.11 не переводятся. Оформление достаётся витрине, чей
манифест его объявил, поэтому интеграция не меняет ни одной живой витрины.
Перевод существующего сайта — отдельное управляемое действие.

Уменьшение постеров не реализовано: заявка с замерами и границами —
`docs/animedia/REQUEST_POSTER_DOWNSCALE.md`. Она ждёт решения владельца о новой
зависимости рантайма и интеграцию 14 исправлений не задерживает.
