# Открытие индексации восьми витрин K2: что требуется и в каком порядке

Готовится заранее, чтобы решение владельца не упиралось в расследование. Все
пути и состояния ниже ИЗМЕРЕНЫ 2026-10-18 на узле `k2-zomro-01`.

Сейчас витрины закрыты согласованно: `desired_state: CLOSED` в паспорте,
`promotion.excluded: true`, счётчика Метрики нет (решение D209 — Метрика на
партии запрещена, Google Analytics вместо неё тоже). Пока это так, вклад K2 в
цель по визитам измерить нечем.

## Четыре независимых затвора

Режим считается ОТКРЫТЫМ, только когда согласны все четыре. Любой
несогласный оставляет витрину закрытой — направление отказа fail-closed.

| № | Затвор | Где лежит | Состояние на 18.10 | Кто меняет |
| --- | --- | --- | --- | --- |
| 1 | разрешение выпуска | `config/site.json` витрины, `indexing.release_permits_open` | `false` у всех восьми | я, обычным выпуском |
| 2 | файл состояния ячейки | `/srv/sites/indexing/<домен>.json`, поля `desired_state: OPEN` и `owner_authorized_open: true` | каталога на узле НЕТ | привилегированный исполнитель (root) |
| 3 | якорь согласия владельца | `/var/lib/site-cells/owner-consent/<домен>.json` | каталога на узле НЕТ | владелец/root |
| 4 | карта режима nginx | `/etc/nginx/cells/lords-1N.robots` | есть, режим CLOSED | root на узле |

Проверено, что затворы действительно независимы: читатель режима
(`automation/host/indexing_mode.py`) отказывает по каждому отдельно и прямо
пишет причину.

## Что НЕ требуется

* **Карта сайта.** Файлов нет намеренно: сборщик при закрытом режиме
  возвращает «режим CLOSED: карта не нужна», а маршрут `/sitemap.xml` даже
  при готовых файлах отвечает 404. Подключение в репозиториях витрин на
  месте (`LORDS_SITEMAP_DIR` из `run.py`, `РАЗДЕЛЫ_КАРТЫ`,
  `seo_layer.запустить_карту` и в репозитории, и в выложенном выпуске).
  После открытия карта соберётся сама. Подробности —
  `docs/verification/checked-clean-20261018.md`.
* **Двойной `X-Robots-Tag`.** Заголовок ставят и ячейка, и nginx — это защита
  в два слоя, а не дефект (`docs/verification/k2-posters-freshness-20261017.md`).
  Но приёмка открытия обязана проверить ОБА источника: если переключить
  только карту nginx, ячейка продолжит отдавать `noindex`.

## Порядок

1. **Решение владельца** об открытии и об аналитике партии (без счётчика
   результат не измерить, а D209 Метрику на партии запрещает — значит нужен
   либо пересмотр D209, либо согласие измерять K2 иначе).
2. Затвор 3 и затвор 2 — операция владельца/исполнителя на узле.
3. Затвор 1 — я выпускаю `release_permits_open: true` на восьми витринах
   обычным порядком (`k2-release-code.sh --release`), с откатом.
4. Затвор 4 — root на узле переключает карту режима и перечитывает nginx
   (`nginx -t` и `systemctl reload nginx` разрешены в `sudo` доставки).

## Приёмка после открытия

```bash
python3 automation/local/indexing-registry-vs-live.py      # расхождений 0
python3 automation/local/indexability-sweep.py             # находок 0
curl -sSI https://lordfilm.group/ | grep -i x-robots-tag   # index, follow в ОБОИХ слоях
curl -sS  https://lordfilm.group/sitemap.xml | head -3     # карта появилась
curl -sS  https://lordfilm.group/robots.txt | grep -i sitemap
```

Ожидание по карте: сборщик опрашивает снимок раз в несколько секунд, поэтому
файлы появляются в течение минут после открытия, а не мгновенно.

Три пункта приёмки добавлены 2026-10-18 — каждый закрывает то, что открытие
меняет, а закрытый режим скрывает:

```bash
# 1. Пустые страницы серий обязаны ОСТАТЬСЯ закрытыми. Открытие меняет режим
#    сайта, а правило страницы от режима не зависит: на одной витрине таких
#    страниц 45 198 из 602 566 объявленных серий.
curl -sS https://lordserial.su/title/skotty/season-1/episode-2/ \
  | grep -o 'name="robots" content="[^"]*"'      # ждём noindex, follow
curl -sS https://lordserial.su/title/skotty/season-1/episode-1/ \
  | grep -o 'name="robots" content="[^"]*"'      # ждём index, follow

# 2. Служебные пути обязаны остаться закрытыми И короткими. Открытие меняет
#    `мета_роботов()`, и запрет служебных путей держится отдельным правилом
#    (`мета_роботов_пути`), а состав ответа — разделением внутреннего и
#    публичного вызова.
python3 automation/local/healthz-exposure.py --path /healthz \
  --path /__template_version --domain lordfilm.group   # про устройство 0

# 3. Карта обязана собраться С ДАТАМИ ИЗМЕНЕНИЯ, а не с датами появления.
#    Снимки каталога на узле собраны до правки `lastmod` (2026-10-18), и в
#    них нет поля `updated_at`: тогда карта честно пойдёт БЕЗ `lastmod`, и это
#    допустимо. Подставленной даты быть не должно ни в каком случае.
python3 automation/local/sitemap-lastmod-check.py --domain lordfilm.group
#    ждём: либо адреса без lastmod, либо даты изменения; «массовая
#    подстановка» — отказ приёмки
```

## Паспорт

После открытия записи в `config/site-cells.json` обязаны перестать расходиться
с живым режимом.

Поправка 2026-10-18 к прежней формулировке. Здесь было написано «по сети таких
расхождений девять». Это неточно, и неточность была в мою сторону — она
преувеличивала тревогу. Расхождение бывает двух родов, и девять случаев
принадлежат первому:

* **запись устарела** — домен открыт ПО РАЗРЕШЕНИЮ владельца (флаг
  `open_authorized` и файл согласия на месте), а текст паспорта описывает
  прежнее состояние. Это бухгалтерия: сайт работает законно. Таких девять;
* **открыт без разрешения** — разрешения нет вовсе. Таких НОЛЬ.

Паспортное поле `indexing.desired_state` — это РАЗРЕШЕНИЕ (слой 1 из четырёх),
а состояние живёт в слое 3 и меняется штатной операцией; смешивать их нельзя
по той же причине, по которой они разделены. Инструмент
`automation/local/indexing-registry-vs-live.py` теперь различает оба вывода и
роняет проверку только на втором.

Для K2 из этого следует ровно одно: после открытия запись паспорта обязана
быть обновлена тем же шагом, что и состояние, — иначе через неделю здесь
появится десятая «устаревшая запись», и причина будет та же.
