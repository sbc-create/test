# Управление сетью витрин редактором (Qwen)

Введено 2026-10-01. Этот документ описывает НОВЫЕ поля, состояния и операции —
они не существовали раньше и за существующие не выдаются.

## Новые понятия этой задачи

| понятие | где живёт | что значит |
| --- | --- | --- |
| `handover_state` | **новое поле**, вычисляется `factory/qwen/registry.py` | состояние передачи сайта редактору; списком домен не ведётся |
| `managed` | значение `handover_state` | выпуск активирован, адаптер семейства поддержан, хранилище на месте — редактор может писать |
| `pending_adapter` | значение `handover_state` | сайт жив и выпущен, но в его рантайме нет читателя наложения: записанное не появится на странице |
| `managed_no_facts` | значение `handover_state` | доставка и отображение работают, а источника фактов у семейства нет: текст должен приходить с уже проверенными фактами извне, операции `prepare` и `facts` недоступны |
| `not_released` | значение `handover_state` | нет ссылки `current` либо домен не отвечает |
| `unknown` | значение `handover_state` | точка входа не сопоставлена адаптеру; названа причина |
| `prepared / verified / written / confirmed` | **новые** состояния материала | подготовлен / прошёл проверки / записан в хранилище / НАЙДЕН в основном блоке страницы |
| `editorial_store` | **новое поле** | абсолютный путь к файлу материалов этого домена (`<корень семейства>/<домен>/title-overlays.json`); корень свой у каждого семейства |
| `editorial_items` | **новое поле** | сколько записей сейчас лежит в этом файле; `null` — файла нет или он не прочитан |
| `operations` | **новое поле** | какие операции доступны ИМЕННО этому сайту; выводится из возможностей адаптера, а не объявляется семейству целиком |
| `handover_reason` | **новое поле** | почему состояние не `managed`; пусто при `managed` |
| `drafts.json`, `unpublished.json`, `history.jsonl` | каталог домена в хранилище | черновики, снятый материал, журнал операций |

**`written` и `confirmed` разделены намеренно.** Запись файла, нулевой код
возврата и наличие отчёта публикацией не являются — это дважды выглядело
успехом при пустой странице. Итоговое состояние считает инструмент по
фактическому HTML.

## Откуда берётся список сайтов

Только из действующих реестров, без второго списка внутри инструмента:

* `config/site-cells.json` — ячейки, которыми управляет очередь выпуска;
* `inventory/network-allowlist.yaml` — домены сети. Реестр ячеек ему НЕ равен:
  `an1mego.site` и `animeg0.site` работают, но ячейками не являются.

Добавление сайта в реестр делает его видимым инструменту без правок кода.
Отдельного внесения домена в списки инструмента не требуется.

## Адаптеры семейств

Адаптер выбирается по ТОЧКЕ ВХОДА рантайма, а не по имени домена:

| точка входа | адаптер | сайтов | состояние |
| --- | --- | --- | --- |
| `animedia-frontend.py` | `animedia` | 2 | **поддержан**, проверен на живых страницах |
| `lords-frontend.py`, `lords01/02-frontend.py` | `lords` | 8 | читатель наложения в рантайме не выпущен |
| `animego-frontend.py` | `animego` | 1 (+2 вне реестра) | то же |
| `yummy-frontend.py` | `yummy` | 5 | хранилище и читатель есть у приложения Next.js; каталоги по домену не заведены |
| `serve.py` | `zona-serve` | 1 | механизм не установлен |

Для неподдержанного семейства инструмент возвращает конкретную недостающую
возможность, а не общий отказ.

## Одна последовательность на все семейства

    факты -> подготовить -> проверить -> опубликовать | снять -> подтвердить

Команды одинаковы независимо от шаблона. Пути, устройство хранилища, UUID и
команды выпуска редактор не угадывает: их отдаёт инструмент.

## Передача текста

Тело материала передаётся файлом (`--body-file`) или стандартным вводом
(`--body-file -`) как данные. В исполняемую строку оболочки пользовательский
текст не попадает ни при каких условиях. Домен, идентификаторы и каталог
хранилища проверяются программно; запись одного сайта не затрагивает другой —
каталог вычисляется от домена и сверяется с корнем хранилища, а проверка
принадлежности внутри хранилища (`wrong_site_in_overlay_payload`) не
отключается.

## Чужую более новую правку не затираем

У `publish` есть `--expect-generation`. Если в хранилище лежит другая версия,
операция отказывает и показывает фактическую. Повтор того же задания дубликата
не создаёт: ключ — `slug`, как у пишущей стороны.

## Снятие с публикации обратимо

`unpublish` переносит запись в `unpublished.json`, оставляет остальные записи и
пишет журнал. Материал и история сохраняются; `restore` возвращает его тем же
текстом. Физического удаления сайтов, репозиториев, тайтлов и исходного
каталога эти операции не выполняют и не предусматривают.

## Проверки качества выросли из найденных ошибок

Отклоняются: обороты про доступность (`доступ`), озвучки, субтитры, «все
серии», «бесплатно», «без регистрации»; текст короче 80 и длиннее 1200 знаков;
текст без названия тайтла и без года из снимка; лишние годы, которых в снимке
нет.

**Чего проверка НЕ умеет.** Она не оценивает осмысленность и не поймает
выдуманный сюжет, сформулированный без запрещённых оборотов. Это ограничение
автоматической проверки качества, и его надо знать: ответственность за факты
остаётся на авторе материала.

## Индексация — отдельные проверяемые операции, только чтение

`indexing` показывает `robots.txt`, `meta robots`, `X-Robots-Tag`, `sitemap.xml`
и `canonical` как отдельные величины. Менять режим инструмент не умеет
намеренно: переход открывается решением владельца либо ранее утверждённым
правилом. **Передача сайта редактору открытием индексации не является**, и
закрытая индексация подготовке и публикации контента не мешает.

## Плеер: наличие тега и воспроизведение — разные утверждения

`diagnose` отдаёт `player_tag_present` (есть ли `<video-player>`) и
`playback_verified: null` с пояснением. Фактическая игра проверяется отдельным
инструментом с браузером — `automation/host/publisher-id-live-check.js`, он
ждёт `readyState>=2` и прирост времени не меньше 10 секунд.
