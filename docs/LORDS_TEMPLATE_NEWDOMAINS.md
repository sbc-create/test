# Выбор версии 1.1.0 для lordserials22.site / .space / .info

Документ отвечает на один вопрос: **как эти три домена получат именно эту
версию шаблона**. Само развёртывание — отдельная задача; здесь порядок,
команды и то, что этому порядку сегодня мешает.

---

## 1. Препятствие, которое надо снять первым

**Пул профилей Lords исчерпан, и он исключительный.**

```
lords-curated    assigned   lords-03  1lordserials1.online
lords-general    assigned   lords-01  lordfilm47.space
lords-genre      assigned   lords-04  (домена нет)
lords-new        assigned   lords-02  lordserial33.biz
```

`config/template-pool.json`, семейство `lords`: `exclusive: true`. Основание
записано там же: профиль владеет страницей произведения и разделами каталога,
и два сайта на одном профиле дали бы одинаковые разделы и заголовки на разных
доменах — тот самый дубль, который ловит гейт `seo-cross-site`.

Значит **трём доменам сегодня выдать нечего**: свободных профилей ноль.
`python3 -m factory cell templates` подтверждает.

Что можно сделать, по возрастанию стоимости:

| Вариант | Что даёт | Чего стоит |
| --- | --- | --- |
| Освободить `lords-genre` у `lords-04` (домена у него нет) | один профиль | решение владельца пула; и профиль всё равно не поддержан 1.1.0 — см. §4 |
| Завести три новых профиля семейства | три домена | по профилю: YAML в `blueprints/lords/profiles/`, значение темы в перечне схемы, запись в `ДИЗАЙН_ПО_ПРОФИЛЮ` рантайма, перепин артефакта, проверки различимости |
| Снять исключительность | три домена сразу | отменяет защиту от дубля разделов и заголовков между доменами; гейт `seo-cross-site` начнёт находить совпадения |

**Рекомендация:** второй вариант. Первый решает один домен из трёх и упирается
в неподдержанный профиль; третий снимает защиту, ради которой правило заведено.

Пока профилей нет, порядок ниже исполним ровно для стольких доменов, сколько
профилей освободят.

## 2. Как домен получает именно версию 1.1.0

Версия не выбирается флагом. Она определяется **коммитом шаблона**, из которого
собран проект сайта, и записывается в трёх местах сразу:

* `pins.lock.json` → `pins.source_commit` — коммит шаблона;
* `pins.lock.json` → `files[*].sha256` — фактические суммы каждого файла;
* `config/template-manifest.json` → `design_version` и `template_origin`.

`design_version` берётся из `status/lords-template-version.json`, а не из
константы в коде. Сверку «что положено — то и закреплено» выполняет
`tests/unit/test_lords_template_single_source.py`.

Поэтому «выбрать 1.1.0» значит: **собрать проект из коммита, на котором
`status/lords-template-version.json` объявляет `1.1.0`**.

```bash
# 0. коммит шаблона с нужной версией
git -C /srv/site-factory/repo log -1 --format=%H claude/lords-template-consolidation-01
python3 -c "import json;print(json.load(open('status/lords-template-version.json'))['version'])"
#   → 1.1.0

# 1. профиль из пула — атомарно, по заказу
python3 -m factory cell reserve --site lords-05 --order <id-заказа> \
        --domain lordserials22.site
#   повтор того же --order возвращает прежнее резервирование и не расходует второй

# 2. проект сайта ИЗ ШАБЛОНА (не копированием с чужого домена)
python3 -m factory cell newsite \
        --site lords-05 --domain lordserials22.site \
        --template <выданный профиль> --port <свободный порт> \
        --site-name "<имя витрины>" \
        --remote https://github.com/sbc-create/site-lordserials22-site \
        --destination var/new-sites/lords-05
```

`newsite` при этом:

* копирует пять файлов рантайма из `automation/host/` ЭТОГО коммита и
  закрепляет их по фактическим суммам;
* кладёт профиль в `config/profile.yaml`;
* пишет манифест с пустыми полями выпуска и неподвижным `template_origin`;
* **записывает ячейку в реестр** (`config/site-cells.json`): размещение, порт,
  учётная запись, каталог данных, `reload: "restart"`. Без этой записи сайт для
  производителей содержимого не существует и обновлений каталога не получит;
* отказывается собирать из грязного дерева: закрепление назвало бы коммит,
  которому файлы не соответствуют.

Проверить, что версия доехала:

```bash
cd var/new-sites/lords-05 && ./checks/run.sh      # 12 проверок
python3 -c "import json;print(json.load(open('config/template-manifest.json'))['design_version'])"
#   → 1.1.0
```

## 3. Что доставляется отдельно и без чего сайт неполон

| Что | Откуда | Без него |
| --- | --- | --- |
| `config/player.json` | Secret Hub, `secret://cdnvideohub/lords/publisher-id` | `run.py` не стартует: «плеер без publisher_id не заработает» |
| `src/community.py` | выпуск `20260923T190000Z-community-2-2-12` | раздел оценок и комментариев показывается выключенным с причиной — рабочее состояние, не поломка |
| ключ модератора | вне Git, `LORDS_05_COMMUNITY_MODERATOR_KEY` | модератора нет: сообщения остаются «ожидает проверки», автору видны, остальным нет |
| снимок каталога | производитель, через `factory.cell.delivery` | `run.py` отказывает: «нет снимка каталога» |

Имена переменных выводятся из `site_id` и печатаются в ответе `newsite`
(`cell.storage_env`, `cell.moderator_key_env`) — выдумывать их не нужно.

## 4. Про lords-genre отдельно

Профиль числится в пуле за `lords-04`, но шаблоном 1.1.0 **не поддержан** и
объявлен таковым в `status/lords-template-version.json` (`profiles_unsupported`)
с причиной. Проверено на свежем экземпляре 2026-09-26:

* в `ДИЗАЙН_ПО_ПРОФИЛЮ` рантайма его нет → витрина отдаёт общий лист
  `lords-sheet` и внешне неотличима от `lords-general`;
* профиль владеет `genres_index`, `years_index`, `countries_index`, а рантайм
  их как самостоятельные страницы не отдаёт: `/years/` и `/countries/` → 404,
  `/genres/` → переход на `/catalog/`.

Выдавать его новому домену нельзя: домен получил бы витрину без собственного
лица и без того содержания, ради которого профиль существует.

## 5. Порядок для владельца, коротко

1. Решить вопрос профилей (§1). Без этого пункты ниже неисполнимы.
2. Зарезервировать профиль на каждый домен, по одному заказу на домен.
3. Создать проекты `newsite` из коммита с версией 1.1.0, с `--remote`.
4. Создать три репозитория сайтов, отправить проекты.
5. Выдать `player.json`, доставить `community.py`, задать ключи модератора.
6. Первая доставка каталога и первый выпуск — штатной очередью.
7. Приёмка: `checks/run.sh`, затем прогон по адресу
   (`artifacts/evidence/lords-template-1.1.0/verify.py`).
