# Контракт событий

Схема: `schemas/site-engine/content-event.schema.json`.

Событие — это утверждение «мы увидели изменение». Не «поставщик изменил» и не
«вышла серия». Разница существенная: она стоила нам одного ложного инцидента.

## Типы

`TITLE_CREATED`, `TITLE_UPDATED`, `EPISODE_ADDED`, `SEASON_ADDED`,
`PLAYBACK_AVAILABLE`, `PLAYBACK_UNAVAILABLE`, `RATING_UPDATED`,
`SCHEDULE_UPDATED`, `ANNOUNCEMENT_UPDATED`, `SOURCE_ANOMALY`.

## Обязательные поля

`schema_version`, `event_id`, `event_type`, `provider`, `provider_id`,
`canonical_title_id`, `observed_at`, `idempotency_key`, `payload`.

## Четыре правила, вытекающие из инцидентов

**`observed_at` — единственная метка, за которую отвечаем мы.**
`provider_timestamp` может отсутствовать: не всякий источник его сообщает.
Публичный API `cdnvideohub` не отдаёт `updated_at` в карточке тайтла вовсе.
Подставлять момент нашего опроса вместо времени поставщика запрещено.

**`idempotency_key` должен быть устойчив.** Повторный цикл, увидевший то же
самое изменение, обязан дать тот же ключ — иначе одно событие попадёт в ленту
дважды.

**Смена алгоритма отпечатка — не изменение данных.** У `source_fingerprint` есть
версия. Однажды правка формата отпечатка озвучек породила 1483 ложных
`VOICEOVER_ADDED` за один проход: watcher честно сравнил новый формат со старым и
увидел разницу везде. Теперь сравнение допускается только при совпадении версий
формата; иначе состояние переписывается молча, без события.

**Событие не создаётся ради появления карточки.** Если серии не выходило,
`EPISODE_ADDED` не выпускается, даже когда витрина выглядит пустой. Проверено
отрицательным контролем: по тайтлу «Бог богатства Чжаньлун Доу» новой серии не
было, и отсутствие события — правильный результат, а не пропуск.

## Связь с кэшем

Каждый тип события отображается в набор тегов кэша — см. `event_map` в
`CACHE-CONTRACT.md`. Событие, не сбрасывающее ни одного тега, бесполезно:
изменение не доедет до страницы.
