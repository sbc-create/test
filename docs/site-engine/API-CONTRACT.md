# Контракт внутреннего API

Документ описывает границу между модулями Site Engine, а не публичный API сайтов.
Публичного API мы не открываем.

## Поставщик: что он на самом деле умеет

`public-api.cdnvideohub.com/api/v1`. Проверено запросами, а не документацией:

| Есть | Нет |
| --- | --- |
| `/titles` с курсорной постраничной выдачей | `/events`, `/updates`, `/feed` — 404 |
| `/titles/{id}` — карточка | `/titles/{id}/episodes` — 404 |
| `/titles/{id}/seasons` | `/titles/{id}/playback` — 404 |
| `kinopoisk_rating`, `imdb_rating` (разреженные) | `updated_at` в карточке — отсутствует |
| `external_ids`: `kp`, `imdb`, `tmdb`, `mdl`, `mal` | рабочий поиск: параметры молча игнорируются |

Сезон отдаёт только `{number, name, episodes_count, available_episodes_count}`.
Списка эпизодов нет ни на одном маршруте — дельта серий вычисляется по счётчикам
сезонов, а не по перечню серий. Это ограничение источника, а не выбор.

Два следствия, зафиксированные в коде:

* поиск нельзя использовать для проверки полноты — он молча вернёт не то;
* отсутствие `updated_at` означает, что свежесть определяется только нашим
  наблюдением (`observed_at`), см. `EVENT-CONTRACT.md`.

## Полнота обхода: обрыв каталога — ошибка

`factory/lords/content_live.py` больше не молчит при упоре в предел страниц:

```
если пройден предел max_pages, а источник обещает продолжение —
SourceError(kind="catalog_truncation")
```

Публиковать неполный каталог как полный запрещено. Прежнее поведение (тихая
остановка на 200 страницах × 24 записи = 4800 тайтлов) выглядело как успешный
прогон и обрезало каталог по дате.

## Границы между модулями

* `provider-adapters` → `content-ingestion`: сырые ответы, без интерпретации.
* `content-ingestion` → `content-catalog`: нормализованные записи, канонические
  идентификаторы.
* `content-catalog` → `homepage-shelves`, `seo`, `renderer-adapters`: чтение.
  Обратного потока нет: витрина и SEO не пишут в каталог.
* Любой модуль → `cache-invalidation`: только события из контракта событий.

## Ссылки на тайтл

Ссылка строится из составного идентификатора `${человекочитаемое}--${uuid}`.
Транслитерированный слаг угадывать нельзя: пять из шести угаданных ссылок
отдавали 404.

## Health и покрытие

Каждый профиль объявляет `health_endpoint: /healthz` и
`coverage_endpoint: /api/v1/coverage`. Покрытие — это отношение локально
известных тайтлов к заявленному источником количеству; именно оно, а не факт
успешного прогона, доказывает полноту.
