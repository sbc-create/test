## 2. Защита от повторной публикации: был пробел, закрыт

### Что проверено

`publish_material` → `factory/qwen/editorial.py: публиковать`. Хранилище
доставки ключуется слагом:

```python
все = [i for i in текущее.get("items") or [] if i.get("slug") != slug]
все.append(запись)
```

Отсюда два разных вопроса, которые раньше смешивались:

* **дубль** второй вызов не создаёт — запись ЗАМЕНЯЕТСЯ, в хранилище остаётся
  одна запись на слаг. Это свойство было и остаётся;
* **потеря правки** была возможна. Сверка версии (`expected_generation`) стояла
  в коде, но была НЕОБЯЗАТЕЛЬНОЙ: без неё проверки не происходило вовсе. Два
  близких запуска записывали каждый своё, побеждал последний — без отказа и без
  следа в ответе. Это и есть повторная публикация, от которой нечем защититься.

### Что исправлено

Повторная публикация того же слага теперь ОБЯЗАНА назвать заменяемую версию:

```
'slug-1' в хранилище уже есть (версия 'qwen-slug-1-…'): повторная публикация
обязана назвать заменяемую версию параметром expect_generation. Прочитайте
текущую через editorial_status и передайте её значение — слепая замена чужого
текста запрещена
```

Первая публикация слага не затронута: заменять нечего.

Тест `test_повторная_публикация_обязана_назвать_заменяемую_версию` проверяет
ПОВЕДЕНИЕ, а не наличие строки в исходнике: первая публикация проходит без
версии, повторная без версии отклоняется, повторная с ЧУЖОЙ версией
отклоняется, повторная с верной версией проходит.

## 3. Отмена ошибочного результата: новый адресный механизм

### Зачем он понадобился

Задание `a3c2d5c3440ba678` (`https://animeg0.site/title/pokemon-myutu-protiv-myu/`),
история из журнала очереди:

```
12:30:05Z task_registered  — заведено, NEEDS_UPDATE
14:23:58Z task_claimed     — арендовано владельцем 'editor-bot-01'
14:24:21Z task_result      — SOURCE_UNAVAILABLE, 23 секунды спустя,
                             detail «Источники не найдены за текущую попытку»
```

Последствия, которые остались в данных:

* `attempts: 1` — одна из трёх попыток до `BLOCKED_INSUFFICIENT_FACTS`
  израсходована;
* `next_attempt_at: 14:39:21Z` — срок повторной проверки;
* в записи реестра `provenance.last_source_failure_at` и
  `last_source_failure_detail` — то есть УТВЕРЖДЕНИЕ о недоступности источника,
  которого никто не проверял.

Написанным текстом это не учлось (`body` пуст, `texts_*` не изменились) — но
«доказанной недоступностью источника» учлось. `reopen` здесь не годится: он
снимает срок и возвращает задание в работу, а попытку и отметки оставляет.

### Что сделано

`editorial_queue_annul` — отменяет ПОСЛЕДНИЙ записанный результат ОДНОГО
задания. Отменяемая запись называется явно (`entry_at` + `expect_outcome`):
отменяют известную запись, а не «последнюю, какая есть».

Что снимается — по перечню `СЛЕДЫ_ИСХОДА`, явному для каждого исхода, а не «всё,
что похоже». Что сохраняется — история: отменённая запись остаётся и получает
отметку `annulled` с причиной, а в историю ДОПИСЫВАЕТСЯ `RESULT_ANNULLED`.

Чего отмена не делает: не отменяет `TEXT_WRITTEN` (записанный текст — работа, а
не след), не трогает действующую аренду другого исполнителя, не касается
проверенного и опубликованного, не затрагивает других заданий, не отменяет
исход в середине истории.

### Применено к названному заданию

```
$ python3 -m factory.qwen queue-annul --site animeg0.site \
    --task-id a3c2d5c3440ba678 --entry-at "2026-10-06T14:24:21Z" \
    --outcome SOURCE_UNAVAILABLE --detail "тестовый исход чужой сессии: …"

annulled_owner        editor-bot-01
attempts_before 1  ->  attempts 0
cleared_provenance    ['last_source_failure_at', 'last_source_failure_detail']
cleared_next_attempt_at  2026-10-06T14:39:21Z
history_entries       2
lease_owner           ''
```

Состояние после отмены, прочитанное из файлов:

```
attempts 0, next_attempt_at пусто, owner пусто
история:
  14:24:21Z 'editor-bot-01' SOURCE_UNAVAILABLE … annulled{at 15:51:18Z, reason …,
                                                 attempts_returned 1}
  15:51:18Z ''              RESULT_ANNULLED     annulled_entry_at 14:24:21Z
происхождение записи: ['brief', 'brief_recorded_at', 'registered_at', 'slug']
статус NEEDS_UPDATE, текст пуст, причина отказа пуста
```

Бриф задания не тронут, текст не появился, счётчики написанных текстов не
изменились — это закреплено тестом
`test_отмена_не_учитывается_как_написанный_текст`.

Семь тестов на отмену: возврат попытки и снятие отметки, обязательность
названия записи и исхода, отказ на `TEXT_WRITTEN`, отказ при действующей чужой
аренде, адресность (сроки и попытки соседних заданий не меняются), повторная
отмена, счётчики текстов.

## 4. Результаты от проверочных личностей: что ещё нашлось и почему я это не правил

За сутки 29 результатов. Из них записаны личностями, по имени опознаваемыми как
проверочные:

| задание | когда | владелец | исход | что установлено |
| --- | --- | --- | --- | --- |
| `a3c2d5c3440ba678` | 14:24:21Z | `editor-bot-01` | SOURCE_UNAVAILABLE | **отменено** (раздел 3) |
| `6c7994f1a2b608a4` | 14:27:01Z | `qwen-editor-probe-20261006-1415` | PAGE_ABSENT | НЕ отменяю: `https://yummyani.site/anime/agent-vremeni-3` действительно отвечает **404** — наблюдение верное |
| `fa190135f85d72c9` | 11:53:15Z | `qwen-seo-check` | SOURCE_UNAVAILABLE | не отменяю: страница отвечает 200, но доступность ИСТОЧНИКОВ я не проверял и назвать запись ложной не могу |
| `f0161e5439947e6c` | 11:37:46Z | `qwen-editor-probe-20261006-1332` | SOURCE_UNAVAILABLE | то же |
| `8b46299f05533fea` | 11:05:13Z | `qwen-editor-probe-20261006-1332` | SOURCES_MISSING | закрыто позже исходом `NO_CHANGE_NEEDED` (прежнее задание) |

У `fa190135f85d72c9` и `f0161e5439947e6c` по два `SOURCE_UNAVAILABLE` подряд,
`attempts: 2` — то есть ОДНА попытка до `BLOCKED_INSUFFICIENT_FACTS`. Это риск, и
он назван; отменять записи без доказательства их ложности нельзя — иначе отмена
станет способом стирать неудобные результаты.

Личности `trial-run-*`, `parallel-*`, `acceptance-*`, `cli-trial` — мои пробные и
приёмочные прогоны 6 октября, выполненные по прямому заданию владельца; они
названы здесь для полноты, а не как чужая работа.
