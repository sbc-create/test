## 1. Что такое `site-factory_editorial_queue_status` и его числа

| звено | где |
| --- | --- |
| инструмент MCP | `factory/qwen/mcp.py` → `инструмент_очереди_состояние` |
| мост | `factory/qwen/queue_bridge.py::состояние` — подпроцесс |
| реализация | `seo_engine/content_operator/editorial_queue.py::status()` |
| дерево с модулем | только `/home/claude/wt-editorial-queue-repair-01` |
| **фактический источник данных** | **`/var/lib/seo-content-operator/registry.json`** (1 276 записей) |

Корень оператора берётся так: `SEO_OPERATOR_ROOT` → записанный файл
`var/state/seo-operator-root` → значение по умолчанию. В дереве по умолчанию
модуля очереди нет, и инструмент честно отказывает, а не отвечает «очередь
пуста».

Смысл полей — из кода `status()`:

| поле | что считает |
| --- | --- |
| `works_total` | различных произведений (`title_id`) в очереди домена |
| `records_total` | записей, включая несколько ревизий одного произведения |
| `texts_present` | записей с непустым `body` — **накопленное**, не суточное |
| `texts_recorded_via_queue` | записей с `provenance.text_recorded_at` |
| `texts_verified` | записей в статусе `READY_VERIFIED` |
| `leases_active` | взятых в работу аренд |
| `shadowed_duplicates` | подавленных повторов |

## 2. Где хранятся материалы — три разных места

1. **Источник текста** — `/var/lib/seo-content-operator/registry.json`,
   запись `items[content_id=…]`. Это то, что пишет и выверяет оператор.
2. **Размещение на витрине** —
   `/srv/sites/<семейство>/runtime/overlays/<домен>/title-overlays.json`,
   запись `items[slug=…]`. Файл наложений и есть то, что витрина показывает на
   странице произведения. Писатель — `seo_engine/content_operator/title_overlays.py`.
3. **Новости и статьи `/posts/`** — в базе самой витрины. На диске их текста
   нет (проверено поиском по `/srv/lords/.frontend`, `/srv/yummyani-site`,
   `/var/lib/seo-content-operator`); `psql` не входит в профиль
   UNATTENDED_SAFE, поэтому **это отсутствие доступа, а не отсутствие текста**.

Описания в данных каталога витрин (`<ячейка>-details.json`, поле
`description_source`) — **текст поставщика**: на animedia-01 и animedia-02 все
6 438 описаний помечены `detail`, редакционных среди них нет.

## 4. Проверка: стоит ли сохранённый текст на странице

Выборка по одному наложению с каждой из 10 витрин: **СОВПАЛ 9, НЕ ИЗМЕРЕНО 1**
(`animedia.icu` ответила HTTP 503 «overloaded, retry later»), расхождений 0.
Наложения действительно отдаются страницами дословно.

Сравнение 17 реестровых записей со статусом живых (`PUBLISHED` 2,
`ALREADY_LIVE` 58; тело сохранено у 17, у 43 **сравнивать нечего**):
СОВПАЛ 9, РАСХОДИТСЯ 8, все страницы отдали HTTP 200.

Из 17 сравнимых записей 9 приходятся на страницы `/posts/` (новости и
статьи) и 8 — на страницы произведений. По `/posts/` сохранённый текст найден
на **7 страницах из 9**: это и есть редакционные материалы, которые реально
читают на витрине помимо описаний произведений.

Восемь расхождений разобраны и объясняются ревизиями, а не пустыми
страницами. Пример `3x3-glaza`: на странице стоит текст 606 знаков, и это
ровно запись `buffer-batch10-17-3x3-glaza-rev1` (`READY_VERIFIED`); проверялась
же другая ревизия того же произведения — `batch10-17-3x3-glaza` (898 знаков,
`ALREADY_LIVE`). То же у `7-semyan`. Статус `ALREADY_LIVE` — утверждение о
странице, а не её измерение: у 43 записей с этим статусом текста нет вовсе.
