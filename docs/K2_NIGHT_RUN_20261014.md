## 4. Блокер запуска: publisher_id (и это fail-closed по замыслу)

Пробный запуск `lords-10` на узле (без root, в домашнем каталоге, порт 19125)
остановился до первого запроса:

```
запуск lordfilm.group остановлен до первого запроса:
  — нет …/config/player.json: плеер без publisher_id не заработает
```

Единственная падающая проверка проекта — `activate-scenarios`, и она говорит то
же: «lords-10 не объявляет publisher_id_expected — сверка не проводилась; номер
соседней витрины подставить нельзя (D138: у каждого домена свой)».

**Измеренный факт, который делает решение владельца простым.** В работающей
сети один publisher_id УЖЕ обслуживает несколько домéнов:

| publisher_id | витрины |
| --- | --- |
| `10238` | lords-03, lords-05, lords-06, lords-07 — **четыре** |
| `10252` | animedia-02, animego-04, zona-01 — три |
| `10373` | lords-01 |
| `10378` | lords-02 |

То есть восемь разных номеров не требуются — это измерение, а не
предположение. Какой номер получает каждый домен, решает владелец: подставлять
чужой или выдуманный запрещено и правилом проекта, и заданием. Инструмент для
назначения готов и сам отказывается от тихого разделения:
`automation/local/assign-publisher-id.py --site <id> --publisher-id <N> [--allow-shared]`.

## 6. Один блок владельца — всё, что требуется до запуска

Порядок важен: пункты 1–4 готовят узел, 5 даёт данные плеера, 6 запускает
первую витрину, 7–8 открывают домен снаружи.

```bash
# host: k2-zomro-01
set -euo pipefail

# --- 1. Зависимости и каталоги ------------------------------------------
apt-get update
apt-get install -y nginx certbot python3-certbot-nginx python3-venv
install -d -m 0755 /var/www/certbot

# --- 2. Предел журналу СРАЗУ (на основном узле его отсутствие дало 4 ГиБ)
install -d -m 0755 /etc/systemd/journald.conf.d
printf '[Journal]\nSystemMaxUse=512M\nSystemMaxFileSize=64M\n' > /etc/systemd/journald.conf.d/50-size-cap.conf
systemctl restart systemd-journald

# --- 3. Учётные записи и каталоги восьми ячеек ---------------------------
# Код — 2775 с группой витрины (выкладку делает k2deploy), данные — 0750 без
# записи для группы: постоянные данные принадлежат только самой витрине.
for acc in lordfilm-group lordfilm-spb-ru lordfilm-msk-ru lordserial-su lordserial-group lordserial-spb-ru lordserial-msk-ru lordserial-net-ru; do
  id -u "$acc" >/dev/null 2>&1 || useradd --system --home-dir "/srv/$acc" --shell /usr/sbin/nologin "$acc"
  install -d -m 2775 -o "$acc" -g "$acc" "/srv/$acc"
  install -d -m 0750 -o "$acc" -g "$acc" "/srv/$acc/data"
  usermod -aG "$acc" k2deploy
done

# --- 4. Юниты и nginx: ставим, ничего не включаем ------------------------
install -m 0644 -o root -g root /home/k2deploy/stage/units/nova-*.service /etc/systemd/system/
systemctl daemon-reload
install -d -m 0755 /etc/nginx/cells /etc/nginx/lords
install -m 0644 /home/k2deploy/stage/cells/lords-1*.robots /etc/nginx/cells/
install -m 0644 /home/k2deploy/stage/cells/lords-1*.upstream /etc/nginx/cells/
install -m 0644 /home/k2deploy/stage/nginx/site-cells-upstreams.conf /etc/nginx/conf.d/
grep -q 'include /etc/nginx/lords/\*.conf;' /etc/nginx/nginx.conf || \
  sed -i 's|include /etc/nginx/conf.d/\*.conf;|include /etc/nginx/conf.d/*.conf;\n\tinclude /etc/nginx/lords/*.conf;|' /etc/nginx/nginx.conf

# --- 5. Узкие права k2deploy: перезапуск своих витрин и перезагрузка nginx
printf 'k2deploy ALL=(root) NOPASSWD: /usr/sbin/nginx -t, /usr/bin/systemctl reload nginx, /usr/bin/systemctl restart nova-lordfilm-group.service, /usr/bin/systemctl restart nova-lordfilm-spb-ru.service, /usr/bin/systemctl restart nova-lordfilm-msk-ru.service, /usr/bin/systemctl restart nova-lordserial-su.service, /usr/bin/systemctl restart nova-lordserial-group.service, /usr/bin/systemctl restart nova-lordserial-spb-ru.service, /usr/bin/systemctl restart nova-lordserial-msk-ru.service, /usr/bin/systemctl restart nova-lordserial-net-ru.service\n' > /etc/sudoers.d/k2deploy-cells
chmod 0440 /etc/sudoers.d/k2deploy-cells
visudo -c -f /etc/sudoers.d/k2deploy-cells

# --- 6. Первая витрина: данные на место и запуск ------------------------
install -m 0640 -o lordfilm-group -g lordfilm-group /home/k2deploy/stage/data/lords-10/lords-10-catalog.json /srv/lordfilm-group/data/
install -m 0640 -o lordfilm-group -g lordfilm-group /home/k2deploy/stage/data/lords-10/lords-10-details.json /srv/lordfilm-group/data/
install -d -m 2775 -o lordfilm-group -g lordfilm-group /srv/lordfilm-group/releases
install -m 0644 /home/k2deploy/stage/nginx/lords-10.conf /etc/nginx/lords/
nginx -t
systemctl reload nginx

# --- 7. Что получилось --------------------------------------------------
getent group lordfilm-group
ls -ld /srv/lordfilm-group /srv/lordfilm-group/data
ls /etc/systemd/system/nova-lord*.service | wc -l
nginx -v
journalctl --disk-usage
df -h /
```

**Ожидаемый результат.** 16 юнитов; `nginx -t` печатает `syntax is ok` и `test
is successful`; `visudo -c -f` — `parsed OK`; журнал после перезапуска не
больше 512 МиБ; `getent group lordfilm-group` показывает `k2deploy` в составе.

**Условия остановки.** `nginx -t` не прошёл — снять
`/etc/nginx/lords/lords-10.conf`, перезагрузку не делать, прислать вывод
(проверено заранее: в заготовке слушается только 80, 443 лежит отдельным
файлом и ждёт сертификата). `visudo -c` не сказал `parsed OK` — файл
`/etc/sudoers.d/k2deploy-cells` удалить немедленно: битый sudoers ломает sudo
целиком. `useradd` отказал на существующем имени — проверить, не занято ли оно
чужой службой.

### Отдельно: три решения, без которых запуск не состоится

| что нужно | почему именно владелец | чего ждать от меня после |
| --- | --- | --- |
| **publisher_id для восьми домéнов** (или решение разделить существующий, например `10238`) | значение приходит от поставщика; подставлять чужой или выдуманный запрещено, и витрина честно не стартует без него | кладу `player.json` в выпуск, запускаю, измеряю память |
| **A-запись восьми домéнов на `145.63.129.86`** в Cloudflare | DNS вне manifest агент не меняет | внешняя проверка по домену, заголовки индексации |
| **certbot для каждого домена** (после DNS) и установка `*-tls.conf` | root и выпуск сертификата | HTTPS-проверка и перевод на 443 |
