# Аудит референсных интерфейсов lordserials.fan и lord-film2026.com

**Дата:** 22.08.2026
**Источники:** `inventory/reference-sources.yaml` → `lordserials-fan`, `lord-film2026`
**Команды:**

```
python3 -m factory reference-audit --ref lordserials-fan     # exit 1, статус unavailable_blocked
python3 -m factory reference-audit --ref lord-film2026       # exit 1, статус unavailable_blocked
```

**Артефакты:** `artifacts/reference/lordserials-fan-run.json`,
`artifacts/reference/lordserials-fan-measurements.json`,
`artifacts/reference/lord-film2026-run.json`,
`artifacts/reference/lord-film2026-measurements.json`

## 1. Результат измерения: не выполнено ни по одному референсу

Оба источника недоступны из этой среды. Браузерный прогон стартовал с ширины 390
и на первом же переходе получил отказ транспорта:

```
net::ERR_TUNNEL_CONNECTION_FAILED at https://lordserials.fan/
net::ERR_TUNNEL_CONNECTION_FAILED at https://lord-film2026.com/
```

Это тот же класс отказа, что и у `amd.online` в CR v2.0: прокси среды исполнения
отклоняет CONNECT к внешнему хосту. Ширины 768, 1440 и 1920 не измерялись — после
отказа на первой ширине прогон не продолжается, чтобы не выдавать серию одинаковых
ошибок за попытку измерения.

**Следствие: в этом документе нет ни одного измеренного числа.** Ни ширина
контейнера, ни плотность сетки, ни размеры карточек, ни порядок секций, ни
поведение шапки, ни оформление фильтров референсов фабрике не известны. Скриншотов
референсов нет. Любое утверждение о том, «как выглядит» lordserials.fan или
lord-film2026.com, было бы выдумкой, а не аудитом.

Инструмент измерения готов и не требует изменений: `tests/tools/measure_reference.js`
через `python3 -m factory reference-audit --ref <ref>` соберёт ширины контейнера и
полей, типографическую шкалу, пропорции карточек, плотность сетки, порядок секций,
поведение шапки, наличие горизонтальной прокрутки и число ссылок пагинации на всех
четырёх требуемых ширинах. Сохраняются только собственные числа и скриншоты;
тексты, изображения, каталог и чужие идентификаторы не выгружаются
(`inventory/reference-sources.yaml: store`).

## 2. Что использовано вместо измерения

Функциональная модель четырёх сайтов построена из двух источников, и оба названы
явно:

1. **Переданная спецификация CR v3.0** — разделы 4 и 5 задания перечисляют
   пользовательские сценарии и структурные элементы, которые заказчик считает
   обязательными: header и навигация, desktop/mobile меню, поиск, фильтры, сетка
   постеров, карточка произведения, страница произведения, сезоны и эпизоды,
   похожее, подборки, пагинация, комментарии, подвал, рекламные места и состояния
   loading/empty/error/unavailable. Это требования владельца проекта, а не
   наблюдения за чужим сайтом.
2. **Собственная база фабрики** — матрица индексируемости
   (`knowledge/SEO_INDEXABILITY_MATRIX.yaml`), решения `knowledge/DECISIONS.md`,
   контракт плеера `knowledge/cdnvideohub/PLAYER_CONTRACT.yaml` и уже проверенный
   blueprint `payload-next-multisite`.

Ни одна визуальная величина (ширина контейнера, кегль, радиус, плотность сетки,
пропорция карточки) не взята «как у референса»: все значения тем заданы внутри
проекта как самостоятельные дизайн-решения и обоснованы в
`docs/FOUR_CINEMA_THEMES.md`.

## 3. Правовая рамка

Задание прямо запрещает копирование логотипов, брендов, исходного кода, текстов,
изображений и иных защищённых материалов референсов. Недоступность источников
делает нарушение технически невозможным: у фабрики нет ни строки их разметки, ни
одного их изображения, ни одного их идентификатора. Названия сайтов D–G —
внутренние рабочие коды (`site_d`…`site_g`), публичные бренды не придуманы.

## 4. Что разблокирует настоящий аудит

Доступ к `lordserials.fan` и `lord-film2026.com` из среды исполнения — либо
разрешение хостов в egress-политике, либо запуск `factory reference-audit` в среде
без такого ограничения. После этого измерение выполняется одной командой, а
результаты ложатся в те же артефакты; изменения кода не потребуются.

Альтернатива, не требующая сети: владелец проекта передаёт собственные измерения
(ширины, кегли, плотность сетки, порядок секций) — они будут записаны как
`provenance: owner_observation` и помечены как непроверенные фабрикой, ровно как
это сделано для `amd.online` в `docs/reference/AMD_ONLINE_UI_AUDIT.md`.
