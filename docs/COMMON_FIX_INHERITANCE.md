само**. Пока ответ «нет», работа не закончена, и её придётся сделать второй раз.

В репозитории есть пересчёт замка (`automation/local/refresh-pins-lock.py`),

доезжает до сайта только повторной ручной правкой — это и наблюдается как
«одно и то же чиним много раз». Записи — MOD-185 … MOD-188.

## Правило завершения общего дефекта

Общий дефект (`scope: common` в `config/seo-module-defects.json`) закрывается
состоянием `released` или `verified` ТОЛЬКО при полном наборе:

1. **причина исправлена в каноническом слое** — поле `canonical`: общий модуль,
   шаблон семейства, генератор или слой развёртывания, а не витрина, ветка или
   окружение;
2. **есть проверка от повторения** — поле `test`: проверка, которая падает без
   исправления (отрицательный контроль обязателен);
3. **названа версия основы**, несущая исправление — поле `base_version`
   (коммит шаблона, тот же, что попадает в `pins.lock.json`);
4. **доказано наследование** — поле `inherited_by`: новый экземпляр, созданный
   ШТАТНЫМ генератором в чистом изолированном окружении, получил исправление
   без ручных допатчей, и названо, чем это подтверждено.

Схема проверяет это условием, а не описанием: запись `scope: common` в
состоянии `released`/`verified` без четырёх полей не проходит валидацию
(`schemas/seo-module-defects.schema.json`, `allOf`).

**Исправление только для одного домена** (`scope: single-domain`) требует поля
`scope_reason` — причины исключения. «Только этот домен» без причины
неотличимо от забытого переноса в основу.

## Перед похожей задачей

Сначала проверяется ГОТОВОЕ решение: `config/seo-module-defects.json` (поиск по
`title` и `example`), затем код канонического слоя. Повторная разработка того,
что уже сделано, считается потерей — и измеряется наравне с прочими.

**У общего компонента один ответственный.** Параллельные исполнители не
разрабатывают одну правку независимо: это уже случилось с вписыванием проверок
в `checks/run.sh` (два самодельных вставителя, MOD-185) и с блоком владельца по
образу `yummyani.site` (две линии, 21.10 и 25.10).

## Чего правило не меняет

Направление, оформление, материалы и стратегия сайта остаются в его профиле.
Домены, `publisher_id`, счётчики, секреты и разрешения на индексацию общими
значениями не становятся: у пробного сайта `probe-inherit-01` приёмка
`activate-scenarios` падает именно потому, что `publisher_id` не задан, — и это
верное поведение (D138), а не дефект. Незавершённые SEO-опыты остаются
отдельно, в `config/experiments.json`.

Обновление действующих сайтов идёт штатной процедурой выпуска с проверкой
совместимости; продвижение версии витрине — решение владельца (MOD-186).

```bash
python3 -m factory cell newsite --site <probe> --domain <probe>.invalid \
    --template <свободный профиль> --port <свободный> --family lords \
    --no-register --destination <изолированный каталог>
cd <изолированный каталог> && git init -q && git add -A && git commit -qm "шаблон"
bash checks/run.sh
python3 automation/local/template-lag.py        # отставание экземпляров
```
