# zonafilm12.site: воспроизведение «Мастер Омюр»

## Причина

Витрина отвечала «Дорожки этой серии ещё нет», хотя источник по той же записи
и **тому же издателю витрины** отдавал две дорожки.

Свежий ответ источника (плейлист, который открывает браузер посетителя;
`pub=10261`, `Origin: https://zonafilm12.site`, запись
`01a0e45a-ba66-7613-879c-f209068f60e3`):

```
titleName "Мастер Омюр", isSerial true
  s1e1  Многоголосый / DiziDenizi   cvhId да, vkId да
  s1e1  Субтитры                    cvhId да, vkId да
```

Цепочка целиком:

| звено | что было |
| --- | --- |
| источник | две дорожки на s1e1, обе с идентификатором потока |
| идентификатор тайтла | `01a0e45a-…` — тот же, что у соседней витрины |
| снимок производителя | собран 03:56, `seasons[0]: eps=1, avail=0` |
| доставка в ячейку | прошла верно: в хранилище тот же `avail=0` |
| чтение службой | верно: рендерер включает плеер по `avail` |
| параметры плеера | издатель 10261, режим `provider-id` — верны |
| страница | `unavailable`, `<video-player>` не отрисован |

**Ни доставка, ни плеер, ни права не виноваты.** Снимок подробностей собирается
раз в сутки, озвучки появились после сборки, а между сборками источник у этой
витрины не спрашивал никто. Поле `avail` оставалось нулём при живых дорожках.

У соседней витрины та же запись имела `avail=1` — там механизм сверки уже
завели. Это и была вся разница, которую видел пользователь.

## Что исправлено

В репозитории `site-zonafilm12-site`, ветка `claude/extract-zonafilm12-site`:

1. **Фоновая сверка доступности.** Поток витрины раз в 15 минут берёт записи с
   недобором, спрашивает плейлист теми же кандидатами, что ставит на страницу
   рендерер, и поднимает `avail` до длины непрерывного ряда от первой серии.
   * в путь запроса страницы сверка не попадает никогда — синхронный вызов
     провайдера при отрисовке означал бы, что страница ждёт чужую службу;
   * **только повышение**: понижение — отдельный класс дефекта, и ошибка в ту
     сторону снимает серии, которые играются со второго кандидата;
   * дорожкой считается запись с идентификатором потока, а не заготовка;
   * без `publisher_id` или без `LORDS_SITE_HOST` поток не заводится.
2. **Очередь упорядочена и движется курсором.** Сначала записи с полным
   недобором, внутри групп по алфавиту; список кольцевой. Без курсора первые
   сорок записей спрашивались бы каждые пятнадцать минут, а пятьсот третья —
   никогда.
3. **Сверка переживает доставку каталога.** Объект подробностей берётся у
   обработчика каждый проход (витрина подменяет его целиком при новом снимке);
   смена снимка сбрасывает курсор; перед записью сверяется `mtime` — файл новее
   нашего чтения означает отказ от записи.
4. **Проверка `checks/episode_availability.py`** ловит класс до выкладки.
   Выборка начинается с полного недобора и упорядочена: первая версия брала
   первые двенадцать записей словаря, и «Мастер Омюр» в них не попал — проверка
   отвечала PASS на дефекте, который обязана ловить.

## Повторный дефект

Тот же класс найден ещё у двух записей Zona: `avatar-korolya-2` (сезон 4,
`avail=0` при `eps=3`) и `boec-baki` (сезон 2, `avail=0` при `eps=24`). Обе
подняты той же сверкой и воспроизводятся.

Общая причина одна: **`avail` — наблюдение суточной давности, а витрина читает
его как факт.** Проверка из пункта 4 ловит именно это.
