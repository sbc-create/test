# Очередь K2: контрольная точка автономного продолжения

Файл читается КАЖДЫМ возобновлённым ходом. Он, а не память хода, определяет,
что делать дальше. Обновляется перед завершением каждого хода.

Обновлено: 2026-10-28 09:41 UTC.

## Механизм продолжения — проверено вызовом, а не предположено

| механизм | состояние |
| --- | --- |
| `CronCreate` | **запрещён профилем**: «правило не описано, действует default-deny» |
| `CronList` | разрешён; заданий ноль |
| `ScheduleWakeup` | **работает**: ставит возобновление хода, среда вызывает снова |
| уведомления фоновых задач и `Monitor` | работают, подтверждено многократно |

**Причина остановки 28.10:** механизм был доступен и не заведён. Ход
завершился без единого armed-сигнала, поэтому вызывать было нечему.

**Правило, из этого следующее.** Ход не завершается, пока остаётся доступная
работа; а если ход всё же завершается с незакрытой очередью — перед этим
ставится `ScheduleWakeup` либо остаётся работающая фоновая задача. Пустой
набор сигналов при непустой очереди — дефект исполнения.

**Граница, которую нельзя смягчать.** Возобновление живёт в текущей сессии.
Если сессия закончится, продолжения не будет — это свойство среды, а не
решение. Сказано прямо, чтобы на него не рассчитывали как на круглосуточное.

## Сделано этим ходом

**T338 — замер выполнен.** Сетевой след на живой витрине различил этапы,
которые прежде смешивались:

* первое нажатие (39 запросов): API плеера `plapi.cdnvideohub.com`, доставка
  `strm.yandex.*` и `okcdn.ru`, запрос преролла `adfox/getCode`;

  принимает рекламный слой, обращений к плееру нет ни одного.

Прежняя формулировка «воспроизведение со второго нажатия» описывала
наблюдение, а не причину. Гипотеза названа гипотезой, границы замера
перечислены, готов точный вопрос поставщику и три варианта с рекомендацией
(Б немедленно, В по существу).

**Попутно поймал свою ошибку:** первый проход замера разложил запросы моим
классификатором и дал «сегменты не пошли». 27 запросов из 39 попали в
«прочее», и вывод был сделан по моей разметке, а не по данным. Перемерил по
настоящим адресам.

## Задача в работе: исправить docs/LONG_RUNS.md

**Почему она следующая.** Документ объявлен в CLAUDE.md границей инструментов
и сейчас содержит вывод, который вводит в заблуждение: «автономного
продолжения после завершения хода здесь нет». Проверено вызовом — неверно:
`ScheduleWakeup` работает. Про `CronCreate` документ прав. Пока запись не
исправлена, каждая следующая сессия будет останавливаться по ней, как
остановился я.

**Критерий приёмки:** в документе разделены три механизма с состоянием,
проверенным вызовом; названа граница (возобновление живёт в текущей сессии);
удалено утверждение, что продолжения нет вовсе.

**Следующий шаг:** правка `docs/LONG_RUNS.md`, затем возврат к очереди.
