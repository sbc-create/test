## Механизм продолжения — проверено вызовом, а не предположено

| механизм | состояние |
| --- | --- |
| `CronCreate` | **запрещён профилем**: «правило не описано, действует default-deny» |
| `CronList` | разрешён; заданий ноль |
| `ScheduleWakeup` | **работает**: ставит возобновление хода, среда вызывает снова |
| уведомления фоновых задач и `Monitor` | работают, подтверждено многократно |

**Причина остановки 28.10:** механизм был доступен и не заведён. Ход
завершился без единого armed-сигнала, поэтому вызывать было нечему.

**Правило, из этого следующее.** Ход не завершается, пока остаётся доступная
работа; а если ход всё же завершается с незакрытой очередью — перед этим
ставится `ScheduleWakeup` либо остаётся работающая фоновая задача. Пустой
набор сигналов при непустой очереди — дефект исполнения.

**Граница, которую нельзя смягчать.** Возобновление живёт в текущей сессии.
Если сессия закончится, продолжения не будет — это свойство среды, а не
решение. Сказано прямо, чтобы на него не рассчитывали как на круглосуточное.

## MOD-223, расширение: девять проверок, а не шесть

Находка владельца общего кода: часть проверок берёт запасной адрес данных по
ИМЕНИ КАТАЛОГА репозитория (`/srv/{КОРЕНЬ.name}/data`), то есть держит второй
источник правды — а `_snapshot_dir.py` прямо говорит, что имя каталога адресом
данных не считается. У `1lordserials1-online` (каталог `site-…`) такой путь
промахивается; у `zonafilm.cc` имя совпадает и вреда сегодня нет.

**Пересчитал: править нужно девять, а не шесть.** Её поиск не нашёл
`indexing_live_switch`, `indexing_mode_rules` и `no_internal_field_names` —
у них форма якоря другая (`ZONA_FIXTURE_DIR`, `pathlib.Path` без окружения).

**И восемь моих проверок трогать НЕ НАДО,** хотя строка `/srv/{КОРЕНЬ.name}`
в них есть: там этот путь стоит ПОСЛЕДНИМ, после окружения, настройки и
домена, то есть ровно как в общем резолвере. Инструмент это различает:
форма с именем каталога правится только там, где шага по настройке нет.

Разделение сделано замером, а не чтением: по каждому файлу проверено, спрашивает
ли он `deployment.data_dir` или домен.

Инструмент расширен на три формы якоря; сухой прогон называет ровно девять.

Четыре проверки начали измерять; три не изменились, потому что у zona-02 имя

(`SyntaxError`), и только третья версия — после документации и после

0. Правило записано в `ANALYSIS_ORDER.md` вместе с отдельным выводом:
инструмент, правящий файлы, готов не по сухому прогону, а когда правленые файлы
ЗАПУЩЕНЫ.

**MOD-223 расширение передано линии ячейки как готовое** — применяет она, по
