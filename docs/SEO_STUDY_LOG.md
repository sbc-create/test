# Журнал изучения SEO: источник → вывод → наш сайт → правка → проверка

Ведёт Архитектор, ежедневно и ограниченным временем. Порядок задан владельцем
18.10. Каждая запись несёт: **источник и дату обращения**, что узнал, к какому
нашему сайту относится, что предлагаю изменить и как проверить результат.

Три вида утверждений не смешиваются:

* **официальная рекомендация** — из документации поисковой системы, со ссылкой;
* **чужое наблюдение** — практика или исследование не из первоисточника;
* **своя гипотеза** — наше предположение, которое ещё не проверено.

Вывод по результату правки берётся из четырёх: **подтверждённый результат**,
**предварительный сигнал**, **эффект не обнаружен**, **данных недостаточно**.

### Вывод 1 — обход по счётчику Метрики: официальный источник обхода

**Источник:** `https://yandex.ru/support/webmaster/ru/indexing-options/link-metrica.md`
и `https://yandex.ru/support/metrica/ru/general/link-webmaster.md`, обращение
2026-10-18. Вид утверждения — **официальная рекомендация**.

**Что узнал.** Робот узнаёт о страницах из разных источников, и один из них —
счётчик Метрики: сайту, подтверждённому в Вебмастере, можно привязать счётчик
и включить обход по его данным. Запрос на привязку отправляется ЛЮБОЙ из двух
сторон: из Метрики (пользователь с правами на редактирование счётчика) или из
Вебмастера (пользователь с правами на управление сайтом); подтверждает
противоположная сторона. Для зеркала счётчик привязывается к ГЛАВНОМУ адресу —
тому, который должен участвовать в поиске. Sitemap при этом не отменяется:
документация прямо называет его дополнением, а не заменой.

**К каким нашим сайтам относится.** К семи домéнам с нулём визитов из Яндекса:
lordfilm47.space, 1lordserials1.online, zonafilm.space, zonafilm.cc,
an1mego.site, an1meg0.site, yummyani.biz. У всех счётчик Метрики установлен
(17 счётчиков в сети), а карта в Вебмастере не отдана — это B029.

**Что предлагаю изменить.** Добавить к B029 второй, независимый путь обхода:
привязку счётчика. Это два действия в интерфейсе на домен («Настройка →
Счётчик → Привязать к Вебмастеру» в Метрике, затем «Настройки → Привязка к
Яндекс Метрике → Подтвердить» в Вебмастере) и не требует работающего API
Вебмастера, который у нас закрыт (B023). Для доменов, которые окажутся
зеркалами по решению B028, привязывать счётчик только к главному адресу.

**Как проверить результат.** В Вебмастере — статус привязки «Подтверждена»;
дальше по нашим данным: события «появилась в поиске» и первые визиты из Яндекса
в `daily_search`. Срок первой проверки — 25.10; при нуле визитов к 25.10 вывод
«данных недостаточно», а не «метод не работает»: срок обхода Яндекс не
обещает.

**Чего вывод НЕ утверждает.** Документация описывает действия в интерфейсе; API
для отправки запроса на привязку в ней не назван, и в замороженном контракте
(`knowledge/YANDEX_ANALYTICS_CONTRACT.yaml`) такого метода нет. Автоматизировать
привязку нельзя — выдумывать эндпоинт запрещено.

### Вывод 2 — «дубли» у Яндекса это страницы ОДНОГО сайта

**Источник:** `https://yandex.ru/support/webmaster/ru/yandex-indexing/about-doubles.md`,
обращение 2026-10-18. Вид утверждения — **официальная рекомендация**.

**Что узнал.** Дубль определён как страницы с почти или полностью одинаковым
текстом **на одном сайте по разным адресам**. Робот объединяет их в группу и
показывает одну, меняя выбор со временем; вред назван прямо: обход тратится на
дубли, новые страницы индексируются медленнее, дубли конкурируют между собой, и
робот может исключить целевую страницу. Список страниц, которые Поиск считает
дублями, доступен в Вебмастере: «Индексирование → Страницы в поиске →
Исключённые, фильтр "Дубль"».

**К каким нашим сайтам относится.** К постановке задач B007 и B028. У нас 12
домéнов делят один каталог, и текст страницы произведения совпадает на
0,81–1,00 внутри кластера; у пары lordfilm47.space ↔ 1lordserials1.online
основной текст `/catalog/` совпадает на 91 %. По этому определению такое
совпадение — НЕ «дубли»: страницы лежат на разных сайтах. Значит разбор должен
идти не по странице о дублях, а по главному адресу (зеркала) и по качеству
сайта (вывод 3).

**Что предлагаю изменить.** Переформулировать B007/B028 в решении владельца: не
«убрать дубли», а назвать роль каждого домена кластера — главный адрес для
поиска либо собственный срез каталога с собственными текстами. И не тратить
работу на canonical между доменами до этого решения: межсайтовый canonical
документация в этом разделе не рассматривает.

**Как проверить результат.** После возвращения Вебмастера (B023) — список
исключённых страниц со статусом «Дубль» по каждому домену кластера: он покажет,
что Поиск считает дублями ВНУТРИ сайта, и отделит внутреннюю задачу от
межсайтовой. До B023 проверить нечем — «данных недостаточно».

### Вывод 3 — каталог без собственных текстов назван признаком некачественного сайта

**Источник:** `https://yandex.ru/support/webmaster/ru/yandex-indexing/webmaster-advice.md`,
обращение 2026-10-18. Вид утверждения — **официальная рекомендация**.

**Что узнал.** Среди примеров сайтов, к которым алгоритмы могут применить
ограничения, прямо названы: сайты, которые копируют или переписывают
информацию с других ресурсов и не создают оригинальный контент; сайты с
автоматически сгенерированным и бесполезным содержимым; **сайты с каталогами,
если они являются только агрегаторами — не создают тексты и описания
самостоятельно и не предоставляют никакого уникального сервиса**; страницы
результатов поиска и отбора по условиям, если они малоинформативны, причём
отдельно сказано, что таких страниц часто много, это увеличивает нагрузку на
сайт и **снижает скорость обхода полезных страниц**.

**К каким нашим сайтам относится.**

* ко всей сети: наш каталог приходит от поставщика, и единственное, что делает
  страницу нашей, — собственное описание. Фоновый редактор пишет описания
  карточкам без них (последний прогон 18.10 19:16:50Z — два описания:
  `animedia.icu/title/moguchaya-berdi-shifr/`,
  `animeg0.site/title/moguchiy-atom-1980/`). По этому выводу такая работа —
  не украшение, а условие участия в поиске;
* к 12 домéнам кластеров: без собственных текстов они попадают под пример
  «только агрегатор»;
* к моей подготовленной правке MOD-79 (565 008 адресов серий в карту): фраза о
  снижении скорости обхода полезных страниц — прямой довод в пользу того, что в
  карту идут ТОЛЬКО серии с дорожкой (48 404 недоступных исключены правкой
  18.10), и довод против расширения карты фильтрами и отборами.

**Что предлагаю изменить.** (1) Поднять приоритет собственных описаний в плане:
это не редакционная косметика, а признак, названный в документации. (2) В
MOD-79 записать этот довод рядом с бюджетом: карта серий допустима только для
страниц с дорожкой. (3) Не открывать фасетные страницы массово (P-03) без
собственной пользы страницы — тот же пример про «результаты отбора».

**Как проверить результат.** По доле карточек с собственным описанием (ведёт
редактор, `var/editor-runs/ledger.jsonl`) против числа страниц с поисковыми
входами по тому же сайту; срок — 25.10 и 01.11. Прямой связи описание → трафик
документация не обещает, поэтому ожидаемый вывод 25.10 — «предварительный
сигнал» либо «данных недостаточно».
