## Одна команда, которой не хватает

    sudo bash /home/claude/wt-portable-site-cell-01/automation/host/authorize-indexing.sh \
      --domain lordserial33.biz \
      --domain yummyani.biz \
      --domain yummyani7.info \
      --domain yummyani7.site \
      --note "разрешение владельца на открытие индексации, задание 2026-10-04"

Путь многодоменного вызова проверен режимом `--show` на этих же четырёх
доменах: обработано 4, отказов 0. Альтернатива без sudo — четыре одноразовых
кода владельца: тогда согласие регистрируется из чата инструментом
`register_owner_consent` (операция `owner-consent` исполнителя).

## Что делать сразу после команды

Для каждого из четырёх доменов, по одному:

1. `set_indexing_mode` (`factory.qwen indexing-set --site <домен> --mode open`)
   — операция сама выберет прикладной слой: файл состояния у `lordserial33.biz`
   и собственный реестр семейства у трёх Yummy (заявка `<site>-core-open`);
2. `confirm_indexing` — итог считается по публичному ответу;
3. карта сайта: у `lordserial33.biz` ждать до 5 минут (`ПАУЗА_КАРТЫ_С = 300`),
   затем `GET /sitemap.xml` -> 200 и свой домен в адресах; у трёх Yummy —
   `sitemapindex` вместо пустого `urlset`;
4. воспроизведение переподтверждать не нужно: оно уже проверено в браузере на
   всех четырёх (см. доказательства), и от режима индексации не зависит.

Чего делать НЕ нужно: повторно регистрировать согласие, выставлять разрешения
выпуска (они выставлены и выложены), открывать `nginx` вручную — его
переключает сама операция.

## Два места, где возможен отказ, и что он будет значить

1. `yummyani.biz`: вердикт слоя nginx — `unknown`. Своего запрета nginx у этого
   домена не добавляет (в блоках, отдающих страницы, `add_header X-Robots-Tag`
   нет), часть конфигураций непривилегированной стороне не читается. Операция
   подаст заявку на слой и примет решение по ПУБЛИЧНЫМ сигналам (D148). Если
   она сообщит «слой остался closed» — читать `evidence`, а не повторять.
2. `lordserial33.biz`: локальная проверка `checks/lords02-taxonomy` отказывает
   на дрейфе классификации живого снимка (17 новых рассогласований). В CI она
   не воспроизводится — читает снимок из `/srv`. Это отдельная работа по
   `config/classification-overrides.json`, к открытию отношения не имеет.
