# Управляющий слой: карта для сопровождения

Документ для того, кто впервые открывает этот код — человека или модели.
По каждому блоку: назначение, владелец, входы и выходы, зависимости, состояние,
поведение при ошибке, чем проверяется, как диагностировать, как откатить и куда
нельзя заходить.

## Общая картина

```
оператор → админка (/admin) ─┐
                              ├→ Control API v1 ─→ очередь ─→ исполнитель ─→ витрина
внешняя автоматика (Qwen) ───┘        │
                                      ├→ профили витрин (config/site-profiles)
                                      ├→ журнал аудита (var/audit)
                                      ├→ метрики (/api/v1/metrics)
                                      └→ следы (var/state/trace)
```

Правило, определяющее всю постройку: **панель не выполняет действий сама**.
Любое изменение проходит через Control API тем же путём, каким его вызвала бы
внешняя автоматика. Логика, продублированная в интерфейсе, расходится с API на
первой правке и расходится молча.

## Блоки

### `factory/site_engine/api/app.py` — читающий слой

- **Назначение**: ответы на вопрос «что сейчас»: состав витрин, каталог, полнота, состояние обхода.
- **Владелец**: ARCHITECT_CORE.
- **Входы**: путь и параметры строки запроса. **Выходы**: `ApiResponse`.
- **Зависимости**: профили витрин, адаптеры, хранилище.
- **Состояние**: нет; читает через открытые интерфейсы модулей.
- **При ошибке**: 404 при выключенном слое — намеренно неотличимо от отсутствия маршрута.
- **Проверяется**: `test_site_engine_api.py`, `test_site_engine_openapi.py`.
- **Выключатели**: `SITE_ENGINE_API_ENABLED` и `SITE_ENGINE_ENVIRONMENT` из `local|test|staging`.

### `factory/site_engine/api/control.py` — записывающий слой

- **Назначение**: изменяющие операции: задания, настройки, инвалидация кэша, журнал, метрики, совместимость, следы.
- **Входы**: метод, путь, тело, заголовки (`Authorization`, `Idempotency-Key`, `traceparent`, `X-Correlation-Id`).
- **Выходы**: `ApiResponse` с `correlationId` и `traceparent`.
- **Состояние**: очередь, блокировки, аудит, ограничение частоты, идемпотентность — всё в `var/` и `queue/`.
- **Конвейер** (пропустить ступень нельзя, он один на все маршруты):
  включённость → аутентификация → право → предел частоты → валидация →
  идемпотентность → блокировка витрины → сверка версии → применение → аудит.
- **При ошибке**: отказ с кодом и причиной; отказы пишутся в аудит и в след.
- **Проверяется**: `test_control_api.py` (43), `test_multiprocess_control.py` (7), `test_tracing.py` (21).
- **Диагностика**: `GET /api/v1/traces/{traceId}` по `traceparent` из ответа.

### `factory/site_engine/api/ratelimit.py` — общий предел частоты

- **Назначение**: не дать сорвавшемуся циклу автоматики занять службу.
- **Состояние**: `var/state/control-ratelimit.json` под блокировкой файла — общее для процессов.
- **Ключи**: среда → витрина → действующее лицо → операция (витрина входит и в ключ операции).
- **При недоступности хранилища**: строгий счётчик в памяти процесса, факт виден в `site_engine_ratelimit_degraded_total`. Ни отказать всем, ни пропустить всех.
- **Откат**: удалить файл состояния — счётчики начнутся заново, данные не теряются.

### `factory/site_engine/api/idempotency.py` — надёжный повтор

- **Назначение**: повтор после таймаута не создаёт вторую мутацию.
- **Состояние**: `var/state/control-idempotency/*.json`, заявка через `O_EXCL`.
- **Состояния заявки**: `reserved`, `in_progress` (409), `replay`, `conflict` (409), `takeover` по истечении аренды.
- **При ошибке**: отказ снимает заявку — исправленный повтор с тем же ключом обязан пройти.
- **Уборка**: `cleanup()` по расписанию, не в запросе.

### `factory/site_engine/api/startup.py` — протокол запуска

- **Назначение**: один порядок проверок для старта службы, выкладки и отката.
- **Различает**: фатальное (нет профилей, запись без токенов, недоступна очередь, столкновение доменов) и ограничивающее (испорченный профиль, чужой контракт, профили только для чтения).
- **Почему так**: служба, падающая из-за одной витрины, превращает местную поломку в общую; служба, поднявшаяся без очереди, обманывает supervisor.
- **Запрещено**: заводить отдельный облегчённый вход «для теста» — закреплено тестом.

### `factory/site_engine/api/lifecycle.py` — жизненный цикл

- **Назначение**: готовность, живость, слив.
- `READY=1` после протокола и открытия сокета; `WATCHDOG=1` вдвое чаще назначенного срока; `STOPPING=1` и слив по `SIGTERM`.
- **При ошибке**: слив не ждёт вечно — systemd всё равно пришлёт `SIGKILL`.

### `factory/site_engine/api/tracing.py` — следы

- **Назначение**: где ушло время и на каком звене сломалось.
- **Формат**: W3C Trace Context; контекст кладётся в задание, иначе цепочка рвётся на асинхронной границе.
- **Выборка**: изменяющее и ошибочное — целиком, успешные чтения — по доле.
- **Защита данных**: закрытый список атрибутов плюс та же чистка, что у аудита.

### `factory/site_engine/admin/` — панель

- **Назначение**: операторский путь поверх Control API.
- **Права**: области токена, своей модели доступа нет. Скрытие кнопок — удобство; запрет держит API.
- **Состояние**: сессии в памяти процесса (перезапуск разлогинивает), два срока — общий и по бездействию.
- **Защита**: CSRF постоянным по времени сравнением байтов, `HttpOnly`, `SameSite=Strict`, `X-Frame-Options: DENY`, `CSP default-src 'none'`, `noindex`.

## Запрещённые зоны

| Кому | Что нельзя трогать |
|---|---|
| ARCHITECT_CORE | шаблонный DOM/CSS, `TemplateManifest`, SEO-тексты, canonical/robots/sitemap, логика индексации |
| TEMPLATES | конвейер Control API, очередь, аудит, ограничение частоты, идемпотентность, юнит и релизы |
| Qwen и внешняя автоматика | всё, кроме объявленных маршрутов OpenAPI; destructive, глобальные, DNS и credential операции недоступны по построению |

## Диагностика за пять шагов

1. Взять `traceparent` или `correlationId` из ответа.
2. `GET /api/v1/traces/{traceId}` — путь запроса по звеньям.
3. `GET /api/v1/audit?siteId=…` — что менялось и кто отказан.
4. `GET /api/v1/metrics` — скорость роста отказов и состав очереди.
5. `journalctl -u site-factory-control-api` — что говорила служба.
