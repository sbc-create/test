# Задел на следующие семейства шаблонов

Это перечень заготовок, а не готовых шаблонов. Ни одно семейство ниже **не
реализовано**, и объявлять их готовыми нельзя.

## Что уже готово как основа

Подключение семейства не требует правки общего отрисовщика. Это не заявление,
а проверка: `tests/lords/test_golden_new_family.py` кладёт новый профиль в
отдельный blueprint, собирает по нему сайт тем же `render_site` и отдельно
доказывает, что в `render.py`, `theme.py` и `plan.py` нет ни одного ветвления
по имени витрины (поиск идёт по коду без строк и комментариев — имя витрины в
объяснении ветвлением не является).

Переиспользуемые примитивы, уже вынесенные в общий слой и управляемые
манифестом:

| Примитив | Чем управляется | Потребителей сейчас |
| --- | --- | ---: |
| Оболочка страницы и контейнер | `container`, `gutter`, `gutter_wide`, `gutter_mode` | 6 профилей |
| Шапка, меню, форма поиска | `header_min_height`, `header_position`, `header_search` | 6 |
| Кнопки | `button_size`, `button_weight`, `button_line_height` | 6 |
| Палитра и радиусы | `bg`, `surface`, `surface_alt`, `text`, `muted`, `accent`, `accent_text`, `border`, `radius` | 6 |
| Типографика | `heading_font`, `h1_size`, `h2_size` | 6 |
| Сетка, карточка, плотность | `layout.columns`, `layout.card_ratio`, `layout.density` | 6 |
| Состав главной и владение разделами | `sections`, `owns`, `owns_title_page` | 6 |

Схема манифеста описывает ровно то, что отрисовщик умеет прочитать, и это
закреплено проверкой в обе стороны: токен без объявления в схеме и поле схемы
без исполнителя одинаково ломают тест.

## Чего в основе ещё нет

Эти примитивы существуют внутри `render.py`, но манифестом не управляются.
Их вынесение — работа следующего семейства, а не этого задела:

- порядок секций главной (сейчас задан профилем частично);
- варианты карусели (шаг, число видимых, стрелки);
- варианты карточки (бейджи, позиция оценки, подпись);
- расположение фасетов (`facet_position` объявлен, вариантов два);
- пагинация (вид и размер страницы);
- состояния пустоты, загрузки и ошибки — сейчас одна форма на всех.

Правило вынесения остаётся прежним: выносить только то, у чего есть минимум
два потребителя, и только если снимки существующих витрин не меняются.

## Заготовки семейств

Для каждого указано, что нужно получить от владельца. Пустое поле — не повод
придумать значение, а `BLOCKED_INPUT`.

### TF-01 — каталог сериалов с сезонами в центре

| Поле | Значение |
| --- | --- |
| Временный ID | `TF-01` |
| Чем отличается от Lords | навигация по сезонам и сериям — основная, а не вложенная в карточку |
| Референс | **BLOCKED_INPUT**: URL, дата съёмки, разрешение на read-only доступ |
| Архетипы страниц | главная, каталог, сериал, сезон, серия, поиск, пустая выдача, 404 |
| Переиспользует | оболочку, шапку, сетку, карточку, пагинацию, палитру |
| Уникальные компоненты | переключатель сезонов, список серий с прогрессом |
| Данные и API | перечень сезонов и серий с длительностью — есть в `content-api`; прогресс просмотра — **BLOCKED_INPUT** |
| Приёмка | отдельный suite: навигация сезон↔серия, глубокие ссылки, hard refresh |
| Ветка | `claude/template-family-tf-01` |
| Артефакт и откат | отдельные, по образцу Lords |
| Production | запрещён до решения Release Ops |

## Общее правило для всех пяти

Пять недоделанных копий Lords хуже одного законченного Lords. Семейство
начинается не с вёрстки, а с закреплённого reference pack: без него визуальная
приёмка невозможна, и это уже проверено на самом Lords — числовой эталон
позволил довести геометрию, а отсутствие снимков оставило пиксельные ворота
недоказуемыми.
