# Blueprint `lords` — спецификация

Документ фиксирует требования к общему blueprint `lords` и к четырём сайтам на
его основе. Это **спецификация, а не реализация**: на момент записи blueprint
`lords` в репозитории не существует (проверено ниже). Документ существует, чтобы
следующая сессия строила от него, а не восстанавливала требования по переписке.

не попали. Уточнять нечего — их предстоит создать по этой спецификации.

## Референсы

Оба референса используются **только** для анализа структуры и пользовательских
сценариев. Код, вёрстка, CSS, логотипы, изображения, описания, комментарии и
любые иные материалы не копируются.

| Референс | В `inventory/reference-sources.yaml` | Измерялся мной |
| --- | --- | --- |
| `lordserials.fan` | нет | нет |
| `lordfilm-hit.org` | нет | нет |

В реестре разрешённых источников одна запись — `amd-online`. В режиме
CLOSED_WORLD открывать хост, которого нет в реестре, запрещено, поэтому
самостоятельного измерения обоих референсов не было и в таблице ниже его нет.

Структура референсов в таблице возможностей взята **из описания владельца** в
постановке задачи. Это переданный вход, а не мой замер. Чтобы измерить
самостоятельно, владельцу нужно внести оба хоста в
`inventory/reference-sources.yaml` (файл закрыт deny-правилом: записи вносит
человек), после чего измерение выполняется командой `factory reference-audit`.

## Конфигурация типов контента

```yaml
content_types:
  movies: true
  series: true
  animation: true
  anime: false
  dorama: false
  collections: true
```

Значения задаются отдельно для каждого сайта. Приведённый набор — пример
структуры, а не значения по умолчанию для всех сайтов.

### Правило отключённого типа

Отключённый тип контента не создаёт **ничего**. Проверяемо это значит:

| Поверхность | Требование при `type: false` |
| --- | --- |
| Маршруты | листинг и карточки типа не регистрируются; обращение даёт 404, а не пустую страницу |
| Меню и навигация | пункт отсутствует, а не выводится неактивным |
| Sitemap | ни одного URL типа, включая пагинацию и фасеты |
| SEO-страницы | ни title, ни description, ни H1, ни JSON-LD для этого типа не генерируются |
| Внутренняя перелинковка | анкоры на разделы типа не создаются |
| Фасеты и фильтры | значения, ведущие только к материалам этого типа, не выводятся |
| Поиск | материалы типа не попадают в выдачу |

Пустой раздел, отдающий 200 с нулём материалов, — нарушение этого правила и
одновременно soft 404. Правило действует и для типа, включённого в пакете, но
не подтверждённого API: см. следующий раздел.

### Автоотключение по факту данных API

Данные для разделов и фильтров берутся только из подтверждённого
Content/CDNVideoHub API. Если API не отдаёт фильмы, мультфильмы, переводы,
сервисы или расписание, соответствующие разделы отключаются автоматически по
тому же правилу, что и `type: false`.

Выдуманными данными раздел не заполняется ни при каких условиях. Отключение по
факту данных фиксируется в отчёте сборки с указанием типа и причины, чтобы
«раздела нет» не читалось как «раздел забыли».

Различие двух состояний обязано быть видно в отчёте:

* `disabled_by_config` — владелец выключил тип в пакете;
* `disabled_by_api` — тип включён, но API не подтвердил наличие данных.

### Непересекаемость по построению

Требование прежних решений проекта (D30, D36–D38) остаётся в силе: раздел-список
имеет явный список владельцев, и не владеющий сайт держит раздел как навигацию с
`noindex`. Для четырёх профилей это значит:

* страницу произведения индексирует ровно один профиль — `lords-general`;
* фасетные страницы индексирует ровно один профиль — `lords-genre`;
* подборку индексирует ровно один профиль — `lords-curated`;
* календарь и новинки индексирует ровно один профиль — `lords-new`.

Заголовки, описания и вводные тексты берутся из профиля, а не из общего шаблона
с подстановкой названия сайта: подстановка бренда в общий шаблон даёт страницы,
которые ворота `cross_site_uniqueness` считают одинаковыми, и справедливо.

Механическая замена слов, синонимизация и автоматически сгенерированный текст
запрещены. Факты — только из подтверждённого источника; рейтинги, отзывы, даты и
авторы не выдумываются.

## Что должно появиться в реализации

1. `blueprints/lords/` с поддержкой `content_types`.
2. Расширение `schemas/site-package.schema.json`: блок `content_types` и четыре
   значения профиля.
3. Четыре пакета сайтов с `deployment_readiness: BLOCKED_INPUT_DOMAIN_TARGET`
   до передачи доменов и целей.
4. Тест правила отключённого типа: для каждой поверхности из таблицы выше —
   проверка, что при `false` она пуста, и проверка, что при `true` она не пуста.
5. Тест различия `disabled_by_config` и `disabled_by_api` в отчёте сборки.
6. Ворота `cross_site_uniqueness` поверх четырёх профилей.
