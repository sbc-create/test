## Референсы

Оба референса используются только для анализа функциональной структуры и
пользовательских сценариев. Код, вёрстка, CSS, логотипы, изображения, описания,
комментарии и любые иные материалы не копируются.

Источник сведений о структуре — `owner_provided_reference_audit`: перечень
разделов передан владельцем в постановке задачи. Собственного сетевого замера
не было: ни `lordserials.fan`, ни `lordfilm-hit.org` не внесены в
`inventory/reference-sources.yaml`, а в режиме CLOSED_WORLD открывать хост вне
реестра запрещено. Живой `reference-audit` остаётся отложенной проверкой и
блокером реализации не является.

## Типы контента

```yaml
content_types:
  movies: true
  series: true
  animation: true
  anime: false
  dorama: false
  collections: true
```

Значения задаются отдельно для каждого сайта. Приведённый набор — пример формы,
а не умолчание: неупомянутый тип считается выключенным, потому что молчание
manifest не должно включать раздел, которого владелец не просил.

### Четыре состояния

| Состояние | Когда | Создаёт поверхности |
| --- | --- | --- |
| `enabled` | тип включён и подтверждён источником | да |
| `disabled_by_config` | владелец выключил тип | нет |
| `disabled_by_api` | тип включён, источник его не подтверждает | нет |
| `blocked_credentials` | тип включён, учётные данные не переданы | нет |

Различие последних трёх обязано быть видно в отчёте сборки: «раздела нет» не
должно читаться как «раздел забыли».

### Правило отключённого типа

Поверхности создаёт только `enabled`. Отключённый тип не создаёт маршрута,
пункта меню, URL в sitemap, SEO-страницы, внутренней ссылки, фасета и результата
поиска. Пустой раздел, отдающий 200 с нулём материалов, — нарушение правила и
одновременно soft 404.

Проверяется семью параметризованными случаями в
`TestDisabledTypeCreatesNothing`, по одному на поверхность.

## Профили

| Профиль | Назначение | Владеет разделами |
| --- | --- | --- |
| `lords-general` | фильмы и сериалы, основной каталог | `/filmy/`, `/serialy/`, `/multfilmy/`, `/anime/`, `/dorama/`, страница произведения |
| `lords-new` | новинки, новые серии, расписание | `/novinki/`, `/raspisanie/` |
| `lords-curated` | подборки и редакционные рекомендации | `/podborki/` |
| `lords-genre` | жанры, годы, страны | `/zhanr/`, `/god/`, `/strana/` |

Каждым разделом владеет ровно один профиль — это проверяется, а не
подразумевается. Не владеющий сайт держит раздел как навигацию с `noindex`:
зритель попадает куда хотел, в индекс уходит одна страница, а не четыре её
копии.

Title, H1, description и вводные тексты лежат в профиле. Общего шаблона с
подстановкой бренда нет, и тест это стережёт: подстановка названия сайта в
единый шаблон даёт страницы, которые ворота уникальности справедливо считают
одинаковыми.

## Секреты

| Что | Ссылка |
| --- | --- |
| Токен API | `secret://cdnvideohub/lords/api-token` |
| Publisher ID | `secret://cdnvideohub/lords/publisher-id` |

Области направлений разделены: `cdnvideohub/amedia`, `cdnvideohub/yami`,
`cdnvideohub/lords`. Значения не хранятся в manifest, git, HTML, сборке, логах и
доказательствах — в пакете лежит только адрес. Публичной переменной с Publisher
ID не существует, и это проверяется обходом отслеживаемых файлов репозитория.

## Что работает без учётных данных

Разбор и проверка контракта, план сайта, состояния типов, ворота дублей, план
синхронизации с идемпотентностью и защитой от дублей, политика устаревших
данных, dry-run и запись доказательств. Не работает ровно одно — живой запрос к
источнику.

## Блокеры

| Блокер | Что закрывает |
| --- | --- |
| `BLOCKED_INPUT_CDNVIDEOHUB_CONTRACT` | контракт `content-api.yaml` имеет `status: not_provided` |
| `BLOCKED_INPUT_CDNVIDEOHUB_CREDENTIALS` | живой запрос, наполнение разделов, два последних столбца таблицы |
| `BLOCKED_INPUT_DOMAIN_TARGET` | домены и цели выката не переданы: canonical, sitemap, выкат |

| Направление `site-a`/`site-b`/`site-c` | владелец не назвал: Amedia или Yami |
