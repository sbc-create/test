# Куда уходят семь часов цикла

Вход для `SITE-ENGINE-02B`. Замерено на живом хосте 30 августа 2026 года, не
оценено.

## Разбор цикла

| Этап | Время | Зависит от |
| --- | --- | --- |
| выборка каталога по трём витринам | 11–15 мин | размера каталога и скорости источника |
| рендер и публикация одной витрины | 2 ч 22 мин | размера каталога |
| три витрины | 7 ч 08 мин | |

Каталог — 53 116 записей, релиз одной витрины — около 1,6 ГБ и порядка 61 тысячи
страниц.

## Главная находка: рендер выполняется всегда

Идентификатор релиза считается **от содержимого уже собранной витрины**:

```bash
release="$(find "$staging" -type f -print0 | sort -z \
           | xargs -0 sha256sum | sha256sum | cut -c1-12)"
target="${runtime}/releases/${release}"
...
if [ "$current" = "$target" ]; then
  log "${site}: каталог не изменился, релиз ${release} уже работает"
```

Проверка «каталог не изменился» стоит **после** сборки. Значит, при неизменном
каталоге цикл всё равно тратит два с половиной часа на витрину, чтобы в конце
получить тот же хеш и ничего не опубликовать. Экономится только копирование
1,6 ГБ и переключение ссылки.

Наблюдалось прямо: прогон 18:42 UTC получил `FRESH, записей 53116` по всем трём
витринам — каталог не изменился ни на запись — и всё равно начал полный рендер
`lords-01`, релиз которого собран из этого же каталога сорок минут назад.

**Подтверждено до конца.** Рендер шёл с 18:57 до 21:12 — два часа пятнадцать
минут — и завершился ничем: список релизов `lords-01` не изменился
(`cb9ad9ca5a24`, `d4296e961e19`), новый каталог не появился, ссылка не
переключалась. Сценарий пересчитал хеш собранного, увидел совпадение с текущим
релизом и пропустил публикацию, как и написано в его коде.

То есть предсказание из чтения кода сбылось с точностью до поведения: два с
четвертью часа процессорного времени потрачены на то, чтобы убедиться, что
менять нечего. При ежедневном цикле это семь часов в сутки на трёх витринах,
когда поставщик ничего не добавил.

## Что из этого следует для 02B

**Проверять изменение до дорогой работы, а не после.** Отпечаток кэша каталога
уже вычисляется на этапе выборки (`FRESH` — это он и есть). Сравнение этого
отпечатка с тем, из которого собран текущий релиз, отсекает весь рендер целиком.
Одна эта правка убирает из цикла до семи часов на тихих сутках.

**Перерисовывать затронутое, а не весь каталог.** Выход одной серии меняет
страницу тайтла, полку новых серий и одну-две страницы листинга — не 61 тысячу
страниц. Инкрементальный рендер приводит стоимость обновления в соответствие с
величиной изменения.

**Разделить свежесть и полноту.** Полный обход нужен для полноты и может идти
раз в сутки. Свежесть новых серий требует минут, а не часов, и должна
обеспечиваться отдельным быстрым путём.

Пока это не сделано, восьми- и десятичасовые пределы остаются подпорками:
серия, вышедшая через пять минут после начала цикла, доедет до витрины через
семь часов независимо от величины предела.

## Смежное: публикация не вполне атомарна

Переключение релиза — `ln -sfn`, то есть `unlink` плюс `symlink`: существует
окно в микросекунды, когда ссылки `current` нет. Запрос, попавший в это окно,
получит ошибку. Атомарный приём — создать ссылку под временным именем и
переставить `mv -T`.

### 497 — так и задумано

Все 497 имеют тип контента `anime`, которого нет среди активных типов
`lords-01`: витрина публикует `movies`, `series` и `animation`. Страницы
строятся из `catalog.of_types(kinds)`, где `kinds` берутся из плана сайта.
Аниме — предмет порталов Yummy, и его отсутствие здесь правильно.

Отсюда следствие для приёмки: **ожидать 53 116 страниц на витрине неверно**.
Проверять нужно, что все тайтлы активных типов получили страницы. Сравнение с
сырым числом записей дало бы ложную недостачу и увело бы от настоящей.

### 207 — дефект

`seen` в `catalog_from_live` ключуется **исходным** слагом, а суффиксная форма в
нём не регистрируется:

```python
count = seen.get(title.slug, 0)
seen[title.slug] = count + 1
if count:
    title = replace(title, slug=f"{title.slug}-{count + 1}")
```

Второй тайтл с именем «Агент времени» получает адрес `agent-vremeni-2`. Тот же
адрес принадлежит настоящему тайтлу «Агент времени 2», и `by_slug` оставляет
одного из двух. Так теряются 207 записей — 0,4 % каталога.

Починка: регистрировать в `seen` итоговый слаг и повторять суффиксацию, пока
адрес не станет свободным. Правка вне разрешения, выданного на два systemd-юнита,
поэтому записана в план `SITE-ENGINE-02B`, а не сделана.
