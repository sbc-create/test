# Публичный fixture-staging направления Lords

Три сайта на трёх доменах из одного blueprint. Каталог синтетический, индексация
закрыта, доступ под паролем. Это стенд для осмотра, а не запуск направления.

## Что где

| Домен | Пакет | Профиль | Порт | Каталог рантайма | Юнит |
| --- | --- | --- | --- | --- | --- |
| `lordfilm47.space` | `lords-01` | `lords-general` | 9101 | `/srv/lords/lords-01` | `lords-01.service` |
| `lordserial33.biz` | `lords-02` | `lords-new` | 9102 | `/srv/lords/lords-02` | `lords-02.service` |
| `1lordserials1.online` | `lords-03` | `lords-curated` | 9103 | `/srv/lords/lords-03` | `lords-03.service` |
| — | `lords-04` | `lords-genre` | — | — | не публикуется |

Источник этой таблицы один — `config/directions/lords.json`. Пакеты сверяются с
ним при каждой сборке: домен, canonical и профиль, разошедшиеся между реестром и
manifest, останавливают сборку, а не выкатываются.

Сопоставление закреплено владельцем (`mapping_status: owner_confirmed`). Ранняя
редакция реестра содержала предположение, выведенное из имён доменов, и
предлагала другое соответствие — оно отменено.

## Команды

```bash
python3 -m factory lords-staging                  # собрать конфигурацию и пакеты
.venv/bin/python tests/tools/dns_check.py         # проверить делегацию и A-записи
.venv/bin/python tests/tools/lords_staging_stand.py   # поднять три стенда локально
npx playwright test --config=playwright.lords-staging.config.js
.venv/bin/python scripts/secret_scan.py           # секреты в отслеживаемых файлах
```

Применение на сервере — одна команда, и она требует root:

```bash
sudo bash automation/host/lords-staging-apply.sh
```

## Четыре барьера, а не один

Ни один из них не заменяет остальные, потому что защищают они от разного:

| Барьер | От чего |
| --- | --- |
| Basic Auth | от людей, случайно нашедших адрес |
| `X-Robots-Tag: noindex, nofollow` на каждом ответе | от роботов, читающих заголовки |
| `robots.txt` с `Disallow: /` | от вежливых роботов, читающих robots.txt |
| Пустой sitemap | от нас самих: нечего отправить в индекс по ошибке |

Плюс `production_authorized: false` и `seo_indexing_enabled: false` в каждом
пакете: включить индексацию нельзя, пока не возразят три независимых условия —
окружение, авторизация владельца и права в Вебмастере.

## Две фазы Nginx

Конфигурация с `ssl_certificate` на несуществующий файл не проходит `nginx -t`.
Поэтому применение идёт двумя фазами:

1. **Фаза 1** — только HTTP: отдаётся ACME-challenge, остальное закрыто ответом
   503. На этой конфигурации выпускаются сертификаты.
2. **Фаза 2** — HTTPS: `www` уходит на apex через **308** (301 не сохранил бы
   метод), сайт закрыт Basic Auth, заголовки стоят на каждом ответе.

`nginx -t` выполняется перед каждой перезагрузкой. Не прошёл — сценарий
останавливается, и `reload` не выполняется.

## Совместимость с nginx 1.18

Целевая версия — 1.18.0. Конфигурация написана под неё:

* `http2` задаётся параметром `listen`, а не отдельной директивой: директива
  `http2` появилась в 1.25.1 и на 1.18 это отказ запуска;
* `ssl_reject_handshake` (1.19.4) не используется — сервер по умолчанию получает
  собственный самоподписанный сертификат;
* `ssl_conf_command` и `keepalive_time` не используются по той же причине.

`factory/lords/nginx_check.py` сверяет каждую директиву с версией, в которой она
появилась. Это **не** замена `nginx -t` и не выдаётся за неё: свежий `nginx -t`
как раз молча примет `http2 on;` и разницу с 1.18 не покажет. Настоящую проверку
делает nginx на самом хосте, до перезагрузки.

## Неизвестный Host

Сервер по умолчанию отвечает **421**. Не 404 — тот признал бы имя своим; и не
первым попавшимся сайтом — это развесило бы его по всем именам, указывающим на
адрес.

Если в `/etc/nginx` уже объявлен `default_server` вне каталога Lords, сценарий
свой не ставит и говорит об этом: два `default_server` на одном порту — отказ
`nginx -t`. Ответ на чужой Host остаётся за существующей конфигурацией, и
проверить её нужно отдельно.

## Изоляция трёх сайтов

* свои профиль, заголовки, H1 и вводные тексты — тест падает, если два раздела
  используют один текст;
* свой canonical, ведущий только на свой домен;
* свой порт, свой каталог рантайма и свой каталог данных;
* конфигурация сайта не упоминает ни чужого домена, ни чужого порта;
* ни одной общей индексируемой страницы.

## Что стенд не делает

Не создаёт счётчик Метрики и не добавляет хосты в Вебмастер. Не выкатывает
production. Не трогает конфигурацию, контейнеры, базы и бэкапы YummyAnime и не
занимает портов вне 9101–9103. Не подставляет настоящий плеер CDNVideoHub:
на его месте заглушка со статусом `BLOCKED_INPUT_CDNVIDEOHUB_CREDENTIALS`,
и она не считается пройденной проверкой контракта.

## Учётные данные

Пароль Basic Auth рождается в сценарии, попадает в `/root/lords-staging-credentials`
с правами `0600` и в вывод не печатается. Повторный запуск существующий пароль
не меняет.
