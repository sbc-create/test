# Рабочие деревья: у каждой сессии своё, и одно из них — production-путь

Записано 2026-10-10 после того, как общее дерево дало измеримый вред.

## 1. Что случилось

Дерево `/home/claude/wt-portable-site-cell-01` и ветку
`claude/nova-publish-memory-01` одновременно использовали две сессии: эта
(память публикации, доставка каталогов) и соседняя (шлюз редактора, трафик,
кандидаты). В одной ветке перемешались четырнадцать коммитов двух разных задач:

```
11ade20 журнал: первые решения шлюза по паузе 20 минут …   ← соседняя сессия
193d6c0 журнал: полный прогон под исправленным издателем …  ← эта
c981611 доставка: заявка названа поколением …               ← эта
a0ebcad шлюз редактора: пересчёт кандидатов …               ← соседняя
74bb62d редактор: пауза 20 минут …                          ← соседняя
…
49ba96a публикация каталогов: витрины по одной …            ← эта
4449037 трафик 10.10: «Стил Бол Ран» …                      ← соседняя
84116ee принесён под версии как есть: nova-catalog-publish  ← эта
```

Чем это плохо именно здесь, а не «вообще»:

* **отчёт о состоянии ветки устаревает, пока его пишут.** Этот отчёт назвал
  HEAD `193d6c0`; к моменту чтения владельцем HEAD был уже `11ade20`;
* **один и тот же файл журнала** (`docs/NETWORK_EDITORIAL_ENABLEMENT_20261009.md`)
  дописывали обе сессии, и редактирование по совпадению строки могло попасть в
  чужой абзац;
* **`git add -A` одной сессии унёс бы чужие незакоммиченные правки** в свой
  коммит с чужим смыслом в сообщении. Спасало только то, что файлы добавлялись
  поимённо;
* **откат одной задачи задевает другую**: `git revert` своего коммита в общей
  ветке — операция над общей историей.

## 2. Как устроено теперь

| дерево | ветка | кто | назначение |
| --- | --- | --- | --- |
| `/home/claude/wt-portable-site-cell-01` | `claude/nova-publish-memory-01` | соседняя сессия (шлюз редактора, трафик) | **плюс production-путь, см. §3** |
| `/home/claude/wt-nova-publish-memory-02` | `claude/nova-publish-memory-02` | эта задача (память публикации, доставка) | правки этой задачи |

Новое дерево заведено от общего HEAD (`11ade20`), а не от `main`. Это сделано
намеренно: обе истории сохранены целиком, ничьи коммиты не потеряны и не
переписаны, конфликтов по общему файлу журнала нет. Соседняя сессия продолжает
в своём дереве и своей ветке, её незакоммиченные файлы (в том числе
`AGENT-REPORT-REQUIREMENT.md`) остались на месте — новое дерево их не забирает,
потому что неотслеживаемые файлы в `git worktree add` не переносятся.

Команда, которой это сделано (для повторения другими сессиями):

```bash
git worktree add -b claude/<своя-задача> /home/claude/wt-<своя-задача> HEAD
```

## 3. Старое дерево НЕЛЬЗЯ удалять: оно читается из production

Это главное, что надо знать до любой уборки. Развёрнутый контур ссылается на
путь `/home/claude/wt-portable-site-cell-01` напрямую:

| кто | что читает | откуда ссылка |
| --- | --- | --- |
| издатель каталогов (`nova-catalog-publish.py`, работает от root) | реестр ячеек `config/site-cells.json` | значение по умолчанию `SITE_CELLS_REGISTRY`; в юните и drop-in переменная НЕ задана, то есть действует именно это умолчание |
| исполнитель очереди (`/usr/local/lib/site-factory-cell`) | `site_repos_root` и `code_source` | `cell-install.json` |

Следствия, которые надо держать в голове:

* **удаление или переименование старого дерева останавливает доставку
  каталогов и выпуски ячеек.** Это не «старая копия», а рабочий путь;
* **правка реестра ячеек в новом дереве на production не действует.** Копии
  сейчас совпадают (sha256 `1c9c94b726379fe9`, 88 813 Б), и если реестр
  понадобится менять, менять надо тот, который читает издатель, — осознанно и с
  записью в журнале, а не «у себя»;
* **проверки, читающие развёрнутые файлы, остаются привязаны к хосту**, а не к
  дереву: `tests/unit/test_publisher_cell_delivery.py` читает
  `/srv/site-factory/repo/automation/host/nova-catalog-publish.py`. Прогонять
  такой тест надо ПОСЛЕ развёртывания, иначе он измеряет дерево, которого на
  хосте уже нет (ошибка, допущенная 10 октября).

## 4. Правило на будущее

1. Одна задача — одно дерево и одна ветка. Имя дерева и ветки совпадают по
   смыслу задачи.
2. Перед первой правкой проверить `git worktree list` и
   `git branch --show-current`: если в дереве уже есть чужие коммиты за
   сегодня — остановиться и завести своё дерево, а не «аккуратно работать
   рядом».
3. Файлы в коммит добавлять **поимённо**. `git add -A` и `git commit -a` в
   общем дереве запрещены: они уносят чужое.
4. Общий журнал дня дописывать **в конец, отдельным разделом**, и перед
   дописыванием перечитывать файл: его мог изменить сосед.
5. Старое дерево из §3 не удалять и не переносить без отдельного решения и
   правки ссылок в `cell-install.json` и в умолчании `SITE_CELLS_REGISTRY`.
