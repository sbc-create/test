# Владельцу: обход семи домéнов по счётчику Метрики

Два действия в интерфейсе на домен. Нужно затем, чтобы робот Яндекса узнал о
страницах сайтов, у которых сейчас **ноль визитов из Яндекса**, и чтобы это не
зависело от закрытого API Вебмастера (B023).

## Почему это предлагается

Официальная рекомендация, обращение 2026-10-18:
`https://yandex.ru/support/webmaster/ru/indexing-options/link-metrica.md` и
`https://yandex.ru/support/metrica/ru/general/link-webmaster.md`.

Робот узнаёт о страницах из разных источников, и один из них — счётчик
Метрики: сайту, подтверждённому в Вебмастере, можно привязать счётчик и
включить обход по его данным. Запрос отправляется с любой стороны (из Метрики
или из Вебмастера), подтверждает противоположная. Sitemap документация при
этом называет дополнением, а не заменой — то есть это ВТОРОЙ путь, а не замена
B029.

Измерено у нас (неделя 11–17.10, выгрузка Метрики 18.10 05:10Z): у этих семи
домéнов визитов из Яндекса ноль, а счётчик установлен у каждого.

## Что уже готово с нашей стороны

Шаг 1 официальной инструкции («добавьте сайт в Вебмастер и подтвердите права»)
**выполнен для всех семи**: в реестре аналитики у каждого домена
`verification_status: VERIFIED` и свой счётчик. Общих счётчиков нет — 19
счётчиков на 19 домéнов, ни один не делится между сайтами.

**Пересчитано 06:54Z 20.10.** У этих семи домéнов Яндекс даёт ноль, а
Google — 477 визитов за 13–19.10. Этот трафик не наблюдается ни одним
инструментом: Вебмастер знает только Яндекс (и молчит с 11.10, B023), Search
Console не подключён (B024). То есть привязка счётчика нужна не «вообще для
обхода», а чтобы единственный работающий на них канал перестал быть
невидимым, и чтобы у Яндекса появился второй источник обхода там, где его
нет совсем.

**Важная оговорка про зеркала.** Документация требует: «зеркало — привяжите
счётчик к главному адресу сайта (адресу, который должен участвовать в поиске)».
Пять из семи домéнов входят в кластеры, роль которых владелец ещё не назначил
(B007, B028). Если по решению владельца домен окажется зеркалом, привязку надо
делать к главному адресу кластера, а не к нему. Для домéнов, которые остаются
самостоятельными, привязка однозначна.

## Что сделать (из официальной инструкции)

Шаг 2, в **Метрике** для каждого счётчика из таблицы:

1. «Настройка» → вкладка «Счётчик»;
2. около адреса сайта нажать «Привязать к Вебмастеру».

Шаг 3, в **Вебмастере** для того же сайта:

1. «Настройки» → «Привязка к Яндекс Метрике»;
2. «Подтвердить» напротив номера счётчика.

После подтверждения включить обход по данным счётчика (там же, в Вебмастере).
Статус привязки виден с обеих сторон: в Метрике — «Настройка → Счётчик», в
Вебмастере — «Настройки → Привязка к Яндекс Метрике».

## Как проверим результат

1. статус привязки «Подтверждена» — проверяем мы, как только Вебмастер
   откроется (B023), либо владелец показывает статус;
2. дальше по нашим данным: события «появилась в поиске» и первые визиты из
   Яндекса в `daily_search` (`var/analytics/cabinet-latest.json`);
3. срок первой проверки — **25.10**.

**Чего мы не обещаем.** Срок обхода Яндекс не гарантирует. Если к 25.10 визитов
из Яндекса не появится, вывод будет «данных недостаточно», а не «метод не
работает»: семь суток — короткий срок для первого обхода. Отдельно: обход не
отменяет требований к качеству страницы — в той же документации сайты-каталоги
без собственных текстов названы примером, к которому алгоритмы могут применить
ограничения, и поэтому работа редактора по описаниям остаётся условием, а не
украшением.
