## Три разных утверждения, которые нельзя путать

| утверждение | состояние на 2026-10-15 |
| --- | --- |
| **файлы подготовлены** | да: код, данные, конфигурации, юниты, файлы плеера — на узле, суммы и содержимое сверены |
| **витрина работает** | нет: служба не запущена, это действие 2 (root). Что она поднимается — измерено пробным прогоном настоящим пускателем на самом узле |
| **публичный выпуск проверен** | нет: домены указывают на прежний узел и отдают ошибку TLS. Проверка публичного адреса возможна только после действий 2 и 3 |

Воспроизведение проверено там, где это возможно без публичного адреса: на
локальном стенде тем же инструментом, что живые витрины (номер в разметке,
номер в запросе поставщику, растущий `currentTime`), и у поставщика — запросом
плейлиста с `Origin` каждого домена.

## Действие 1 (root на узле): подготовка узла — один раз

Текст блока — `docs/K2_NIGHT_PLAN_20261013.md` §3. Ставит зависимости (nginx,
certbot, python3-venv), предел журналу, восемь системных учётных записей с
каталогами данных `0750`, юниты (без `enable`), объявления upstream и
включаемые файлы режима индексации в состоянии **CLOSED**.

## Действие 2 (root на узле): запуск витрин — по одной

```bash
# host: k2-zomro-01, от root
cd /home/k2deploy/stage
for s in lords-10 lords-11 lords-12 lords-13 lords-14 lords-15 lords-16 lords-17; do
  bash k2-launch-site.sh "$s" || break
done
```

Сценарий сам: кладёт конфигурацию nginx, проверяет `nginx -t` ДО перезагрузки,
ставит данные с правами витрины, разворачивает выпуск из бандла, ставит файл
плеера в `config/player.json` (0640, владелец — витрина), включает и запускает
юнит, проверяет `/healthz` и откатывает изменения при неуспехе. Порог памяти
2000 МиБ проверяется перед каждой витриной; при неуспехе одной цикл
останавливается (`|| break`) — так разбирается одна причина, а не восемь.

Проверка после каждой витрины (без root, с управляющего узла):

```bash
python3 automation/host/launch-domain.py --domain <домен>
```

## Действие 3 (root на узле): записи A и сертификаты — после действия 2

Пока DNS указывает на прежний узел (`45.131.182.225`), домены отдают ошибку
TLS: сертификата на эти имена там нет. Порядок обязателен — сертификат
выпускается только после того, как имя указывает на узел.

```bash
# 1. На стороне DNS: по одной записи A на домен -> 145.63.129.86
#    lordfilm.group, lordfilm.spb.ru, lordfilm.msk.ru, lordserial.su,
#    lordserial.group, lordserial.spb.ru, lordserial.msk.ru, lordserial.net.ru
# 2. Проверить распространение (с любой машины):
dig +short A lordfilm.group @8.8.8.8      # ожидается 145.63.129.86
# 3. host: k2-zomro-01, от root — сертификат и блок 443 на каждый домен:
certbot --nginx -d lordfilm.group --non-interactive --agree-tos -m <почта владельца>
```

## Чего в этом комплекте НЕТ намеренно

* **Открытия индексации.** Витрины рождаются закрытыми и остаются такими:
  включаемый файл режима создаётся в состоянии CLOSED, а открытие — отдельная
  заявка `indexing-nginx --mode open`, а не правка конфигурации.
* **Удаления прежних копий восьми сайтов.** Условие владельца — подтверждённая
  работоспособность на новом сервере; до запуска и проверки ничего не удаляется.
* **Назначения номеров.** Номер назначен: 10454 у всех восьми.
