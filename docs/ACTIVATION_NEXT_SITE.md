# Активация zonafilm.space — команда владельцу

Следующий сайт очереди. Проверено всё, что можно проверить без root; остался
единственный шаг, требующий привилегий.

## Команда

```bash
cd /home/claude/wt-portable-site-cell-01
sudo /home/claude/wt-portable-site-cell-01/.venv/bin/python -m factory cell activate \
  --site zona-01 \
  --commit 25f6808a8388e83391389af4e25f02773401ca8a \
  --expect-digest sha256:abcb74f173705af04edae5f79f57e7215a5c9751a23e3af2de97178fb23ca5be \
  --confirm-activation
```

Без `--confirm-activation` та же команда только печатает план и ничего не меняет.
Сухой прогон уже выполнен — вывод совпадает с планом ниже.

`cd` обязателен: из другого каталога `python -m factory` подхватывает другую
копию пакета (в ней нет команды `cell`). Это проверено запуском.

## Что команда сделает

1. Проверит, что zona-01 есть в реестре ячеек и у него собственный репозиторий.
2. Проверит, что дерево репозитория чистое и HEAD равен названному коммиту.
3. Соберёт артефакт **из этого коммита** и сверит digest с `--expect-digest`.
   Не совпало — остановится, ничего не тронув.
4. Запустит `deploy/activate.sh` этого же репозитория: учётная запись
   `zonafilm-space`, каталоги `/srv/zonafilm-space/{app,data}`, распаковка
   проверенного артефакта, копия настроек плеера и снимков каталога.
5. Остановит и **снимет с автозапуска** `nova-zona-01.service`, установит и
   запустит `nova-zonafilm-space.service` на том же порту 9120.
6. Проверит `/healthz`; при неудаче откатится на прежнюю службу.

Конфигурацию nginx команда не трогает: она и сейчас указывает на 127.0.0.1:9120.
DNS, TLS и режим индексации не затрагиваются.

## Что проверено заранее

* Репозиторий, коммит и успешный CI — отдельные, свои у этого сайта.
* Код ячейки совпадает **побайтово** с назначенным сайту релизом
  `zona-01-a0209877e1db`; устаревшего снимка здесь нет.
* Сценарии активации выполнены (не разобраны): сухой прогон, успешное
  переключение и сбой с откатом — в песочнице, с проверкой digest.
* Права: `/srv/lords` и `/srv/lords/.frontend` — 755, снимки каталога 644;
  новая учётная запись их прочитает.
* Отрендеренные страницы (2854 файла) остаются у производителя в
  `/srv/lords/zona-01/current/site`; ячейка читает их там же, а не копией.
* Пользовательских данных (комментарии, голоса) у zona-01 нет — их каталог пуст,
  терять нечего.
* Конкурирующей выкладки нет: последнее изменение контура — 16 часов назад,
  состояние приёмщика Lords двухнедельной давности.

## После активации

```bash
cd /home/claude/wt-portable-site-cell-01
.venv/bin/python -m factory cell deliver --site zona-01      # контент в новое хранилище
curl -s https://zonafilm.space/ | grep -o 'site-factory-build-id" content="[^"]*"'
```

Ожидаемый публичный build-id: `25f6808a8388-zona-01`. Сегодня сайт отдаёт
`zona-01-a0209877e1db` — прежнюю сборку.

Базовый слепок публичного поведения снят до активации: `var/базовый-слепок.json`
(главная 200 / 123 922 байта, catalog и search — 308, robots.txt закрыт,
X-Robots-Tag: noindex, nofollow). Сравнение с ним и есть приёмка.

## Если что-то пойдёт не так

Скрипт откатывается сам: выключает новую службу, возвращает `nova-zona-01.service`
и проверяет, что витрина отвечает. Ручной откат — `deploy/rollback.sh` в том же
репозитории.
