# ADR-002. Записывающий слой управляющего API

- Статус: принято
- Дата: 2026-09-04
- Область: `factory/site_engine/api/control.py`

## Контекст

Читающая часть Site Engine API (11 маршрутов, только GET) отвечает на вопрос
«что сейчас». Для управления массивом витрин снаружи — в том числе автоматикой —
нужны операции, которые меняют состояние: поставить задание, изменить настройку,
сбросить кэш. Такие операции опасны не сами по себе, а тем, что их вызывает
программа: она повторяет запрос при таймауте, ошибается в поле и не читает
предупреждений.

## Решение

Записывающий слой добавлен отдельным модулем с единым конвейером, через который
проходит каждая операция: включённость → аутентификация → право → лимит частоты →
валидация → идемпотентность → блокировка сайта → сверка версии → применение →
аудит. Конвейер один на все маршруты, поэтому ступень нельзя пропустить забыв.

Четыре решения ограничивают возможности намеренно:

**Отдельный выключатель записи.** `SITE_ENGINE_CONTROL_WRITES` не связан с
выключателем чтения. Открытое чтение — утечка; открытая запись — чужой контроль
над витриной. При выключенной записи маршрут отвечает 404, а не 403: ответ 403
подтверждал бы, что здесь есть что включать.

**Список изменяемых настроек закрыт.** Меняются `keep_releases`, `cache_policy`,
`feature_flags` — обратимые и принадлежащие ядру. Отклоняются намеренно, с
указанием причины в ответе: `domains`, `canonical_host`, `site_type`,
`indexing_enabled`, `seo_enabled`, `locale`, `timezone`, `theme`, `render_mode`.
Тихое отключение индексации через вызов API замечают через недели по падению
трафика — у такого изменения должны быть ревью, автор и выкладка.

**Инвалидация кэша ставится в очередь, а не исполняется на месте.** Управляющий
слой не имеет доступа к хранилищам витрин. Тогда его ошибка остаётся ошибкой
планирования, а не порчей чужого состояния.

**Права разделены по областям.** `read`, `jobs:write`, `config:write`,
`cache:write`, `audit:read`. Один токен на всё означал бы, что задача «дать
автоматике перезапускать индексацию» незаметно выдаёт и право переписать
конфигурацию.

## Транспорт

До этой итерации описание API существовало, а обратиться к нему было нельзя:
`create_api` не вызывался нигде, кроме тестов, службы не было. Контракт без
транспорта выглядит готовым и не является таковым — поэтому добавлен
`factory/site_engine/api/server.py` на стандартной библиотеке, по образцу
`factory/secret_hub/panel/server.py`.

Транспорт включается третьим, независимым выключателем `SITE_ENGINE_HTTP`.
Служба слушает `127.0.0.1`; привязка к любому другому адресу требует явного
`--allow-public-bind` и иначе падает с объяснением. Причина: строка
`host: 0.0.0.0` в конфигурации проходит ревью как настройка сети, хотя означает
выставление управляющего API наружу. Требовать отдельный флаг — значит требовать
отдельного решения.

Тело ограничено 256 КБ: без предела отправитель решает, сколько памяти занять.
Внутренние ошибки отдаются без подробностей — трассировка в ответе есть карта
устройства, выданная тому, кто не смог сформировать корректный запрос.
Завершение TLS и список допустимых источников остаются задачей обратного прокси:
служба, которая делает и то и другое, обновляется по расписанию обеих задач.

## Отвергнутые варианты

*Записывать без сверки версии.* Проще, но теряет конкурентную правку молча — обе
стороны считают, что их изменение применено. Сверка идёт по хэшу содержимого, а
не по времени изменения: время меняется при копировании файла, содержимое — только
при правке.

*Идемпотентность как «повтор игнорируется».* Недостаточно: тот же ключ с другим
телом — это другой запрос под уже использованным ключом, и выполнить его молча
значит выполнить дважды по-разному. Такой случай отвечает 409.

*Писать в журнал только удачные операции.* Журнал тогда отвечает на вопрос «что
изменилось», но не на вопрос «кто пытался». Второй задают ровно тогда, когда он
уже важен, поэтому отказы тоже записываются.

## Последствия

Ограничение частоты (30 запросов в минуту на токен) считается в памяти процесса:
при нескольких экземплярах предел кратен их числу. Это осознанно — ограничение
задумано против сорвавшегося цикла автоматики, а не против злоумышленника.

Перечни допустимых действий и областей импортируются в генератор OpenAPI из
кода проверок, поэтому описание не может разойтись с тем, что действительно
проверяется.
