# Передача: превью полки без карточки-заглушки, zona-01 (zonafilm.space)

Кому: линии, которая выпускает `automation/host/collection_contract.py` на
витрины семейства. Моя сессия изолирована: `git` в репозитории ячеек из неё не
пускает защита рабочих копий (проверено, не предположено).

Домен назван по реестру: **zona-01 → zonafilm.space**, статус `live`, канарейка
пилотов главных (на ней выпущен T284).

> **БАЗА ИСПРАВЛЕНА С 1 НА 6, И ВОТ ПОЧЕМУ.** Первая редакция этой передачи
> называла одну карточку. Линия SEO независимо насчитала шесть, и права она.
> Мой зонд смотрел **первые 24 карточки страницы**, а полка «Высокие оценки

>

> **ОТСУТСТВИЕ `<img>`** в блоке карточки, а НЕ наличие класса `zt__none`:
> у `teddi-2` и `elektro-andy` в одной карточке есть И `<img>`, И `zt__none`,
> то есть по наличию заглушки их сочло бы дефектными ошибочно. Сырой подсчёт по
> `zt__none` даёт на этой же странице 10 — на четыре больше правильного.

Страница произведения показывает заглушку тоже — значит постера у записи нет
вовсе, и это пробел ДАННЫХ. Но полка — визуальное обещание: заглушка на главной
читается посетителем как сломанный сайт, и до исправления данных её там быть не

## 3. Что меняется — ТОЛЬКО точечный патч, файлом отдавать нельзя

> **ПРЕДУПРЕЖДЕНИЕ, ДОБАВЛЕНО ПОСЛЕ ЗАМЕЧАНИЯ ЛИНИИ ЯЧЕЙКИ ПО ДРУГОМУ ПОВОДУ.**
> Установленный файл и файл этой ветки РАСХОДЯТСЯ, и замена целиком принесла бы
> изменения, которых никто не заказывал:
>
> | файл | размер | окна подборок новизны |
> | --- | --- | --- |
> | `/srv/zonafilm-space/app/src/collection_contract.py` (установлено) | **35 269 байт** | `recent_days: 90` у ОБЕИХ, заголовки «Недавно добавленные» / «Недавно добавленные фильмы» |
> | `automation/host/collection_contract.py` (эта ветка) | **47 180 байт** | `fresh_days` 14 и 30, заголовки «Новое за 14 дней» / «Новые фильмы за 30 дней» |
>
> Живые описания на витрине говорят «за последние **90** дней» — то есть
> установлена первая. Отдать файл целиком значит сменить окна с 90 на 14/30 и
> переписать заголовки двух подборок заодно с правкой постеров.
>
> **Поэтому доставлять нужно ТОЛЬКО два куска ниже**, вписав их в установленный
> файл: новую функцию и одну строку в `_собрать`. Больше ничего из этой ветки
> не переносить.

Новая функция (добавить рядом с `_собрать`):

```python
def превью_с_постерами(набор: list[dict], предел: int) -> list[dict]:
    если_есть = [з for з in набор if str(з.get("poster") or "").strip()]
    if len(если_есть) >= предел:
        return если_есть[:предел]
    без = [з for з in набор if not str(з.get("poster") or "").strip()]
    return (если_есть + без)[:предел]
```

и в `_собрать`:

```python
    if предел is not None:
        кусок = превью_с_постерами(набор, предел)   # было: набор[:предел]
        номер = 1
```

## 4. Чего правка НЕ делает, и каждое закреплено проверкой

| свойство | проверка |
| --- | --- |
| полная страница подборки записи без постера НЕ теряет — это поверхность каталога | `test_полная_страница_записей_без_постера_НЕ_теряет` |
| полка не становится короче: при нехватке постеров остаток добирается | `test_превью_не_становится_короче_чем_просили`, `test_превью_полки_при_нехватке_постеров_не_пустеет` |
| порядок внутри каждой из двух групп сохраняется | `test_превью_сохраняет_порядок_внутри_групп` |
| постер из одних пробелов считается отсутствующим | `test_пустой_постер_из_пробелов_считается_отсутствующим` |
| **проводка применена, а не только функция написана** | `test_превью_полки_действительно_обходит_заглушку` |

Последняя строка появилась потому, что подстановка это и выявила: первые
проверки вызывали `превью_с_постерами` напрямую и проходили ПРИ СЛОМАННОМ
`_собрать` — в снимке модуля постеры есть у всех записей, и отбор ничего не
менял. Теперь постер снимается у записи, которая иначе попала бы в превью
ПЕРВОЙ, и она обязана из превью исчезнуть.

Прогон: **28 проверок** `tests/unit/test_lords_collections.py` проходят;
подстановка `кусок = набор[:предел]` даёт целевое падение одной проверки.

## 5. Приёмка на витрине — после выпуска, не вместо

```bash
python3 automation/local/poster-coverage.py zonafilm.space
python3 automation/local/homepage-cards-audit.py --domain zonafilm.space
```

Ожидаемый итог, названный ДО выпуска: `без изображения 0`, и в ревизии главных
замечаний 0. **База «до» — 6 карточек** (не 1: см. поправку в разделе 1);
снимок состава «до» снят линией SEO в
`var/seo-audit/zona01-shelf-posters-before-20261020.json`.

**Состав полки подвижен**, и это надо учесть приёмщику: заметную долю в ней
сейчас занимают записи с оценкой 8.7, и набор меняется со временем. Поэтому
сравнивать надо не список слагов, а ЧИСЛО карточек без изображения — ноль
против шести.

**Отрицательный контроль, обязательный:** число карточек в полке «Высокие оценки
недели» остаётся **24**. Если станет меньше — отбор начал обеднять полку, и
правку надо откатывать, а не досматривать.

Второй отрицательный контроль: `/collection/top_rated/` (полная страница)
обязана ПО-ПРЕЖНЕМУ содержать `facing-grizzlies`. Правка трогает превью, а не
каталог.

## 6. Границы

Правка в ОБЩЕМ контракте подборок, то есть затронет все витрины семейства, где
он выпускается. Выпускать по одной витрине за раз, начиная с канарейки
`zonafilm.space`, — прежнее правило канарейки остаётся в силе.

**Переносить только два куска из раздела 3.** Установленный файл на 12 КБ
меньше файла этой ветки, и у него СВОИ спецификации подборок zona (окно 90 дней
у обеих, другие заголовки). Полная замена сменила бы окна и заголовки заодно —
это ровно та ловушка, которую линия ячейки поймала у меня в блоке по Yummy:
подвижный носитель несёт оба изменения.

Исправление самих данных (постер у `facing-grizzlies` и у остальных 840 записей)
этой правкой не делается и остаётся за линией данных.

**Порядок раскатки по измеренной пользе.** Канарейка `zonafilm.space` первой
(там 6 карточек), затем приёмка. Четыре чистые витрины трогать смысла нет:
правка им ничего не изменит, а риск любого выпуска не нулевой. Это и есть
отрицательный контроль раскатки: если после выпуска на чистой витрине число
карточек в полках изменится — правка задела не то.

### Про `lordserial33.biz` — ожидаемый итог НЕ обещается

Замечание линии SEO, и оно верное: там карточки без постера лежат в **сериальных
полках** (`data-section="series"`: «Сериалы в каталоге», «Обновления сериалов»),
а не в «Высоких оценках недели». Эта правка их **не затронет**, и вот почему она
и не должна:

**Отбор применяется ТОЛЬКО к полкам, отсортированным по ОЦЕНКЕ**
(`sort_spec.field == "rating"`). У полки новизны он переставил бы порядок по
дате, то есть сломал бы её смысл: «новое первым» важнее, чем «с картинкой
первым». Это закреплено проверкой
`test_полка_новизны_порядок_по_дате_НЕ_меняет`, и подстановка «применять ко
всем полкам» даёт её падение.

Поэтому:

* ожидаемый итог для `zonafilm.space` — `без изображения` падает до нуля **в
  полке «Высокие оценки недели»**;
* для `lordserial33.biz` ожидаемый итог этой правкой **не обещается**: заглушки
  там в полках новизны, и их исправление — отдельное решение (либо постеры в
  данных, либо отдельно обсуждённый отбор для сериальных полок);
* числа линии SEO по базам «до» (`var/seo-audit/home-posters-before-20261020.json`):
  `zonafilm.space` 7, `zonafilm12.site` 5, `lordserial33.biz` 14. Расхождение с
  моими 6 и 11 — подвижный состав полок, каждая заглушка проверена линией SEO
  вручную и подлинна.
