# Что действительно недоступно в эталоне Lords

Перечень только того, что заблокировано. Всё, что удалось снять и сравнить,
здесь не значится — оно в `LORDS-REFERENCE-PARITY.md`.

## Доступ к хостам

Владелец разрешил read-only открытие и снимки двух референсов. Разрешение
внесено в `inventory/network-allowlist.yaml` с указанием происхождения.

| Хост | Итог |
| --- | --- |
| `lordfilm-hit.org` | доступен, снят: 8 архетипов × 7 ширин = 56 снимков |
| `lordserials.fan` | **недоступен**: `curl: (52) Empty reply from server` по HTTPS и по HTTP, воспроизведено трижды |

Обход защиты, подбор заголовков и авторизация запрещены заданием и не
выполнялись. Второй референс остаётся `BLOCKED_REFERENCE` целиком.

## Архетипы, которых нет у доступного эталона

Снято 8 из 11. Недостающие четыре не удалось получить, потому что их адреса
не выводятся из навигации эталона: разделы отдают разметку без ссылок на
произведения — перечни собираются скриптом. Придумывать адреса запрещено.

| Архетип | Состояние |
| --- | --- |
| страница фильма | адрес неизвестен; доступна только одна страница произведения, и она сериал |
| сезон | отдельного адреса не обнаружено |
| эпизод | отдельного адреса не обнаружено |
| подборка | раздела не обнаружено |

Что снято: `home`, `catalog` (`/filmy/`), `series_catalog` (`/serialy/`),
`genre` (`/boevik/`), `title_series` (`/3629-bunker-2023.html`), `search`
(`/index.php?do=search`), `new` (`/films-2026/`), `not_found`.

## Пиксельные метрики: блокировка не эталоном, а оснасткой

Снимки эталона есть — 56 файлов с sha256 каждого. Вычислить по ним SSIM,
ΔE по изображению и наложение **нечем**: в окружении нет ни одной библиотеки
обработки изображений.

```
numpy нет   PIL нет   skimage нет   cv2 нет   scipy нет
pixelmatch нет   pngjs нет
```

Установка потребовала бы сетевого доступа к хранилищу пакетов. Владелец
разрешил два хоста референса и только чтение; расширять это до пакетного
хранилища по своей инициативе нельзя. Поэтому:

- `MASKED_SSIM=BLOCKED_TOOLING`;
- `OVERLAY_REVIEW=BLOCKED_TOOLING`;
- ΔE по **измеренным цветам** посчитан (арифметика, библиотек не требует):
  фон эталона и витрины совпадает, ΔE = 0.0.

Это разные блокировки, и смешивать их нельзя: эталон для пикселей есть,
инструмента нет. Снимки сохранены — посчитать можно будет, не переснимая.

## Что оказалось несопоставимым по методу

35 проверок цвета текста помечены `NOT_COMPARABLE_BY_SELECTOR`.

У эталона `body` вычисляется как `rgb(68,68,68)` на фоне `rgb(17,17,17)` —
такой текст был бы нечитаем; настоящий текст у него белый. То есть `#444` —
унаследованное умолчание, а не цвет читаемого текста. Цвет, снятый одним
`querySelector` на двух разных сайтах, сравнивает разные элементы, и ΔE между
ними ничего не значит.

Сопоставимое сравнение цвета требует либо проб пикселей со снимков (нужна
библиотека, см. выше), либо кропов одноимённых компонентов с обеих сторон.

Отдельно: цвет кнопки эталона `rgb(121,193,66)` совпадает с нашим акцентным
токеном `#79c142` **точно**. Это один сравнимый цвет, и он сходится.

## Расхождения, оставленные решению владельца

13 проверок не сошлись, и все они — свойства конкретных страниц, а не общей
раскладки:

| Что | Эталон | Наше | Клеток |
| --- | --- | --- | ---: |
| кегль H1 страницы поиска | 24px/600 | 18px/600 | 7 |
| отступ контейнера на поиске (360–768) | 340 / 370 / 748 | 350 / 380 / 758 | 3 |
| ширина блока страницы 404 | 280 | 350 / 380 / 758 | 3 |

Подгонять их не стал. Кегль заголовка — часть шкалы типографики: у эталона на
главной он 18px, как у нас, и 24px на поиске. Сделать «как на поиске»
означает завести постраничный размер заголовка по одной странице одного
референса. Ширина блока 404 у эталона — узкая колонка 280px; это решение об
оформлении страницы ошибки, а не про контейнер витрины.

Оба вопроса — к владельцу, и оба измерены, а не описаны словами.
