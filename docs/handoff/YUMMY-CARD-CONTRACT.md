# Handoff: дополнение карточки тайтла внутри приложения

**Кому:** владельцу контентного контура (Архитектор) и владельцу приложения
`yummyani/web`.
**От кого:** слой шаблонов Site Factory, семейство `yummy`.
**Статус:** блокер. Компонент готов и проверен фикстурой; нативно включить
его нельзя, пока приложение не видит контур чтения.

## Что случилось

Блок дополнял карточку витрины полями, которых на ней нет: сезоны, фон,
рекомендации, внутренняя оценка. Он выводился отдельным узлом в конце `body`
— и это был DOM-мост: чужой узел в дереве React ломал восстановление
страницы (`Minified React error #418`), а вместе с ним отказывала вся
клиентская часть, включая поиск.

Мост снят. Блок из production убран полностью и наружу не идёт.

## Почему нельзя просто перенести в компонент

Данные блока живут в контуре чтения `yummy-read-model/1.x` — это файл
SQLite на хосте витрины:

```
/srv/lords/.frontend/yummy-readmodel.sqlite3
```

Контейнеры приложения его не монтируют и о нём не знают. Встроить блок в
React-компонент карточки — значит дать приложению доступ к этому источнику,
то есть изменить контракт данных. Своей волей я этого не делаю.

## Что нужно, чтобы включить нативно

Один из двух путей, решение за владельцем контура:

**А. Приложение читает контур напрямую.** Монтировать файл в контейнеры
`web-site`, `web-org`, `web-biz` только на чтение и добавить серверный
модуль доступа. Контракт и все поля описаны в
`docs/YUMMY-TEMPLATE-READINESS.md`; переходник, который уже это делает, —
`automation/host/yummy_contract.py`.

**Б. Контур отдаёт поля через API приложения.** Тогда приложению нужен
источник, а витрине — ничего: блок рисует сам компонент карточки.

Необходимые поля (все — необязательные, отсутствующее скрывается поодиночке):

| поле | смысл |
| --- | --- |
| `seasons` | число сезонов |
| `backdrop` | фон карточки |
| `recommendations[]` | `canonical_path`, `poster`, `title`, `year`, `kind`, `ratings[]`, `reason`, `source` |
| `personal` | шкала, число голосов, своя оценка; нужен рабочий API оценок |

Остальные поля полной карточки витрина уже рисует сама — их дублировать
нельзя, список объявлен в `automation/host/yummy_entity.py:РИСУЕТ_ВИТРИНА`.

## Что уже готово с нашей стороны

* компонент `yummy_entity.карточка_тайтла` — 20 полей, каждое скрывается
  поодиночке, пустых подписей и нулей не печатает;
* переходник `yummy_contract.py` — читает контур, подхватывает новые
  колонки и таблицы-связки по мере появления;
* фикстура контракта `tests/fixtures/yummy/contract_fixture.py` и тесты
  `tests/unit/test_yummy_entity_view.py` — заполненное и пустое состояние.

Ничего из этого не требует переделки при подключении: нужен только
источник данных.
