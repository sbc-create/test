# Передача в чат «Шаблоны»: показ массива оценок

Статус: **готово к применению, не применено**. Ветка «Шаблоны» активна и этой
задачей не трогалась.

## Зачем

4 421 оценка Shikimori уже лежит в данных с полным происхождением, но на
страницу не выходит. Причина одна: функция `оценки()` в
`lords-frontend.py` собирает список из двух полей и ни из чего больше.

```python
def оценки(деталь: dict) -> list:
    собрано = []
    кп = _число(деталь.get("kinopoisk_rating"))
    им = _число(деталь.get("imdb_rating"))
    if кп:  собрано.append(("kp", "Кинопоиск", кп))
    if им:  собрано.append(("imdb", "IMDb", им))
    return собрано
```

`ratings_by_source` рендерер не читает вовсе — ноль вхождений в файле.

Цена этого ровно измерена: в сегменте ANIME покрытие данными 95.15 %, а
публично видно 35.48 %. Разница — это Shikimori.

## Что уже есть в данных

Каждая запись бокового файла может содержать `ratings_by_source` — словарь
`источник → запись оценки`. Поля записи:

| поле | смысл | пример |
|---|---|---|
| `source` | источник | `"shikimori"` |
| `provider` | адаптер, который принёс | `"shikimori"` |
| `external_id` | идентификатор у источника | `"1037"` |
| `value` | значение как отдал источник | `6.04` |
| `value_on_ten` | приведённое к десятибалльной | `6.04` |
| `scale` | шкала источника | `10.0` |
| `votes` | число голосов, если источник даёт | `null` |
| `retrieved_at` | когда получено | `"2026-09-14T17:41:02Z"` |
| `canonical_title_id` | наш идентификатор | `"019f..."` |
| `match_state` | как сопоставлено | `"external_id_exact+title_verified"` |

Плоские поля `kinopoisk_rating` и `imdb_rating` остаются как есть: их
заполняют только Кинопоиск и IMDb, и менять это нельзя.

## Предлагаемый контракт отображения

Заменить тело `оценки()` на сбор из обоих мест. Плоские поля остаются
первичными, `ratings_by_source` добавляет то, чего в них нет.

```python
#: Подпись под числом обязана быть правдой: источник называется своим именем.
#: Порядок задан здесь, а не порядком ключей в данных, — иначе одна и та же
#: карточка показывала бы оценки в разной последовательности.
ПОДПИСИ = (
    ("kinopoisk",  "kp",        "Кинопоиск"),
    ("imdb",       "imdb",      "IMDb"),
    ("shikimori",  "shikimori", "Shikimori"),
    ("myanimelist","mal",       "MyAnimeList"),
    ("amd",        "amd",       "AMD"),
)

def оценки(деталь: dict) -> list:
    """Оценки с источником. Показывается только то, что у записи есть.

    Плоские поля первичны: их заполняют Кинопоиск и IMDb, и значение из
    массива их не подменяет. Остальные источники берутся из
    `ratings_by_source` и подписываются своими именами — записать Shikimori
    в поле IMDb значило бы соврать о происхождении числа.
    """
    массив = деталь.get("ratings_by_source") or {}
    собрано = []
    for источник, код, метка in ПОДПИСИ:
        значение = None
        if источник == "kinopoisk":
            значение = _число(деталь.get("kinopoisk_rating"))
        elif источник == "imdb":
            значение = _число(деталь.get("imdb_rating"))
        if значение is None:
            запись = массив.get(источник)
            if isinstance(запись, dict):
                значение = _число(запись.get("value_on_ten", запись.get("value")))
        if значение:
            собрано.append((код, метка, значение))
    return собрано
```

Возвращаемая форма прежняя — кортеж `(код, метка, значение)`. Оба места, где
результат используется (строки 1691 и 2032), перебирают его циклом и правок
не требуют.

Число голосов намеренно не выводится: у Shikimori его нет, а показывать его
у одних источников и не показывать у других — это разная достоверность под
одинаковым оформлением. Если голоса нужны, это отдельное решение с полем
`votes`, которое уже сохраняется.

## Тестовый контракт

```python
def test_плоское_поле_первично():
    """Значение из массива не подменяет Кинопоиск и IMDb."""
    д = {"kinopoisk_rating": 7.1, "imdb_rating": 6.4,
         "ratings_by_source": {"kinopoisk": {"value_on_ten": 3.0},
                               "imdb": {"value_on_ten": 2.0}}}
    assert оценки(д) == [("kp","Кинопоиск",7.1), ("imdb","IMDb",6.4)]

def test_shikimori_добавляется_своей_подписью():
    д = {"ratings_by_source": {"shikimori": {"value_on_ten": 6.04}}}
    assert оценки(д) == [("shikimori","Shikimori",6.04)]

def test_shikimori_не_подменяет_imdb():
    """Оценка Shikimori не может оказаться подписанной как IMDb."""
    д = {"ratings_by_source": {"shikimori": {"value_on_ten": 8.8}}}
    assert all(код != "imdb" for код, _, _ in оценки(д))

def test_показывается_только_существующее():
    assert оценки({}) == []
    assert оценки({"ratings_by_source": {}}) == []

def test_ноль_не_оценка():
    д = {"ratings_by_source": {"shikimori": {"value_on_ten": 0}}}
    assert оценки(д) == []

def test_порядок_устойчив():
    """Порядок задан контрактом, а не порядком ключей в данных."""
    д = {"imdb_rating": 6.0,
         "ratings_by_source": {"shikimori": {"value_on_ten": 7.0},
                               "kinopoisk": {"value_on_ten": 5.0}}}
    assert [к for к, _, _ in оценки(д)] == ["kp", "imdb", "shikimori"]
```

## Чего этот контракт не делает

Не меняет вёрстку, CSS, порядок секций и оформление. Возвращаемая форма та
же, что и сейчас, — меняется лишь состав списка. Не трогает поля Кинопоиска
и IMDb. Не выводит источник, которого у записи нет.

# Вторая передача: включение раскладки Animedia

Статус: **данные готовы и проверены; раскладка написана вами и закрыта
version-gate; выкладка артефакта — за вами**.

## Уточнение к первоначальной формулировке

Сначала я записал это как «у семейства animedia нет раскладки». Проверка
показала, что формулировка неточна, и точность здесь существенна.

Раскладка **есть**: `ВидАнимедиа` написан в ветке
`claude/templates-zona-animedia-visual-parity-005` и закрыт версией:

```python
ПЕРЕРАБОТАНО_С = {"zona": "1.2.0", "animedia": "1.2.0"}
```

`ВидАнимедиа` регистрируется только при включённой переработке. Гейт заведён
намеренно и по хорошей причине, описанной в вашем же
`version-gating-finding.md`: артефакт `lords-frontend.py` один на шесть
витрин, и выкладка файла ради Animedia при прежнем условии молча сменила бы
оформление боевой Zona, которая стоит на 1.1.0 и о смене не просила.

Выложенный сейчас артефакт — прежний: в нём
`ВИДЫ_1_1 = {"lords": ВидЛордс, "zona": ВидЗона}` и `ПЕРЕРАБОТАНО_С`
отсутствует. Поэтому на живых доменах `animedia.icu` и `animedia.space`
недоступны **все** карточки: 12 из 12 ссылок главной не открываются, а
`/title/` отдаёт 503.

`/` и `/catalog/` при этом работают: токены и раскладка списка у семейства
есть и в прежнем артефакте.

воспроизводится командой

```bash
python3 automation/host/nova-catalog-publish.py \
  --sites animedia-01,animedia-02 --staging-out /tmp/animedia-staging
```

## Что нужно от «Шаблонов»

Ничего писать не нужно — нужно выложить. Два шага, оба ваши:

1. выложить артефакт рендерера с `ПЕРЕРАБОТАНО_С` и `ВидАнимедиа`;
2. перевести манифесты `animedia-01` и `animedia-02` на `design_version:
   1.2.0` — по одной витрине, как и записано в вашем принципе; откат остаётся
   возвратом одного поля.

Zona при этом не затрагивается: она объявляет 1.1.0 и по гейту получает
прежнее оформление.

После этого публикация каталога — одна команда:

```bash
python3 automation/host/nova-catalog-publish.py --apply --sites animedia-01,animedia-02
```

Защита от преждевременной публикации стоит в самом инструменте: пока в
профиле витрины есть `production_заблокирована`, `--apply` отказывает с
указанием причины. Снимать её нужно тем же коммитом, что добавляет вид.

## Почему каталог не опубликован сейчас

Опубликовать 7 408 карточек в семейство без страницы тайтла значило бы
увеличить число ссылок в никуда с 3 999 до 7 408. Пустая витрина лучше
витрины, которая выглядит наполненной и не открывается.
