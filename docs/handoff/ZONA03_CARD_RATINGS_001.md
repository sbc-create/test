**Десять из пятнадцати** карточек с оценкой на первом экране держатся на

**Главное: сама витрина на другой своей странице делает это честно.** Страница
произведения печатает «IMDb 9.4 из 10, **5 голосов**», а карточка главной —
только «IMDb 9.4»:

```

           … <span class="zt__rn" aria-hidden="true">9.4</span></span>
страница:  IMDb 9.4 из 10, 5 голосов
```

То есть расхождение не с моим мнением, а между двумя поверхностями одного
сайта. Данные для честной подписи уже разобраны: `оценки_по_источникам`
(строка 882) кладёт в результат поле `голоса`, и карточка его просто не
использует.

Рядом с `ОЦЕНОК_НА_КАРТОЧКЕ` объявить порог числом:

```python
#: Ниже этого числа голосов оценка подписывается их количеством прямо на
#: карточке. Порог назван, а не подобран: при 5–9 голосах «IMDb 9.4» читается
#: как признание, которого нет, а при сотнях число голосов уже не меняет
#: смысла подписи и только удлиняет строку.
МАЛО_ГОЛОСОВ = 100
```

И стиль (одна строка рядом с `.zt__rn`):

```css
.zt__rv{font-size:11px;opacity:.65;margin-left:3px}
.zt__rv::before{content:"·"}
```

**Чего правка намеренно НЕ делает:** не прячет оценку, не меняет её значение,
не трогает порядок источников и не добавляет вторую строку — число голосов
печатается только там, где оно меняет смысл, и в подсказке, которая у карточки
уже есть.

**Отрицательный контроль, названный заранее:** у карточек с большим числом
голосов (`tom-i-cherri` — 7 482, `tipa-grand-tur-2` — 2 356, `kvest-vizhna` —
1 400) видимая подпись остаётся прежней «IMDb 9.0», без числа. Если число
появилось у всех — порог не работает и правку надо откатывать. Высота страницы
на телефоне остаётся около 8 141 px (±2 %): подпись не имеет права разложить
карточки в перенос.

## 4. Что по этому пилоту проверено отдельно и правкой НЕ закрывается

* **Воспроизведение.** Проверено новым инструментом
  `automation/local/playback-verify.py` с раздельными исходами: из четырнадцати
  карточек с `playable: false` **тринадцать воспроизводятся** (время основной
  дорожки растёт: 17–20 с за замер), и только `tom-i-cherri` остаётся в
  состоянии «источник ответил, показ не идёт» — проверено дважды, 50 и 60
  секунд. Поэтому **фильтровать полку по `playable` нельзя**: это убрало бы
  тринадцать рабочих карточек. Запись о недостоверности поля — MOD-97.
* **Крупные постеры.** 5 изображений из 37 отдаются вдвое крупнее показа
  (500×750 в слот 184 px на компьютере и 147 px на телефоне) — это MOD-96,
  общий для сети, и он ждёт ответа о возможностях CDN постеров.
* **Повторы и пустые полки.** На этой главной их нет: повторов между полками 0,
  карточек без изображения 0, пустых полок нет.
