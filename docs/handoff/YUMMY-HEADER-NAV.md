# Handoff: маршруты витрины в глобальной шапке YummyAnime

**Кому:** владельцу приложения витрины (`yummyani/web`).
**От кого:** слой шаблонов Site Factory (семейство `yummy`).
**Статус:** маршруты работают публично, пункты меню добавлены посредником;
нужна правка в модуле-владельце, чтобы посредник перестал быть нужен.

## Что не так

Витрина отдаёт четыре раздела, которых нет в её собственном меню:

| маршрут | что показывает | код ответа |
| --- | --- | --- |
| `/new/` | новые серии и свежие поступления | 200 |
| `/top/` | Топ-100 по внешним оценкам с указанием провайдера | 200 |
| `/collections/` | подборки и актуальное | 200 |
| `/schedule/` | расписание, онгоинги и анонсы | 200 |

Раздел, до которого нельзя дойти по меню, для посетителя не существует, а для
краулера — существует, но без входящих ссылок. Это не косметика: именно так
рабочие маршруты годами выглядят «нереализованными».

## Файл-владелец

```
src/components/layout/header-nav.tsx
```

* функция **`HeaderNav()`** (строка 227) — рисует `<nav class="portal-nav">`;
* константа **`ANIME_LINKS`** (строка 14) — выпадающий список «Аниме»;
* константа **`COMMUNITY_LINKS`** (строка 22) — выпадающий список «Сообщество».

Проверено на `/srv/sites/yummyani-staging/repo` (образ `yummyani/web:staging`,
рабочий каталог compose `/srv/sites/yummyani-staging/repo`).

## Нужная правка

Четыре пункта относятся к «Аниме», поэтому дешевле всего расширить
`ANIME_LINKS` — верстку и клавиатурную навигацию `NavDropdown` менять не надо.

```diff
 const ANIME_LINKS = [
   { href: "/catalog", label: "Каталог аниме" },
+  { href: "/new/", label: "Новинки" },
+  { href: "/collections/", label: "Подборки" },
   { href: "/catalog/ongoing", label: "Онгоинги" },
   { href: "/catalog/announcement", label: "Анонсы" },
   { href: "/catalog/schedule", label: "Расписание онгоингов" },
+  { href: "/schedule/", label: "Расписание и анонсы" },
   { href: "/catalog/add-anime", label: "Добавить аниме" },
 ] as const;
```

`/top/` отдельным пунктом первого уровня не нужен: в шапке уже есть «Топ-100»
на `/catalog/top`. Достаточно поменять адрес — обе страницы про одно и то же,
но `/top/` показывает провайдера и шкалу у каждой оценки:

```diff
-      <Link href="/catalog/top" className="portal-nav-link">
+      <Link href="/top/" className="portal-nav-link">
         <NavIcon>{icons.top}</NavIcon>
         <span className="portal-nav-text">Топ-100</span>
       </Link>
```

Правка требует пересборки образа `yummyani/web` и передеплоя трёх контейнеров
`yummyani-staging-web-{biz,org,site}`. Со стороны шаблонов ничего менять не
нужно: посредник видит свою метку и второй раз пункты не добавляет.

## Что сделано до этой правки

Пункты добавляются в проксируемую разметку рантаймом витрины
(`automation/host/yummy-frontend.py`, метод `_вставить_навигацию`), классами
самого приложения (`portal-nav-link`, `portal-nav-text`), с меткой
`data-sf-nav="1"`. Порядок пунктов задаётся профилем домена
(`нав_порядок` в `automation/host/yummy_variants.py`), текущий раздел
получает `aria-current="page"`.

Это временная мера, а не решение: она держится на разметке шапки. Пропадёт
класс `portal-nav` — пропадут и пункты. Поведение закреплено тестами
`tests/integration/test_yummy_runtime_contract.py::TestНавигация`.

После правки в модуле-владельце вставку можно снять: удалить вызов
`self._вставить_навигацию(тело)` в `_обогатить` и соответствующие тесты.
