# Передача: «Онгоинг» у мультсериала 1973 года

Кому: **линии шаблона семейств Animedia и AnimeGo** — адрес сессии назовёт
владелец или линия ячейки; поручение по РОЛИ здесь не годится по правилу
`docs/ACCEPTANCE_CHAIN.md`. Установленное дерево витрины —
`/srv/animedia-space`, профиль шаблона тот же у `animedia.icu`,
`animedia.space` и трёх витрин AnimeGo.

Выпуск не мой: доступ к репозиториям ячеек из моей сессии отклоняется защитой
рабочих копий (проверено, не предположено).

## 1. Что видно посетителю

`animedia.space/title/hitkliff/` — «Хитклифф», мультсериал **1984 года**:

```
Год 1984   Тип Аниме   Страна США, Франция, Канада
Статус Онгоинг    Доступно серий 43    Вышло серий 86
```

Сериал закончился сорок с лишним лет назад. Страница утверждает обратное — и
не формулировкой, а полем статуса.

## 2. Правило, по которому это получается, ИЗМЕРЕНО, а не угадано

Статус выводится из доли доступных серий. Проверено 21.10 (22:1xZ) на шести
работах с одинаково старым годом и разной доступностью:

| работа | год | доступно / вышло | статус на странице |
| --- | --- | --- | --- |
| `dyavolskiy-princ-enma-2` | 1973 | 2 из 25 | **Онгоинг** |
| `vokrug-sveta-s-villi-fogom` | 1981 | 2 из 26 | **Онгоинг** |
| `moguchie-orboty` | 1984 | 6 из 13 | **Онгоинг** |
| `3000-mil-v-poiskah-materi` | 1976 | 52 из 52 | Вышел |
| `3x3-glaza` | 1991 | 7 из 7 | Вышел |
| `1-2-ray` | 1990 | 2 из 2 | Вышел |

Нижние три — это контроль: при ПОЛНОЙ доступности тот же шаблон и тот же год
дают «Вышел». Значит дело не в годе и не в типе, а ровно в неполноте.

## 3. Сколько страниц это затрагивает

По доставленному снимку `animedia-02-details.json` (21.10 03:15:26Z, 8 691
запись):

| признак | записей |
| --- | --- |
| доступно меньше, чем вышло | **285** (3.3 %) |
| из них год ≤ 2024 | **182** |
| из них год ≤ 2015 | **133** |

Каталог аниме общий у пяти витрин (`animedia.icu`, `animedia.space`,
`animeg0.site`, `an1meg0.site`, `an1mego.site`), поэтому страниц с неверным
статусом в сети до пяти раз больше, чем записей. Точное число страниц зависит
от того, какие из них открыты для индексации, и здесь НЕ ИЗМЕРЕНО.

## 4. Почему нельзя просто «взять статус из данных»

В записи поставщика поля статуса НЕТ вовсе. Поля записи: `description`,
`description_source`, `external_ids`, `genres`, `id`, `imdb_rating`, `name`,
`original_name`, `playable`, `poster_source`, `poster_url`,
`ratings_by_source`, `ratings_source`, `seasons`, `sources`, `type`, `year`.
Поэтому витрина и считает статус сама — другого источника у неё нет.

Придумать статус запрещено правилом сети. Значит выбор между двумя
безопасными решениями, и оба не требуют новых данных:

* **A. Не утверждать то, чего не знаем.** Показывать «Доступно N из M» без
  строки статуса, когда год работы старше предыдущего. Поле «Статус»
  появляется только там, где неполнота правдоподобна (год текущий или
  предыдущий);
* **B. Назвать неполноту неполнотой.** Вместо «Онгоинг» писать «Доступно N из
  M серий» в том же месте, без утверждения о производстве.

Рекомендую **A**: она убирает ложное утверждение и ничего не добавляет
взамен. B тоже верна, но ставит в поле «Статус» то, что уже написано рядом.

## 5. Приёмка

1. `hitkliff` (1984, 43 из 86) строки «Статус Онгоинг» больше не несёт;
2. контроль не сломан: `3000-mil-v-poiskah-materi` (1976, 52 из 52) по-прежнему
   «Вышел»;
3. работа ТЕКУЩЕГО сезона с неполной доступностью статус сохраняет — иначе
   правка выключит признак вместо того, чтобы его исправить;
4. в структурированных данных страницы статус согласован с текстом;
5. число страниц с «Онгоинг» падает примерно на 133–182 записи каталога, а не
   до нуля.

## 6. Откат

Возврат прежнего правила вернёт «Онгоинг» на 285 записей — это цена отката, а
не его безопасность.
