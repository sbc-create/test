## Задача (в вашем формате)

* **site**: yummyani7.site, yummyani7.info, animedia.icu, yummyani.site
  (непаузированные; Lords/Zona — после снятия паузы, порядок тот же).
* **problem**: 3426 визитов из поиска за 14 суток приходят на страницы
  произведений без нашего текста; отбор кандидатов спрос не учитывает.
* **expected effect**: текст появляется там, где поиск уже приводит людей.
  Ожидание проверяемое, а не обещанное: см. сравнение ниже.
* **readiness criterion**: партия из 20 произведений верхнего спроса получила
  `verified` черновик и опубликована; текст виден в живом HTML страницы.
* **release**: штатный путь редактора, по одной витрине; независимые
  ограничения витрин и контрольные группы T075/T087 не затрагиваются (списки
  ниже пересечений с ними не имеют — проверьте перед выпуском).
* **verification**: `demand-vs-text.py --domain <витрина>` показывает «есть
  текст» у выпущенных; визиты из поиска на эти страницы сверяются через 14
  суток по той же выгрузке.

## Сравнение: группы страниц, а не два домена

Два домена сравнивать нельзя — у них разный спрос и разный возраст. Поэтому
**парное назначение внутри одной витрины**:

1. берём 40 произведений витрины с наибольшим спросом БЕЗ текста;
2. сортируем по визитам и разбиваем на 20 пар соседей (спрос внутри пары
   близкий);
3. в каждой паре один тайтл идёт в опыт (текст сейчас), второй — в контроль
   (текст после оценки). Назначение фиксируется ДО выпуска.

Так опыт и контроль имеют почти одинаковое распределение спроса, и разница не
объясняется «в опыт попали более популярные».

**Метрика**: визиты из поиска на страницы произведения (тайтл + его серии) за
14 суток, из `search_landing_pages` той же выгрузки.

**Оговорка, без которой вывод будет ложным**: выгрузка отдаёт верхние пути, а
не весь хвост (на yummyani.site — 52 пути). Для тайтлов со спросом ниже порога
видимости «ноль» означает «не попал в выгрузку», а не «нет визитов». Поэтому в
пары берутся только тайтлы с визитами ≥20 за 14 суток; остальные публикуются
без претензии на измерение.

## Критерии решения — назначены заранее

| исход | условие |
| --- | --- |
| **продолжать** | у опыта визиты из поиска выросли, и рост больше, чем у контроля, на ≥20 % от базы опыта |
| **расширять** | то же плюс выполнено на двух витринах независимо |
| **исправлять** | рост есть, но меньше контрольного: порядок отбора не вреден, но и не причина — менять не отбор, а содержание текста |
| **останавливать** | у опыта визиты упали, а у контроля нет |
| **данных недостаточно** | в выгрузке меньше 14 суток после выпуска, либо у более трети пар один из двух тайтлов выпал из выгрузки |

Срок оценки — не раньше **14 суток** после публикации последней пары (политика
минимального наблюдения), то есть при старте 19–20.10 оценка 03–04.11.

## Запись опыта — за вами

Реестр `config/experiments.json` свежее у вас (6 записей против 1 в моей
ветке), поэтому запись добавляю не я, чтобы не затереть ваши пять канареек.
Готовый блок:

```json
{
  "experiment_id": "exp-editor-demand-order",
  "site_id": "yummyani7.site",
  "hypothesis": "Текст на произведениях с уже измеренным поисковым спросом даёт больше поисковых визитов, чем текст в порядке каталога",
  "primary_metric": "search_landing_visits_14d",
  "applicability": "Произведения витрины с визитами из поиска >= 20 за 14 суток и без нашего текста",
  "scope_page_share": 0.01,
  "phase": "canary",
  "observation": {"days_elapsed": 0, "impressions": null, "primary_metric_delta": null},
  "verdict": null,
  "verdict_reason": "наблюдение не начато",
  "evidence": "docs/handoff/ARCHITECT_TO_SEO-003.md"
}
```

`scope_page_share` 0.01 — двадцать страниц опыта при каталоге витрины в
тысячи; порог канарейки (≤10 % страниц, ≤1 витрина на старте) соблюдён.
