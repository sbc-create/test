# Передача в Core: durable-состояние индексации

Документ отвечает на один вопрос: что именно SEO ждёт от Core, чтобы открытая
витрина перестала зависеть от того, какие файлы лежат на хосте.

## Что уже сделано на стороне SEO

| Что | Где |
| --- | --- |
| контракт потребителя и read-модель | `factory/indexing/state.py` |
| вычисление всех слоёв из одного снимка | `factory/indexing/layers.py` |
| ворота релиза по матрице | `factory/indexing/gate.py` |
| правила достоверности карты сайта | `factory/seo/sitemap_truth.py` |
| harness deploy/restart/rollback | `tests/unit/test_indexing_persistence_harness.py` |

SEO **читает** состояние. Функции, меняющей желаемое состояние, в этих модулях
нет, и её появление ловит отдельная проверка
(`test_у_seo_нет_способа_изменить_желаемое_состояние`).

## Что найдено в Core

Ветка `claude/fleet-core-003-r2` содержит:

* `contracts/control-plane/1.3.1/schemas/DesiredObservedState.json`;
* Action Ledger — `factory/site_engine/audit/ledger_*.py`.

Чего в ней **нет**:

* состояния индексации как предметной области;
* команд OPEN и CLOSE;
* поля `revision`/`generation`;
* `source_event_id`;
* понятия last-known-good;
* открытого PR.

`DesiredObservedState` объявляет `desired_state`, `observed_state`,
`drift_status` — и на этом останавливается. Для задачи «состояние переживает
любое число выкладок» этого недостаточно: без монотонной revision нельзя
отличить возврат старого релиза от нового решения владельца.

## Что требуется от Core

Один провайдер, один писатель. SEO подключится к нему заменой одной строки —
`CoreLedgerProvider` вместо `GitProfileProvider`.

**Read-модель на сайт** (SEO читает только это):

```
site_id                    идентификатор сайта
domain                     канонический домен
desired_state              OPEN | CLOSED
revision                   монотонно растущее целое
updated_at                 UTC ISO 8601
source_event_id            запись Action Ledger, породившая состояние
last_known_good_revision   последняя подтверждённая revision
```

**Требования к поведению:**

1. Сайт без зарегистрированного состояния — `CLOSED`. Не ошибка, а решение с
   основанием «решения об индексации не принимали».
2. OPEN и CLOSE — отдельные owner-команды через Action Ledger. Deploy, restart,
   rollback, CI, обновление шаблона и генерация карты сайта желаемое состояние
   **не меняют**.
3. Повтор команды идемпотентен: та же revision, тот же результат.
4. Снимок отдаётся целиком, одной revision на весь флот. Частичная выдача
   означает возможность опубликовать смешанное состояние.
5. Старая revision не переписывает новую. Возврат файлов прежней выкладки не
   возвращает прежнее решение.
6. При недоступности реестра провайдер обязан **сообщить об отказе**, а не
   вернуть пустой или предположительный ответ. SEO в этом случае берёт
   подтверждённый снимок и блокирует релиз, не трогая живое состояние.

**Чего Core делать не должен:** отдавать SEO mutation endpoint. Второй писатель
означает два ответа на вопрос «открыт ли сайт».

## Как подключение будет проверено

`tests/unit/test_indexing_persistence_harness.py` уже содержит сценарии A, B, C
и D на фикстурах. После появления провайдера те же сценарии прогоняются против
него без изменения самих проверок: harness работает через интерфейс, а не через
конкретную привязку.

## Отдельная передача: генератор карты сайта

Дефекты `lastmod` и `images.xml` (см. `SITEMAP-TRUTH-AUDIT.md`) исправляются не
здесь. Генератор живёт в `github.com/sbc-create/yummyani`,
`src/lib/seo/sitemap.ts`; на хосте он развёрнут по пути
`/srv/sites/yummyani-staging/repo` — это production-путь, и источником истины
он не является.

Требуется в том репозитории:

1. `seasons` и `episodes` перестают получать общую константу; дата берётся из
   события публикации или изменения, а неизвестная — пропускается.
2. Исключение карточки из `images.xml` сопровождается записанной причиной.
3. `/catalog/schedule` либо убирается из карты, либо перестаёт отдавать
   `noindex` — сейчас он делает и то и другое.

Правила уже выражены исполняемо в `factory/seo/sitemap_truth.py`: после правки
генератора те же проверки подтвердят результат.
