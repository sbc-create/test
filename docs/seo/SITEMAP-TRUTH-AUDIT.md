# Достоверность карты сайта yummyani.site

Замер 2026-09-16, только чтение публичного адреса. Ни одной записи в
production. Открытая витрина одна — `yummyani.site`; остальные восемь закрыты, и
их карты в этой работе не трогались.

## Что измерено

| Шард | URL | с `lastmod` | уникальных дат | самая частая дата |
| --- | ---: | ---: | ---: | --- |
| `static` | 19 | 19 | 10 | `2026-08-21T00:00:00.000Z` ×10 |
| `titles` | 7299 | 7299 | 6560 | `2026-09-04T08:00:52.000Z` ×475 |
| `seasons` | 30 | 30 | **1** | `2026-08-21T00:00:00.000Z` ×30 |
| `episodes` | 3449 | 3449 | **1** | `2026-08-21T00:00:00.000Z` ×3449 |
| `images` | 7296 | 7296 | 6560 | `2026-09-04T08:00:52.000Z` ×473 |

Все пять шардов отдают 200.

## Дефект 1: массовая заглушка вместо даты изменения

`30 + 3449 = 3479` адресов сезонов и эпизодов несут одно значение
`2026-08-21T00:00:00.000Z`. Это же значение стоит в `lastmod` самого индекса
карты — то есть перед нами время сборки, а не изменения содержания.

Почему это важнее, чем кажется. Поле `lastmod` существует ради одного вопроса:
что изменилось с прошлого обхода. Ответ «всё изменилось одновременно, в момент
сборки» не является ответом. Робот, которому соврали в одном шарде, перестаёт
доверять полю целиком — и тогда честные 6560 уникальных дат в `titles` тоже
перестают работать. Один неверный шард обесценивает достоверные.

**Карта происхождения даты.**

| Поверхность | Сейчас | Должно быть |
| --- | --- | --- |
| `static` | смешанно: 10 из 19 — дата сборки | дата публикации или значимой правки страницы |
| `titles` | 6560 уникальных — похоже на реальное обновление карточки | `content_updated_at` карточки |
| `seasons` | одна константа на все 30 | дата появления или изменения сезона; неизвестна — пропустить |
| `episodes` | одна константа на все 3449 | дата публикации эпизода; неизвестна — пропустить |
| `images` | наследует дату карточки | дата изменения изображения или карточки |

Требование «у каждой страницы своя дата» здесь **не** ставится: одинаковые даты
законны, когда за ними стоит одно и то же подтверждённое событие. Запрещено
другое — брать дату из времени процесса.

## Дефект 2: молчаливое исключение трёх карточек

`images.xml` содержит 7296 записей при 7299 карточках в `titles.xml`. Разбор
показал ровно три страницы без изображения:

* `/anime/bessmertie-obitel-bessmertnyh-tayyuan`
* `/anime/letopis-opustoshennogo-boga-gora-linlun-serial`
* `/anime/strana-desyati-tysyach-chudes-6`

Все три отдают 200, но постера у них нет: `og:image` откатывается на общий
`https://yummyani.site/opengraph-image`, а единственные `<img>` на странице —
логотип и счётчик. **Исключение обоснованное.**

Дописывать три записи ради ровной цифры нельзя: выдуманное изображение хуже
отсутствующего. Недостаёт не записей, а причины — сейчас она нигде не
зафиксирована, и со стороны потеря неотличима от ошибки генератора.

**Состояние покрытия.**

| Величина | Значение |
| --- | ---: |
| всего опубликованных карточек | 7299 |
| источник изображения доступен | 7296 |
| пригодных (`eligible`) | 7296 |
| включено | 7296 |
| исключено с причиной | 3 |
| исключено молча | **3 → 0 после фиксации причины** |
| покрытие пригодных | 100 % |

**Качество включённых.** Все 7296 — `https`, единственный хост
`poster.cdnvideohub.com`, ни одной заглушки, ни одного пустого адреса. Выборка
25 записей: 0 битых, 0 редиректов, 0 чужих сущностей (UUID из карты
присутствует на своей же странице). Совпадение по slug здесь непригодно как
проверка — адреса построены на UUID.

## Дефект 3: адрес в карте с `noindex`

`https://yummyani.site/catalog/schedule` объявлен в `static.xml` и при этом
отдаёт `noindex`. Карта говорит «проиндексируй», страница — «не индексируй».
Робот выберет страницу, а карта останется утверждением, которому нельзя верить.

Проверены все 19 статических адресов: нарушение одно, остальные 18 отдают 200
без `noindex`.

## Структура: нарушений нет

10 797 адресов (`static + titles + seasons + episodes`):

```
схема          https        10797/10797
хост           yummyani.site 10797/10797
с параметрами  0
дублей         0
служебных      0
пределы        каждый шард < 50 000 URL и < 50 МБ (максимум 1,39 МБ)
```

Выборка 32 адресов по всем шардам: 200, self-canonical, без редиректов;
единственное нарушение — `/catalog/schedule` выше.

## Кому принадлежит исправление

Генератор карты находится **не в этом репозитории**. Он живёт в приложении
витрины — `github.com/sbc-create/yummyani`, выложенном на хосте по пути
`/srv/sites/yummyani-staging/repo`, модуль `src/lib/seo/sitemap.ts`.

Поэтому здесь сделано то, чем владеет SEO: правила достоверности и ворота
релиза (`factory/seo/sitemap_truth.py`, 25 проверок). Релиз, чья карта нарушает
правила, не выкладывается. Сама правка генератора — передача в репозиторий
приложения; см. `docs/seo/CORE-HANDOFF-PERSISTENT-INDEXING.md`.
