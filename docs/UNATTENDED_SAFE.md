# Профиль UNATTENDED_SAFE

Постоянный режим работы фабрики: обычная разработка идёт без подтверждений,
обязательные стоп-сигналы остаются на месте. Профиль включён для всех сессий
этого репозитория — он задан в основном `.claude/settings.json`, а не в
локальном файле сессии.

## Где живёт решение

| Слой | Файл | Что делает |
| --- | --- | --- |
| Запреты фабрики | `.claude/hooks/guard_rules.py` | `deny` по G-* правилам. Вердикт окончателен. |
| Запреты оператора | `seo_operator/guardrails.py` | `BLOCKED_PATTERNS`, production-поверхности. |
| Профиль | `seo_operator/unattended.py` | Умеет **только** `allow`. Ни одного запрета не отменяет. |
| Хуки | `.claude/hooks/guard_bash.py`, `guard_write.py`, `seo_operator/hookguard.py` | Отдают решение Claude Code. |
| Матрица | `tests/unit/test_permission_matrix.py` | Проверяет цепочку целиком, а не отдельные правила. |

Порядок вычисления: `deny` (любой слой) → `ask` (стоп-сигнал или production без
авторизации) → `allow` (профиль) → иначе решают обычные permission rules, то
есть подтверждение запрашивается.

## Как разбирается команда

Разбор синтаксический, а не по подстроке:

1. команда режется на сегменты по `&&`, `||`, `;`, `|` с учётом кавычек;
2. у сегмента снимаются перенаправления (`2>&1`, `>out.log`, `&>/dev/null`, `< in`);
3. снимаются присваивания и обёртки: `VAR=1`, `env FOO=2`, `timeout 300`, `nice`, `stdbuf`, `nohup`;
4. остаток классифицируется по первой программе.

Разрешение выдаётся, только если рутинен **каждый** сегмент. Один непонятный
сегмент снимает разрешение со всей команды: безопасная команда не ручается за
то, что к ней приписали через `&&`.

Поэтому `git status; timeout 300 git push origin claude/... 2>&1 | tail -3`
выполняется без подтверждения, а `git status && /usr/local/bin/unknown` — нет.

## Что выполняется автономно

- чтение, поиск, анализ; создание и правка любого файла внутри репозитория;
- сборка, тесты, линтеры: `pytest`, `ruff`, `mypy`, `npm`/`pnpm`/`yarn`, `npx`,
  Playwright, `tsc`, `eslint`, `php`, `composer`, `docker`, `make`;
- установка зависимостей проекта (`npm ci`, `pip install -r`, `composer install`, …);
- команды фабрики, кроме выката и отката вне staging;
- `git status/diff/log/show/fetch/add/commit/branch/checkout/switch/merge/rebase/cherry-pick/revert/tag`;
- создание рабочих веток и обычный `git push` **только** в ветку `claude/*`;
- HTTP к стенду `127.0.0.1` и к хостам из `inventory/network-allowlist.yaml`;
- `ssh`/`scp`/`rsync`/`ansible` — только к целям из `inventory/ssh-hosts.yaml`;
- DNS — только по зонам из `inventory/dns-zones.yaml`.

Три последних пункта сейчас не дают ничего: все три инвентаря пусты, потому что
хосты, зоны и контракты интеграций не переданы. Пустая запись означает
`BLOCKED_INPUT`, а не «разрешено всё».

## Что по-прежнему останавливает работу

Всегда запрещено (`deny`, любой слой):

- `git push --force`, `git push -f`, `--force-with-lease`, `+refs/`;
- переписывание истории: `reset --hard`, `filter-branch`, интерактивный rebase;
- удаление веток (`branch -D`, push с `--delete` и с рефспеком `:ref`);
- прямой push в `main`/`master`;
- удаление серверов, баз, ролей, DNS-зон, бэкапов и самих сайтов;
- вывод, копирование и публикация секретов; чтение `.env`, `secrets/`, ключей;
- подключение к хостам вне inventory;
- оплата услуг, покупка и перенос доменов;
- отключение защиты: `--dangerously-skip-permissions`, `bypassPermissions`,
  `--no-verify`, удаление и снятие исполняемости с `.claude/hooks/`.

Требует подтверждения человека (`ask`):

- `factory deploy` и `factory rollback` вне `--environment staging`;
- любая команда с `--environment production`;
- `kubectl apply/delete/rollout`, `terraform apply`;
- всё, что профиль не опознал.

## Как расширять

Новая рутинная программа добавляется в набор `RUNTIMES`/`READ_ONLY` профиля
**вместе со строкой в матрице** `tests/unit/test_permission_matrix.py`. Правило
без теста в матрице считается отсутствующим: матрица гоняет настоящую цепочку
хуков, поэтому ловит случай «правило есть, а хук его не отдаёт».

Ложное срабатывание защиты чинится в самой защите вместе с regression-тестом,
а не обходится. Так починены три случая этой сессии: `2>&1` разрывал команду на
сегменты, `env VAR=1 cmd` считался дампом окружения, `sed -n '1,50p' file`
считался записью в файл.
