## Команда

Перед запуском: убедиться, что по `yummyani.site` не идёт выпуск или публикация
(контейнер пересоздаётся, запросы в этот момент оборвутся).

```bash
WEB_SITE_IMAGE=yummyani/web:rel-944c932e76ff \
docker compose \
  -f /home/claude/wt-yummy-mail-biz/compose.staging.yaml \
  -f /home/claude/wt-portable-site-cell-01/automation/host/yummy-biz-indexing.override.yaml \
  -f /home/claude/wt-portable-site-cell-01/automation/host/yummy-overlays.override.yaml \
  -p yummyani-staging \
  up -d --no-deps web-site
```

Три файла и их порядок взяты не из предположения, а из метки
`com.docker.compose.project.config_files` работающего контейнера — то есть
ровно тот набор, которым витрина поднята сейчас. `--no-deps` оставляет базу,
Redis и nginx нетронутыми.

**Почему образ `rel-944c932e76ff`, а не `rel-095aecc7ca27`.** Оба дают 7 частей.
Первый работает на трёх витринах, включая индексируемую `yummyani.biz`; второй —
на одной. Чем они различаются между собой, я не измерял и поэтому выбираю
проверенный на большем числе витрин. Если у владельца есть причина
предпочесть `rel-095aecc7ca27`, замена значения переменной — единственное, что
меняется в команде.

Эталон для проверки 2 снят **20.10 в 09:40Z, до правки**, и лежит на этом узле

снять — проверка 2 тогда отпадает, а не превращается в зелёную. Снять заново
на другом домене: тот же вызов с `--snapshot`.

**Один немедленный отрицательный замер вердиктом не является.** Карта

## Чего эта правка НЕ чинит

**Даты серий.** На исправленном образе `lastmod` у серий не подставляется
неверно — его просто НЕТ. Измерено 20.10 на `yummyani.biz`: из 123 302 адресов
серий дату несут 290, то есть **123 012 адресов идут без `lastmod` вовсе**
(`episodes-3.xml` — 0 из 23 302). Это строго лучше, чем одна неверная дата на
100 % адресов, как сейчас у `.site`, но требование «`lastmod` равен дате выхода
серии» не выполнено ни на одной витрине семейства. Поле `airDate` у серии в
данных есть и не используется — это MOD-105, отдельная правка приложения.

**Полноту карты относительно каталога.** Что после пересоздания в карту попадут
ВСЕ серии каталога `.site`, здесь не доказано. Доказано другое: сейчас не
попадают, и данные для этого у домена есть. Сколько именно появится — проверяется
после правки сверкой с собственными страницами домена, тем же способом, что в
таблице выше. Сосед взят для диагностики, а не образцом.
