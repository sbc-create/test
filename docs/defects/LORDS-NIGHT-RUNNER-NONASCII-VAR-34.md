# LORDS-NIGHT-RUNNER-NONASCII-VAR-34

**Состояние:** закрыт — исправлено, покрыто исполняемой проверкой, self-test PASS
**Слой:** runner ночной выкладки (оболочка), не продуктовый код витрины
**Заведён:** 2026-09-08

## Что произошло

`/usr/local/sbin/lords-night-release` не запустился:

```
/usr/local/sbin/lords-night-release: line 25: СВОЙ=/usr/local/sbin/lords-night-release: No such file or directory
```

Production не затронут: ни одна витрина не переключалась, таймер обновления
остался `active`.

## Причина

В строке стояло `СВОЙ="$(readlink -f "$0")"`. Кириллица недопустима в имени
переменной shell, поэтому bash разбирает строку **не как присваивание**, а как
имя команды с аргументом — и сообщает, что такой команды нет.

`bash -n` этого не обнаружил и обнаружить не мог: синтаксически строка
безупречна, это корректный вызов команды с необычным именем. Разбор проходит,
исполнение — нет. Проверка разбора не заменяет проверку исполнения, и здесь
разница стоила ночи.

Ошибка была не единичной. Поиск по всем сценариям выкладки нашёл **17**
не-ASCII имён: `СВОЙ`, `итог`, `было`, `ширина`, `маршрут`, `код` в runner,
`ОСТАЛЬНЫЕ`, `итоги`, `свод`, `выложить`, `сайт` в дирижёре, `СВОЙ` в
launcher. Часть из них не успела выстрелить только потому, что до этих строк
дело не дошло.

## Исправление

Все имена переменных, функций и переменных цикла — ASCII. Русский остался там,
где он полезен и безопасен: в комментариях и в текстах сообщений. Голые
кириллические аргументы (`phase предполёт`) взяты в кавычки — bash их принимает,
но правило должно быть однозначным, иначе проверять его нечем.

Заодно закреплены `PATH` и локаль: под `env -i` окружения нет вовсе, и без этой
строки не находились ни `readlink`, ни `findmnt`, ни `mktemp`. Проверено
запуском под `env -i`, а не предположением.

## Проверка

`scripts/shell_ascii_check.py` — контролёр не-ASCII там, где shell ожидает
идентификатор или голое слово. Тело heredoc не проверяется: это данные другого
языка. Разбор посимвольный, потому что `#` внутри кавычек не начинает
комментарий, а `$(` открывает независимый разбор — в том числе **внутри** двойных
кавычек. Первая редакция контролёра этого не учитывала и объявляла нарушением
безупречную строку `v="$(cat "${f}" || echo "СЛОВО")"`; проверка на этот случай
теперь стоит в наборе.

`tests/unit/test_shell_ascii_identifiers.py` — 19 проверок. Первая предъявляет
контролёру ровно ту строку, что уронила выкладку, и требует её отвергнуть:
контролёр, молчащий на известном дефекте, хуже отсутствующего, потому что
создаёт уверенность.

`--self-test` у самого runner исполняет стартовую часть по-настоящему, ничего не
меняя в production: 30 проверок — собственный путь, отвержение неизвестного
аргумента кодом 2, создание всех трёх рабочих сценариев и `bash -n` каждого,
ASCII-имена, наличие семи путей, взятие блокировки и отказ второго захвата,
состав команды detached-юнита (настоящий `systemd-run` подменён записью
аргументов), параметризация дирижёра и сравнение состояния витрин до и после.

Выполнено фактически:

| проверка | результат |
| --- | --- |
| `bash -n` четырёх файлов | принят |
| ShellCheck 0.8.0, severity ≥ warning | код 0 на источниках и на собранном файле |
| `--self-test` из исходного места | `SELF_TEST=PASS`, exit 0 |
| `--self-test` из копии на исполняемом разделе | `SELF_TEST=PASS` |

| мокированный `systemd-run` | аргументы записаны, настоящий не вызван |
| защита noexec | условие срабатывает для `/run`, не срабатывает для `/usr/local/sbin` |
| ссылки витрин и таймер | не изменились ни в одном прогоне |
| `tests/unit` | см. отчёт этапа |

## Урок

Статический разбор ловит то, что нельзя разобрать, а не то, что нельзя
исполнить. Для второго нужен запуск — поэтому `--self-test` теперь часть
runner, а не приложение к нему.
