# Узел K2: весь необходимый комплект операций владельца — одним блоком

Всё, что требует root или решения владельца, собрано здесь. Остальное уже
сделано и проверено с управляющего узла.

Проверяемость: блок помечен `# host: k2-zomro-01`, источники его команд
проверены **на самом узле** инструментом
`automation/local/check-remote-block-sources.py` (отсутствующих 0).

## Что изменилось против первой редакции

| было | стало | почему |
| --- | --- | --- |
| `sudoers` писался сразу в `/etc/sudoers.d/`, потом проверялся | пишется во ВРЕМЕННЫЙ файл в `/root`, проверяется `visudo -c`, и только потом ставится | битый файл в `/etc/sudoers.d` ломает `sudo` целиком — проверять после установки поздно; временный файл внутри самого каталога тоже нельзя: он парсится наравне с остальными |
| запуск витрины останавливался до настройки nginx, если нет `publisher_id` | nginx настраивается и проверяется НЕЗАВИСИМО; служба не стартует, и это сказано отдельно | маршрут домена к плееру отношения не имеет; до запуска домен честно отвечает 502, DNS на узел всё равно не переведён |
| регулярного обновления каталога не было вовсе | есть цепочка «издатель → доставка → корневой таймер узла» | перенесённый снимок стареет; без цепочки витрины застыли бы на дне переноса |

## Блок

```bash
# host: k2-zomro-01
set -euo pipefail

# --- 1. Зависимости и каталоги ------------------------------------------
apt-get update
apt-get install -y nginx certbot python3-certbot-nginx python3-venv
install -d -m 0755 /var/www/certbot

# --- 2. Предел журналу СРАЗУ (на основном узле его отсутствие дало 4 ГиБ)
install -d -m 0755 /etc/systemd/journald.conf.d
printf '[Journal]\nSystemMaxUse=512M\nSystemMaxFileSize=64M\n' > /etc/systemd/journald.conf.d/50-size-cap.conf
systemctl restart systemd-journald

# --- 3. Учётные записи и каталоги восьми ячеек ---------------------------
# Код — 2775 с группой витрины (выкладку делает k2deploy), данные — 0750 без
# записи для группы: постоянные данные принадлежат только самой витрине.
for acc in lordfilm-group lordfilm-spb-ru lordfilm-msk-ru lordserial-su lordserial-group lordserial-spb-ru lordserial-msk-ru lordserial-net-ru; do
  id -u "$acc" >/dev/null 2>&1 || useradd --system --home-dir "/srv/$acc" --shell /usr/sbin/nologin "$acc"
  install -d -m 2775 -o "$acc" -g "$acc" "/srv/$acc"
  install -d -m 0750 -o "$acc" -g "$acc" "/srv/$acc/data"
  usermod -aG "$acc" k2deploy
done

# --- 4. Юниты ячеек и каркас nginx: ставим, ничего не включаем -----------
install -m 0644 -o root -g root /home/k2deploy/stage/units/nova-*.service /etc/systemd/system/
install -d -m 0755 /etc/nginx/cells /etc/nginx/lords
install -m 0644 /home/k2deploy/stage/nginx/site-cells-upstreams.conf /etc/nginx/conf.d/
grep -q 'include /etc/nginx/lords/\*.conf;' /etc/nginx/nginx.conf || \
  sed -i 's|include /etc/nginx/conf.d/\*.conf;|include /etc/nginx/conf.d/*.conf;\n\tinclude /etc/nginx/lords/*.conf;|' /etc/nginx/nginx.conf
systemctl daemon-reload

# --- 5. sudoers: проверка ВО ВРЕМЕННОМ файле, установка только после неё --
# Временный файл НЕ в /etc/sudoers.d: всё, что там лежит, парсится сразу.
tmp_sudoers="$(mktemp /root/k2deploy-cells.XXXXXX)"
cat > "$tmp_sudoers" <<'SUDOERS'
k2deploy ALL=(root) NOPASSWD: /usr/sbin/nginx -t
k2deploy ALL=(root) NOPASSWD: /usr/bin/systemctl reload nginx
k2deploy ALL=(root) NOPASSWD: /usr/bin/systemctl restart nova-lordfilm-group.service, /usr/bin/systemctl restart nova-lordfilm-spb-ru.service, /usr/bin/systemctl restart nova-lordfilm-msk-ru.service, /usr/bin/systemctl restart nova-lordserial-su.service, /usr/bin/systemctl restart nova-lordserial-group.service, /usr/bin/systemctl restart nova-lordserial-spb-ru.service, /usr/bin/systemctl restart nova-lordserial-msk-ru.service, /usr/bin/systemctl restart nova-lordserial-net-ru.service
k2deploy ALL=(root) NOPASSWD: /usr/bin/systemctl status nova-lord*, /usr/bin/systemctl is-active nova-lord*
SUDOERS
chmod 0440 "$tmp_sudoers"
visudo -c -f "$tmp_sudoers"
install -m 0440 -o root -g root "$tmp_sudoers" /etc/sudoers.d/k2deploy-cells
rm -f "$tmp_sudoers"
visudo -c

# --- 6. Регулярное обновление каталога: приёмщик и таймер ----------------
install -m 0755 -o root -g root /home/k2deploy/stage/k2-catalog-apply.sh /usr/local/sbin/k2-catalog-apply.sh
install -m 0644 -o root -g root /home/k2deploy/stage/units/k2-catalog-apply.service /etc/systemd/system/
install -m 0644 -o root -g root /home/k2deploy/stage/units/k2-catalog-apply.timer /etc/systemd/system/
install -d -m 0755 -o k2deploy -g k2deploy /home/k2deploy/stage/incoming
systemctl daemon-reload
systemctl enable --now k2-catalog-apply.timer
systemctl list-timers k2-catalog-apply.timer --no-pager

# --- 7. Каталог для файлов плеера (значения — вход владельца) ------------
install -d -m 0755 -o k2deploy -g k2deploy /home/k2deploy/stage/player

# --- 8. Первая витрина: маршрут сейчас, служба — когда будет publisher_id -
/home/k2deploy/stage/k2-launch-site.sh lords-10 --dry-run
/home/k2deploy/stage/k2-launch-site.sh lords-10 --nginx-only

# --- 9. Что получилось ---------------------------------------------------
getent group lordfilm-group
ls -ld /srv/lordfilm-group /srv/lordfilm-group/data
ls /etc/systemd/system/nova-lord*.service | wc -l
nginx -v
systemctl is-enabled k2-catalog-apply.timer
journalctl --disk-usage
df -h /
```

**Ожидаемый результат.** `visudo -c -f` печатает `parsed OK` ДО установки;
`ls … | wc -l` даёт **16** юнитов; `nginx -t` внутри запуска —
`syntax is ok` / `test is successful`; таймер `k2-catalog-apply.timer`
становится `enabled` и показывает ближайший запуск; журнал не больше 512 МиБ.

**Условия остановки.** `visudo -c -f` не сказал `parsed OK` — временный файл
удалить и прислать вывод: в `/etc/sudoers.d` при этом ничего не попало, `sudo`
цел. `nginx -t` не прошёл — конфигурация витрины снимается самим сценарием,
перезагрузка не делается. `useradd` отказал на существующем имени — проверить,
не занято ли оно чужой службой.

## Второй блок: управляющий узел (claude-control-01)

Половина цепочки обновления живёт здесь — снимок поставщика и издатель. Без
этого блока доставка остаётся ручной, а витрины тихо стоят на снимке дня
переноса: сайт отвечает 200 и со старым каталогом, и узнать об этом неоткуда.

```bash
# Выполняется от root на claude-control-01.
install -m 0644 -o root -g root /home/claude/wt-nova-publish-memory-02/automation/host/k2-catalog-deliver.service /etc/systemd/system/
install -m 0644 -o root -g root /home/claude/wt-nova-publish-memory-02/automation/host/k2-catalog-deliver.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now k2-catalog-deliver.timer
systemctl list-timers k2-catalog-deliver.timer --no-pager
```

**Ожидаемый результат.** Таймер `enabled`, ближайший запуск — 05:20 UTC
(в стороне от суточного прогона производителя в 03:3x, чтобы доставлять свежий
снимок, а не вчерашний). Служба работает от учётной записи `claude`: root ей не
нужен, она пишет только в домашний каталог `k2deploy` на узле, а установку с
правами витрины делает корневой приёмщик ТАМ.

**Пределы в юните поставлены по измерению:** `MemoryMax=3G` при измеренном пике
издателя 1,197 ГиБ, `TimeoutStartSec=2700` при измеренных 281 секунде на восемь
витрин.

**Условие остановки.** Если прогон упадёт по `MemoryMax` — не поднимать предел
первым делом: сначала посмотреть, не вырос ли снимок поставщика, потому что
издатель держит его в памяти целиком.

## Проверено, что обновление пойдёт штатно после подготовки

Установка каталога проверена НЕ только разбором комплекта, но и настоящим
выполнением — в отдельном каталоге, где каталог данных принадлежит
запускающему. Приёмщик спрашивает не «я root», а «можно ли писать в каталог
данных»: в производстве это одно и то же (0750 и владелец — витрина), зато
проверяемо целиком.

| проверка на узле | результат |
| --- | --- |
| комплект установлен в пустой каталог данных | **OK** — файлов было 0, стало 2 |
| режим и владелец установленного файла | **OK** — `640 k2deploy:k2deploy` |
| входящий комплект убран после установки | **OK** |
| повтор без нового комплекта ничего не ставит | **OK** — «установлено витрин: 0» |
| прежний снимок сохранён как `.prev` | **OK** — метка `previous` нашлась именно в `.prev` |
| порченый комплект отвергнут, установленное цело | **OK** — сумма файла не изменилась, входящее осталось |

Итог: **6 проверок из 6**. Вместе с разбором комплекта (5 случаев из 5) и
доставкой восьми наборов (приёмщик принял 8 из 8) цепочка проверена на всех
звеньях, кроме одного — корневого таймера узла, который ставится блоком выше.

## Три решения, которые остаются за владельцем

| что | почему именно владелец | что будет дальше |
| --- | --- | --- |
| **publisher_id восьми доменов** — новый номер или явное разделение существующего (например `10238`, который уже обслуживает четыре домена) | значение приходит от поставщика; подставлять чужой или выдуманный запрещено правилом и заданием, и витрина сама не стартует без него | кладу `player.json`, запускаю витрину, измеряю RSS, подтверждаю вместимость |
| **A-записи восьми доменов на `145.63.129.86`** в Cloudflare | DNS вне manifest агент не меняет | внешняя проверка по домену и заголовкам |
| **certbot** по каждому домену после DNS и установка `*-tls.conf` | root и выпуск сертификата | перевод на 443 и проверка HTTPS |

## Регулярное обновление каталога — как это устроено

```
управляющий узел                                  узел K2
──────────────────                                ────────
совместимый издатель  ──> комплект + SHA256SUMS ──> /home/k2deploy/stage/incoming/<site>/
(из ЖИВОГО кода,                сверка на узле          │
 восемь витрин вставкой)                                │ таймер k2-catalog-apply (root, 15 мин)
                                                        ▼
                                         проверка комплекта → /srv/<учётка>/data (0640, владелец — витрина)
```

Права при этом не ослабляются: `k2deploy` кладёт файлы только в свой домашний
каталог, а в данные витрины пишет корневой приёмщик. Он отказывает, если
комплект неполон, суммы не сходятся, `site` внутри файла не тот, элементов
меньше порога или ревизии каталога и sidecar разошлись; при отказе входящий
комплект остаётся нетронутым. Установка атомарна (`mv` в том же разделе),
прежний снимок сохраняется как `.prev`.

Команда доставки с управляющего узла (выполняю я, root не нужен):

```bash
cd /home/claude/wt-nova-publish-memory-02
bash automation/local/k2-deliver-catalog.sh lords-10 lords-13
```
