## Блокеры, измеренные по следам службы, а не предположенные

Штатный публикатор (`seo-tech-publish.timer`, срабатывает каждые ~5 минут)
отказывается с одной и той же причиной — в его собственном журнале
`var/seo-tech/publish.jsonl`:

```
08:47:15Z  голова ветки выпуска aceb5cccb154 не равна живому d1627b4b7eaa
08:52:06Z  то же
08:57:11Z  то же
```

То есть **первый блокер — не файлы, а база**: ветка выпуска стоит на
`aceb5cccb154`, а живой выпуск — `d1627b4b7eaa`. Пока они не равны,
публикатор не возьмёт ни одну задачу этой витрины, включая T175.

**Почему база отстала — установлено:** у коммита `aceb5cccb154` НЕ БЫЛО ни
одного прогона CI (`actions/runs?head_sha=aceb5cccb154` → `total_count: 0`),
хотя рабочий поток запускается на `push` в `claude/**` без фильтров по путям.
Коммит отправлен 2026-10-15 20:30:49Z, последний прогон на ветке — 20:20:03Z
на прежнем коммите. Триггер фабрики берёт «последний успешный CI», поэтому
видел только `d1627b4b7eaa` и отвечал «нечего выкладывать».

**Условие владельца про диапазон проверено** (через GitHub API, без git в
клоне): `d1627b4b7eaa...aceb5cccb154` — **один коммит, один файл**:
`TEMPLATE-CANDIDATES.md`, `+42 / -0`, статус `modified`. Это документация, и
ничего кроме неё в диапазоне нет.

## Почему остаток не выполняется из этой сессии

Триггер отказывает по коду фабрики, а не по хуку:

```
ворота защищённых данных не прочитаны (RegistryError: lords-03: repo.path
уводит за пределы /home/claude/wt-nova-publish-memory-02:
/home/claude/wt-portable-site-cell-01/var/site-repos/1lordserials1-online);
заявка не подаётся, пока состояние данных неизвестно
```

Клон витрины физически лежит внутри `/home/claude/wt-portable-site-cell-01`.
Для моей сессии это чужой корень, и фабрика отказывается читать ворота
защищённых данных вне корня — правильно отказывается: иначе выпуск шёл бы с
непрочитанным состоянием данных сайта. Обходить это я не буду ни обёрткой, ни
через другую сессию.
