# Инциденты

## Немедленные действия

1. Зафиксировать состояние: `python3 -m factory status --site <id> --json`,
   последний результат задания в `artifacts/jobs/<id>/`, хвост `var/audit/audit.jsonl`.
2. Остановить распространение: при затронутом production — откат (`docs/ROLLBACK.md`).
3. Только потом разбираться в причинах.

## Отчёт

Файл `docs/incidents/<YYYY-MM-DD>-<site_id>-<slug>.md`, разделы:

1. **Что произошло** — точный статус (`DEPLOY_FAILED`, `ROLLED_BACK`, `QUARANTINED`,
   `BLOCKED_SEO`, …), job ID, site ID, commit фабрики, target, время начала и обнаружения.
2. **Влияние** — какие URL, была ли публикация, была ли утечка данных между сайтами.
3. **Что фактически проверялось** — команды, их exit code, пути к артефактам.
4. **Root cause** — техническая. «Флак» и «помог повторный запуск» причиной не являются.
5. **Что предотвратит повтор** — конкретный тест, гейт или правило, добавленные в том же изменении.
6. **Данные** — делался ли бэкап, подтверждено ли восстановление, целостность БД.

Секреты в отчёт не попадают: весь вывод проходит `factory.redaction`.

## Карантин заданий

Задание, исчерпавшее retry, уходит в `queue/quarantine` с причиной. Разбор:

```bash
cat queue/quarantine/<job_id>.json         # причина и стадия
python3 -m factory report --site <id>      # артефакты проверок
```

Ошибки конфигурации, лицензии, прав и авторизации не ретраятся: повтор не создаёт
отсутствующий вход. Их лечит только исправление пакета или inventory.
