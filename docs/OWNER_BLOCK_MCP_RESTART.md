## Действия

На **claude-control-01** (этот же сервер, где лежит рабочее дерево):

```bash
# 1. До: зафиксировать, что перезапускаем и что ничего не идёт
systemctl show -p MainPID,ActiveState,ExecMainStartTimestamp site-factory-mcp
tail -1 /home/claude/wt-portable-site-cell-01/var/editor-runs/gate.jsonl
# замок издателя: занят или свободен — проверяется ЗАХВАТОМ, а не датой файла
python3 - <<'EOF'
import fcntl, pathlib
п = pathlib.Path('/srv/sites/animedia/runtime/overlays/animedia.icu/.publish.lock')
f = open(п, 'r+')
try:
    fcntl.flock(f, fcntl.LOCK_EX | fcntl.LOCK_NB)
    print('замок СВОБОДЕН — публикации не идёт, перезапуск безопасен')
    fcntl.flock(f, fcntl.LOCK_UN)
except BlockingIOError:
    print('замок ЗАНЯТ — публикация идёт, перезапуск отложить')
EOF

# 2. Перечитать описание юнита и перезапустить
sudo systemctl daemon-reload
sudo systemctl restart site-factory-mcp

# 3. После: процесс новый и соответствует юниту
systemctl show -p MainPID,ActiveState,ExecMainStartTimestamp site-factory-mcp
tr '\\0' ' ' < /proc/$(systemctl show -p MainPID --value site-factory-mcp)/cmdline; echo
```

Ожидаемый результат шага 3: `ActiveState=active`, `MainPID` ОТЛИЧАЕТСЯ от
1499831, `ExecMainStartTimestamp` — сегодняшний, а командная строка процесса
совпадает с ДЕЙСТВУЮЩИМ `ExecStart`:

```
/usr/bin/python3 -m factory.qwen.mcp --http 127.0.0.1:9000
```

**ПОПРАВКА 08:45Z, и она важна, иначе вы прочитаете успех как провал.** Выше в
этом документе ранее стояло «в командной строке появляется `--read-only` (его
сейчас нет)». Это было **неверно**, и ошибку нашла линия ячейки. Проверено мной
по файлам юнита:

* базовый `/etc/systemd/system/site-factory-mcp.service` действительно несёт
  `ExecStart=… --read-only`;
* но дополнение `/etc/systemd/system/site-factory-mcp.service.d/10-write-mode.conf`
  **очищает** `ExecStart` (пустым значением) и задаёт запуск **без**
  `--read-only` — намеренно: в режиме только чтения мост не смог бы публиковать,
  а публикация описаний — его работа;
* живой процесс 1499831 этому дополнению **соответствует**.

Значит `--read-only` после перезапуска НЕ появится, и это правильно. Ждать его
— значит записать верный перезапуск как неудачу.

`daemon-reload` всё равно нужен: без него systemd запустит процесс по описанию,
которое держит в памяти с 12.10, и дополнения, изменённые позже, не применятся.

Ещё одно, что стоит знать заранее: `WorkingDirectory` службы —
`/home/claude/wt-portable-site-cell-01`. После перезапуска мост возьмёт код
ветки той рабочей копии, а не этой.

## Цена и риск

Перезапуск обрывает соединения моста на время старта (`RestartSec=5`). Сейчас
ни одна партия редактора не идёт, поэтому обрывать нечего; если запускать после
21:15Z, стоит повторить шаг 1 и убедиться, что `gate` отвечает `run: false`.
`Restart=on-failure` и `StartLimitBurst=5` на месте: неудачный старт systemd
повторит, а после пяти неудач остановится — это видно в `ActiveState`.
