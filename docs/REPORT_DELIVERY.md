## Что и когда уходит

| что | когда | юнит |
| --- | --- | --- |
| полный отчёт: короткая сводка + файл `.md` | 09:00 МСК (06:00 UTC) | `notify-daily.timer` → `notify@daily` |
| только ошибки, требующие вмешательства | проверка каждые 10 мин, круглосуточно | `notify-alerts.timer` → `notify@alerts` |
| почасовые сводки | **не отправляются**, только журнал `var/seo-regular/hourly/` | — |

Срочными считаются: критическая проблема сайта из последней проверки сети
(главная недоступна, canonical на чужой домен, индексация расходится с
состоянием, чужой счётчик), неполный запуск фонового редактора или его сбой,
снимок аналитики старше двух дней. Одна ошибка отправляется один раз; повторно —
только если она исчезла и появилась снова (`var/notify/sent-alerts.json`).
Неудачная отправка не помечается отправленной и повторяется на следующей проверке.

Если к 09:00 суточный отчёт не сформирован, приходит сообщение об этом, а не
тишина.

## Секрет

* `/etc/site-factory/secrets/telegram/bot_token` — root, 0600; вводится
  установщиком скрытым вводом (`read -s`), не попадает в историю оболочки,
  argv, журналы и репозиторий.
* `/etc/site-factory/secrets/telegram/chat_id` — подтверждённый владельцем чат.
* Служба получает оба через `LoadCredential`; код читает их из
  `$CREDENTIALS_DIRECTORY` и не печатает. Адрес запроса с токеном не выходит из
  функции вызова API (тест `test_token_never_reaches_state_files`).
* Сессия агента токена не получает: без `LoadCredential` команда отвечает
  «не настроено» (код 78).

## Подключение — два шага владельца

0. В Telegram: создать бота у @BotFather, со своего аккаунта написать боту `/start`.
1. `sudo bash /home/claude/wt-portable-site-cell-01/automation/host/install-notify.sh`
   — спросит токен скрытым вводом, поставит юниты, покажет чаты, написавшие
   боту (id, тип, имя). Сообщений не отправляет.
2. `sudo bash /home/claude/wt-portable-site-cell-01/automation/host/install-notify.sh --chat <chat_id>`
   — подтверждение СВОЕГО чата (только id из списка шага 1), включение отчёта и
   ошибок, тестовое сообщение и ответ Telegram на него.

## Проверка доставки

`var/notify/deliveries.jsonl` — каждая отправка с ответом Telegram (`ok`,
`message_id`, описание ошибки), без токена. Канал считается подключённым только
после принятого Telegram сообщения; суточный отчёт и почасовая сводка пишут
состояние канала по этому журналу, а не по наличию файлов.
