# Две ячейки AnimeGo: одна команда владельца на каждую

`an1mego.site` (animego-02) и `animeg0.site` (animego-03). Правка готова, прогон
CI на этих коммитах зелёный, установщик проверен и имеет откат. Остаётся одно
действие под root — оно описано здесь целиком: что поставит, что проверит и как
вернёт прежнюю версию при отказе.

## Почему именно команда владельца, а не очередь

Эти две ячейки живут по схеме «служба исполняет дерево `app/`», и их штатный путь
обновления — их собственный установщик `deploy/install.sh`. Он и раскладывал код
до сих пор. Каталог `app/` принадлежит учётной записи сайта, а установка требует
root (`systemctl`, `/etc/nginx`, права на файлы), поэтому сессия его выполнить не
может. Перевод этих ячеек на схему `releases/` + `current` — отдельная операция с
отдельной приёмкой, и ради правки текста её делать не нужно.

Проверено сухим прогоном очереди: `python3 -m factory cell trigger --site
animego-02` отвечает `BLOCKED_INPUT` — зелёный прогон лежит на ветке
`claude/an1mego-panels-01`, а исполнитель принимает только `main`,
`claude/extract-*` и `release/*`. То есть зелёный CI сам по себе этого пути не
открывает.

## Команды

```bash
sudo bash /home/claude/wt-portable-site-cell-01/var/site-repos/an1mego-site/deploy/install.sh
sudo bash /home/claude/wt-portable-site-cell-01/var/site-repos/animeg0-site/deploy/install.sh
```

Две команды, по одной на ячейку. Каждая меняет только свой сайт: ни DNS, ни
соседние сайты, ни publisher ID других домен она не трогает.

## Что именно поставит

| | an1mego.site | animeg0.site |
| --- | --- | --- |
| site_id | animego-02 | animego-03 |
| ветка | `claude/an1mego-panels-01` | `claude/animeg0-launch` |
| build_id ПОСЛЕ установки | `__BUILD_02__` | `__BUILD_03__` |
| build_id сейчас на сайте | `animego-02-2bad793aafb4` | `animego-03-017d8f6aea20` |
| порт витрины | 9150 | 9151 |
| служба | `nova-an1mego-site.service` | `nova-animeg0-site.service` |
| прогон CI на этом коммите | `__CI_02__` | `__CI_03__` |

Содержимое правки — две вещи, обе про то, что видит посетитель и обход:

1. **публичный текст без внутренних слов фабрики.** Из описаний разделов, подписи
   подвала, текста 404, пустых состояний каталога и подборок и из сообщений
   плеера убраны «витрина», «снимок каталога», «утверждённый снимок» и
   «провайдер». Смысл сохранён везде: сообщения плеера по-прежнему говорят, что
   именно не работает и что остальное на странице работает. Полезные пояснения не
   тронуты — часовой пояс, различие эфира и появления серии, причина
   недоступности конкретной серии;
2. **канонический адрес раздела.** `/movies/` объявлял каноническим
   `/movies/?type=movie`, `/series/` — `/series/?type=tv`: параметр подставлял сам
   маршрут, читатель его не просил, и страница объявляла дублем саму себя. Теперь
   canonical строится по запрошенному адресу.

Плюс перенос в проверки ячейки того, что у соседних ячеек уже работало:
доказательство «в чужие данные мы не писали» по владельцу файлов вместо побайтной
сверки каталога соседа, и названный пропуск вместо отказа, когда песочницу не
поднять по правам на `config/player.json`.

## Чего команда НЕ тронет

* **каталог данных** `/srv/<аккаунт>/data` — установщик пишет только в `app/`;
  снимки каталога, `site-data`, редакционные материалы и журналы остаются как есть;
* **настройку плеера.** `config/player.json` живёт вне git; установщик забирает
  действующий файл и исключает его из `rsync --delete`. Publisher ID обеих ячеек —
  10252, он объявлен в их пакетах и ниоткуда не заимствуется;
* **режим индексации** — состояние живёт в `/srv/sites/indexing/<домен>.json`,
  вне выпуска;
* **счётчик Метрики** — `113105751` у an1mego.site и `113105753` у animeg0.site,
  они заданы юнитами и правкой не затронуты;
* **соседние сайты и DNS.**

## Что проверит сама команда

1. `checks/manifest_and_entrypoint.py`, `checks/no_secrets.py`,
   `checks/ascii_shell_identifiers.py` — до любой записи;
2. `run.py --check --data-dir /srv/<аккаунт>/data` — полнота конфигурации,
   наличие и совпадение publisher ID, наличие снимка каталога. Ошибка здесь
   останавливает установку ДО первой записи;
3. после раскладки и `systemctl restart` — что порт отдаёт тот самый `build_id`,
   который объявляет репозиторий. Это ловит случай «код разложен, а процесс
   остался прежним»: именно поэтому в установщике `restart`, а не `enable --now`;
4. `/healthz` отвечает в течение 40 секунд.

## Как вернёт прежнюю версию при отказе

* **до первой записи** в `app/` создаётся снимок прежнего кода в
  `/srv/<аккаунт>/app.prev` (`cp -a`, один снимок, данные не копируются);
* если **build_id не совпал** или **`/healthz` не ответил** — установщик
  вызывает `restore_previous`: возвращает код из `app.prev`
  (`rsync -a --delete --exclude config/player.json`), возвращает владельца файлов,
  перезапускает службу и ждёт `/healthz` до 40 секунд. Исход печатается словами:
  «откат выполнен» либо «ОТКАТ НЕ ПОДТВЕРЖДЁН» с последними 30 строками журнала;
* удаление снимка идёт только по пути, который заканчивается на `/app.prev` —
  иначе установщик отказывается с кодом 2;
* если снимка нет (первая установка на пустой `app/`) — установщик говорит это
  прямо и код не трогает повторно.

Ручной откат, если он понадобится отдельно:

```bash
sudo rsync -a --delete --exclude config/player.json \
    /srv/an1mego-site/app.prev/ /srv/an1mego-site/app/
sudo chown -R an1mego-site:an1mego-site /srv/an1mego-site/app
sudo systemctl restart nova-an1mego-site.service
```

## Приёмка после установки

Выполняется с этой стороны, root не нужен:

```bash
python3 automation/local/public-acceptance.py an1mego.site animeg0.site
python3 automation/local/public-text-audit.py an1mego.site animeg0.site
python3 automation/local/sitemap-acceptance.py an1mego.site animeg0.site
python3 automation/local/player-idle-check.py https://an1mego.site/title/keyon/ 60
```

Ожидается: публичный `x-site-factory-build-id` равен установленному `build_id`;
в видимом тексте главной, каталога и подборок ни одного внутреннего слова;
`canonical` разделов — без параметров; карта сайта и её части 200, адресов 8069,
дублей 0; плеер без нажатия не пересоздаётся; publisher ID и счётчик Метрики те же.
