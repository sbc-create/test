# Недостающий вход владельца: publisher_id пяти новым доменам

Отдельный документ потому, что это ЕДИНСТВЕННЫЙ недостающий вход, который
держит запуск пятёрки, и смешивать его с операторскими шагами нельзя: те
выполняются правами, а этот — решением владельца.

## Что именно нужно

Пять чисел, по одному на домен. Ничего больше.

| домен | ячейка | куда попадёт значение |
| --- | --- | --- |
| lordserials1.cc | lords-18 | `/home/k2deploy/stage/player/lords-18-player.json` → выпуск витрины |
| lordserials1.info | lords-19 | `…/lords-19-player.json` |
| lordserials21.cc | lords-20 | `…/lords-20-player.json` |
| lordserials21.info | lords-21 | `…/lords-21-player.json` |
| lordserials21.mobi | lords-22 | `…/lords-22-player.json` |

Формат файла: `{"publisher_id":"<номер этого домена>","source_mode":"provider-id"}`,
режим 0640, владелец — учётная запись витрины. Значение приходит из Secret Hub
и в git не попадает.

## Чего нельзя и почему

Номер принадлежит КОНКРЕТНОМУ домену (D138/D177). Подставить 10454 (им живут
восемь витрин партии K2), 10373, 10368 или номер соседней витрины нельзя:
провайдер отдаёт источники по издателю, и чужой номер означал бы чужой
каталог воспроизведения на нашем домене. Пустое поле — это `BLOCKED_INPUT`, а
не разрешение подставить умолчание.

## Что из-за этого не работает, а что работает

**Не работает:** служба витрины не стартует вовсе — пусковая проверка
`run.py: check_player` отказывает кодом 78 («нет config/player.json: плеер без
publisher_id не заработает»), а `k2-launch-site.sh` доводит всё до службы и
выходит кодом 3. Это защита, и снимать её самовольно нельзя.

**Работает и проверено без номера** (измерено 25.10 на экземпляре, поднятом
из доставленного бандла на непубличном порту): семнадцать публичных маршрутов
отдают 200, каталог и разделы по 48 карточек, карточка произведения с девятью
постерами, поиск с `noindex`, мобильный viewport, `robots.txt` закрыт
полностью. Полки главной пусты по той же причине: `новинки_с_источником`
берёт только записи со `состояние_плеера == "playable"`, а это требует
publisher_id. То есть номер наполняет главную сам, без правок.

## Что произойдёт сразу после получения номеров

1. Пять файлов плеера на узле (шаг D.6 операторского блока).
2. По одной витрине: `bash /home/k2deploy/stage/k2-launch-site.sh lords-18` —
   он поднимет службу, дождётся `healthz`, прогреет и доложит RSS.
3. Фабрика догоняет узел: `python3 -m factory cell record-live --site
   lords-18,lords-19,lords-20,lords-21,lords-22`.
4. Остаётся то, что от номера не зависит: перевод DNS (пять A-записей),
   сертификаты (`k2-enable-tls.sh`), счётчики Метрики и проверка приёмки по
   пользовательским сценариям.

## Чем подтверждается, что ничего не подставлено

* в паспортах пяти ячеек поле `publisher.publisher_id` отсутствует, а
  примечание называет причину (`config/site-cells.json`);
* `publisher_id_expected` в `config/site.json` каждой витрины — `null`;
* приёмочная проверка каждой витрины падает ровно на этом: `activate-scenarios`
  → «lords-NN не объявляет publisher_id_expected … номер соседней витрины
  подставить нельзя (D138)»;
* таблица выпуска узла печатает по пятёрке остаточный блокер, а не «готово»:
  пустое ожидание само является блокером (MOD-197).
