# Контракт `seo-route-binding` — журнал изменений

Версионирование по SemVer, отдельно для схемы и для контракта.

* **major** — потребитель обязан измениться: убрано или переименовано поле,
  изменено машинное значение существующего, ужесточено обещание;
* **minor** — добавлено необязательное поле или новое значение перечисления,
  которого потребитель может не знать;
* **patch** — исправлена формулировка, не меняющая машинных значений.

Слово `latest` в ссылках на контракт запрещено. Контракт, на который
ссылаются словом «последний», нельзя ни закрепить, ни откатить.

Первый выпуск. Закрывает блокер, измеренный SEO: 159 записей очереди из 268

### Обещания, проверяемые при создании записи

* неустановленный и конфликтный вид не может нести вид — только `UNKNOWN`;
* оценка вне состояния `RATED` не может нести значение: ноль означал бы оценку «ноль»;
* `PLAYABLE` не может обойтись без момента наблюдения;
* `BOUND` не может обойтись без устойчивого ключа и однозначного маршрута;
* идентификатор из необъявленного пространства прав не получает;
* конфликт вида без двух кандидатов конфликтом не является;
* запись без кода причины не создаётся.

### Как строится маршрут

Вызовом `factory.lords.live_catalog.slugify` — **той же функции**, которой
витрина строит свои адреса, — и воспроизведением её правила разведения
совпадений: второму и последующим совпадениям слага приписывается номер, в
порядке ответа источника.

Измерено на боевом снимке: без воспроизведения правила связывалось 139
адресов очереди из 155 при 15 коллизиях; с ним — 155 из 155, коллизий ноль.

### Следствие, ради которого идентичность отделена от адреса

Номерной адрес получают 5 603 записи каталога из 53 232. Порядок ответа
источника меняет адреса местами. Поэтому идентичность — `contentId`, а
`routeId` из неё выводится и может меняться, не разрывая связи.

### Что контракт не несёт

Токенов поставщика, приватных адресов потока, идентификаторов агрегатора и
любых секретов. `playbackState` отвечает на вопрос «можно ли обещать
просмотр», а не «где лежит файл». Проверено сканированием: `aggregator`,
`title_id`, `m3u8` и `token` в выгрузке отсутствуют.

### Совместимость

`PROVISIONAL` до подтверждения матрицей. Потребительские проверки выполнены
против SEO `99e12ba7588693b17229046bd6a747675be7bbc9`: 10 случаев,
50 проверок, отказов нет.

Проверка идёт **через границу процесса**: ядро работает на Python 3.10.12,
потребитель — на 3.11.16 и пользуется `enum.StrEnum`, которого в 3.10 нет.
Контракт пересекает границу в виде JSON — ровно так, как в работе.

### Прежний потребитель

Продолжает работать без правок: поле `contentIdentity` отдаёт вид в форме
`content-identity/1.0.0`, где он его и читал. Новых полей он не видит, и они
ему не мешают — проверено.
