# Прогрев карт сайта (B016) — измерение и готовый шаг 2026-10-15

Пункт 3 недельной очереди. Повод, измеренный SEO-сессией 12–13 октября: индекс
карт у витрин Yummy отвечает 200 за 0,1 с, а вложенная `/sitemap/titles.xml`
первым обращением отдаёт 504 ровно через 30 с либо молчит дольше 40 с; повтор
— 200 за 0,2–0,9 с. Для робота это значит, что недоступны ВСЕ тайтлы, причём
проверка «карта отдаёт 200» в это время зелёная: она смотрит на индекс.

## Что измерено сейчас

```bash
python3 automation/local/sitemap-chain.py --domain yummyani7.site --domain yummyani7.info
домен                     robots  sitemap вложенных  адресов медленн.  замечания
yummyani7.site               200      200         5    16581      1 с  —
yummyani7.info               200      200         5    16581      1 с  —
доменов с замечаниями: 0 из 2
```

**Дефект сейчас не воспроизводится: кэш тёплый.** Это важная поправка к
формулировке пункта — «карты отдают 504» в настоящем времени неверно. Остаётся
окно сразу ПОСЛЕ сборки, когда кэш пуст: именно в нём первое обращение платит
за генерацию, и платит им робот.

## Готовый шаг

```bash
python3 automation/local/warm-sitemaps.py --domain yummyani7.site --domain yummyani7.info
домен                       индекс  карт  холодн.  тёплая  замечания
yummyani7.site                 200     5     0.6с    0.6с  —
yummyani7.info                 200     5     0.8с    0.3с  —
# exit 0; на тёплом кэше холодное и тёплое время совпадают — так и должно быть
```

Сценарий обходит индекс и КАЖДУЮ вложенную карту, и отдельно измеряет второе
обращение: прогрев считается состоявшимся, когда быстр второй запрос, иначе
отчёт показывал бы время робота, а не результат. Коды возврата различают три
случая: 0 — всё прогрето, 1 — вложенная карта не ответила 200, 2 — индекс
недоступен и прогревать нечего.

Поднятие таймаута шлюза отвергнуто сознательно и это решение сохранено: оно
прячет медленную генерацию, прогрев её устраняет.

## Куда шаг ставится — и почему не мной

Прогрев имеет смысл **в конце выкладки**, пока кэш пуст. Выкладкой витрин Yummy
распоряжается площадка владельца (`/srv/sites/yummyani-staging/repo/deploy/
staging/deploy.sh` со сторожем `indexability_guard.py`), и дописывать в неё
строку этой сессии нельзя: это чужой развёрнутый контур, и у него свой порядок
изменений. Строка для конца сценария:

```bash
python3 /home/claude/wt-nova-publish-memory-02/automation/local/warm-sitemaps.py \
    --domain yummyani7.site --domain yummyani7.info --timeout 90 || \
  echo "ВНИМАНИЕ: карты не прогреты — робот заплатит за генерацию"
```

`|| echo` намеренно: прогрев не должен ронять выкладку. Он устраняет окно, а не
решает, выпускать ли витрину.

```bash
python3 -m pytest tests/unit/test_warm_sitemaps.py -q     # 10 passed
```

## Своя ошибка в этом же инструменте

Первый прогон напечатал «индекс карт ответил UnicodeEncodeError» про домены,
которые отвечают 200: в `User-Agent` стояла кириллица, а заголовки HTTP
кодируются latin-1, и запрос падал ещё до сети. Исправлено, и проверка на
ASCII-значение заголовка добавлена — иначе та же ошибка вернулась бы при
следующей правке пояснения.
