Причина установлена чтением кода: в развёрнутой службе MCP
(`/home/claude/wt-portable-site-cell-01/factory/qwen/editorial.py`) **нет**

поле другой стороны исчезает на очередной публикации.

Выкладки SEO-сессии к этому отношения не имеют: потеря произошла до них и
независимо.

## 4. Почему не установлено мной

Служба MCP работает прямо из рабочего дерева другой сессии
(`WorkingDirectory=/home/claude/wt-portable-site-cell-01`). Моя сессия
изолирована в своём дереве, и харнесс отказывает дословно:

```
This session is isolated in the worktree /home/claude/wt-nova-publish-memory-02,
but this command redirects git to the shared checkout via -C. Refusing to run it
```

Править чужой checkout мимо его владельца я не стал: именно общее дерево ранее
едва не отправило в выпуск чужие незакоммиченные правки
(`docs/WORKTREE_OWNERSHIP.md`).

Проверено, что шаг безопасен: `git merge-base --is-ancestor 0a5d5d0476d9 HEAD`
проходит (ускоренное слияние возможно, 48 коммитов), `branch-overlap-check.py`
даёт **пересечений с незакоммиченными правками той сессии — 0**. Ветка выложена:
`refs/heads/claude/nova-publish-memory-02` = `4c290040151aa04bc9c09542ed3442101173fad5`.

## 5. Одна команда владельца

```bash
git -C /home/claude/wt-portable-site-cell-01 merge --ff-only claude/nova-publish-memory-02 \
  && sudo systemctl restart site-factory-mcp.service \
  && python3 /home/claude/wt-nova-publish-memory-02/automation/local/post-integration-check.py \
  && python3 /home/claude/wt-nova-publish-memory-02/automation/local/editorial-overrides-audit.py
```

Первая команда root не требует и чужие правки не затрагивает — `--ff-only`
отказывается сам, если это не ускоренное слияние. Вторая перечитывает код
службой. Третья обязана напечатать «внедрено во всех службах». Четвёртая —
«защищённые поля на месте» и код 0.

**Ожидаемый результат:** в службе появляется `_живые_правки`, публикация
описаний перестаёт затирать ручные поля, и паузу публикации на семи доменах
Lords/Zona можно снять.

**Откат:** `git -C /home/claude/wt-portable-site-cell-01 reset --hard 0a5d5d0476d9`
плюс `sudo systemctl restart site-factory-mcp.service`. Данные сайтов при этом
не затрагиваются: правка меняет только код службы. Откат вернёт и прежний
дефект — то есть он на крайний случай, а не на «если что».
