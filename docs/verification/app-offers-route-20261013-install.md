# Маршрут «где смотреть» на рабочем адресе — состояние до установки

Задача: довести серверный маршрут `GET /api/app/v1/titles/{id}/offers?region=RU`
до работы на `animedia.icu` для приложения «Кинатека» (sandbox-152, код
`5d0a669`). Подготовленные изменения — ветвь `claude/app-offers-01`, коммит
`a1cc5b6`.

## 1. Что было на самом деле (измерено до любых действий)

| проверено | факт |
| --- | --- |
| ветвь `claude/app-offers-01` | есть локально и на `origin`; ровно один коммит `a1cc5b6` поверх `4c29004` |
| влит ли в рабочую ветвь | **нет**: `git merge-base --is-ancestor a1cc5b6 HEAD` → ложь |
| служба | `app-read-api-animedia-01.service` (через дефис, не точку), процесс pid 1147134, порт 9180 |
| установленный код | `/usr/local/lib/site-factory/app-read-api-animedia-01.py`, 27 832 Б, sha256 `8dc7f32a347df4a0`, от 11.10 11:53Z, `offers` в нём **нет** |
| кто-то установил раньше меня | нет: установленный файл побайтово совпадает с версией ДО слияния (`4f94542`) |

То есть «рабочая служба возвращает 404» подтверждается: маршрута в выложенном
коде просто нет.

## 2. Приёмка рабочего адреса ДО установки

Через публичный nginx с ключом клиента (`/etc/app-read-api/client-key`,
`0640 root:claude` — читается рабочей учётной записью, значение не печатается),
штатным инструментом, а не самодельным запросом:

```
python3 automation/local/app-api-acceptance.py \
    --base https://animedia.icu --key-file /etc/app-read-api/client-key
```

Результат: **расхождений 2**, и оба — ровно «где смотреть»:


**Все прежние маршруты каталога работают.** Ломается только новый маршрут, и
ломается ожидаемо.

Отдельно: тело ответа различает два разных 404, и это важно для приложения.

| ответ | значение |
| --- | --- |
| `{"error":{"code":"not_found","message":"нет такого маршрута"}}` | **маршрута нет** — ошибка маршрутизации, «нет данных» из неё выводить нельзя |
| `{"error":{"code":"not_found","message":"тайтла нет в снимке"}}` | произведения нет в каталоге — это ответ самого маршрута |

Сейчас на все три запроса (с регионом, без региона, неизвестный идентификатор)
приходит ПЕРВЫЙ вариант. После установки должны приходить соответственно 200
`unknown`, 400 `bad_request` и 404 «тайтла нет в снимке».

Своя оговорка о собственной ошибке измерения: первый мой запрос шёл с
заголовком `X-Api-Key` и получил 401 на всех путях. Заголовок называется
`X-App-Key` (контракт, раздел «Ключ клиента»); 401 был артефактом проверки, а
не состоянием службы.

## 3. Интеграция в рабочую ветвь

Штатным слиянием, без force push:

```
git merge --no-ff --no-edit claude/app-offers-01
→ Merge made by the 'ort' strategy; 5 files changed, 373 insertions(+), 1 deletion(-)
```

Единственный общий файл с моими изменениями — `docs/APP_READ_API.md`; слияние
свело обе правки автоматически, и обе на месте: раздел про источник ключа
(моя ветвь) и раздел про `offers` (ветвь приложения). Остальные четыре файла
ветвь добавляет целиком, пересечений нет.

Проверки изменённого backend, без лишнего: `pytest tests/unit/test_app_read_api.py
tests/unit/test_app_read_api_installer.py tests/unit/test_app_read_api_install_rehearsal.py`
— **85 passed**. Android-сборок, эмуляторов и длинных просмотров не
запускалось: к этой установке они отношения не имеют.

## 4. Готовность установки и откат

Сухой прогон установщика (`bash automation/host/install-app-read-api.sh --dry-run`,
root не нужен) прошёл все проверки до изменений:

```
OK файл службы компилируется
OK снимок читается учётной записью claude
OK конфигурация сайта найдена, HTTPS-блок на месте
OK upstream витрины объявлен (её маршруты не затрагиваются)
OK include уже стоит: повторная установка ничего не удвоит
OK ключ уже существует: не перезаписываю
OK код службы отличался от выложенного — потребуется перезапуск
```

**Зафиксированная версия до установки:** sha256 `8dc7f32a347df4a0`, 27 832 Б —
побайтово равна `4f94542:automation/host/app-read-api.py`. Это и есть источник
отката: содержимое доступно из git, отдельная копия файла не нужна.

**Способ отката версии** (не путать с `--rollback`, который снимает установку
целиком и увёл бы в офлайн ВСЁ API каталога):

```bash
cd /home/claude/wt-nova-publish-memory-02
git show 4f94542:automation/host/app-read-api.py > /tmp/app-read-api.rollback.py
sudo install -m 0644 -o root -g root /tmp/app-read-api.rollback.py \
  /usr/local/lib/site-factory/app-read-api-animedia-01.py
sudo systemctl restart app-read-api-animedia-01.service
```

После отката приёмка обязана снова дать «расхождений: 2» (два отказа «где
смотреть») и ноль по остальным: это признак того, что откат вернул именно
прежнюю версию, а не сломал каталог.

## 5. Что остаётся и почему

Установка требует root: установщик кладёт код через `install -o root -g root` в
`/usr/local/lib/site-factory` и перезапускает юнит. Обходить sudo я не стал и не
буду. Команда — в `docs/OWNER_BLOCK_20261013_EVENING.md`, шаг 6.

Реального поставщика предложений нет: файла `<site>-offers.json` в каталоге
данных не существует, и контракт прямо называет это состояние — `status:
unknown`, `reason: NO_AVAILABILITY_SOURCE`. Вымышленные ссылки, ссылки на поиск
и тестовые предложения в рабочий каталог не добавлялись и не будут: подключение
источника — отдельная задача.
