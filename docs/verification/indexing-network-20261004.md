## Уточнение по доставке разрешения (D147)

Первый вариант доставки был неверен, и это поймал тест, а не рассуждение:
корневая копия реестра не вправе ссылаться на файл в рабочем каталоге, потому
что реестр задаёт учётную запись, порт, имя юнита и пути установки — право
записи в него равнялось бы праву решать, что поставит root
(`tests/unit/test_executor_no_repo_code.py`).

Как сделано вместо этого: копия остаётся копией, а разрешение владельца
доставляет в неё САМА команда владельца — она уже работает от root и переносит
только четыре поля разрешения названного домена:

```bash
sudo bash automation/host/authorize-indexing.sh --domain <домен>
```

Поэтому после единственной переустановки исполнителя дальнейшие разрешения
дойдут до него без переустановки.

### Что требуется от администратора один раз

```bash
sudo bash /home/claude/wt-portable-site-cell-01/automation/host/install-cell-executor.sh
```

Эта команда закрывает всё перечисленное выше одновременно: доставляет
`owner_consent.py` (его в установленной копии нет вовсе), обновляет
`protected.py` (из-за него отклонён готовый выпуск lords-02) и переносит
реестр с уже записанным разрешением владельца на lordserials22.info.

Отдельно (необязательно, но полезно) — применить обновлённый юнит моста, чтобы
его вывод попадал в файлы под `var/log` и читался без root: сегодня смерть
службы по пределу памяти не оставила ни одной читаемой строки.

### Что станет возможно сразу после этого

```json
set_indexing_mode {"site": "lordserials22.info", "mode": "open", "expect_release": "09d6db02828e"}
```

Остальные восемь технически готовых домена ждут отдельной команды владельца
(`authorize-indexing.sh --domain <домен>`) — разрешение с контрольного домена
не копируется и не переносится.

### Карта сайта: пробел не этой операции, но названный

Измерено по девяти доменам: `/sitemap.xml` отдаёт 200 ТОЛЬКО animedia.space
(186 байт, индекс на `sitemap-1.xml`), у остальных восьми — 404 и ссылки
`Sitemap:` в `robots.txt` нет. У lordserials22.info карта отвечала 404 и ДО
открытия — это видно в снимке «до» (`sitemap_http: 404`), то есть операция
здесь ничего не изменила.

Чего не хватает, по частям:

1. генератора не вызывает НИКТО: `seo_layer.построить_sitemap` есть во всех
   репозиториях семейства и не вызывается ни в одном;
2. маршрут `/sitemap.xml` в рантайме lords есть, но требует
   `LORDS_SITEMAP_DIR`; drop-in'ы с этой переменной существуют только для
   прежних имён юнитов (`nova-lords-03`, `lords-nova-01`, `nova-zona-01`), а у
   действующих ячеек её нет;
3. `_тело_robots()` семейства lords зовёт `robots_txt(состояние)` без
   `sitemap=`. Честная реализация уже написана у animedia и ставит ссылку
   только если карта действительно отдаётся — её и нужно перенести в шаблон
   семейства.

Это отдельная работа с новой публичной поверхностью на уже открытом домене и
решением о свежести карты при обновлении каталога, поэтому она названа, а не
сделана попутно.
