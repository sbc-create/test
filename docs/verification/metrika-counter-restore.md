# Восстановление счётчика Метрики после переноса в ячейку

## Что было сломано

При миграции витрин в переносимые ячейки значение счётчика потерялось: оно
объявлялось только в drop-in монолитных служб, например
`/etc/systemd/system/lords-nova-01.service.d/metrika.conf`. Юниты ячеек таких
drop-in не наследуют, переменная `LORDS_METRIKA_COUNTER` оставалась пустой, и
рантайм не выводил разметку счётчика. Публичный HTTP 200 это не показывал.

Затронуто четыре перенесённых домена. Отсюда правило: **при переносе сверять не
только файлы кода и данных, но и переменные окружения действующего юнита.**

## Исправление своего сайта

`config/site.json` → `environment.LORDS_METRIKA_COUNTER = "112582938"`,
коммит `350de09`, CI 36262379375 (success), выпуск через очередь:
`status=ok outcome=activated stage=live_verified`.

## Остальные витрины

Идентификаторы уже существуют в `config/analytics.json`; создавать новые не
нужно. Правка для чужих репозиториев (ведут свои сессии) — та же строка в
`config/site.json`:

## Поступление данных — НЕ ПОДТВЕРЖДЕНО

Разметка на странице доказывает только отправку. Приходят ли данные в кабинет,
я проверить не могу: доступа нет. Нужен OAuth-токен Метрики с правом чтения
статистики (файлом вне репозитория, путь — в конфигурации). Topvisor в проекте
не настроен вовсе: ни ключа, ни идентификатора проекта.
