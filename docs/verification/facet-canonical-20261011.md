# Canonical фасетов: год и страна, 11 октября 2026

Поверхности `/year/<гггг>/` и `/country/<код>/` до 11 октября **не мерились
вовсе** — их не было в перечне разделов приёмки. SEO-сессия назвала их по коду
витрин, и первый же замер нашёл дефект на витрине, которую обе сессии считали
исправной во всех разделах (`lordserial33.biz`).

Все измерения ниже — чтение живых страниц, команда и артефакт названы в §5.

## 1. Что нашлось

`/year/2024/` объявляет канонической `/catalog/` — то есть страницу с ДРУГИМ
набором карточек. Проверено сверкой состава, а не длины страницы: у фасета и у
цели по 48 карточек, общих — одна.

| витрина | `/year/2024/` → canonical | состав цели |
| --- | --- | --- |
| lordserial33.biz | `/catalog/` | 48 против 48, общих **1** |
| lordfilm47.space | `/catalog/` | то же |
| 1lordserials1.online | `/catalog/` | то же |
| lordserials22.info | `/catalog/` | то же |
| an1mego.site | `/catalog/` | 24 против 24, общих **0** |
| animeg0.site | `/catalog/` | то же |
| an1meg0.site | `/catalog/` | то же |
| animedia.icu | `/catalog/?year=2024` | 58 против 58, общих **58** |
| animedia.space | `/catalog/?year=2024` | то же |
| zonafilm.space | `/catalog/?year=2024` | 28 против 28, общих **28** |
| zonafilm12.site | `/catalog/?year=2024` | то же |

`/country/rossiya/` — так же: у четырёх Lords canonical `/catalog/`, общих
карточек 0 из 45; у Zona `/catalog/?country=rossiya` с тем же составом; у
Animedia и AnimeGo раздела нет (404).

**Расхождение — только первые семь строк.** Canonical на другую СХЕМУ адреса
(`/catalog/?year=2024`) с тем же составом и кодом 200 — это сведение дублей к
одной схеме, норма п.1, а не потеря поверхности. Отличить одно от другого можно
только походом по цели и сверкой состава; поэтому норма ходит.

Нарушено: §1 п.4 замороженной базы («canonical не указывает на нерелевантную
страницу») и `REQ-SEO-PAGINATION` п.3. Касается **первой** страницы, а не
только пагинации: поверхность не индексируется вовсе, а её карточки остаются
доступны лишь через каталог.

Отдельно, у тех же семи витрин, `/year/2024/?page=2` тоже отдаёт canonical
`/catalog/` — это уже п.3, и оно не покрывалось решением D202: D202 про
canonical на страницу ТОГО ЖЕ отбора, а здесь отбор теряется.

## 2. Причина — в маршруте, а не в обработчике

`/srv/lordserial33-biz/current/src/lords-frontend.py:6851`:

```python
год = self.МАРШРУТ_ГОДА.match(путь)
if год:
    зпр["year"] = [год.group("year")]
    return self._отдать_список(в, "/catalog", зпр, путь)
```

Раздел передан литералом `"/catalog"`, а условие уходит в запрос. Дальше в
`список` (строка 4617) canonical собирается как `разд + "/"`, а условие
`только_страница = стр > 1 and not (set(зпр) - {"page"})` ложно, потому что в
`зпр` лежит `year`. Итог: `/catalog/` и для первой страницы, и для второй.

`/country/<код>/` — строка 6873, та же подстановка.

**Образец правки уже есть в том же файле**: ветка жанра (строка 4604) задаёт
`база = f"/genre/{код}"` и собирает canonical от него. Фасеты года и страны
этой ветки просто не получили.

Проверка причины: фасет путём против фасета запросом.

| | `/year/2024/?page=0` | `/catalog/?year=2024&page=0` |
| --- | --- | --- |
| lordserial33.biz | 404 | 404 |
| animedia.icu | 404 | 404 |
| zonafilm.space | **200, 28 карточек** | 400 |

У Lords и Animedia обе схемы ведут себя одинаково — дефект только в canonical.
У Zona путевой маршрут фасета — **отдельная поверхность, которая параметр
`page` не разбирает вовсе**: любое значение отдаёт первую страницу, а
`?page=9999` — 200 с пустым шаблоном, то есть soft 404, прямо запрещённый §1
п.8. Это второй, независимый дефект, и у Zona он есть при верном canonical.

## 3. Чем закрыто с моей стороны

**Норма фасета** (`норма_фасета` в `automation/local/public-acceptance.py`):
canonical первой страницы фасета должен быть либо на себя, либо на другую схему
с кодом 200 и тем же составом. Проверка жёсткая сразу для всех доменов, без
списка исключений: спорных прочтений у потери условия отбора нет. 11 тестов —
`tests/unit/test_facet_canonical_norm.py`, включая тот, который требует падения
на реальном случае «48 против 48, общих 0»: проверка по числу карточек или по
длине страницы пропустила бы его целиком.

**Исправлена ложная тревога в собственной мере.** Строгость п.2 стояла домену
целиком с обоснованием «редирект в их коде один на все разделы, и измерение это
подтверждает». Измерение подтверждало его лишь на тех разделах, которые тогда
мерились. На фасетах Zona приёмка выдала «РЕГРЕСС: редирект пропал» о
поверхности, где редиректа никогда не было. Строгость п.2 переведена на
разделы, как у п.3; отчёт, утверждающий регресс там, где его не было,
обесценивает остальные строки.

**Строгие списки п.3 расширены ровно по измерению:**

* `lordserial33.biz` — восемь разделов (добавлены `/animation/`, `/anime/`,
  `/dorama/`, `/new/`);
* `1lordserials1.online` — шесть (второй раунд `392fb7bf0e7f-lords-03`
  проверен мной: build ID совпадает с установленным, п.3 держится);
* `zonafilm.space` — шесть.

Фасет года в строгие не попал ни у кого — и тест это сторожит, чтобы дефект не
был записан нормой.

**Чисты восемь витрин из двенадцати:** обе Animedia, все четыре Lords, обе
Zona. Остаются три AnimeGo (canonical фасета плюс известный soft 404 в
разделах вида) и `zonafilm.cc`.

### Два независимых дефекта на одних поверхностях

Измерение их различило, и путать их нельзя — правки разные:

* **canonical сбрасывает условие отбора** — у Lords и AnimeGo. Разбор номера
  страницы при этом верен;
* **путевой маршрут не разбирает `page`** — у Zona. Canonical при этом верен
  (сведение к схеме запроса с тем же составом).

`zonafilm.cc` несла оба, и причина первого у неё своя — не маршрут, а слой
`canonical_requested`, читающий перечень запрошенного из строки запроса.

### Почему строгость осталась по разделам

Фасеты Zona в строгие карты вошли, но карты остались по разделам, а не по
доменам. Причина, по которой домен целиком строгим быть не может, никуда не
делась: разные поверхности одной витрины обслуживаются разным кодом, и
`zonafilm.cc` тому доказательство — у неё два отдельных места правки.
