#  Ворота cross-site: не запускались на живой сети вовсе, а теперь нашли 6 находок

Запись ночного цикла 12 октября. Definition of Done блокирует `DONE`, если
«обнаружена cross-site утечка». Ворота для этого есть, они покрыты тестами и
вызываются из CLI — но **на живой сети они не запускались ни разу**, и причин
было две.

## 1. Две причины недостижимости, обе измерены

**Первая: адаптер цели.** `cmd_seo_cross_site` разрешал цель ДО того, как
читал `--base`:

```
$ python3 -m factory seo-cross-site --site lords-02 --base https://lordserial33.biz
[BLOCKED_ACCESS] Неизвестный adapter цели: 'operator_applied'.
нужно: adapter: local_disposable | payload_multisite | ssh_ansible
```

Адаптер `operator_applied` — не ошибка конфигурации, а сознательное решение:
«агент к серверу не подключается и подключаться не должен», фабрика готовит
пакет и сценарий, применяет оператор на хосте. Цель в этих воротах нужна РОВНО
за базовым адресом, и когда адрес дан явно, строить её незачем. Отказ из-за
адаптера был препятствием без предмета.

**Вторая: падение на участнике без домена.** После первой правки ворота дошли
до запросов и упали:

```
TypeError: expected string or bytes-like object
  ... http/client.py, putheader
```

Причина — `other["domain"]`, уехавший в заголовок `Host` значением `None`.
В группе `lords-quartet` четыре участника, и у `lords-04` домен не объявлен.

Падение здесь хуже отказа: по traceback не видно, что сравнение не
состоялось, а проверка, которая не сравнила, уникальностью не является.
Теперь участник без домена **называется и пропускается**, а его имя попадает в
отчёт (`group_members_without_domain`, `skipped_members`) — по артефакту видно,
с кем сравнение не проводилось.

Третья правка попутно: сайт без пакета в `sites/` получал traceback
`FileNotFoundError`. Теперь — чистый отказ с объяснением, что ворота группы
сравнивают сайты, объявленные пакетами, а ячейки реестра этой проверкой не
покрыты.

## 2. Проба проверена на подлинность ДО того, как доложены находки

Ворота опрашивают один базовый адрес, подменяя заголовок `Host`: три сайта
стенда живут на одном порту. На живых доменах это сработало бы ложно, если
nginx не маршрутизирует по `Host` — тогда все три «сайта» вернули бы
содержимое одного, и дубли изготовила бы сама проба.

Проверено прямым замером:

| запрос | `x-site-factory-build-id` |
| --- | --- |
| `https://lordserial33.biz/catalog/` со своим `Host` | `bec2c5440da6-lords-02` |
| тот же адрес с `Host: lordfilm47.space` | **`fbc2b8ab923c-lords-01`** |

С чужим `Host` приходит ЧУЖОЙ build — значит маршрутизация по `Host` работает,
каждый запрос попадает на свой сайт, и сравнение подлинное.

## 3. Что ворота нашли — с разделением по весу

```
python3 -m factory seo-cross-site --site lords-02 --base https://lordserial33.biz
# FAILED | sites 3, pages 15, indexable_pages 15, duplicates 6,
#          group_members_without_domain 1, skipped_members lords-04
```

Шесть находок, и читать их надо не одним числом.

**Существенная — CSU-4.** `lordfilm47.space/catalog/` ↔
`1lordserials1.online/catalog/`: основной текст совпадает **на 91 %** — «это
одна и та же страница на двух доменах». Это согласуется с известным
устройством: каталоги всех Lords собирает один производитель из одного
источника, и у каждой витрины в данных лежит снимок на 62 652 записи. То есть
находка не про шаблон, а про то, что один каталог отдаётся под несколькими
индексируемыми доменами.

**Пересекается с текущей работой SEO — CSU-3.** Совпадает H1 на
`/catalog/` у всех трёх («каталог») и на `/collections/` у двух («подборки»).
SEO-сессия в эту же ночь закрывает ровно этот класс на `/country/<код>/`, где
у каждой страны был H1 «Каталог». Отдельной работы здесь, похоже, не нужно —
нужно, чтобы правка дошла и до этих двух разделов.

**НЕ доказывает заявленного — CSU-6.** Три находки говорят «состав
индексируемых адресов совпадает полностью: это зеркала, а не два
самостоятельных сайта». Основание слабее вывода: `pages: 15` на три сайта —
это по **пять адресов** на сайт, и все пять берутся из ОДНОГО объявленного
пакетом состава поверхности. Совпадение такого набора неизбежно по построению
пробы и зеркальности не доказывает. Говорить «это зеркала» на пяти адресах
нельзя, и я этого не говорю.

## 4. Чего я не решаю

Правильно ли отдавать один каталог под несколькими индексируемыми доменами —
вопрос владельца, не мой. Моя часть: ворота фабрики текущее состояние
ОТВЕРГАЮТ, совпадение 91 % измерено и подлинность пробы проверена. Решение о
том, менять ли содержимое, разводить ли каталоги или сознательно принять
риск, принимает владелец, и теперь у него есть число вместо ощущения.

Отдельно стоит сказать, чего ворота НЕ покрывают: у Zona, Yummy, AnimeGo и
Animedia пакетов в `sites/` нет — они живут в реестре ячеек, и эта проверка на
них не распространяется. Девять живых витрин из семнадцати остаются без
cross-site ворот, и это не «пройдено», а «не проверено».

## 5. Чем закрыто

```
python3 -m pytest tests/unit/test_cross_site_gate_reachable.py -q   # 6 passed
python3 -m pytest tests/unit/test_cross_site_uniqueness.py -q       # 16 passed
```

Новые проверки закрепляют поведение, а не имена: участник без домена не роняет
прогон и попадает в отчёт по имени; чужая группа не участвует; пакет без
группы не тянет чужие сайты; все участники без домена дают ноль сайтов (и это
не «уникально»); нечитаемый чужой пакет по-прежнему не роняет проверку.
Отдельно в подделке запроса стоит `assert isinstance(host, str)` с
пояснением — именно так ворота и падали.
