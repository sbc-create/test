# an1mego.site и animeg0.site: два ложных блокера и что осталось владельцу

Дата измерений: 2026-10-05, хост `claude-control-01`. Задание — открытие
оставшихся production-доменов штатным механизмом.

## Исходное состояние

Согласие владельца зарегистрировано его собственным запуском скрипта
2026-10-05T13:41:38Z: якоря `/var/lib/site-cells/owner-consent/an1mego.site.json`
и `animeg0.site.json` (root:root, `0444`, 611 байт), объявления в реестре
ячеек — отдельный коммит. Установка витрин выполнена: `/srv/an1mego-site/app`
(13:11) и `/srv/animeg0-site/app` (13:18), точки входа импортируют
`indexing_mode`.

## Ложный блокер 1: вердикт искал код в несуществующем каталоге

Первый прогон `python3 -m factory.qwen indexing --site an1mego.site`:

    status = MECHANISM_UNPROVEN
    reason = "читатель в релизе есть, но ни один файл выпуска его не
              подключает: использование не подтверждено"

При этом `runtime_reader = /srv/an1mego-site/app/src/indexing_mode.py`, а
`/srv/an1mego-site/app/src/animego-frontend.py:110` содержит
`import indexing_mode as ИНДЕКС`. То есть механизм работает, а вердикт назвал
его неподтверждённым.

Причина: читателя искали по ОБОИМ корням (`корни_выпуска` — `current`, затем
`app`), а подключение читателя, доказательство чтения и источник
установленного выпуска — зашитым `/srv/<учётная запись>/current`. У витрины
прямой установки ни `current`, ни `releases/` нет вовсе (измерено: в
`/srv/an1mego-site/` только `app` и `data`).

Исправлено: корень определяется по тому, где НАЙДЕН читатель — тем же
признаком, которым его искали (D183). После исправления:

    reader.release_dir = "app"
    wiring = {"imports": ["animego-frontend.py"], "entrypoint": "animego-frontend.py"}
    installed_release.source = "/srv/an1mego-site/app"
    release_permits_open = true, owner_authorized_open = true, operation_can_open = true

## Ложный блокер 2: поле отчёта отменило операцию

Штатная операция `indexing-set --site an1mego.site --mode open` вернула:

    ok = false
    reason = "an1mego.site: исполнитель не применил слой nginx (исход None):
              animego-02: у ячейки не записан путь репозитория | ВНИМАНИЕ:
              слой nginx вернуть не удалось …, домен остался в режиме слоя
              'UNKNOWN' — требуется немедленный разбор"

Результаты заявок исполнителя (файлы очереди, читаются как есть):

| заявка | статус | ошибка | время |
| --- | --- | --- | --- |
| `animego-02-idx-open` | `rejected` | `animego-02: у ячейки не записан путь репозитория` | 14:07:00.55 → 14:07:00.87 |
| `animego-02-idx-closed-rst140706` | `rejected` | то же | 14:08:01.29 → 14:08:01.62 |

Причина: `cell.repo_path` — не поле, а свойство, возбуждающее
`RegistryError`, когда путь не записан; вычислялось оно в строке отчёта
(`"cell_repo"`) ПОСЛЕ применения слоя. Слою nginx репозиторий не нужен вовсе —
операция названа в `ОПЕРАЦИИ_БЕЗ_РЕПОЗИТОРИЯ`. Поэтому: слой переключён,
заявка отвергнута, ОТКАТ отвергнут тем же самым, домен объявлен в режиме
`UNKNOWN`.

Исправлено: имя рабочей копии берётся через
`_имя_репозитория_для_отчёта` — отчёт не вправе отменить операцию (D184).
Закреплено тестом `test_отсутствие_пути_репозитория_не_отменяет_слой`.

## Фактическое состояние площадки после неудачной попытки

Проверено измерением, а не выводом операции.

| признак | an1mego.site | animeg0.site |
| --- | --- | --- |
| главная | `HTTP/2 200` | `HTTP/2 200` |
| `X-Robots-Tag` | `noindex, nofollow` | `noindex, nofollow` |
| `<meta name="robots">` | `noindex, nofollow` | `noindex, nofollow` |
| `robots.txt` | `User-agent: * / Disallow: /` | то же |
| слой nginx | **управляемый** (`$cell_robots_animego_02`, `/etc/nginx/cells/animego-02.robots`, `# режим: CLOSED`, `default "noindex, nofollow"`) | прежний зашитый `add_header X-Robots-Tag "noindex, nofollow" always;` |
| `managed_by_this_operation` в вердикте | `true` | `false` |
| вердикт | `CHECKS_FAILED` — «слой nginx: closed», то есть домен закрыт и ждёт открытия | — (не трогался) |

Состояние согласовано на всех трёх слоях: закрыто. Аварии, о которой сообщила
операция, нет — сообщение было следствием того же дефекта, что и отказ.
Соседний домен не затронут: попытка касалась только `an1mego.site`.

**Чего я установить не могу:** перезагружался ли nginx между 14:07:00 (файл
режима записан со значениями OPEN) и 14:08:01 (перезаписан значениями CLOSED).
Доступа к журналу системных служб у сессии нет. Если перезагрузка в этот
промежуток была, до минуты заголовок `X-Robots-Tag` на обычных страницах
отдавал открытое значение; два других сигнала — `<meta name="robots">` и
`robots.txt` — оставались закрытыми всё время, они решаются приложением, а не
nginx. Текущее измерение: закрыто всеми тремя.

## Отдельная находка: у этого семейства нет карты сайта

    https://an1mego.site/sitemap.xml   404
    https://animeg0.site/sitemap.xml   404
    https://an1meg0.site/sitemap.xml   404   ← домен УЖЕ ОТКРЫТ

`robots.txt` открытого соседа строки `Sitemap:` не содержит. Маршрут в коде
есть (`/sitemap.xml` и `/sitemap-N.xml`), но отдаёт 404, пока пуста переменная
`LORDS_SITEMAP_DIR`, а `run.py` этого семейства её не выставляет ни у одной из
трёх витрин. То есть пробел не в открываемых доменах, а в семействе целиком, и
он старше этого задания. Производителя файлов карты у семейства тоже нет —
подключение переменной без него дало бы 404 по другой причине. Здесь это
названо фактом, а не починено: это отдельная работа, и она не входит в
открытие домена.

## Что осталось владельцу — одно действие

    sudo bash /home/claude/wt-portable-site-cell-01/automation/host/install-cell-executor.sh

Исполнитель работает из КОРНЕВОЙ копии пакета
(`/usr/local/lib/site-factory-cell`, root-владение) — так сделано сознательно:
юнит не исполняет код из каталога, куда может писать обычная учётная запись.
Поэтому исправление дефекта доходит до исполнителя только повторным запуском
установщика. Та же команда обновляет и копию реестра ячеек, в которой у
`animego-02`/`animego-03` путь репозитория появился коммитом `eb5195c`
(13:26), то есть позже снимка, с которым работает исполнитель.

После этого открытие — моя работа, штатной операцией:

    python3 -m factory.qwen indexing-set --site an1mego.site --mode open
    python3 -m factory.qwen indexing-set --site animeg0.site --mode open

Повторных согласий и повторной установки витрин не требуется.
