# Политика индексации: источник истины, выкладка, откат

Документ отвечает на один вопрос: как сделать так, чтобы решение владельца о том,
какие сайты видит поиск, переживало любой штатный deploy, рестарт и откат.

## Почему это отдельный контур

До сентября 2026 решение жило в трёх независимых местах: список доменов в коде
посредника, профиль сайта на хосте вне Git и `compose.staging.yaml` в ветке,
которой нет в `main`. Совпадали они случайно. Обычный deploy из `main` возвращал
посредника, безусловно закрывающего витрину, — и живой сайт с поисковым трафиком
закрывался молча, без единой ошибки в логах.

Поэтому правило контура одно: **решение принимается в одном файле, все остальные
слои из него производятся.**

## 1. Где источник истины

`config/site-profiles/<site_id>.json` в репозитории. Один файл на сайт.

Обязательные поля:

| Поле | Смысл |
| --- | --- |
| `schema_version` | версия схемы профиля |
| `site_id` | идентификатор сайта |
| `domains` | домены сайта; маска запрещена |
| `canonical_domain` | собственный домен сайта, обязан входить в `domains` |
| `environment` | `production`, `staging` или `demo` |
| `profile_family` | семейство шаблона; **на индексацию не влияет** |
| `profile_version` | версия профиля |
| `seo_profile.indexing_expected` | `open` или `closed` |
| `seo_profile.indexing_reason` | основание решения, свободный текст |

Ничего, кроме этого файла, разрешения на индексацию не выдаёт.

## 2. Как добавить новый домен

1. Генератор сайта создаёт профиль со значением `indexing_expected: "closed"`.
2. Профиль коммитится вместе с остальным сайтом.
3. Без профиля deploy известного домена **блокируется** — это не предупреждение,
   а остановка до любых изменений production.

Новый домен закрыт по умолчанию. Семейство, общий флаг и настройки соседей
открыть его не могут.

## 3. Как открыть домен

Одним изменением его профиля:

```json
"seo_profile": {
  "indexing_expected": "open",
  "indexing_reason": "решение владельца от 2026-09-15, коммит 1490271"
}
```

PR с таким изменением показывает diff матрицы: домен, было, стало, основание.
Ворота релиза не пропустят открытие, которое не заявлено в списке одобренных
изменений.

## 4. Как закрыть домен

Тем же способом — значением `closed` в его профиле. Срочное закрытие можно
выполнить окружением: оно **может сузить** разрешение, не дожидаясь правки файла.
Открыть окружением нельзя: обратный путь однажды открыл бы всё семейство общего
рендерера сразу.

## 5. Маршрутная политика — отдельно от доменной

Открытый домен не означает открытых служебных маршрутов. `/dev`, `/api`,
`/login`, `/register`, `/search`, `/admin` остаются закрытыми правилами
приложения, а не политикой домена. Доменная политика решает «видит ли поиск этот
сайт», маршрутная — «видит ли поиск эту страницу».

## 6. Как собрать артефакт

```bash
python3 -c "
from pathlib import Path
from factory.indexing.artifact import build, write
write(build(Path('config/site-profiles')), Path('var/indexing-policy.json'))"
```

Сборка детерминирована: из одного дерева получается байт в байт один и тот же
файл. Манифест несёт отпечаток каждого профиля и отпечаток матрицы, поэтому
расхождение отпечатков означает расхождение входа, а не случайность
сериализации.

Посредник читает готовый артефакт и ничего не решает сам. Отсутствующий, пустой,
повреждённый файл и чужая схема означают «закрыто всем»: открытая по
недоразумению витрина попадает в индекс, и обратно это уже не забрать.

## 7. Как работают ворота релиза

До любых изменений production ворота:

1. читают инвентарь обслуживаемых доменов;
2. читают версионируемые профили;
3. проверяют схему и окружение;
4. строят ожидаемую матрицу;
5. сравнивают её с матрицей, разрешённой владельцем;
6. сравнивают кандидата с измеренным живым состоянием;
7. показывают точный diff;
8. запрещают выкладку при любом незаявленном изменении.

Выкладка запрещается, если: у известного домена нет профиля; профиль повреждён;
найден неизвестный домен или дубликат; смешаны окружения; кандидат открывает
незаявленный домен; матрица отличается от разрешённой; живое состояние не
измерено или находится в промежуточном состоянии.

## 8. Как проверить origin и публичный адрес

CDN перед сайтами нет: публичный edge — тот же nginx, ответы отдаются с
`Cache-Control: no-store`. Проверять всё равно нужно оба конца, потому что
совпадение внутреннего порта и публичного адреса — это факт, который меняется
при первой же правке конфигурации.

```bash
curl -sSI http://127.0.0.1:9132/          # origin
curl -sSI https://yummyani.site/          # публичный адрес
```

Заголовки и тело следует брать **одним GET**. `HEAD` как единственное
доказательство не годится: посредник добавляет `X-Robots-Tag` только на `GET`, и
однажды именно `HEAD` привёл к неверному выводу о том, какой слой закрывает
витрину.

## 9. Как диагностировать дрейф

```bash
seo-operator indexing-drift
```

Проверка read-only: операций записи в модуле нет. Она сверяет фактическое
состояние каждого домена с решением из реестра и различает три исхода —
совпадает, разошлось, не измерено. Неизмеренное состояние не проходит как
«в порядке».

## 10. Как выполнить откат

Откат возвращает **весь набор**, а не один файл:

* артефакт приложения;
* профили сайтов;
* окружение;
* compose/юнит;
* конфигурацию прокси.

Откат считается выполненным только после публичной проверки: код 200, ожидаемые
слои и совпадение матрицы. Перезапуск службы без такой проверки ничего не
доказывает.

## 11. Что требует отдельного разрешения

* открытие любого домена;
* изменение DNS и TLS;
* отправка карты сайта или адресов в поисковые системы;
* широкая очистка кеша CDN;
* любые действия с плеером, шаблонами и provider bindings.

## 12. Как убедиться, что поисковым системам ничего не отправлено

Контур не умеет отправлять. Проверяется двумя разными поисками, и важно, что
именно ищется.

```bash
# 1. Отправляющие вызовы: их нет ни одного.
grep -rniE "requests\.post|urlopen|\.post\(|submit|ping\?sitemap" \
     seo_operator/datasources/ factory/indexing/

# 2. Упоминания поисковых систем: они есть, и это нормально.
grep -rniE "searchconsole|webmaster" seo_operator/
```

Первый поиск обязан быть пустым — это и есть доказательство.

Второй пустым не будет и не должен: `GoogleSearchConsole` и источники Яндекса
объявлены в `seo_operator/datasources/live.py` как источники **чтения**
(`kind = "search_analytics"`, метрики `impressions`, `clicks`, `ctr`,
`position`). Они умеют спрашивать статистику и не умеют ничего отправлять.
Путать наличие имени с наличием возможности — ровно та ошибка, ради которой
здесь две команды вместо одной.

## Известные расхождения слоёв

**`www.yummyani.site` отдаёт 308 с `X-Robots-Tag: noindex`.** Алиас открытого
домена несёт запрет, который апексу не нужен. На индексацию апекса это не
влияет — редирект не индексируется, — но слои говорят разное, и заголовок здесь
лишний. Правка в конфигурации nginx (`add_header` в блоке www-редиректа),
требует root.
