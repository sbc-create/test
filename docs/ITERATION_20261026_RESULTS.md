## 4. Что требует владельца — одним блоком

Блок один, и ни один его шаг не отменяет другого. Каждый проверяется отдельно;
отказ одного не мешает остальным.

### 4.1. Topvisor: расписание съёма позиций

Сервер: управляющий узел (этот), пользователь `root` через `sudo`.

```bash
# ДО: убедиться, что таймера нет и позиции не снимались
systemctl list-timers 'topvisor*' --all --no-pager
ls -la /home/claude/wt-portable-site-cell-01/var/topvisor/ | head

# Установка юнитов проверки доступа (операции ЧТЕНИЯ: check и plan)
# Путь проверен 26.10 22:01:51Z: файл лежит в рабочей копии линии, которая ведёт
# Topvisor, и юнит на неё же и указывает (WorkingDirectory).
install -m 0644 \
  /home/claude/wt-portable-site-cell-01/automation/host/topvisor-check.service \
  /etc/systemd/system/topvisor-check.service
systemctl daemon-reload

# Первый прогон — вручную, чтобы увидеть отчёт целиком
systemctl start --wait topvisor-check.service
systemctl status topvisor-check.service --no-pager | tail -20
cat /home/claude/wt-portable-site-cell-01/var/topvisor/check-latest.txt
```

Ожидаемый результат: файл `check-latest.txt` непустой и называет профиль,
баланс и список проектов. **Непустой журнал и старый файл результатом не
считаются**: проверять надо время записи файла и то, что в нём названы проекты.

Откат: `systemctl disable --now topvisor-check.service; rm -f
/etc/systemd/system/topvisor-check.service; systemctl daemon-reload`. Данных
операция не меняет: `check` и `plan` — чтение, мутации делает только `apply`,
и его в юните нет.

Чего этот шаг НЕ даёт: новых позиций. Съём позиций — отдельная платная
операция (`collect`), и её расписание ставится только после того, как `check`
подтвердит доступ и баланс. Недоступность Вебмастера (B023) к этому шагу
отношения не имеет: это другой поставщик и другой блокер.

### 4.2. publisher_id для пяти новых витрин

Пять значений из Secret Hub, по одному на домен (D138: у каждого домена свой;
подставить соседний нельзя). Куда положить — в проект каждой витрины,
`config/player.json`, рядом с уже существующим `config/player.json.example`.

```bash
# ДО: убедиться, что файла нет и проверка честно отказывает
for s in lords-18 lords-19 lords-20 lords-21 lords-22; do
  ls -la /home/claude/wt-nova-publish-memory-02/var/new-sites/$s/config/player.json 2>&1 | tail -1
done
```

Ожидаемый результат после выдачи: `bash checks/run.sh` в каждом проекте даёт
16 PASS без FAIL (сейчас 15 PASS и один FAIL с названной причиной).
