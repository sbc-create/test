# Эксплуатация единого модуля оценок

## Перед любым изменением схемы

```bash
python3 - <<'PY'
from pathlib import Path
from factory.ratings.prod_db import backup_db, resolve_canonical_db
db = resolve_canonical_db()
print(backup_db(Path(db), Path(db).parent / "backups"))
PY
```

Бэкап без проверенного восстановления бэкапом не является. Проверка —
копия бэкапа, открытая отдельно, и `PRAGMA integrity_check`, а не факт
существования файла.

Порядок: бэкап → dry-run миграции на копии → проверка восстановления →
применение → проверка, что старые запросы возвращают то же самое.

Миграция 0007 только расширяет схему. Применяется на живой БД в WAL без
остановки gateway: ни одна существующая таблица не изменяется.

## Ступени сбора

| Ступень | Команда | Ограничение |
| --- | --- | --- |
| A — discovery | `discover --probe` | только чтение, сбора нет |
| B — пилот | `pilot --source <key>` | не более 20 тайтлов |
| C — выборка | `sample --source <key>` | не более 100 тайтлов |
| D — инкрементальный | `ingest --source <key>` | только после `gates` |

`gates --source <key>` показывает, что мешает перейти к ступени D:
пройденные пилот и выборка, отсутствие ложных автоматических
сопоставлений, применённая миграция.

Ступени разделены командами, а не флагами: `pilot` не может взять больше
двадцати тайтлов физически.

## Когда источник отказывает

| Симптом | Что делает модуль | Что делать оператору |
| --- | --- | --- |
| `HTTP 429` | конечное число повторов, затем `RATE_LIMITED`; источник ставится на паузу | ничего; пауза снимется сама |
| `HTTP 401/403` | `AUTH_REJECTED`, источник гасится целиком, повторов нет | проверить, не изменились ли условия доступа |
| `HTTP 412` (Simkl) | `CREDENTIAL_REQUIRED`, повторов нет | выдать `secret_ref simkl_client_id` |
| таймаут | до трёх повторов с ограниченным backoff, затем `TIMEOUT` | проверить сеть; прогон записан со статусом `FAILED` |
| `SCHEMA_DRIFT` | источник гасится | сверить контракт, обновить адаптер и подтверждение шкалы |

Бесконечных повторов нет нигде. Пауза одного источника не останавливает
остальные.

## Очередь проверки сопоставлений

```sql
SELECT review_id, title_id, source_key, reason_code, detail
FROM unified_review_queue WHERE status='PENDING';
```

Записи из очереди **не публикуются автоматически** и не попадают в
отображение: строка источника получает состояние `PENDING_REVIEW`.

Принять связь вручную — поставить `unified_source_links.status`
в `reviewed` с заполненными `verified_by` и `verified_at`, затем закрыть
запись очереди.

## Проверка агрегата

```python
from factory.unified_ratings.community import CommunityRatings
community.verify_aggregate(scope_kind="tenant", scope_id="yummy", title_id="nova:...")
```

Возвращает две независимые сверки: `row_intact` (строка против своей
контрольной суммы) и `agrees_with_ledger` (строка против пересчёта из
ledger). `match` истинен только когда обе истинны.

Восстановление агрегата из ledger — `rebuild(tenant_id=..., title_id=...)`;
пересчёт читает ledger внутри транзакции записи, поэтому параллельные
пересчёты не затирают друг друга.

## Kill switch

Существующий `AntifraudGuard`: `set_kill_switch(True)` останавливает
запись голосов, `set_read_only(True)` переводит в режим только чтения.
Оба состояния читаются из флагов раскатки через `sync_from_rollout()`.

Сбор внешних оценок kill switch не затрагивает — это разные контуры.

## Метрики

`unified_metrics` различает `MEASURED` (считали, вышло столько) и
`UNMEASURED` (не считали, вот причина). В отчёте метрика, которую никто
не записал, выглядит как `UNMEASURED`, а не как ноль: график, где
недоступный источник показывает ноль ошибок, выглядит здоровым.

## Чего этот модуль не делает

Не включает виджет, не меняет шаблоны сайтов, не трогает DNS, TLS, nginx,
robots, sitemap и индексацию, не расширяет подготовленный 1% canary и не
публикует непроверенные внешние оценки. Сбор данных и публичная раскатка
интерфейса — разные этапы, и прохождение одного не является разрешением
на другой.
