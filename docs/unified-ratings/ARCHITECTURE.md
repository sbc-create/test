# Единый модуль оценок 1–10

Подключаемый модуль оценок для Yummy, Animedia, Zona, Lords и следующих
сайтов. Три вида оценок живут раздельно и не перезаписывают друг друга.

## Три вида оценок

| Вид | Что это | Шкала | Где хранится | Кто пишет |
| --- | --- | --- | --- | --- |
| Внешняя | Снимок рейтинга разрешённого источника | исходная шкала источника → 1.0–10.0 | `unified_external_snapshots`, `unified_external_current` | адаптер источника |
| Пользовательская | Оценка посетителя | целое 1–10 | `community_votes`, `community_vote_events` (существующий ledger) + `unified_user_aggregates` | `CommunityRatings` поверх `CommunityVotesService` |
| Редакционная | Наша оценка | целое 1–10 | `unified_editorial_ratings`, `unified_editorial_audit` | `EditorialRatings`, только по RBAC |

Общей таблицы «оценка» нет. Это не стилистика: пока три вида лежат в одной
таблице с колонкой `kind`, ошибка в `WHERE` превращает редакционную оценку
в пользовательскую, и такую ошибку приходится ловить проверкой. При трёх
таблицах это состояние не существует.

В интерфейсе редакционная оценка называется **«Наша оценка»** и никогда —
IMDb, Кинопоиском, AniList или оценкой зрителей.

## Таблицы (миграция 0007, только расширение)

| Таблица | Назначение |
| --- | --- |
| `unified_titles` | канонический тайтл: ru/оригинал/альтернативы, год, сезон, эпизоды, внешние ID |
| `unified_title_tenant_map` | (tenant, subject) → title_id; сервер определяет тайтл сам |
| `unified_source_links` | связь с источником: external_id, метод, confidence, кто и когда подтвердил, статус `exact/reviewed/pending/rejected/conflict` |
| `unified_external_snapshots` | append-only снимки: исходное значение, шкала, формула, нормализованное, голоса, пользователи, даты, версия адаптера, хеш ответа, состояние валидации, причина отклонения, provenance, ссылка на предыдущую версию |
| `unified_external_current` | текущее принятое значение + `last_checked_at` и серия неизменившихся проверок |
| `unified_editorial_ratings` | редакционная оценка, область global/tenant |
| `unified_editorial_audit` | кто, когда, старое, новое, основание, пакет |
| `unified_user_aggregates` | среднее, число голосов, распределение 1–10, контрольная сумма, tenant- и сетевой агрегат |
| `unified_import_runs` | журнал прогонов: cursor, requested/received/exact/pending/rejected/inserted/updated/unchanged/failed/rate_limited/retries, следующий checkpoint, версия кода |
| `unified_review_queue` | неоднозначные сопоставления; автоматически не публикуются |
| `unified_schedule_state` | тир, интервал, следующий срок, серии неизменений и отказов, пауза |
| `unified_metrics` | метрики; `MEASURED` со значением и `UNMEASURED` с причиной — разные записи |

Миграция не изменяет и не удаляет ни одной существующей таблицы. Старый
виджет и gateway продолжают читать `rating_current`, `community_votes` и
`community_aggregates` теми же запросами.

## Шкала и нормализация

Внутренняя шкала — от 1.0 до 10.0. Ноль в неё не входит: ноль означает
«оценки нет», а не «оценка ноль».

| Исходная шкала | Формула | Пример |
| --- | --- | --- |
| 0–10 | `normalized = raw` | Shikimori 8.6 → 8.6 |
| 0–100 | `normalized = raw / 10` | AniList 86 → 8.6; Kitsu «82.27» → 8.227 |
| 0–5 | `normalized = raw * 2` | 4.25 → 8.5 |

Формула берётся из контракта конкретного источника и применяется только к
источнику, для которого проверена. Универсальное правило вида «поделить на
десять, если больше десяти» превратило бы 9.5 по пятибалльной шкале в 0.95
молча и правдоподобно.

Одновременно хранятся: исходное значение, исходная шкала, нормализованное
значение и идентификатор формулы.

Внешние оценки показываются с одним знаком после запятой. Пользовательские
и редакционные вводятся целыми.

### Состояния значения

Отсутствие, ноль, значение вне шкалы и неизмеренное — четыре разных
состояния, и ни одно не превращается в другое:

* `OK` — значение в диапазоне 1.0–10.0;
* `ABSENT` — источник не вернул значение;
* `ZERO_NOT_A_RATING` — источник вернул 0, что у всех наших источников
  означает «ещё не оценили»;
* `OUT_OF_RANGE_LOW` / `OUT_OF_RANGE_HIGH` — значение реально, но вне
  нашей шкалы; не публикуется и не подтягивается к границе;
* `INVALID_TYPE` — не число;
* `CONTRACT_UNVERIFIED` — контракт шкалы источника не подтверждён;
* `UNMEASURED` — измерение не выполнялось.

## Источники

| Источник | Доступ | Статус | Шкала | Голоса |
| --- | --- | --- | --- | --- |
| AniList | официальный публичный GraphQL, без ключа | READY | 0–100 (`Media.averageScore`) | сумма `stats.scoreDistribution[].amount` |
| Kitsu | официальный публичный JSON:API, без ключа | READY (резервный) | 0–100 (`averageRating`, строка) | сумма `ratingFrequencies`; `userCount` — это библиотеки, не голоса |
| Shikimori | уже разрешённый коннектор проекта | READY | 0–10 (`animes[].score`) | сумма `scoresStats[].count` |
| Simkl | официальный API, требует `client_id` | **BLOCKED_SECRET** | не подтверждена | не подтверждено |
| IMDb | договорный фид поставщика | FEED_ONLY | 0–10 | фид не передаёт |
| Кинопоиск | договорный фид поставщика | FEED_ONLY | 0–10 | фид не передаёт |

Приоритет доступа: официальный API → уже разрешённый коннектор проекта →
публичный документированный источник → разбор публичной страницы. Понижать
приоритет самостоятельно нельзя: недоступный из-за отсутствующего ключа
официальный API делает источник BLOCKED, а не поводом парсить страницу.
Ни один источник в модуле не использует разбор страниц.

Что никогда не становится оценкой: `popularity`, `favourites`, `rankings`,
`trending` у AniList; `popularityRank`, `ratingRank`, `userCount`,
`favoritesCount` у Kitsu; `malId` у Shikimori.

## Сопоставление тайтлов

Приоритет: точный внешний ID → ранее подтверждённое сопоставление →
оригинальное название + год + тип → альтернативное название + год + тип →
название + сезон + эпизоды → fuzzy только как кандидат в очередь.

Похожее название само по себе не связывает ничего.

Точный ID тоже не безусловен: если источник по нашему MAL ID отдаёт фильм
2009 года там, где каталог знает сериал 2016-го, сходится не тайтл, а
ошибка в одном из каталогов, и связь уходит в очередь со статусом
`conflict`.

Обязательные причины карантина: `YEAR_MISMATCH`, `MOVIE_VS_SERIES`,
`SEASON_MISMATCH`, `FRANCHISE_MISMATCH`, `REMAKE`,
`SPECIAL_OVA_VS_MAIN`, `EXTERNAL_ID_CONFLICT`, `INSUFFICIENT_CONFIDENCE`,
`MULTIPLE_EQUAL_CANDIDATES`.

Сравнение типа учитывает пометки в названии: наш каталог знает только
`tv` и `movie`, тогда как AniList и Kitsu различают OVA и спецвыпуски, и
сравнение одних объявленных полей отправляло бы в карантин каждый второй
спецвыпуск.

## Отображение

API отдаёт строки раздельно и в этом порядке:

```
Наша оценка
Оценка зрителей
AniList
Simkl
Kitsu
Shikimori
IMDb
Кинопоиск
```

У каждой строки есть состояние: `PRESENT`, `NO_RATING_AT_SOURCE`,
`NOT_LINKED`, `PENDING_REVIEW`, `SOURCE_BLOCKED`, `UNMEASURED`.
Отсутствующее значение не заменяется нулём и не исчезает молча.

Единый «общий рейтинг» по умолчанию не вычисляется: у источников разные
аудитории, шкалы и объёмы голосов, и среднее по ним меняется от того,
какой источник ответил сегодня.

Сортировочный показатель — отдельный, версионируемый
(`weighted_bayes_v1`), с приором, минимальным числом голосов, списком
использованных и исключённых источников, пересчитываемый и не
подменяющий исходные значения. Источники без числа голосов в него не
входят: их вес пришлось бы придумать.

## Пользовательская оценка

Голоса пишет существующий проверенный ledger `CommunityVotesService`:
идемпотентность, история событий, антифрод, rate limit, CSRF/Origin,
kill switch и privacy-safe identity (`SIGNED_PSEUDONYMOUS_DEVICE_V1`,
открытый IP в таблице голосов не хранится).

Добавлено: определение `title_id` сервером по паре (tenant, subject) —
клиент его не передаёт; агрегат с распределением 1–10 и контрольной
суммой; сетевой агрегат по одному явному правилу.

Правило сетевого агрегата
(`one_active_vote_per_actor_per_title__latest_wins/v1`): один активный
голос участника на тайтл во всей сети; при голосах на нескольких
площадках учитывается последний по времени изменения. Простое сложение
площадочных агрегатов дало бы такому участнику два голоса.

Контрольная сумма проверяется двумя независимыми сверками: строка сама с
собой (её поля против её же контрольной суммы) и строка против пересчёта
из ledger. Одной сверки мало — правка `vote_count` без правки
контрольной суммы её не нарушает.

## Расписание

| Тир | Стартовый интервал | Границы подстройки |
| --- | --- | --- |
| ONGOING (выходящие/текущего года) | 24 часа | 12–72 часа |
| RECENT_FINISHED (завершённые за последний год) | 7 дней | 2–21 день |
| ARCHIVE | 30 дней | 14–90 дней |
| RETRY | 6 часов | 1 час – 7 дней, не более 5 отказов подряд |

Неизменившееся значение отодвигает следующую проверку, изменившееся —
приближает, отказ отодвигает сильнее. Подстройка не выходит за границы
тира. Источник в rate limit ставится на паузу до разрешённого времени.
Одновременного полного обхода всех источников нет.

## Запуск по ступеням

```bash
python3 -m factory.unified_ratings.cli --db <path> discover --probe
python3 -m factory.unified_ratings.cli --db <path> seed-titles --catalog <catalog.json>
python3 -m factory.unified_ratings.cli --db <path> pilot  --source anilist   # ≤ 20
python3 -m factory.unified_ratings.cli --db <path> sample --source anilist   # ≤ 100
python3 -m factory.unified_ratings.cli --db <path> gates  --source anilist
python3 -m factory.unified_ratings.cli --db <path> ingest --source anilist
python3 -m factory.unified_ratings.cli --db <path> schedule --source anilist --enroll
python3 -m factory.unified_ratings.cli --db <path> report
```

Ступени разделены командами, а не флагами: `pilot` физически не умеет
взять больше двадцати тайтлов, а `ingest` отказывается работать, пока
ворота не пройдены. Разделение флагом позволило бы запустить массовый
сбор опечаткой.

## Границы этапа

Сбор внешних оценок и публичная раскатка виджета — разные этапы. Этот
модуль пишет данные и отдаёт модель отображения; он не включает виджет,
не меняет шаблоны сайтов, не трогает DNS, TLS, nginx, robots и sitemap и
не расширяет подготовленный 1% canary.
