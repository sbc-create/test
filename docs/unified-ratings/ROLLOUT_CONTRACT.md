# Контракт раскатки единого модуля оценок

Документ отвечает на один вопрос: что обязана предоставить площадка, чтобы
получить блок оценок, и чего модуль от неё **не** требует. Контракт написан
так, чтобы вторая площадка подключалась записью в реестре, а не правкой кода:
в модуле нет ни одного условия вида «если это Animedia».

Реестр — `config/unified-ratings-tenants.json`. Инструмент —
`tools/unified_ratings_publish.py`. Матрица готовности — его вывод, а не
отдельная таблица, которую кто-то поддерживает руками.

## Что обязана дать площадка

| Требование | Зачем | Чем проверяется |
| --- | --- | --- |
| `details` — снимок собственного каталога | Знаменатель покрытия. Процент от каноничных 53 596 произведений сказал бы о площадке неправду | `details_present`, `catalog_size` в матрице |
| `provider` и формат идентификатора `<provider>:<id>` | Связь строк витрины со строками модуля без угадывания | `titles_known` — сколько идентификаторов площадки модуль вообще знает |
| `space` — пространство имён | Голоса зрителей и редакционные оценки не смешиваются между площадками | Ключи флагов `RATINGS_PUBLIC_*_<SPACE>` |
| Два пути на диске: `projection`, `flags` | Витрина читает файлы и никогда не ходит в базу оценок | `status: PUBLISHED` и sha256 проекции |
| `authorized: true` в реестре | Разрешение живёт в реестре, а не в строке запуска | `BLOCKED_AUTHORIZATION` для всех остальных |

## Чего модуль не требует

* **Общей базы с витриной.** Витрина читает JSON; соединения с SQLite у неё нет,
  заблокировать запись модуля она не может.
* **Правки nginx, DNS, canonical, robots и sitemap.** Блок оценок живёт внутри
  уже работающего процесса витрины на её собственном порту.
* **Единого шаблона.** Проекция отдаёт значения и подписи; как их рисовать —
  дело витрины. Виджет Animedia — пример, а не зависимость.
* **Одинакового набора источников.** Площадка с двумя источниками получит
  сводную оценку, площадка с одним — строку `SINGLE_SOURCE_ONLY` и ни одной
  придуманной цифры.

## Умолчания раскатки

Все три флага выключены, пока их не включили решением:

```
RATINGS_PUBLIC_READ_<SPACE>  = 0
RATINGS_PUBLIC_WRITE_<SPACE> = 0
PUBLIC_WRITE_ROLLOUT_PERCENT = 0
KILL_SWITCH                  = 0
allowlist[<space>]           = []      # пусто — это «никому», а не «всем»
owner_test_access_only       = true
```

Пустая когорта не означает «показать всем». Отсутствие флага не означает
«включено». Файл проекции может существовать задолго до решения её показать.

## Порядок подключения новой площадки

1. Добавить запись в `config/unified-ratings-tenants.json` с `authorized: false`.
2. `tools/unified_ratings_publish.py --matrix` — увидеть свой блокер.
3. Закрыть блокер (обычно это отсутствующий `details` или неизвестный провайдер
   идентификаторов).
4. `--tenant <id> --dry-run` — убедиться, что `titles_in_projection` не ноль и
   `skipped_no_data` объясним.
5. Перевести `authorized: true`, выложить проекцию и флаги.
6. Показ — отдельным решением: сначала когорта владельца, потом чтение,
   и только потом запись зрителей.

(`lords-runtime-registry.json` знает шесть площадок трёх семейств). Записывать

каталога целиком, а его `details` — тот же канон. Для него нужен отдельный
знаменатель по фильмам, и до этого раскатку считать нечем.
