Поэтому шаг запускается для ТРЁХ доменов, а не одного: команда ниже повторяется
с `animedia.icu` и `zonafilm12.site` на месте домена. Домены независимы: отказ
на одном не отменяет остальные.

Сервер: управляющий узел (этот), через `sudo`. Юнит уже установлен.


Ожидаемый результат: в отчёте перечислены созданные цели, и
`analytics status` показывает `целей 9/9` у `zonafilm.space`.

**Целей стало десять.** 27.10 к восьми добавились `block_view` (рекомендательный
блок показан) и `block_click` (из блока перешли в карточку) — они нужны оценке

Подтверждение ПРИЁМА событий (после выпуска кода и живого прохода по сайту):

```bash

python3 -m factory analytics report --domain zonafilm12.site \
    --date1 2026-10-27 --date2 2026-10-27
```

**Оговорка к сравнению доменов.** Цель `player_start` у линии Zona уходит по
сообщению поставщика `requestPlay` («площадка запросила показ»), а у
`animedia.icu` такого сообщения в контракте нет, и выдумывать его нельзя:
там цель уходит на первом продвижении медиа. Условие строже запроса, поэтому
`player_start` на `animedia.icu` может показать меньше просмотров, чем было,
но не больше. Складывать эти числа между доменами как одну величину нельзя.

**Чем результат НЕ считается.** Наличие счётчика на странице — не отправка
события; отправка — не приём. Пока в отчёте нет достижений цели, нули означают
«событие не дошло», а не поведение зрителей: считать их поведением нельзя.

Откат: `systemctl stop` для обоих юнитов. Цели в кабинете создаются
необратимо — но это и есть запрошенная операция; данных витрин она не касается.

## 8. Расписание для проверки состава подборок (таймер)

**Повод измеренный, 27.10.** Отчёт итерации называл меру `editorial` ночного
прохода «регулярным прогоном» и считал её работу подтверждённой артефактом.
Линия редакционных наборов это оспорила, и проверка показала, что права она:
**расписания у проверки нет.** `night-surface-pass.py` не упоминается ни в
одном `.service` и ни в одном `.timer` репозитория. Формулировка в отчёте
исправлена.

Что есть на самом деле: проверка написана и ОДИН РАЗ отработана вручную —
`var/surface/2026-10-27/editorial.json`, 09:14:27Z, три витрины, дефектов 0,
не измерено 0, код возврата 0. Это доказывает, что проверка работает, и не
доказывает, что она запускается сама.

**Чем мешает отсутствие расписания.** Состав подборок привязан к постоянным
`id` каталога. Каталог обновляется регулярным прогоном обновлятеля; работа,
пропавшая из снимка или потерявшая видео либо постер, перестаёт отрисовываться,
и подборка молча становится короче. Проверка это ловит — но только когда её
запускают руками. Между выпусками состав не сверяется ничем.

**Что нужно от владельца.** Поставить таймер на меру `editorial`. Проверка
только ЧИТАЕТ: публичные страницы не трогает вовсе, работает от учётной записи
`claude`, без `sudo` и без секретов, пишет только в `var/`, постоянных данных
витрин не касается (`docs/RUNTIME_DATA_OWNERSHIP.md`). Поставить расписание сам
я не могу: `systemctl` вне профиля сессии.

Та же просьба уже стоит по двум другим проходам —
`docs/OWNER_BLOCK_REGULAR_PASSES_20261021.md` (`sitemap-reconcile` и
`selection-indexability`); эту меру разумно добавить тем же решением.

**Проверка до:**

```bash
cd /home/claude/wt-nova-publish-memory-02
python3 automation/local/night-surface-pass.py --only editorial
# ожидание: «витрин 3, с дефектом 0, не измерено 0», код 0, артефакт в var/surface/<дата>/
```

**Проверка после установки таймера:**

```bash
systemctl list-timers --all | grep -i surface      # таймер объявлен и имеет NEXT
journalctl -u <имя юнита> -n 20 --no-pager         # последний прогон и его код
ls -l var/surface/                                 # каталоги по датам растут сами
```

**Чем результат НЕ считается.** Один ручной прогон расписанием не является, и
называть его «регулярным» в отчёте — ошибка отчёта. Пока таймера нет, в любом
отчёте о подборках пишется: проверка есть, расписания нет.

**Варианты, между которыми выбор ваш.**

1. Оставить как есть: витрина аниме, снимок утверждён, обложка — обложка.
2. Попросить источник снимка о признаке возрастного ограничения и скрывать
