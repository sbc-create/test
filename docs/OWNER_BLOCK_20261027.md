## 1. Цели Метрики: создать отсутствующие и подтвердить ПРИЁМ событий

Почему это нужно именно сейчас. Отправка событий выложена в код линии Zona
(коммиты `e298c76` и `33ea8bb`), а 27.10 — и в код `animedia.icu` (своими
точками плеера: у этой линии нет ни `requested`, ни `nextOrFail`). Подтвердить
ПРИЁМ сессия не может: токен читает служба, и `factory analytics` отвечает
`BLOCKED_SECRET`. Отдельно измерено: у `zonafilm.space` в кабинете создано
**0 целей из 9**, у `zonafilm12.site` — 9 из 9, у `animedia.icu` (счётчик
`113288667`) все девять целей за 20–26.10 равны нулю при 4417 визитах — то
есть событие не отправлялось, а не зритель так себя вёл.

Поэтому шаг запускается для ТРЁХ доменов, а не одного: команда ниже повторяется
с `animedia.icu` и `zonafilm12.site` на месте домена. Домены независимы: отказ
на одном не отменяет остальные.

Сервер: управляющий узел (этот), через `sudo`. Юнит уже установлен.

```bash
# ДО: что сейчас в кабинете
python3 -m factory analytics status --domain zonafilm.space | grep -E 'zonafilm'

# Создать отсутствующие цели ОДНОГО домена (дубля не создаёт: счётчик ищется
# по домену и переиспользуется; при двух счётчиках прогон останавливается)
sudo systemctl start 'analytics-connect@zonafilm.space.service'
systemctl status 'analytics-connect@zonafilm.space.service' --no-pager | tail -5
cat /home/claude/wt-portable-site-cell-01/var/analytics/connect-zonafilm.space.json
```

Ожидаемый результат: в отчёте перечислены созданные цели, и
`analytics status` показывает `целей 9/9` у `zonafilm.space`.

**Целей стало десять.** 27.10 к восьми добавились `block_view` (рекомендательный
блок показан) и `block_click` (из блока перешли в карточку) — они нужны оценке
03.11: показов блоков не измеряла ни одна цель, и «блок показали, но из него не
переходят» было неотличимо от «блок никто не видел». Ключ подборки в цель не
передаётся по устройству отправки; разбивка берётся из просмотров
`/collection/<key>/`. В реестре (`config/analytics.json`) они объявлены трём
витринам, где эти блоки есть: zonafilm.space, zonafilm12.site, animedia.icu.

Подтверждение ПРИЁМА событий (после выпуска кода и живого прохода по сайту):

```bash
sudo systemctl start analytics-cabinet.service
python3 -m factory analytics report --domain zonafilm12.site \
    --date1 2026-10-27 --date2 2026-10-27
```

**Оговорка к сравнению доменов.** Цель `player_start` у линии Zona уходит по
сообщению поставщика `requestPlay` («площадка запросила показ»), а у
`animedia.icu` такого сообщения в контракте нет, и выдумывать его нельзя:
там цель уходит на первом продвижении медиа. Условие строже запроса, поэтому
`player_start` на `animedia.icu` может показать меньше просмотров, чем было,
но не больше. Складывать эти числа между доменами как одну величину нельзя.

**Чем результат НЕ считается.** Наличие счётчика на странице — не отправка
события; отправка — не приём. Пока в отчёте нет достижений цели, нули означают
«событие не дошло», а не поведение зрителей: считать их поведением нельзя.

Откат: `systemctl stop` для обоих юнитов. Цели в кабинете создаются
необратимо — но это и есть запрошенная операция; данных витрин она не касается.

## 5. Пересобрать недельный снимок популярного (операция по расписанию)

Почему это нужно именно сейчас. Блок «Высокие оценки зрителей» (бывшие
«Высокие оценки недели») ранжировал мнение десятка человек: наверху стояли
8.5 при 14 оценках, 8.5 при 16, 8.2 при 12, рядом — фильмы 1973–1994 годов, у
которых числа оценок в каталоге нет вовсе. Поручение владельца 27.10: «высокая
оценка с несколькими голосами не должна автоматически давать первое место».

Правило исправлено в двух местах: сборщик снимка ранжирует только работы с
известным числом оценок не ниже порога (`MIN_VOTES`, по умолчанию 1000) и
смотрит на 3000 последних поступлений вместо 400; витрина применяет тот же
порог ПРИ ЧТЕНИИ, чтобы старый снимок не показывал запрещённое.

Следствие, названное прямо: опубликованный снимок недели `2026-W44` собран
26.10 старым правилом, и после порога из него остаётся 2 работы в полке
фильмов и ноль в остальных. Блок на главной скроется (вкладка короче четырёх
карточек не рисуется) и вернётся после пересборки снимка.

```bash
# Пересобрать недельный снимок текущим правилом (пул 3000 + порог 1000).
sudo -u zonafilm-space python3 /srv/zonafilm-space/app/src/popular_weekly.py \
    --catalog /srv/zonafilm-space/data/zona-01-catalog.json \
    --details /srv/zonafilm-space/data/zona-01-details.json \
    --out /srv/zonafilm-space/data/zona-01-popular-weekly.json
# То же для zonafilm12.site с его путями.
```

Ожидаемый результат: в снимке `ranking_signal:
source_rating_in_recent_pool_min_votes`, `min_votes: 1000`, в полках по 11–12
работ, и у каждой число оценок не ниже порога. Проверка —
`python3 automation/local/editorial-sets-validate.py` и живой просмотр
главной: в блоке нет работ без числа оценок.

**Чем результат НЕ считается.** Снижение порога ради наполнения блока и
добивание полки случайными карточками запрещены поручением; пустой блок
скрывается — это допустимый исход, а неверные числа — нет.

```

<title>Zona Cinema — кинопортал</title>
```

названия закрыто режимом CLOSED_WORLD, а подставить «Zonafilm» потому, что так
называется домен, — это и есть придумать. Пустое поле разрешением не является.

**Что нужно от владельца:** назвать строку для `zonafilm12.site`, отличную от
`zonafilm.space`. Поставлю в тот же день.
