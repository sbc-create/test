# UNATTENDED_NO_ASK

Режим для работы без человека у клавиатуры. Решений ровно два: `allow` и `deny`.
`ask` не выдаётся ни одним слоем, которым управляет репозиторий.

Обоснование простое. Вопрос предполагает, что кто-то на него ответит. В
неинтерактивном запуске отвечать некому, поэтому `ask` останавливает конвейер так
же надёжно, как запрет, но не оставляет следа в отчёте: работа не сделана, и
причина не названа. Запрет строже и виден.

## Правило разрешения

| Класс операции | Решение |
| --- | --- |
| Штатный цикл разработки и staging | `allow` |
| Необратимое, разрушительное, выводящее секреты | `deny` |
| Неизвестный инструмент, неразобранный payload | `deny` (fail closed) |
| Правка самой защитной машинерии | `deny` |

Последняя строка — намеренное ужесточение. Раньше правка `.claude/settings.json`
и `.claude/hooks/*` уходила на подтверждение. Теперь она закрыта: автоматика,
которая может переписать собственные ограничения, ограничений не имеет. Менять
защитный контур можно только отдельным PR с ревью человека.

## Что разрешено автоматически

`git clone/fetch/status/diff/add/commit/checkout/switch`; обычный push в ветки
`claude/*` и `cursor/*`; `gh` для чтения, веток и pull request; правка файлов
внутри репозиториев и `/srv/sites`; `pnpm`/`npm`, Docker и Docker Compose;
build, test, lint, Playwright; Prisma `generate`, `migrate status`,
`migrate deploy`; backup, health-check, reverse proxy и staging deployment;
чтение состояния хоста (`hostname`, `df`, `free`, `ss`, `ps`); HTTP-запросы к
хостам из inventory.

## Что закрыто автоматически

force push и push в `main`/`master`; удаление веток, репозиториев, баз и
backups; `prisma migrate reset`, `db:reset`, `db push --accept-data-loss` и
автоматический `db:seed`; вывод секретов (`gh auth token`, `printenv`, `echo
$*_TOKEN`); слияние pull request; изменение DNS и перенос доменов; покупки;
отключение backup, rollback, аудита и хуков; неизвестные хосты и API.

`migrate deploy` разрешён и остаётся единственным способом применить миграции:
он накатывает готовые миграции и не удаляет данные. Всё, что пересоздаёт или
дозаполняет базу, закрыто — demo-строки в реальной базе нарушают Definition of
Done.

## Границы: чего этот режим не меняет

Два файла остаются под запретом на правку автоматикой и потому не переведены в
`UNATTENDED_NO_ASK` из сессии агента:

- `.claude/settings.json` — секция `permissions.ask` (5 правил);
- `.claude/hooks/pretooluse-guard.sh` — fallback `ask`, когда guard недоступен.

Их правит человек. Точные изменения — в описании pull request этой ветки.
Пока они не применены, `ask` может прийти из слоя настроек, хотя ни один хук
его больше не выдаёт. Решение хука сильнее списка `ask` в настройках, поэтому на
практике штатный цикл уже проходит без остановок.

`bypassPermissions` не включается ни в каком виде.

## Проверка

```bash
.venv/bin/python -m pytest tests/unit/test_unattended_no_ask.py -q
```

Тест проходит полный цикл YummyAnime — от `git clone` до `gh pr create` — и
требует `allow` на каждом шаге, `deny` на каждой опасной операции и ноль `ask`.
