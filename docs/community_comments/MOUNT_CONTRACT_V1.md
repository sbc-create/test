# Контракт подключения модуля сообщества, версия 1

Для терминала ZONA-02 (zonafilm.cc) и любой следующей витрины. Фиксирует
проверенную версию модуля и то, что витрина обязана ему передать.

Основание — f54a5f6 из `claude/zona-real-slider-01`: два дефекта точки
подключения, найденные до раскатки. Здесь они закреплены как контракт, чтобы
следующая витрина не завела данные под неверным ключом.

## Проверенная версия модуля

| Что | Значение |
| --- | --- |
| Модуль | `factory/animedia/community.py` |
| Формат хранилища | `ФОРМАТ = 2` (записи под постоянным ключом) |
| Релиз-образец | `20260923T001500Z-community-public-03` |
| Проверка | `automation/host/community_public_shadow_verify.py` — 53 сценария |
| Модульные тесты | `tests/unit/animedia/test_community_moderation.py` — 25 |

## Что витрина обязана передать

```python
хранилище = community.открыть(ПУТЬ_ХРАНИЛИЩА, витрина=САЙТ_ID)
состояние = хранилище.состояние(subject, ключ_посетителя,
                                модератор=..., slug=slug)
```

* **`витрина`** — идентификатор КОНКРЕТНОГО сайта: `zona-01`, `zona-02`,
  `animedia-01`. **Не семейства.** `zonafilm.space` и `zonafilm.cc` — обе
  витрины семейства `zona`; общее пространство показало бы сообщения одного
  публичного сайта на другом. Хранилище запоминает витрину в поле `site_id` и
  отказывается обслуживать чужую.
* **`subject`** — постоянный идентификатор записи (`details[<slug>]["id"]`,
  UUID). **Не slug.** Адрес меняется, и переименование осиротило бы все
  сообщения тайтла.
* **`slug`** — только справочно и для переноса старых записей. Если запись
  уже заведена под адресом, первая же правка переносит её под постоянный ключ
  вместе с содержимым (`migrated_from_slug`).

## Fail-closed

Нет постоянного идентификатора — **раздел не показывается вовсе**. Завести
данные под ключом, который потом придётся мигрировать, хуже, чем не завести.

## Разметка точки подключения

```html
data-comments-space="zona-02"              <!-- витрина, не семейство -->
data-comments-subject="<uuid>"             <!-- постоянный ключ -->
data-comments-subject-kind="content-id"    <!-- род ключа объявлен -->
data-comments-slug="<slug>"                <!-- справочно -->
```

Каждая форма записи несёт скрытые `subject` и `csrf`. Обработчик POST берёт
ключом `subject`; `slug` принимает только как подсказку для переноса.

## Одно хранилище — один писатель

У каждой витрины свой файл. Путь задаётся окружением
(`ANIMEDIA_COMMUNITY_STORE` у Animedia); по умолчанию он выводится из
идентификатора витрины. Два процесса в один файл не пишут: правка идёт под
`flock`, а `site_id` отсекает чужую витрину.

## Модерация

Новое сообщение получает `status="pending"` и в общей ленте не появляется.
Автор видит своё со словесным статусом — иначе он решит, что отправка не
сработала. Модератор определяется кукой `amd_mod`, значение сравнивается с
`ANIMEDIA_COMMUNITY_MODERATOR_KEY`; пустой ключ означает, что модератора на
витрине нет вовсе, а не что им является любой.

Записи без поля `status` считаются опубликованными: это данные, заведённые до
премодерации, и прятать их задним числом нельзя.

## Что контракт не покрывает

Внешние рейтинги (IMDb, Кинопоиск, Shikimori, MAL) живут отдельно и в это
хранилище не попадают. Смешивать их с голосами посетителей запрещено: на
странице они идут разными группами.
