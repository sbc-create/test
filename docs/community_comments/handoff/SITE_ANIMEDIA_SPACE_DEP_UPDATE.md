Для терминала визуальных правок. **Его рабочая ветка здесь не трогалась**:
репозиторий `animedia-space` живёт отдельно
(`/home/claude/wt-portable-site-cell-01/var/site-repos/animedia-space`), и

## 2.0.1 — исправление, найденное при приёмке

2.0 падал с `NameError` в `списки_посетителя`: при переходе на новую схему
голосующего телу метода добавили `account_id`, а параметру — нет. На витрине
это рвало страницу «Списки» на первом же запросе. Дефект нашла приёмка
animedia.space, не наши тесты: этот метод не вызывал ни один из них.

Закрыт двумя правками: сигнатура приведена к образцу соседних методов
(`account_id: str = ""`), и добавлен тест, который зовёт **каждый** публичный
метод модуля и падает, если появится метод, которого он не знает. Проверено,
что тест ловит именно эту регрессию: с возвращённой старой сигнатурой он
падает, с исправленной проходит. `/lists/` добавлен в теневую приёмку.

Файл `community.py.v2.0` удалён из передачи намеренно — чтобы его нельзя было
закрепить по ошибке.

## Чего одного файла НЕ хватит

Модуль 2.0 принимает постоянный ключ темы, а не адрес, и знает про витрину:

```python
хранилище = community.открыть(ПУТЬ, витрина="animedia-02")
с = хранилище.состояние(content_id, ключ_посетителя, slug=slug)
хранилище.добавить_голос(content_id, значение, ключ_посетителя,
                         slug=slug, account_id="")
```

Точки, которые придётся тронуть в рантайме витрины:

1. `открыть(...)` — передать `витрина="animedia-02"`, иначе хранилище не
   опознает владельца;
2. все вызовы голосования и комментариев — ключом `content_id`
   (`details[<slug>]["id"]`), `slug` только подсказкой для переноса;
3. колонка рейтинга — искать голоса по `content_id`, не по адресу (на
   animedia.icu этот же дефект показывал «Посетители ещё не голосовали» при
   живых голосах);
4. форма голосования — после сохранения показать «Ваша оценка: N» и убрать
   форму: сервер всё равно откажет, и предлагать нажатие нечестно;
5. `ГолосЗакреплён` — наследник `ValueError`, отдельная обработка не нужна,
   но причину стоит показать посетителю.

Готовый образец всех пяти правок — в патче
`automation/host/build_community_release.py` (секции 6–8) и в собранном релизе
`20260923T074500Z-community-one-vote-06`.

## Данные animedia.space

В `/srv/animedia-space/data/site-data/animedia-community.json` уже есть записи
посетителей. Перед обновлением:

```
python3 automation/host/community_votes_audit.py <путь к файлу>
```

Аудит ничего не меняет; он показывает незавершённый перенос и оценки вне
шкалы. Существующие голоса после обновления становятся **окончательными** —
их владельцы больше не смогут переголосовать. Это ожидаемое следствие правила,
а не потеря данных.

## Проверка после применения

`automation/host/community_public_shadow_verify.py` поднимает витрину на
отдельном порту и проходит первый голос, повтор той же оценки, попытку
изменить, восстановление состояния и изоляцию двух витрин семейства. Боевые
данные не трогает.

Полное описание версии — `docs/community_comments/MODULE_VERSION_2_0.md`.
