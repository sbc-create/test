## 2. Доказанная причина повторов

Автоматизация писать тексты не может (пункт 1), поэтому их пишет сессия Qwen.
И вот что у неё есть и чего не было:

| что | где | доступно Qwen |
| --- | --- | --- |
| записи редакционной работы | `/var/lib/seo-content-operator/registry.json`, 306 записей, 297 произведений | **нет** |
| журнал решений | `queue_events.jsonl` | **нет** |
| долговечные подавления | `suppression.json` | **нет** |
| ворота качества | `quality_policy_v2` | **нет** |
| инструменты канала | 28 инструментов моста: факты, состояние витрины, запись материала | да |
| инструмент очереди | **не существовал ни один** | — |

То есть каноническое состояние было полным, а взять задание, узнать прежний
вердикт и записать результат извне демона было нечем. Единственной памятью
запуска оставались его собственные файлы — `queue.md`, `ongoing-queue.md`,
`ready.md`, версии `updated`/`fixed`. Их на сервере нет: поиск по `/srv`,
`/var/lib`, дереву фабрики и дереву оператора не нашёл ни одного такого файла.
Они живут в окружении Qwen, и сервер их не видит.

Отсюда следуют ровно те четыре регрессии, что названы в задании:

* **возврат к отвергнутому соответствию** — вердикт «неверно сопоставлено»
  некуда было записать, и следующий запуск начинал с нуля;
* **вторая очередь рядом с первой** — свой файл был единственным способом
  помнить;
* **правка слуга** — адрес выводился из названия, хотя в реестре он уже лежал:
  у ДжоДжо запись `catalog-019d0533-…` с `canonical_url`
  `/anime/neveroyatnoe-priklyuchenie-dzhodzho-gonka-stalnoy-shar` и статусом
  `NEEDS_UPDATE`;
* **«карточка удалена» по 404** — наблюдения и срока повторной проверки в
  состоянии не было, поэтому единственным выводом оказывался окончательный.

Дефекты 4 и 5 — мои, в новом коде, и их нашла не вычитка, а живой прогон.

## 3. Что исправлено

Один канонический источник, без второй системы:
`seo_engine/content_operator/editorial_queue.py` не хранит ничего своего.
Записи — `ContentRegistry`, подавления — `SuppressionLedger`, журнал —
`queue_events.jsonl`, повышение статуса — `quality_policy_v2`, аренда —
отдельный файл рядом в `StateDirectory`.

| правило задания | как сделано |
| --- | --- |
| разделить произведение и задание | `task_id` = домен + адрес + вид материала; `work_id` = `title_id`. Один work_id даёт разные task_id на разных витринах |
| проверенные исправления сохраняются | `READY_VERIFIED` в выдачу не попадает. Вернуть в работу можно только явным переводом статуса |
| не подтверждать ID по одному старому файлу | `IDENTITY_REJECTED` закрывает задание навсегда; `rejected_identity` переживает перезапуск |
| URL из реестра, не из названия | присланный `canonical_url` сверяется с записью; расхождение — отказ |
| `NEEDS_IDENTITY` / `NEEDS_SOURCES` / `REVIEW_REQUIRED` | словарь очереди поверх существующего перечня статусов (`НАЗВАНИЕ_ОЧЕРЕДИ`), новых синонимов в `ContentStatus` не вводилось |
| имя `ready.md` не повышает статус | `label` принимается и игнорируется, факт игнора уходит в журнал |
| отсутствие `description` в JSON-LD ничего не доказывает | задание несёт `own_text_in_overlay_store` из хранилища накладок + оговорку; на живых карточках `h1` есть, а `description` в JSON-LD и `meta` нет ни одного |
| счётчик эпизодов не доказывает статус показа | `airing_status` в задании: `ONGOING_OBSERVED` со временем наблюдения либо `НЕ УСТАНОВЛЕН` с причиной; срок наблюдения — тот же TTL, что у суточного цикла |
| черновик не заменяет источник | своё тело больше не является происхождением; «проверено» требует адреса, даты, перечня фактов и названного источника |
| один исполнитель на задание | аренда 45 минут, подтверждение выдачи перечитыванием файла аренды |
| ограниченные попытки и срок возврата | 3 попытки, задержки 15 мин / 1 ч / 4 ч, затем `NEEDS_SOURCES` |
| 404 не удаляет карточку | `NO_TARGET_PAGE` + наблюдение со временем + повтор через 6 часов, запись сохранена |
| нет бесконечных версий | версия не создаётся вовсе: результат пишется в ту же запись, а статистика считает `versions_beyond_works` отдельно |
| статистика по данным очереди | `works_total`, `versions_beyond_works`, `texts_present`, `texts_recorded_via_queue`, `texts_verified` — пять отдельных величин |
| занятость ≠ пустая очередь | занятая секция поднимает отказ с причиной; пустой список означает именно отсутствие свободных заданий |

Канал Qwen: `factory/qwen/queue_bridge.py` и три инструмента моста
(`editorial_queue_next`, `editorial_queue_result`, `editorial_queue_status`) —
31 инструмент вместо 28. Логика очереди остаётся одним модулем в оператора,
мост вызывает её отдельным процессом под интерпретатором оператора (тем же
способом, что уже вызывается хранилище накладок). Взятие задания отнесено к
ПИШУЩИМ операциям: оно записывает аренду.

Инструкция `QWEN-CANONICAL.md` поднята до `2026-10-06.1`: десять пунктов «что
изменилось» и новый раздел 2в. Версия в коде поднята тем же числом — она
печатается в каждом ответе, и расхождение обнаруживается сравнением.
