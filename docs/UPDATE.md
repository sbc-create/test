# Обновление

## Обновление DLE

1. Смена мажорной версии требует отдельной compatibility-проверки и **нового**
   knowledge freeze: `/research-freeze`, затем `python3 -m factory knowledge freeze --version <…>`.
   Автоматический переход запрещён (`dle_version` в схеме зафиксирована на `20.0`).
2. Backup БД и mutable data до начала; восстановимость проверяется.
3. Сначала staging: `build` → `deploy --environment staging` → полный `site-qa`.
4. Production — только после зелёного staging и при выполненных условиях из `DEPLOY.md`.

## Обновление темы или плагина

Изменение темы меняет `build_id` (в адрес входит дайджест темы и исходников фабрики),
поэтому создаётся новый релиз, а прежний остаётся точкой отката.

После обновления обязательно сравнить фактический рендер с матрицей индексируемости:
изменения шаблонов не должны молча поменять canonical, robots, пагинацию или структуру
хлебных крошек. Это ловят `seo-lint` и `seo-crawl`.

## Идемпотентность

Повторный запуск обновления не создаёт дубль сайта, БД, cron-задачи, сертификата,
DNS-записи или релиза. Проверяется `tests/integration/test_idempotency.py`.

## Cron

Задачи создаются только из `blueprints/dle20/cron/jobs.yaml` (создаётся из
`jobs.template.yaml` по официальной документации; пока файла нет — cron не настраивается): уникальный `id`,
`schedule`, `command`, `lock`, `timeout_seconds`, `log`, `max_retries`. Дубликат `id`
или отсутствие lock/timeout/лога — `BLOCKED_INPUT`.
