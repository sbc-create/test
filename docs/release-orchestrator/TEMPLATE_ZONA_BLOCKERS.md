# TEMPLATE_ZONA_BLOCKER — дефекты шаблона Zona, найденные при заведении zonafilm.cc

Найдены при полном цикле развёртывания `zonafilm.cc` (витрина `zona-02`,
2026-09-22). Все относятся к **исходному шаблону**, а не к новому сайту.

Ветка разработки шаблона (`claude/zona-real-slider-01`, worktree
`/home/claude/wt-zona-real-slider-01`) в этой работе **не трогалась**: на момент
задачи в ней шла активная сессия другого терминала. Правок туда не внесено,
коммиты оттуда не подхвачены. Ниже — воспроизведение и точная правка; применять
её владельцу шаблона.

Закреплённый артефакт, на котором всё измерено:

```
/srv/lords/.frontend/releases/zona-slider-2650fad6/lords-frontend.py
sha256 7ccf094a1d7f2b5e648a38f51f6a63de9627576637d96f6c966fe1759ad8fa1e
source_commit 5863d296264867f85138bd771f1b90a86ac9c599
```

## TEMPLATE_ZONA_BLOCKER-01 — герой не слайдер, а одна статичная картинка

**Статус:** известен владельцу шаблона, работа идёт в параллельной ветке.

Оформление 1.2.0 семейства `zona` рисует `zhero` с одним произведением и одной
кнопкой «Подробнее». Ни трека, ни точек, ни стрелок, ни автопереключения в
разметке нет:

```
$ curl -s -H 'Host: zonafilm.cc' http://127.0.0.1:9123/ \
    | grep -o 'class="zhero[a-z_-]*"' | sort | uniq -c
      1 class="zhero"
      1 class="zhero__body"
      1 class="zhero__cta"
      1 class="zhero__desc"
      1 class="zhero__kicker"
      1 class="zhero__media"
      1 class="zhero__meta"
```

Требование задания — «настоящий слайдер минимум с несколькими различными
тайтлами, автоматическое и ручное переключение» — опубликованным шаблоном
**не выполняется**. Проверка `home.slider_multiple_titles` в приёмке
(`automation/host/zonafilm-cc-acceptance.py`) даёт `slides: 0` и остаётся
красной намеренно: смягчить её под текущее поведение значило бы объявить
отсутствие блока его наличием.

Правка существует, но не опубликована: коммит `6513e7e7` («настоящий слайдер
героя вместо одной статичной картинки») лежит в ветке параллельного терминала и
вводит разметку `data-zhero-*` и скрипт `ЗОНА_СКРИПТ_ГЕРОЯ`. Подхватывать его
этой задаче запрещено.

**Что нужно от владельца шаблона:** довести и опубликовать слайдер, подняв
версию оформления. После публикации контур `zonafilm.cc` переводится на неё
одной сменой `design_version` в своём манифесте — ворота выкладки проверят, что
артефакт эту версию действительно исполняет.

## TEMPLATE_ZONA_BLOCKER-02 — объявленная версия оформления не исполняется молча

**Тяжесть:** высокая. Витрина может годами объявлять одно, а исполнять другое.

Артефакт объявляет конечный набор исполняемых версий:

```python
ОФОРМЛЕНИЕ_ВЕРСИИ = {ОФОРМЛЕНИЕ_1_1, ОФОРМЛЕНИЕ_1_2, ОФОРМЛЕНИЕ_1_2_1}
ОФОРМЛЕНИЕ_НОВОЕ  = (ВЕРСИЯ in ОФОРМЛЕНИЕ_ВЕРСИИ)
```

Версия вне набора **не вызывает отказа**. `ОФОРМЛЕНИЕ_НОВОЕ` становится `False`,
и витрина уходит на дореформенные ветки, а маршруты 1.1+ (`/title/`,
`/collection/`, `/genre/`, `/country/`, `/year/`) обслуживаются `старое()` —
отдачей из ранее отрисованного статического релиза.

Манифест `zona-01` объявляет `design_version = "1.3.0"`. На момент измерения
(2026-09-22T11:50Z) его назначенный релиз — `zona-slider-2650fad6`, знающий
только до `1.2.1`. Следствие видно на боевой витрине:

```
$ curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: zonafilm.space' \
    http://127.0.0.1:9120/title/40-dney-2/
404
```

Карточка есть в каталоге витрины (53 652 записи), а её страница отдаёт 404 —
потому что статический релиз, из которого она отдаётся, отрисован 10 сентября и
содержит 3 868 записей. На новой витрине, у которой такого релиза нет по
определению, это дало 404 на **всех сорока** проверенных карточках первого
прогона приёмки.

**Воспроизведение:** `tests/unit/test_zona_declared_design_version.py`.
Тест читает набор версий из самого артефакта и сверяет с манифестом.

**Точная правка:** отказ вместо тихого отката. В месте вычисления
`ОФОРМЛЕНИЕ_НОВОЕ`:

```python
if ВЕРСИЯ not in ОФОРМЛЕНИЕ_ВЕРСИИ:
    raise SystemExit(
        f"манифест витрины объявляет оформление {ВЕРСИЯ}, которого этот артефакт "
        f"не исполняет ({sorted(ОФОРМЛЕНИЕ_ВЕРСИИ)}): запуск прекращён"
    )
```

Отказ при старте лучше тихой деградации ровно по той причине, по которой
загрузчик уже отказывается поднимать витрину без релиза: поднять её на
неизвестном коде хуже, чем не поднять вовсе.

**Как закрыто в контуре `zonafilm.cc`:** выкладка
(`automation/host/zonafilm-cc-release.py`) читает `ОФОРМЛЕНИЕ_ВЕРСИИ` и
`ПЕРЕРАБОТАНО_С` из артефакта и отказывается записать в манифест версию,
которой в нём нет. `zona-02` объявляет `1.2.0` — единственную версию, на
которой семейство `zona` исполняет переработанное оформление.

## TEMPLATE_ZONA_BLOCKER-03 — главная отдаётся за секунду с лишним, кэша нет

**Тяжесть:** средняя. Цель canary (origin TTFB p95 ≤ 800 мс) не достигается.

Измерено семью запросами подряд на каждый адрес, один и тот же способ на обеих
витринах:

| адрес | zona-02 (1.2.0) | zona-01 (дореформенная ветка) |
| --- | --- | --- |
| `/` | median 1073 мс, p95 1167 мс | median 3826 мс, max 5393 мс |
| `/catalog/` | median 521 мс | median 4 мс |

Новый контур **быстрее** боевого на главной в 3,5 раза, но цель не достигнута.
Причина структурная: каждый запрос заново разрешает восемь коллекций над
53 652 записями, а ответ уходит с `Cache-Control: no-store` — то есть кэшировать
его не может ни nginx, ни CDN.

Профиль сайта при этом объявляет `cache_policy` с TTL по слоям
(`homepage_shelves: 300`, `catalog: 900`). Рантайм `nova` эту политику не
исполняет: объявление есть, реализации нет.

**Что не сделано намеренно.** Можно было выставить в nginx
`proxy_ignore_headers Cache-Control` и микрокэш на 5–10 с. Это дало бы цифру,
но ценой игнорирования контракта приложения на витрине, закрытой от индексации,
— ровно тот класс решений, из-за которого кэш потом открывает индексацию. Число
оставлено честным.

**Что нужно:** реализовать объявленный `cache_policy` в рантайме, либо снять
его из профиля. Объявленная и неисполняемая политика хуже отсутствующей.

## TEMPLATE_ZONA_BLOCKER-04 — кириллический адрес без слэша обрывает соединение

**Тяжесть:** высокая. Обрыв неотличим от падения службы.

```python
путь = unquote(разбор.path)                      # str с кириллицей
...
if ОФОРМЛЕНИЕ_НОВОЕ:
    if len(путь) > 1 and not путь.endswith("/"):
        цель = путь + "/" + (("?" + разбор.query) if разбор.query else "")
        self.send_response(308)
        self.send_header("Location", цель)       # ← latin-1, UnicodeEncodeError
```

`http.server` пишет заголовки в latin-1. `Location`, собранный из
раскодированного пути, содержит символы вне latin-1, `send_header` возбуждает
`UnicodeEncodeError`, обработчик умирает до `end_headers()`.

Измерено:

| запрос | zona-02 (1.2.0) | zona-01 (дореформенная ветка) |
| --- | --- | --- |
| `/no-such-page-xyz` | 308 | 404 |
| `/%D1%8D%D1%82%D0%BE%D0%B3%D0%BE-%D0%BD%D0%B5%D1%82` | **обрыв соединения** | 404 |
| то же со слэшом | 404 | 404 |

Задевает любое семейство на оформлении 1.1+, не только Zona.

**Воспроизведение:** `tests/unit/test_zona_nonascii_trailing_slash.py`
(`xfail(strict=True)` — как только правка появится, тест станет XPASS и
потребует снять и пометку, и обход).

**Точная правка — одна строка:**

```diff
-            цель = путь + "/" + (("?" + разбор.query) if разбор.query else "")
+            цель = quote(путь, safe="/") + "/" + (("?" + разбор.query) if разбор.query else "")
```

плюс `quote` в импорт рядом с `unquote`.

**Как закрыто в контуре `zonafilm.cc`:** переход на слэш вынесен в nginx и
выполняется до проксирования (`automation/host/nginx/zona-02.conf`), поэтому до
сломанной ветки запрос не доходит. Это обход, а не исправление.

## Находка вне шаблона — дрейф реестров

Не блокер шаблона, но обнаружено там же и влияет на выкладку.

`config/release-registry.json` называет для `zona-01` юнит `zona-01.service`.
На хосте это **легаси-юнит** статической витрины на порту 9104
(`ExecStart=/usr/bin/python3 /srv/lords/zona-01/current/serve.py`), на который
не ссылается ни один vhost. Действующая витрина — `nova-zona-01.service` на
9120, и именно на 9120 проксирует `/etc/nginx/lords/zona-01.conf`.

Аллокатор (`factory/release_orchestrator/allocator.py`) отказался выбирать
между источниками и потребовал назвать связывающий явно. Для `zona-02` взят
`runtime_registry` — по трём совпадениям: vhost → 9120, `ExecStart` → 9120,
запись реестра диспетчера → 9120.

**Что нужно:** привести `service_name` для `zona-01` в
`config/release-registry.json` к `nova-zona-01.service` либо вывести легаси-юнит
из эксплуатации. Пока расхождение живо, любой инструмент, читающий ops-реестр,
перезапустит не ту службу.

## TEMPLATE_ZONA_BLOCKER-05 — удалённая запись продолжает отвечать 200 до перезапуска

**Тяжесть:** высокая для SEO и приёмки. Обнаружено пробой автообновления
`automation/host/zonafilm-cc-freshness-probe.py` (2026-09-22).

Рантайм умеет подхватывать изменившийся каталог без перезапуска
(`_ensure_fresh_snapshots`), и это работает: добавленная запись появилась на
главной, в `/collection/recently_added/` первой строкой и на своей странице,
без единого рестарта.

Обратная сторона не работает. После **атомарного возврата** каталога к
исходному файлу:

| что проверялось | результат |
| --- | --- |
| sha256 файла каталога | `5cd67cf2…` — побайтно исходный |
| маркер в файле каталога | 0 вхождений |
| `X-Catalog-Revision` в ответе | `0b59f77b…` — исходная ревизия |
| маркер в `/collection/recently_added/` | отсутствует |
| `/title/synthetic-freshness-probe/` | **HTTP 200, страница отрисована полностью** |

Проверка повторена примерно через десять минут — по-прежнему 200. После
остановки и чистого запуска службы тот же адрес отдаёт **404**.

То есть подхват каталога **добавляет** записи, но не **снимает** исчезнувшие:
указатель по slug сохраняет удалённое до перезапуска. Ревизия при этом уже
объявлена новой, поэтому по заголовкам состояние выглядит согласованным.

Почему это важно: поставщик снимает записи регулярно. Каждая снятая запись
продолжает отдавать 200 с полной страницей, пока службу не перезапустят. Для
витрины, открытой к индексации, это страницы, которых уже нет, с кодом 200 —
и никакой сигнал о них не поступает.

**Механизм не установлен.** `построить_индекс` собирает `по_slug` заново из
`данные.items`, и прямого пути для выживания старого ключа в коде не видно;
утверждать причину без доказательства здесь нечем. Зафиксировано наблюдаемое
поведение и способ его воспроизвести.

**Воспроизведение:** `tests/unit/test_zona_stale_slug_after_shrink.py`.

**Обходной путь до исправления:** перезапуск службы витрины после публикации,
в которой каталог уменьшился. Для `zona-02` это оформлено в рабочей инструкции;
автоматически из этой задачи не включается — перезапуск службы требует root.
