# Шаблон Yummy: готовность принять контентный контракт

Версия шаблона: **1.4.5** — последняя выложенная; изменения ветки
`claude/yummy-original-parity-01` в неё ещё не входят, номер следующей сборки
назначает выкладка. Контракт представления: `yummy-entity-view/1.0.0`.
Принимаемый контур: `yummy-read-model/1.x`.

Документ отвечает на один вопрос: **что произойдёт, когда Архитектор передаст
данные**. Ответ должен быть «они отобразятся», а не «понадобится переделка
шаблона». Всё, что здесь описано, проверено — на фикстуре и по HTTP.

---

## Что готово и чем это доказано

| Компонент | Где | Чем доказано |
| --- | --- | --- |
| Полная карточка тайтла (20 полей) | `yummy_entity.карточка_тайтла` | `test_yummy_entity_view.py::TestПолнаяКарточка`, `test_yummy_runtime_contract.py::TestКарточкаПоHTTP` |
| Рекомендации (≥6 карточек) | `yummy_entity.рекомендации` | `TestРекомендации`, `test_рекомендации_дошли` |
| Внутренняя оценка (6 состояний) | `yummy_entity.личная_оценка` | `TestЛичнаяОценка` |
| Шесть независимых лент | `yummy_entity.лента` | `TestЛенты` |
| Материалы редакции | `yummy_entity.пост` | `test_пост_рисуется_с_источником_и_датой` |
| Переходник контур → представление | `yummy_contract.py` | весь `TestЛенты`, `TestСовместимость` |
| Навигация по четырём маршрутам | `yummy_pages.первый_экран` | `test_yummy_own_pages.py`, `TestСобственныеСтраницы` |
| Три различающихся варианта | `yummy_variants.ВАРИАНТЫ` | `TestВарианты` |
| Разделы из контура, а не разбором чужой разметки | `yummy-frontend._поверхности` | `TestДанныеСобственныхСтраниц` |
| Запасной поиск и расширение запроса | `yummy_contract.поиск`, `варианты_запроса` | `tests/unit/test_yummy_search.py` |

Строка навигации переписана: скрипт вставки пунктов в чужую шапку удалён
ещё в 1.4.x — он и ломал восстановление страницы React. Разделы витрины
показывает собственная полоса на её же страницах.

Фикстура контракта — `tests/fixtures/yummy/contract_fixture.py`. Она описывает
контур **в том виде, в каком он придёт**: базовые таблицы 1.0.0 плюс жанры,
студии, страны, персоны, озвучки, альтернативные названия, рекомендации и
материалы редакции. Данные заведомо синтетические (префикс «Фикстура»), и
отдельный тест следит, чтобы они не попали в рантайм.

Проверка идёт двумя уровнями, и второй важнее первого:

1. **компоненты на фикстуре** — умеет ли разметка показать поле;
2. **рантайм по HTTP** — доходит ли поле до страницы.

Второй уровень закрывает разрыв, который в этом проекте обходился дороже
всего: код в репозитории есть, тесты зелёные, а до публичной страницы ничего
не доходит. Поднимается настоящий сервер витрины на фикстурном контуре, и
поля проверяются в теле ответа.

## Что шаблон ждёт от контура

Представление читает контур через `yummy_contract.py` — единственное место,
где шаблон знает про таблицы. Расширять его под каждое новое поле не нужно:

* **необязательная колонка `entity`** подхватывается по карте `КОЛОНКИ`
  (`description`, `backdrop_path`, `age_rating`, `duration_minutes`, `seasons`,
  `episodes_total`, `aired_from`, `aired_to`; у каждого поля несколько
  допустимых имён);
* **таблица-связка** подхватывается по карте `СВЯЗКИ` (`entity_title`,
  `entity_genre`, `entity_studio`, `entity_country`, `entity_dub`,
  `entity_person` с колонкой `role`);
* **рекомендации** — таблица `recommendation` с `entity_id`,
  `target_entity_id` и необязательными `reason`, `source`, `weight`;
* **версия контракта** — таблица `read_model_meta(contract)`; без неё
  считается `yummy-read-model/1.0.0`.

Мажорная версия проверяется: `2.0.0` будет отвергнута явно, а не показана
наполовину.

## Чего шаблон не делает и делать не будет

* не подбирает рекомендации сам — только `recommendations[]` контура;
* не выводит статус показа из «доступных серий меньше заявленного»;
* не заменяет пустую ленту общим каталогом;
* не печатает ноль вместо неизвестного числа голосов;
* не сводит оценки разных провайдеров в одно безымянное число;
* не имитирует сохранение оценки.

Проверка против нарезки одного массива под разными заголовками — не намерение,
а код: `yummy_entity.совпадения()` считает долю пересечения секций страницы, и
поверхность, совпавшая с соседней на 80 % и более, не рисуется. Обратный тест
подсовывает один массив дважды и требует, чтобы детектор сработал.

## Границы: что нельзя называть исправленным

Ниже — то, что **готово принять данные, но данных не имеет**. Пока Архитектор
не передал их и рабочий API, ни один из пунктов не является исправленным:

| Поверхность | Строк в контуре на 2026-09-21 | Что видно публично |
| --- | --- | --- |

| Новости | 0 | секция скрыта |
| Анонсы | 0 | секция скрыта |
| Подтверждённый онгоинг | 0 `CONFIRMED`, 47 `DERIVED` | секция скрыта — решение YP-04 |
| Расписание | 0 подтверждённых будущих серий (`next_episode_at` пуст у всех 7299) | секция скрыта |
| Рекомендации | таблицы нет | секция скрыта |
| Пользовательские оценки | 0 строк, API нет | компонент выключен флагом |
| События появления серий | 6, у всех шести `source_event_at` пуст | карточки показаны, дата события не печатается |
| Пополнение контура | последний успех `2026-09-10T15:32:41Z`, далее шесть записей `EMPTY_SOURCE` | собственные страницы называют этот момент вслух |

Возраст данных объявлен на странице намеренно. Пустая полка без него читается
как дефект шаблона, хотя остановился импорт: обе причины выглядят одинаково,
а чинятся в разных местах.

Пустая секция означает отсутствие событий, а не отсутствие раздела, и подменять
её каталогом запрещено. Секция без данных не рисуется вовсе — ни заголовка, ни
рамки: пустое место на странице читается как поломка, а «пока пусто» в рамке —
как работающий раздел без данных.

## Откуда данные у собственных страниц

`/new/`, `/collections/`, `/schedule/` и `/top/` рисует сама витрина —
приложение этих маршрутов не отдаёт (404). Данные для них берутся **из
контура чтения**, того же, на котором стоит `/__contract`.

Разбор полезной нагрузки приложения регулярными выражениями удалён целиком и
не возвращается (решение YP-01). Он сломался молча — приложение сменило
порядок полей в плитке, — и наружу это вышло не ошибкой, а пустыми разделами
и плитками с заглушкой «Нет постера». Причина глубже опечатки в выражении:
документ приложения приходит потоком, и его текстовый порядок не совпадает с
порядком на экране, поэтому извлечение «по тексту между заголовками» — не
чтение, а догадка.

| Раздел | Поверхности контура | Критерий, объявленный на странице |
| --- | --- | --- |
| `/new/` | `new_episodes`, `fresh`, `ongoing` | события появления серии; дата публикации записи в источнике; подтверждённый статус показа |
| `/collections/` | `trending`, `rated`, `news` | формула актуальности; внешние оценки с провайдером и шкалой; материалы редакции |
| `/schedule/` | `schedule`, `announcements` | подтверждённые даты будущих серий; заявленные релизы |
| `/top/` | внешние оценки | оценка провайдера, число провайдеров, год, идентификатор |

Карточка рисуется компонентами приложения — `portal-catalog-tile`,
`poster-slot--catalog`, `portal-catalog-type`, `portal-catalog-year`. Своей
системы карточек на собственных страницах нет: две системы рядом — это
расхождение с оригиналом, видимое глазом.

## Поиск

Поиск ведёт приложение. Витрина его не подменяет: пока приложение что-то
находит, отвечает оно. Ноль обрабатывается двумя шагами — расширением
запроса и запасным поиском по собственному каталогу контура (решение YP-03).
Причина, по которой это понадобилось, и правка на стороне приложения —
`docs/handoff/YUMMY-SEARCH-ANIME-FILTER.md`.

## Как включить, когда данные придут

```bash
# рекомендации: появится таблица recommendation — секция включится сама
# внутренняя оценка: только после рабочего API оценок
systemctl set-environment YUMMY_CAP_PERSONAL_RATING=1   # либо Environment= в юните
systemctl restart nova-yummy-biz nova-yummy-org nova-yummy-site
curl -s https://yummyani.biz/__contract        # объявление: что принято, что наполнено
```

`/__contract` отвечает на каждом домене и называет: контракт представления,
принимаемый мажор контура, capability-флаги, режим карточки, вариант домена и
**число строк в каждой поверхности**. Пустая поверхность названа нулём, а не
словом «готово».

## Режим карточки

Витрина рисует карточку тайтла сама и делает это полно: название, оригинал,
альтернативные названия, оценки провайдеров, тип, год, возраст, жанры, страны,
режиссёр, съёмочная группа, серии, премьера, длительность, озвучки, описание.
Показывать то же вторым блоком — дать посетителю два списка жанров из разных
источников.

Поэтому по умолчанию `YUMMY_CARD_MODE=supplement`: представление рисует только
то, чего у витрины нет (сезоны, фон, рекомендации, внутренняя оценка). Список
полей витрины объявлен в `yummy_entity.РИСУЕТ_ВИТРИНА` и проверяется тестом.
Полный режим `YUMMY_CARD_MODE=full` проверен на фикстуре и включается, если
витрина перестанет рисовать карточку.

## Правило вставок: ничего внутри дерева React

Витрину рисует React, и он восстанавливает страницу по своей разметке. Любой
наш узел внутри его контейнера — расхождение: `Minified React error #418`,
пересборка поддерева и отказ всей клиентской части страницы. Удаление чужого
узла хуже вдвое: позже React ищет его родителя и получает `null`.

Поэтому действует правило, закреплённое тестами:

* в разметку витрины не добавляется ни одного узла — только атрибуты
  (`action`/`method` у формы поиска) и содержимое `<head>`;
* собственные блоки (полоса разделов, дополнение карточки, служебный бейдж)
  стоят последними узлами `body` и позиционируются стилем;
* ничего чужого не удаляется и не переносится — ни узла, ни мета-тега;
* скриптов, наблюдателей и отложенных вставок нет вовсе.

Ожидание `load` правилом не является и проверку не проходит: на публичном
домене страница приходит потоком, и к `load` React ещё достраивает поздние
границы. Это было измерено — 0 ошибок на локальном адресе против 4 из 4 на
публичном при одинаковом HTML.

## Плеер

Не изменялся. Прокси переносит ответ витрины байт в байт, разметка плеера не
переписывается, источники не трогаются. Проверяется отсутствие горизонтального
переполнения на 390, 768 и 1440 — и только это.
