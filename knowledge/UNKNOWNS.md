# UNKNOWNS — чего действительно не хватает

Полный пакет запроса к пользователю — `docs/INPUT_REQUEST.md` и `artifacts/input-request.json`.
Здесь — только классификация неизвестного и то, что именно оно блокирует.

## U1. Официальная документация недоступна из этой сессии (egress policy 403)

| Что | Почему нужно | Что блокирует |
|-----|--------------|---------------|
| DLE 20.0 online-документация | writable paths, cron, структура шаблонов, plugin/VFS, требования к PHP/БД, процедура обновления | `blueprints/dle20/profiles/paths.yaml` → реальная установка DLE (`BLOCKED_INPUT`) |
| Лицензионное соглашение DLE | точная формулировка ограничения по доменам | сейчас используется утверждение пользователя (F5.2); гейт уже реализован |
| Google Search Central, Яндекс Вебмастер, web.dev, W3C WCAG 2.2, Playwright docs | сверка SEO/a11y-правил с первоисточником | ничего не блокирует технически: правила реализованы по мастер-промпту и помечены `verified_against_official_docs: false` |

Разблокируется одним из двух способов: (а) добавить хосты в egress allowlist сессии,
(б) передать официальные экспорты/копии страниц в `knowledge/imported/`.

## U2. Инфраструктура не передана

Нет ни одного SSH-хоста, домена, DNS-зоны, staging-сервера, реквизитов мониторинга,
registry и backup-хранилища. Инвентаризация (§1.2) выполнена на пустом множестве — это
зафиксированный факт F1.2, а не пропущенный шаг.

Блокирует: `PRODUCTION_DEPLOY`, реальный `STAGING_DEPLOY`, DNS cutover, ACME/TLS,
интеграцию с мониторингом. Статусы: `BLOCKED_ACCESS`, `BLOCKED_INPUT`.

## U3. DLE-дистрибутив и лицензии

Нет лицензионного архива, его SHA-256 и реестра лицензий с покрываемыми доменами.

Блокирует: integration test чистой установки, update-тест, любую production-установку
(`BLOCKED_LICENSE`).

## U4. VK / VK Видео

Нет лицензионного каталога/выгрузки, rights manifest, списка разрешённых полей,
contract белого плеера, VK API-документации, рекламного contract VK/Adman/AdTech
(placement/product IDs, разрешённые события, policy refs).

Блокирует: любой site package с `content_source.kind: vk` (`BLOCKED_RIGHTS`),
рекламный слой. Реализованы адаптеры и mock только для staging.

## U5. Бренд, право, приёмка

Нет бренда, логотипов, палитры, шрифтов, юридического лица, контактов, текстов
legal-страниц, reference-скриншотов и индивидуальных порогов приёмки.

Блокирует: реальный site package (`BLOCKED_INPUT`), visual baseline.

## U6. Организационно-технические неизвестные

- Не подтверждено, установлен ли Claude Code CLI на исполняющем worker'е (в этой сессии
  бинарь `claude` в PATH не проверялся как часть контура фабрики — фабрика от него не зависит).
- Не подтверждена политика ретенции бэкапов и требования по GDPR/152-ФЗ для сайтов контура.
- Не подтверждён порядок обработки жалоб правообладателей (DMCA/иное) — влияет на
  состояние страницы при недоступности VK-видео.
- Событие хука `PermissionRequest` не подтверждено: замороженная документация
  Claude Code (SRC-CC-HOOKS, снята 2026-08-21) перечисляет контракт
  `hooks.<Event>[].matcher`, но такого события среди описанных нет, а проверить
  вживую в CLOSED_WORLD нельзя. Профиль UNATTENDED_SAFE реализован целиком на
  `PreToolUse`, которого достаточно: решение `allow`/`deny`/`ask` выдаётся до
  вызова инструмента. Если событие существует, добавление обработчика — правка
  одного блока в `.claude/settings.json`; выдумывать имя события ради строки в
  конфигурации нельзя.
