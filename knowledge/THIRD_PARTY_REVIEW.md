# THIRD_PARTY_REVIEW — сторонние идеи и материалы

## Правило
Сторонние наборы `CLAUDE.md`, rules, skills, hooks, SEO-скрипты и deployment-workflow
в этой сессии **не устанавливались и не копировались**. Причина — сочетание двух факторов:
egress-политика закрывает доступ к произвольным репозиториям (F3.3), а мастер-промпт прямо
запрещает автоматическую установку чужих наборов и неизвестных скриптов.

## Что изучено и принято

| Идея | Источник | Решение | Почему |
|------|----------|---------|--------|
| Короткий CLAUDE.md + вынос деталей в path-scoped rules | SRC-CC-MEMORY (официальная документация) | принято | прямая рекомендация вендора, проверяемый лимит 200 строк |
| Детерминированные запреты через PreToolUse-hook, а не через текст | SRC-CC-MEMORY, SRC-CC-HOOKS | принято | CLAUDE.md не является enforcement (F4.1) |
| Sandbox с `failIfUnavailable` для unattended-запусков | SRC-CC-SANDBOX | принято | документация прямо называет это сценарием managed-развёртывания |
| `--bare` для CI-запусков | SRC-CC-HEADLESS | принято | исключает исполнение hooks/MCP из чужого site package (F4.11) |
| Reviewer-subagents в свежем контексте | SRC-CC-SUBAGENTS | принято | независимая проверка без загрязнения основного контекста |
| Готовые «awesome-claude-code» наборы правил и хуков | публичные репозитории | отклонено | недоступны из сессии; происхождение и лицензия не проверяемы; риск исполнения непроверенного кода |
| Готовые SEO-краулеры (screaming-frog-подобные, sitemap-генераторы npm) | npm/PyPI | отклонено для ядра | краулер фабрики должен проверять именно матрицу индексируемости и гейты статусов; внешние утилиты можно подключить позже как дополнительный источник сигнала |
| Playwright как движок браузерной приёмки | SRC-PLAYWRIGHT (документация недоступна), но сам пакет доступен из npm | принято условно | API стабилен и известен; спецификации написаны, запуск помечен как требующий установки пакета в среде исполнения |
