# SEO_KNOWLEDGE_PACK

**Провенанс.** Официальные источники (Google Search Central, Яндекс Вебмастер, web.dev,
Schema.org-гайдлайны, документация DLE) недоступны из этой сессии — egress-политика
организации отвечает 403 (F3.3). Поэтому нормативной базой пакета является мастер-промпт
пользователя v1.1 от 21.08.2026 (SRC-USER-MASTERPROMPT), требования которого перенесены
сюда без переформулирования смысла. Каждое правило помечено
`verified_against_official_docs: false` в `SEO_INDEXABILITY_MATRIX.yaml` и подлежит сверке
при открытии доступа к первоисточникам. Ни одно правило не взято из блога или пересказа.

## 1. URL и дубли (REQ-SEO-URL)

1. URL короткие, стабильные, человекочитаемые, в едином регистре, слова через дефис,
   без session/tracking ID.
2. До первого production freeze выбирается единственная политика: HTTPS, www/non-www,
   trailing slash, регистр, транслитерация, URL первой страницы пагинации. Политика
   фиксируется тестами (`tests/unit/test_url_policy.py`).
3. Все неканонические варианты → ровно один 301 на итоговый URL, без цепочек и циклов.
4. Каждая indexable-страница со статусом 200 имеет абсолютный self-canonical. Canonical
   не указывает на redirect, 4xx, `noindex`, другой язык или нерелевантную страницу.
5. Внутренние ссылки, sitemap, hreflang, OG и structured data используют один и тот же
   канонический URL.
6. Query-параметры делятся на три класса: меняющие канонический объект; допустимые
   индексируемые landing; неиндексируемые (sort/filter/view/tracking/session).
7. `robots.txt` не используется как средство защиты секретов; URL, с которого робот
   должен прочитать `noindex`, не закрывается в robots до подтверждения деиндексации.
8. Удалённая страница отдаёт честный 404 или 410. Пустой шаблон со статусом 200 — soft 404,
   запрещён.

## 2. Пагинация и подгрузка (REQ-SEO-PAGINATION)

1. Каждая страница пагинации имеет уникальный стабильный URL по одному утверждённому
   шаблону (`?page=N` **или** `/page/N/`), схемы не смешиваются.
2. Первая страница имеет один канонический URL; `?page=1` и прочие дубли редиректят на него.
3. Каждая полезная indexable-страница пагинации имеет self-canonical, а не canonical на page 1.
4. Последовательность связана настоящими `<a href>`-ссылками; роботы не обязаны нажимать
   «Показать ещё» и не выполняют scroll-события.
5. Infinite scroll и «Показать ещё» — только progressive enhancement поверх доступной
   серверной пагинации: каждый chunk открывается напрямую по URL и работает без JS-события.
6. Порядок выдачи детерминирован; определён tie-breaker, чтобы карточка не прыгала между
   страницами при одном snapshot данных.
7. Для page 2+ используется утверждённый шаблон title/H1/description с номером страницы;
   новый фактический текст не генерируется.
8. Out-of-range и нечисловые номера страниц не возвращают копию page 1: 404 либо
   нормализующий redirect по заранее зафиксированному правилу.
9. `rel=next/prev` допустим для навигационных клиентов, но crawlability доказывается
   обычными ссылками.

## 3. Категории, теги, фильтры, сортировки, поиск (REQ-SEO-FACETS)

1. Индексируемые landing-страницы — только из allowlist. Фильтр становится индексируемым
   лишь при подтверждённом назначении, стабильном URL, уникальном переданном контенте,
   self-canonical и внутренних ссылках.
2. Комбинаторные фильтры, сортировки, вид отображения, tracking-параметры и внутренний
   поиск по умолчанию не индексируются и не попадают в sitemap.
3. Порядок параметров нормализуется; повторяющиеся и неизвестные ключи запрещены —
   это предотвращает комбинаторный взрыв URL.
4. Пустые категории/теги/фильтры не публикуются как indexable 200.
5. Архивы, авторы и теги индексируются только при самостоятельной ценности, иначе
   `noindex,follow` либо отсутствие публичной страницы.
6. SEO landing-страницы не создаются автоматически из ключевых слов.

## 4. Metadata, заголовки, сниппеты (REQ-SEO-META)

1. Один понятный H1 и уникальный title на indexable-страницу, из переданных полей и
   утверждённых шаблонов.
2. Description точно описывает видимый контент; одна description на тысячи страниц и
   несуществующие факты запрещены.
3. Жёсткий лимит символов не является критерием истины: проверяются уникальность,
   читаемость, отсутствие обрезанных сущностей и шаблонного мусора.
4. Хлебные крошки видимы пользователю, построены из реальной иерархии и совпадают с
   `BreadcrumbList`.
5. Keyword stuffing, скрытый текст, doorway pages, клоакинг, подмена контента для роботов
   и имитация поведения пользователей запрещены.

## 5. Sitemap, robots, управление обходом (REQ-SEO-CRAWL)

1. Sitemap содержит только канонические indexable URL со статусом 200.
2. Исключены redirects, 4xx/5xx, `noindex`, фильтры/сортировки/поиск, test/staging и дубли.
3. Для крупного сайта — разделение по типам контента и sitemap index, с соблюдением
   действующих официальных лимитов, сжатия и кодировки.
4. `lastmod` меняется только при существенном изменении индексируемого контента, а не
   при каждом cron или деплое.
5. `robots.txt` ссылается на канонический sitemap и генерируется отдельно для
   staging и production. Staging закрыт авторизацией и `noindex`; один robots.txt
   защитой staging не считается.
6. Перед production robots, sitemap и выборка URL проверяются отдельными тестами.

## 6. Structured data и видеостраницы (REQ-SEO-SD)

1. Только типы, соответствующие видимому содержимому: `Organization`, `WebSite`,
   `BreadcrumbList`, `Article`/`NewsArticle`, `Movie`, `TVSeries`, `TVEpisode`,
   `VideoObject` — и только при фактической применимости.
2. Поля JSON-LD берутся из site/content package или документированного VK contract.
   Рейтинги, отзывы, просмотры, даты, длительность, актёры, `uploadDate`, `contentUrl`,
   `embedUrl`, thumbnails и availability не выдумываются.
3. Страница без доступного видео или где видео не является существенной видимой частью,
   не размечается как `VideoObject`.
4. Белый плеер и основное видео легко находимы на mobile, не спрятаны за несколькими
   действиями и одинаковы для робота и пользователя.
5. Preview/thumbnail — только с разрешённым стабильным URL и правами; proxy/rehost без
   явного разрешения запрещены.
6. Валидатор без ошибок не отменяет quality/policy review.

## 7. Качество контента массовой фабрики (REQ-SEO-QUALITY)

1. Массовое создание сайтов не должно превращаться в scaled content abuse: общий blueprint
   допустим, но каждый опубликованный сайт и каждый indexable URL решает реальную задачу
   пользователя и имеет переданные права/данные.
2. Один каталог и одни тексты не размножаются по множеству доменов. У каждого сайта
   фиксируются уникальные назначение, аудитория, бренд и контентный scope.
3. Страница не является пустой оболочкой вокруг плеера: понятная навигация, статус
   доступности, полезный контекст.
4. Полученные VK-данные не переписываются синонимайзером и не дополняются вымышленным
   AI-текстом ради уникальности.
5. Мимикрия под VK, правообладателя, телеканал или бренд запрещена — в домене, логотипе,
   title и интерфейсе.

## 8. Internal linking, media, mobile-first (REQ-SEO-LINKS)

1. Важные страницы достижимы обычными crawlable-ссылками; orphan indexable page — ошибка.
2. Крошки, категории, сезоны/эпизоды и related — только из переданных отношений.
3. Anchor text описывает целевую страницу; «сюда» и JS-only навигация не считаются связью.
4. Mobile и desktop имеют эквивалентный основной контент, metadata, robots и structured data.
5. Изображения и preview: стабильные URL, размеры/aspect ratio, responsive-варианты, alt
   из разрешённых данных; LCP-медиа не lazy-load; размеры резервируются против CLS.
6. Рекламные слоты резервируют размер, не перекрывают основной контент, не создают
   intrusive interstitials и не сдвигают плеер/заголовок после загрузки.

## 9. Пороговые значения производительности

Полевые цели (75-й перцентиль): LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1.
Lab-бюджеты фиксируются отдельно в `sites/<site_id>/package.yaml: acceptance.performance`
и не выдаются за полевые данные. Lighthouse-скор не является доказательством полевых CWV.

## 10. Условия `BLOCKED_SEO`

Критическая ошибка canonical/robots/sitemap; массовые дубли; soft 404; неиндексируемый
основной контент; недоступная пагинация; misleading structured data; мимикрия;
scaled-content pattern; публикация страницы без подтверждённой пользовательской ценности.
