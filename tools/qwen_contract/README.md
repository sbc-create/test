# Поставка рецептов Qwen: формат qwen-dish/1

С 23.10.2026 Qwen поставляет **одно блюдо — одну полноценную редакционную версию**.
Пять текстовых вариантов на тему больше не нужны. Старый архив (qwen-night/1) по-прежнему
читается тем же приёмником.

Образец: [`example/`](example/). Он проходит все проверки, кроме одной: источник —
`example.org`, поэтому приёмник останавливает его как `BLOCKED_RIGHTS`. Образец показывает
формат и никогда не публикуется.

## Как проверить поставку до отправки

```bash
python3 tools/qwen_recipes_intake.py check <каталог или архив поставки>
```

Код выхода 0 и `"status": "READY"` — можно отправлять. Код 1 и `NEEDS_FIX` — у блюда в поле `fix`
сказано, что исправить. Это те же правила, что при приёме, проверка ничего не записывает.

## Состав поставки

```
<SET_ID>/manifest.json           {"format": "qwen-dish/1", "set_id", "items": [{"dish_id", "file"}]}
<SET_ID>/dishes/<dish_id>.json   одно блюдо (поля ниже)
```

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `dish_id` | да | постоянный id блюда в поставках Qwen |
| `site` | да | `bestreciept.site` (повседневная еда) или `myfood.mobi` (выпечка и десерты) |
| `title`, `category` | да | название блюда и раздел |
| `source.url` | да | страница опубликованного рецепта, по которой взяты факты; без неё — `BLOCKED_RIGHTS` |
| `servings` | да | число порций из источника; неизвестно — блюдо не принимается, порции не придумываются |
| `prep_minutes`, `cook_minutes`, `total_minutes` | что есть в источнике | время в минутах |
| `oven` | для выпечки | `temperatures_c`, `bake_minutes`, `form` (размер формы), если они есть в источнике |
| `ingredients[]` | да | `name`, `quantity`, `quantity_max`?, `unit`, `note`?; масса или объём, а не «1 банка» |
| `source_steps[]` | да | шаги источника строками: по ним проверяется редакционный текст, на сайт они не идут |
| `editorial.intro` | да | своё вступление, не короче 40 знаков, без «я», «проверенный», «полезный», «идеальный» |
| `editorial.steps[]` | да | `instruction` — действие, `explanation`? — пояснение, `base_steps` — номера шагов источника (с 0), `readiness_cue`? — как понять, что готово |
| `editorial.display_names` | нет | `{"<индекс>": "название для показа"}` |
| `nutrition` | нет | примерная калорийность, только с расчётом (ниже) |
| `image_job` | нет | `look` — как выглядит подача по рецепту, `alt` — подпись для незрячих |

## Правила приёма

1. Факты — только из источника: количества, единицы, время, температура, размер формы,
   время остывания. Если чего-то нет, блюдо не публикуется. Значения по умолчанию не подставляются.
2. Каждый шаг источника покрыт по порядку. Шаги можно объединять или делить, но каждое действие,
   продукт, время и температура шага источника остаются в шагах версии.
3. `instruction` и `explanation` не вытесняют друг друга: на сайте шаг — это действие, а за ним пояснение.
   Число в пояснении (минуты, градусы) должно быть в шаге источника, иначе шаг не принимается.
4. Текст — пересказ: шаги, почти дословно повторяющие источник, не принимаются.
5. Одно блюдо — на одном сайте. Если такое блюдо уже есть на любом из двух сайтов, новая страница
   не создаётся, а блюдо уходит на сверку с опубликованным.
6. Нельзя: рейтинги, отзывы, автор, «готовили сами», «самый популярный», упоминания ИИ
   и служебные пометки.

## Калорийность

```json
"nutrition": {
  "kcal_per_serving": 230,
  "protein_g": 6.5, "fat_g": 7.5, "carbs_g": 34,
  "method": "расчёт по составу: сумма по ингредиентам / число порций",
  "data_source": "таблица химического состава продуктов, издание",
  "per_ingredient": [{"index": 0, "kcal": 626}, …]
}
```

* Нужны `kcal_per_serving`, `method` и `data_source` (по каким данным посчитано), а также известное число порций.
* Если есть `per_ingredient`, то это строка на каждый ингредиент, и сумма, делённая на число порций,
  должна сходиться с `kcal_per_serving` (допуск 5 %).
* Неполный расчёт не блокирует блюдо. Калорийность просто не переносится, причина попадает
  в `warnings` отчёта.
* На сайте показывается «≈ N ккал на порцию» с основанием расчёта. При пересчёте порций меняется
  калорийность всего блюда, а на порцию она остаётся той же.

## Изображения

Приёмник выдаёт каждому принятому блюду `recipe_id` — id материала на сайте. К нему привязаны
задания на изображение (`data/media/image-jobs.json`) и приём файлов
(`python3 -m fooddaily.media intake --dir … --tool … --license … [--only <slug>]`). Изображения
в поставку рецептов не входят.
