## Три цикла между подсистемами

Считаны разбором `ast`, а не поиском по строкам: слово «import» встречается и
в комментариях, и в примерах.

```
factory.lords → factory.build       → factory.lords
factory.lords → factory.recs        → factory.lords
factory.lords → factory.site_engine → factory.lords
```

Цикл — это не вопрос стиля. Он означает, что ни одну из двух подсистем нельзя
вынести, не вынеся вторую: разрезать нечего, пока связь идёт в обе стороны.

Третий цикл — самый тяжёлый: `site_engine` это управляющий слой и админка,
`lords` — одна из витрин. Управляющий слой, зависящий от конкретной витрины, не
может быть общим для всех.

**И держится он на одном импорте.** В сторону «управление → витрина» ведёт
ровно одна связь:

```
factory.site_engine.adapters.lords_seo_binding → factory.lords.live_catalog
```

Обратно — четыре:

```
factory.lords.content_live  → factory.site_engine
factory.lords.fast_path     → factory.site_engine
factory.lords.live_catalog  → factory.site_engine.catalog_identity
factory.lords.player        → factory.site_engine
```

Обратное направление законно: витрина вправе зависеть от общих контрактов.
Прямое — нет, и оно единственное. Это первый кандидат на разрыв, и он дешёвый.

## Общее изменяемое состояние

Литеральных путей, названных двумя подсистемами, один: `var/targets/`
(`factory.site_engine` и `factory.targets`). Мало — потому что пути идут через
`factory.paths`, и считать надо по нему.

Из 19 объявленных областей состояния:

* 15 имеют одного потребителя;
* 3 общих: `automation` (`factory`, `factory.targets`), `knowledge`
  (`factory`, `factory.seo`), `schemas` (`factory`, `factory.secret_hub`).

Оговорка, без которой число вводит в заблуждение: «один потребитель» у
большинства областей — это `factory`, то есть двадцать семь плоских модулей
верхнего уровня. Они трогают почти всё, и именно они, а не пакеты, сейчас
размывают границы.

## Что из этого следует для порядка работ

1. Разрыв цикла `site_engine ↔ lords` начинается с одного импорта и не требует
   перемещения файлов.
2. Назначение владельца трём общим областям состояния — предусловие любого
   переноса, а не его следствие.
3. Двадцать семь плоских модулей — главный источник размытых границ; их
   распределение по доменам и есть содержание последующих циклов.
4. Перемещать нечего до появления characterization-тестов: ни один из трёх
   циклов сейчас не закреплён проверкой, и разрыв нельзя будет отличить от
   поломки.
