Контракты: `yummy-read-model/1.0.0`, `yummy-canonical-link/1.0.0`,
`yummy-content-store/1.0.0`. Ветка `claude/yummy-content-contour-36`.

Хранилище собрано в стороне (`state/yummy-content.sqlite3`). Боевые базы
только читались; ни одна строка в них не записана.

## 1. Контракт для шаблонного агента

Общее правило: **шаблон не собирает адрес.** Каждая карточка приходит с
`entityId` и `canonicalPath`. Карточка без них не существует — она не
попадает в проекцию вовсе, а не приходит пустой.

Адрес — **без завершающей косой черты**: `/anime/{slug}`. Это измерено, а не
выбрано: приложение отвечает на `/anime/tofu-boy/` кодом **308** и переводит
на форму без неё. Косая черта означала бы лишний переход на каждой карточке.

### Поверхности

| поверхность | функция | чем наполняется |
|---|---|---|
| Актуальное | `readmodel.актуальное(соед, предел)` | формула ниже |
| Новые серии | `readmodel.новые_серии(соед, предел)` | только события `episode_event` |
| Сейчас выходит | `readmodel.сейчас_выходит(соед, предел)` | только `airing_status='CONFIRMED_ONGOING'` |
| Новости | `readmodel.новости(соед, "news")` | `editorial_post` |
| Анонсы | `readmodel.новости(соед, "announcement")` | `editorial_post` |
| Внешние рейтинги | `readmodel.внешние_рейтинги(соед, entity_id)` | `external_rating` |
| Оценка пользователя | `readmodel.пользовательский_рейтинг(соед, entity_id, user_id)` | `user_rating` |
| Резолвер адреса | `readmodel.разрешить_адрес(соед, entity_id)` | `entity` |

### Карточка

```json
{"entityId": "019efa4c-…", "canonicalPath": "/anime/neobyatnyy-okean-3",
 "title": "Необъятный океан 3", "poster": "https://…/p.webp",
 "year": 2026, "kind": "SERIES", "publishedAt": "2026-06-24T15:43:30Z",
 "contract": "yummy-read-model/1.0.0"}
```

«Новые серии» добавляют `season`, `episode`, `voice`, `sourceEventAt`,
`publishedAt`, `source`. **`sourceEventAt` — время выхода серии, `publishedAt`
— время нашей публикации. Подменять первое вторым запрещено**, и на это есть
проверка.

«Сейчас выходит» добавляет `airingStatus`, `lastEpisodeAt`, `nextEpisodeAt`,
`episodesReleased`, `source`, `checkedAt`, `ttlSeconds`.

### Формула «Актуального» — зафиксирована и воспроизводима

```
балл = 0.50·свежесть + 0.35·рейтинг + 0.15·показ
свежесть = 0.5 ^ (дней_с_публикации / 14)
рейтинг  = среднее по провайдерам от (n·v + 500·7.0) / (n + 500) / 10
показ    = 1, если airing_status = CONFIRMED_ONGOING, иначе 0
```

Байесовское сглаживание с порогом 500 голосов — защита от источников с малой
выборкой: три голоса с десяткой не обгоняют тысячу голосов с восьмёркой (есть
проверка). **Голоса неизвестны — считаются нулём**, и рейтинг стягивается к
априорному 7.0: иначе источник без счётчика голосов обгонял бы источник с ним.

Каждая карточка отдаёт `scoreParts` — разложение балла. Раздел, который нельзя
разложить, нельзя и оспорить.

### Пустой блок — это ответ

Пустая лента означает **отсутствие событий**, а не отсутствие данных, и
подменять её общим каталогом запрещено. Сейчас пусты «Новые серии» и «Сейчас
выходит»: источник не даёт ни событий серий, ни подтверждённого статуса
показа. Заполнить их «похожим» — значит соврать.

### API оценок

```
readmodel.поставить_оценку(соед, user_id, entity_id, value) -> {ok, …}
   VALUE_OUT_OF_RANGE — вне шкалы 1..10
   ENTITY_UNKNOWN     — произведения нет в контуре
```
Повторная оценка тем же пользователем обновляет строку, а не добавляет
вторую. Личная оценка и внешний рейтинг — **разные сущности в разных
таблицах**; смешивать их нельзя.

## 2. ТЗ для SEO-агента

SEO-модуль **не выдумывает ни новостей, ни дат**. Он получает подтверждённые
данные из контентного контура и только оформляет их.

Обязательные поля новости или анонса — все, без исключений:

| поле | правило |
|---|---|
| `postId` | стабильный, выводится из `(source, source_key)`; повторная выборка того же материала обязана дать ту же строку |
| `source` | кто дал материал |
| `title`, `summary` | текст |
| `publishedAt` | время источника, не время сборки |
| `updatedAt` | время последней правки |
| `canonicalPath` | адрес; выдумывать нельзя |
| `provenance` | откуда взято; самоцитата доказательством не является |
| `relatedEntityIds` | связанные произведения, каждое — существующий `entity_id` |
| `image` | необязательно; отсутствие — не пустая строка, а `null` |

Дедупликация — по `UNIQUE (source, source_key)`. Проверка на повторную подачу
есть и проходит.

Freshness SLA: новость считается протухшей через 48 часов без обновления
`updatedAt`; протухшая не показывается, но и не удаляется.

**Чего SEO-агенту делать нельзя:** заводить второй контур новостей, ставить
`publishedAt` из времени пересборки, публиковать материал без
`canonicalPath` или с `relatedEntityIds`, которых нет в `entity`.

## 3. План backfill и безопасного включения

### Что сейчас доказано

* импорт 7299 сущностей из 7314 маршрутов за 2,3 с;
* повторный импорт даёт `new: 0` и не двигает `first_seen_at`;
* пустая выборка не затирает данные, уходит в DLQ с кодом `EMPTY_SOURCE`;
* обвал источника отклоняется целиком по коду `SOURCE_SHRINK`;
* 12 канонических адресов отвечают ровно `200` на живом приложении.

### 463 записи контент-отдела

Их в наших хранилищах нет: `STATUS_DRAFT`, `cvhSent`, `cvhError` не
встречаются нигде на хосте. `cvhSent` и `cvhError` пусты **одновременно** —
это «отправка не запускалась», а не «отправка не удалась». Backfill с нашей
стороны для них невозможен: пока записи не уйдут в CVH, импортировать нечего.

Порядок, когда они появятся в CVH:

1. `build.py` — импорт идемпотентен, повторный прогон безопасен;
2. записи без канонического маршрута отклоняются (`rejected`), а не публикуются;
3. проверка `test_3` подтверждает отсутствие дублей при повторе.

### Включение — три шага, каждый обратим

1. **Тень.** Собирать контур по таймеру рядом с нынешней проекцией, не
   переключая витрину. Сравнивать состав и адреса.
2. **Сверка.** Прогнать `test_1`/`test_2` по полной выборке, а не по 12
   карточкам: каждая карточка обязана отвечать `200`.
3. **Переключение.** Только после решения владельца. Откат — возврат к
   прежнему файлу проекции.

Шаги 1–3 не выполнены: задание запрещает переключать production.

### Чего в контуре нет и почему

`episode_event` и `airing_status` пусты: каталог поставщика не отдаёт ни
событий серий, ни статуса показа. Механизм их приёма реализован и покрыт
проверками (`test_4`, `test_4b`, `test_5`), но источника нет. Нужен доступ к
detail-выдаче CVH с полями серий и статуса — это внешний блокер, и он назван,
а не обойдён выдумыванием данных.
