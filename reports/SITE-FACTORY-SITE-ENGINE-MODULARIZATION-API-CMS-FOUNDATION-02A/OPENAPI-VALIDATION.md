# Сверка OpenAPI с поведением

Описание порождается из кода: `factory/site_engine/api/openapi.py`. Файл —
`schemas/site-engine/openapi-v1.json`, 11 маршрутов, OpenAPI 3.1.

Отдельно написанное описание расходится с кодом за одну итерацию, поэтому
источник здесь один, а тесты сверяют результат.

## Что проверяется

| Проверка | Смысл |
| --- | --- |
| каждый описанный маршрут отвечает | описание, обещающее несуществующий маршрут, хуже отсутствия описания |
| у каждого маршрута описан 404 | что бывает при отсутствии — часть контракта |
| у страничных маршрутов описаны пределы и 400 | предел должен быть назван, а не подразумеваться |
| файл в репозитории совпадает с порождённым | иначе файл отстаёт от кода |
| тело ошибки соответствует схеме `Error` | одна форма у всех ошибок |
| краткая карточка соответствует схеме `TitleBrief` | в том числе `available_episodes: null` |

Схемы проверяются `jsonschema`, а не сравнением строк.

## Что описание говорит прямо

`available_episodes` объявлен как `["integer", "null"]`. Это не послабление
типа, а утверждение: неизвестное число серий — не ноль.

`limit` имеет `maximum`, и у страничных маршрутов описан ответ 400. Молчаливое
усечение до предела контрактом не предусмотрено.

## Результат

7 проверок, все проходят.
