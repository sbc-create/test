# Новый род сайта

`demo-books` — профиль сайта, не похожего ни на витрину Lords, ни на
аниме-портал. Заведён, чтобы проверить утверждение, а не украсить отчёт: движок
обязан принять новый род сайта без правки ядра.

## Что в нём необычного

Ни собственного загрузчика, ни поставщика. Контент приходит готовым:

```json
"normalized_content_source": {"kind": "site-engine-api", "ref": "site-engine/v1"},
"content_providers": [],
"enabled_modules": ["content-catalog", "homepage-shelves", "seo",
                    "site-configuration", "cache-invalidation",
                    "monitoring-audit", "renderer-adapters"]
```

Семь модулей вместо двенадцати у Lords и тринадцати у Yummy. Тип сайта —
`reading-catalog`, направление — `book`. Ни одной строки кода под него не
написано.

## Что он поймал

Сборка этого профиля обнаружила в гейте ту же ошибку, которую владелец уже
однажды поправлял для SEO. Правило требовало модуль `provider-adapters` у
всякого сайта. Сайт, берущий готовый контент из общего API, к поставщику не
ходит вовсе — требовать от него адаптер значит требовать код, которому нечего
делать.

Исправлено: адаптер поставщика требуется тому, кто к поставщику ходит
(`content-ingestion` или непустые `content_providers`); заявленный без
надобности — отклоняется.

Схема профиля правилась в ту же сторону: `content_providers` может быть пустым,
но пустыми не могут быть оба — либо свои поставщики, либо объявленный источник
готового контента. Сайт без содержимого не сайт.

## Из чего создаётся сайт

| Составляющая | Где живёт |
| --- | --- |
| профиль | `config/site-profiles/<site_id>.json` |
| набор модулей | `enabled_modules` в профиле |
| адаптер поставщика | реестр `provider-adapters`, либо источник готового контента |
| адаптер рендерера | реестр `renderer-adapters`, выбор по `render_mode` и `site_type` |
| тема | `theme` в профиле |
| профиль SEO | `seo_profile` |
| политика кэша | `cache_policy` |
| политика релизов | `release_policy` |
| health и покрытие | `health_endpoint`, `coverage_endpoint` |
| флаги | `feature_flags` |

## Проверено

Профиль проходит ARCHITECTURE_GATE и BOUNDARY_GATE наравне с шестью
действующими. API отдаёт по нему `/api/v1/sites/demo-books` с
`normalized_content: site-engine-api`.

Домен не регистрировался, сайт не выкладывался. Профиль объявляет
`demo-books.invalid` — зарезервированную зону, которая не может существовать.
Отдельный тест проверяет, что ни один недействующий профиль не заявляет домен
действующего сайта.
