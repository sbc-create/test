# Редакционный слой CMS

Реализовано: `factory/site_engine/editorial.py`, `factory/site_engine/audit.py`.
Тесты: `tests/unit/test_site_engine_editorial.py` (18).

## Правило, из которого следует всё остальное

**Данные поставщика доступны только для чтения.** Редактор не исправляет
карточку — он объявляет правку, и правка накладывается при показе. Поэтому
повторный обход не затирает работу редактора, а снятие правки возвращает ровно
то, что сообщил источник.

Это выражено типом, а не соглашением: `Title.with_overrides` возвращает копию и
отказывается трогать поля, принадлежащие поставщику. Список правимых полей
закрыт: `name`, `original_name`, `poster_url`, `year`, `kind`. Правка сезонов
или счётчиков серий означала бы, что витрина сообщает о содержимом небывшее.

## Модели

`EditorialOverride`, `Draft`, `Revision`, `Publication`, `PublicationTarget`,
`AuditEvent`, `Role`, `Permission`, `PreviewToken`, `BulkOperation`, `ChangeSet`.

## Роли и права

| Роль | Права |
| --- | --- |
| `viewer` | чтение |
| `editor` | чтение, правка черновика |
| `publisher` | + публикация, снятие, откат, сброс кэша |
| `admin` | всё, включая массовые операции и запуск обхода |

Область сайтов входит в личность (`Principal.site_ids`), а не проверяется
где-то потом: иначе редактор одного сайта однажды опубликует на всех шести.

## Сценарии и их свойства

| Сценарий | Свойство, закреплённое тестом |
| --- | --- |
| создание черновика | повтор с тем же ключом идемпотентности не создаёт второй |
| правка черновика | расхождение версий — конфликт, а не потеря чужой работы |
| предпросмотр | LIVE не меняется; чужой токен не подходит |
| публикация | список сайтов обязателен и явен; «на все» не бывает |
| снятие | показ возвращается к данным поставщика |
| откат | возвращает конкретную ревизию; несуществующая — отказ |
| массовая операция | без сухого прогона не применяется |

Каждое изменение пишется в аудит с автором, временем, причиной и отпечатком.
Правка без причины не принимается: через месяц никто не вспомнит, почему
название другое.

## Write-контракты: описаны, не опубликованы

Публичных изменяющих маршрутов нет и не будет, пока нет настоящей авторизации.
Ниже — форма будущих операций; каждая требует личности, области сайтов, ключа
идемпотентности, ожидаемой версии, сухого прогона и записи в аудит.

| Операция | Право | Особенности |
| --- | --- | --- |
| создать правку | `draft:write` | ключ идемпотентности |
| изменить черновик | `draft:write` | ожидаемая версия |
| предпросмотр | `read` | токен, срок действия |
| опубликовать | `publish` | явный список сайтов |
| снять с публикации | `unpublish` | возврат к данным поставщика |
| откатить ревизию | `rollback` | номер ревизии обязателен |
| закрепить на полке | `draft:write` | закрепление — тоже правка показа |
| скрыть ошибочную запись | `publish` | скрытие не удаляет данные поставщика |
| изменить SEO-текст | `draft:write` | предмет стыковки с SEO |
| сбросить кэш | `cache:invalidate` | поддерживает сухой прогон |
| запустить обход | `ingestion:trigger` | не изменяет данные поставщика |
| массовая операция | `bulk` | сухой прогон обязателен |

## Чего нет намеренно

Админ-панели. Полноценный интерфейс без решённой авторизации — это дыра, а не
удобство. Слой сценариев готов и покрыт тестами; панель — предмет `02B`.
