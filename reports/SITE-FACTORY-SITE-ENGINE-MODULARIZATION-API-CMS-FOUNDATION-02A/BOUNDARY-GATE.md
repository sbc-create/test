# Гейт границ модулей

`factory/site_engine/boundaries.py`. Тесты:
`tests/unit/test_site_engine_boundaries.py` (14).

## Что проверяется

| № | Правило |
| --- | --- |
| 1 | Модуль обращается к публичному интерфейсу другого, а не к его внутренностям |
| 2 | Модуль не импортирует того, что запрещено ему реестром |
| 3 | `core-contracts` не зависит ни от чего |
| 4 | Универсальный модуль не называет конкретный сайт или технологию |
| 5 | Между модулями нет взаимных зависимостей |
| 6 | Заявленная в реестре реализация существует |
| 7 | `CONTRACT_ONLY` не объявляет реализацию |

Правила берутся из `config/site-engine/module-registry.json` — того же файла, из
которого порождается документация. Разойтись они не могут.

## Гейт обязан падать

Проверка, которая проходит всегда, ничего не проверяет. Поэтому в тестах гейт
сначала ломают о заведомо неверные фикстуры:

* ядро с зависимостью от адаптера поставщика;
* загрузчик, потянувший рендерер (ingestion, меняющий вёрстку);
* хранилище, потянувшее адаптер поставщика (владелец данных, ставший клиентом);
* обращение к `api.app` в обход `api`;
* реестр, объявляющий несуществующий файл;
* модуль `CONTRACT_ONLY` с реализацией.

Каждая фикстура роняет гейт по своей причине, а не по общей.

## Две поправки, сделанные после первого запуска

**Разделение адаптеров по ролям.** Поставщик и рендерер — разные модули с
разными разрешёнными зависимостями. Пока оба жили в одном файле, файл требовал
прав обоих сразу, то есть границы между ними не существовало. Теперь
`adapters/lords.py` и `adapters/lords_renderer.py` — разные файлы.

**Слова предметной области ищутся в коде, а не в объяснениях.** Первая редакция
проверки читала комментарий «витрины Lords месяцами показывали старый каталог»
как нарушение. Правило запрещает ядру вести себя по-разному для разных сайтов,
а не упоминать их в объяснении причины; причина ценнее формальной чистоты
текста. Комментарии и строки документации теперь отбрасываются токенизатором, а
литерал `"lords-01"` внутри условия остаётся нарушением и ловится тестом.

## Правило, которое пришлось сделать работающим

Проверка «импорт лезет во внутренние файлы» при плоской раскладке модулей не
могла сработать никогда: путей глубже двух уровней в пакете просто нет. Правило,
которое нельзя нарушить, выглядит как покрытие, не будучи им. Теперь названы
пакеты с публичным интерфейсом (`api`), и обращение к их внутренностям снаружи
отклоняется — а внутри самого пакета остаётся законным, иначе интерфейс нечем
было бы собрать.
