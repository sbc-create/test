# Следующие шаги

## Немедленно после завершения цикла Lords

1. Установить в production: `lords-fast-render.py`, обновлённые `fast_path.py`,
   `fingerprint.py`, `lords-render-gate.py`, `lords-content-refresh.sh`.
2. Первый цикл: снимка произведений нет → полный рендер → снимок записан.
3. Второй и третий циклы: убедиться, что неизменившийся цикл даёт
   `rendered_pages=0` и не создаёт релиза.
4. Зафиксировать три подряд идущих timer-цикла с временами и результатами.

Ни один из шагов не требует решения владельца.

## Предложение по расписанию Lords

Период таймера — 11 часов, цикл — около девяти. Витрина обновляется примерно раз
в двадцать часов.

Быстрый путь этого сам не меняет: он сокращает работу **внутри** цикла, а не
приближает его начало. Но он делает частый таймер возможным: неизменившийся цикл
теперь стоит 53 секунды, а не девять часов.

Разумный следующий шаг — уменьшить период до 15–30 минут и убедиться, что
неизменившиеся циклы действительно дёшевы. Это решение владельца: оно меняет
нагрузку на провайдера.

## Ближайшая задача

| Пункт | Почему сейчас |
| --- | --- |
| SLA на настоящем событии Lords | механизм готов, недостаёт события |
| Исполнитель команд Control Plane | сейчас команда принимается и остаётся `DRAFT`; исполнение — отдельный контур с отдельными правами |
| Хостовые сценарии Yummy на одной ревизии с контейнерами | расхождение не видно ни по одной ревизии |
| Источники `shelves`, `schedules`, `announcements`, `ratings`, `media`, `seo-documents` в API | сейчас отвечают 501 — честно, но неполно |

## Что нужно для поточного создания сайтов

Сухой прогон уже проходит девять шагов. Чтобы создать сайт **действительно**
поточно, недостаёт трёх вещей:

1. **Исполнителя** команды `site.create`: сейчас она принимается, но каталог
   сайта, домен и юнит создаются руками.
2. **Темы как данных.** Тема сейчас — код в `factory/lords` и `blueprints/`.
   Новый сайт с новой темой требует программиста, а не оператора.
3. **Автоматической проверки визуальной регрессии** для новой темы: сейчас
   геометрия сверяется сличением с предыдущим образом, что предполагает наличие
   предыдущего.

## Чего делать не стоит

Выносить движки в сетевые службы. Границы уже проверяются автоматически и
соблюдаются; сеть добавит отказов, а не порядка. Разделение оправдано, когда
модуль потребует отдельного масштабирования, — сейчас такого нет.
