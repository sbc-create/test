# Решения food-daily

| ID | Решение | Почему | Где |
| --- | --- | --- | --- |
| FD-01 | **Конфликт с CLOSED_WORLD.** CLAUDE.md запрещает поиск и скрапинг в интернете; ТЗ владельца TEMPLATE-FOOD-DAILY-01 прямо поручает аудит 12 перечисленных сайтов, подсчёт страниц и пилотный импорт. Решение: выполнять только для хостов из ТЗ, внесённых в `inventory/network-allowlist.yaml` с провенансом, только GET, robots.txt по RFC 9309, 1 запрос на хост. Новых хостов по своей инициативе не добавлял (условия Еды на `help.rambler.ru` не открывались). | Явное поручение владельца — источник выше правила общего режима; конфликт записан, а не обойдён молча. Production этим решением не затрагивается. | `inventory/network-allowlist.yaml`, `config/crawl.yaml` |
| FD-02 | **Права на контент.** Публично — только факты источника (продукты, количества, порции, время, порядок действий) и собственный текст со ссылкой на источник. Исходные тексты — в `var/food-daily/private` (0700, вне git и сборки, 30 дней, `import purge-expired`). Фото и видео источников не скачиваются и не публикуются. | Условия gastronom разрешают только цитирование со ссылкой; условия Еды не проверены; у 1000.menu условий перепечатки нет. **Production блокирован (BLOCKED_RIGHTS)** до юридической оценки этого режима. | `fooddaily/pipeline.py`, `editorial.snapshot`, `test_snapshot_belongs_to_site_and_has_no_source_text` |
| FD-03 | Свой разбор robots.txt вместо `urllib.robotparser`. | Стандартный модуль не понимает `*` и `$` и ошибся в обе стороны: закрыл открытый sitemap food.ru и пропустил бы закрытые шаблонами адреса. | `fooddaily/robots.py` |
| FD-04 | Агент не подменяется, CAPTCHA и 403/406 не обходятся. | edimdoma отвечает 406 на sitemap, russianfood после обхода — 403. Это ограничения источника; охват помечен `partial`. | `docs/audit/competitor-audit.md` |
| FD-05 | Живого API к Qwen нет — файловый контур заданий; черновики пилота написаны сессией Claude с `producer.mode=manual_standin`. | Обратного канала фабрика → srv-qwen нет. Выдавать черновики за Qwen запрещено; режим хранится в версии. | `fooddaily/qwen.py`, `docs/INTEGRATIONS.md` |
| FD-06 | Проверки импорта сильнее схемы: пропорции и количества берутся только из фактов, шаги покрывают исходные по порядку, числа времени/температуры — только из исходных шагов, запрет 8 слов подряд из исходника, запрет рейтингов/калорий/«проверено на кухне». | Это и есть «сохранять пропорции, порядок и условия» и «не копировать текст» в проверяемом виде. | `qwen.validate`, `tests/test_pipeline.py` |
| FD-07 | Сопоставление тем — по префиксу исходного токена слага, а не по скелету без гласных. | Скелет склеивал tost/testo, olive/lavandovyj и превращал «uha» в пустую строку: 16 из 214 записей пилота (7,5 %) получили чужую тему. Записи перепривязаны (`import retopic`). | `fooddaily/topics.py::term` |
| FD-08 | Ворота публикации отдельно от импорта: неправдоподобные количества («400 л бульона», «100 стаканов сливок») не пускают материал в preview. | Ошибку единиц источника нельзя «исправить» догадкой; черновик виден редактору, но не читателю. | `fooddaily/quality.py` |
| FD-09 | Рецензент — только человек; новая версия снимает одобрение; журнал конфликта пишется вне отменённой транзакции. | Последнее — дефект, найденный тестом: откат транзакции стирал запись `version_conflict`. | `editorial.review`, `store.add_version` |
| FD-10 | Без `image` в Recipe JSON-LD и без video-страниц. | Фото с подтверждёнными правами нет, роликов нет; иллюстрация раздела — не фото блюда. Расширенный результат Recipe недоступен до своих фото — известное ограничение. | `fooddaily/seo.py`, `docs/SEO-MATRIX.md` |
| FD-11 | SSR на Python + Jinja2, одна файловая БД, процесс на петле, без Compose. | Минимум общей инфраструктуры; ничего не трогает в общем Docker; сборка артефакта — из `git archive` только этого каталога. | `fooddaily/server.py`, `fooddaily/build.py` |
| FD-12 | Preview закрыт режимом, а не только robots.txt: `X-Robots-Tag` и meta noindex на всех ответах, bind только на петлю, редактор за паролем. Production — отдельный переключатель, требующий домена. | robots.txt не защищает доступ; без домена production невозможен (BLOCKED_INPUT). | `config/site.yaml`, `test_preview_is_closed`, `test_production_without_domain_is_blocked` |
| FD-13 | Конфликт FD-01 записан здесь, а не в `knowledge/DECISIONS.md`. | Центральный журнал входит в замороженную базу знаний: строка D128 сломала `KNOWLEDGE_FREEZE` и заблокировала пайплайн (BLOCKED_INPUT в `test_authorization`). Изменение `knowledge/` — только через `/research-freeze`; это handoff, а не правка этой ветки. | `docs/ISOLATION.md` |
| FD-B1 | Вариант B `fridge-first` — ветка `claude/template-food-daily-b` от A (066688b), порт 8863, свои `fridge.css`/`fridge.js`, ключи `fdb.*`, отдельный путь секрета редактора. | Изоляция вариантов. | `config/site.yaml`, `OWNERSHIP.yaml` |
| FD-B2 | Подбор «что есть дома» — по продуктам-темам рецепта (теги), а не по полному составу: «Из продуктов списка больше ничего не нужно» не значит «есть всё». | Честность: соль, масло, лаваш и т. п. в темы не входят. | `views.py::fridge`, `fridge.html` |
| FD-B3 | `/iz-holodilnika/` без параметров индексируется; с параметрами — noindex без canonical; неизвестный продукт — 400 и сообщение. | Бесконечные сочетания не индексируются. | `server.py::fridge` |
| FD-B4 | Каталог — таблица с сортировкой (`sort=vremya|nazvanie`; неизвестное значение игнорируется); сортировка = фильтр (noindex). Рецепты без времени — в конце. | Компактный просмотр; не индексировать перестановки. | `server.py`, `catalog.html` |
| FD-B5 | Модальный режим готовки A заменён отметками шагов на самой странице (сохраняются, сброс). Два теста вёрстки A перенесены на структуру B с теми же инвариантами. | Другая композиция рецепта; тесты не удалялись. | `recipe.html`, `tests/test_site_seo.py` |
