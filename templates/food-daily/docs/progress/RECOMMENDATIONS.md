# Рекомендации: какой вариант брать за основу

Предложение исполнителя для просмотра владельцем; варианты A/B/C остаются альтернативами, ничего не слито.
Основание — проверенные действия из `verification-*.json` (коммиты в галерее), sitemap живых превью и скриншоты главных.

Общее наблюдение: C у 9 сайтов построен на A, у games-survival — на B, и **все проверенные действия базы есть в приёмке C**
(сверено по ключам `actions`/`scenarios`). Поэтому выбор C ничего не теряет из базы; то, что есть только в другом варианте,
перечислено в «перенести». Там, где B предлагает иной основной сценарий (food-baking, food-appliances), рекомендую B.
Вес страниц у всех вариантов мал (HTML главной 3,5–17 КБ, JS ≤ 12 КБ), лабораторный LCP ≤ 636 мс — на выбор это не влияет.

## food-daily: C party-list

- Все действия A есть и в C: карточки, фильтр, пересчёт порций, режим готовки, избранное, покупки; плюс 10 действий списка на компанию — всего 36 (A 26, B 31).
- Индексируемая поверхность у B и C одинакова (52 URL в sitemap), так что выбор C ничего не отнимает у SEO.
- Пересчёт на 1–20 гостей — единственный инструмент сети, который суммирует несколько рецептов; ввод проверяется (400 с role=alert на плохое число гостей).

Перенести:

- B: страница «Что есть дома» (подбор с недостающим) — самый частый бытовой сценарий; в A/C есть только чипсы продуктов в поиске.
- B: каталог-таблица с сортировкой по времени — как второй вид каталога.

## food-weekly: C own-week

## food-appliances: B step-console

- 30 действий, 13 только в B: настройка прибора в шаге источника, таймер на время шага, отметки с сохранением, таблица сравнения всех рецептов.
- Главная претензия к конкурентам (аудит): параметры теряются в тексте — B ставит их рядом с шагом, где их назвал источник.
- Без JS шаги и настройки видны, таймеры и отметки корректно скрыты (nojs_steps_and_settings, nojs_timers_and_marks_hidden).

Перенести:

- A/C: табло «режим / °C / время» в начале рецепта со ссылками на шаги.
- C: очередь нескольких блюд по прибору и температуре — вторичный сценарий.

## Что потребуется после решения

- Слить выбранный вариант: для C — сначала его базу (A, у games-survival — B), затем C; пробное слияние A → B у games-rpg дало конфликты в `quest/qa.py` и `templates/entry.html`, их разрешать при выборе.
- Перенос функций из других вариантов — отдельными коммитами с приёмкой на актуальном коммите.
- Production по-прежнему заблокирован (BLOCKED_INPUT: нет домена и `production_authorized`).
