# Аудит перед шаблоном food-appliances («Готовим в технике»)

Замеры: `python3 -m techkitchen.audit` → `docs/audit-measurements.json`
(2026-10-12T06:54:57Z, серверный HTML без JS, 11 GET-запросов, только хосты из
`inventory/network-allowlist.yaml`, robots.txt соблюдён, одна загрузка на страницу).
Счётчики — грубые маркеры по тексту страницы, не оценка качества.

## Наблюдения

1. **SharkNinja.** Навигация строится по прибору, режим назван словами прибора
   (Air Fry, Bake, Roast): на хабах 125–218 упоминаний режима. Но в серверном HTML нет ни
   температуры, ни времени — всё в карточках, которые подгружаются по пути
   `/on/demandware.store/…`, а он закрыт robots.txt. Отдельные рецепты мы не загружали.
2. **1000.menu.** Режимы и время есть в тексте шага. Температура в тексте шага
   встречается редко (0 совпадений шаблона «N °C/градусов» на двух страницах). На странице
   рецепта 88 рекламных маркеров, параметры прибора теряются между блоками.
3. **Еда.** Параметры — только внутри текста шагов, сводки «режим / t° / время» нет.
   В категории приборы смешаны: мультиварка, аэрогриль и духовка в одной ленте.
4. **Общее.** Ни один референс не даёт в одном месте «прибор → режим → температура → время
   → какой шаг». Пользователю приходится перечитывать шаги, стоя у прибора.

## Что сделано лучше (5)

1. **Табло прибора** в начале рецепта: режим, температура и время в приборе. Каждое значение —
   ссылка на шаг, откуда оно взято. Тест `test_parameters_link_to_steps_of_same_recipe`.
2. **Режимы только из источника.** Валидатор черновика отклоняет режим в кавычках, которого
   нет в шагах источника, и число, которого нет в соответствующем шаге (`drafts.validate`).
   Пустое значение показывается как «не назван» / «не указана», а не подставляется.
3. **Страницы режимов** `/rezhim/<прибор>-<режим>/` появляются только при ≥2 рецептах.
   Разделы прибора × категория — тоже от 2 рецептов, иначе 404. Пустых страниц-заглушек нет.
4. **Лёгкий серверный HTML без JS и без рекламы:** весь рецепт, табло и поиск работают с
   выключенным JavaScript (сценарии `nojs_*` в `verification-browser-qa.json`).
5. **Инструкция «Как читать режимы»** объясняет, что названия программ различаются у
   моделей. Модели приборов не выдумываются: в рецептах их нет, потому что их нет в источнике.
