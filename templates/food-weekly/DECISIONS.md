# Решения food-weekly

| ID | Решение | Почему |
| --- | --- | --- |
| FW-01 | Рецепты не копируются: план ссылается на материал food-daily по ленте `recipe-catalog/1`. | Задание: меню недели связывает рецепты, а не создаёт их дубли. |
| FW-02 | Ссылки строятся по реестру `config/network.yaml`; production-адресов нет — в preview ссылки ведут в закрытый preview соседа (`preview_adapter`). | Домены не выдумываются; статус связи виден в подвале и отчёте. |
| FW-03 | Список покупок: количество × люди / порции рецепта; одинаковые продукты складываются только при совпадении единицы; объединение названий — явная таблица; вода не покупается. | Перевод граммов в штуки был бы выдумкой; «яйцо» и «яйца» — один продукт, «сливки» и «сливки 33 %» — нет. |
| FW-04 | Замена блюда — GET-параметр, работает без JS; замена только в пределах приёма пищи; недопустимая отклоняется с пояснением. | Состояние в адресе, без регистрации; такие страницы noindex и без canonical. |
| FW-05 | Планы составлены сессией Claude (`manual_standin`) из каталога, не Qwen. | Канала к Qwen нет; авторство и статус записаны в файле плана. |
| FW-06 | Снимок каталога хранится в репозитории (только адреса и факты). | Публичное чтение меню не зависит от доступности соседнего сайта. |
| FW-07 | Аудит: 3 хоста по заданию (menunedeli, Mealime и выбранный третий планировщик — Plan to Eat), только измерения. | Задание разрешает выбрать третий планировщик; другие хосты не добавлялись. |
