# Подготовленные юниты: не установлены

Здесь лежат тексты службы и таймера ежедневного аудита. Они **не установлены**
и в systemd не зарегистрированы.

Причина не в осторожности вообще, а в конкретном правиле: новый root-unit
сначала входит в общую транзакцию hardening. Поставить его отдельно значило бы
открыть ещё один обход границы root ради удобства одного отчёта — и обход
остался бы навсегда, потому что чинить неработающее никто не приходит.

## Хранение отчётов

Отчёт за день перезаписывает сам себя: файл один на дату, `seo-health-ГГГГ-ММ-ДД.json`.
Предлагаемое хранение — 90 дней. Меньше не даёт увидеть медленную деградацию,
больше не нужно: сравнение ведётся со вчера, а не с прошлым кварталом.

Каталог `/srv/lords/.seo-reports` должен принадлежать `lords:lords` с правами
`0750`. В юните он единственный доступный на запись.

## Что проверить при установке

* таймер срабатывает и служба завершается за отведённое время;
* ненулевой код возврата при критическом нарушении виден в журнале;
* отчёт не пытается запускать платные методы Topvisor;
* каталог отчётов не растёт бесконечно.

## Канал доставки

Не настроен. До решения владельца статус — `WAITING_OWNER_DESTINATION`.
Файл на диске уведомлением не является: никто его не получит, пока за ним не
придут.
