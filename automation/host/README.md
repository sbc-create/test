# `automation/host` — автоматизация control-host

Что здесь лежит и в каком отношении к боевому хосту. Подробности каждого файла —
в его собственной шапке; здесь только карта, чтобы не читать шестнадцать
скриптов ради ответа «а где ротация логов».

## Установка

```
sudo bash automation/host/install-units.sh                      # все unit'ы
sudo bash automation/host/install-units.sh ИМЯ.service ИМЯ.timer  # только названные
```

При явном списке timer'ы не включаются: это отдельный, осознанный шаг. Отбор
идёт до проверки root, поэтому опечатку видно без `sudo`.

## Периодические проверки хоста

| файл | что делает | запускается |
|---|---|---|
| `site-factory-health.sh` | диск, иноды, память, TLS, свежесть бэкапа; код выхода = число алертов | `site-factory-health.timer`, 15 мин |
| `site-factory-selfcheck.sh` | схемы, реестры, guardrails, чистота дерева | `site-factory-selfcheck.timer`, сутки |
| `check-unit-provenance.sh` | из артефакта или из рабочего дерева git исполняется служба | вручную |

## Резервное копирование

| файл | что делает |
|---|---|
| `site-factory-backup.sh` | состояние хоста: архив + распаковка + сверка SHA-256; запись `*.verified.json` только после сверки |
| `backup-space-precheck.sh` | политика «хватит ли места» до упаковки; учитывает общую файловую систему |
| `backup-retention.sh` | подтверждённые тройки сверх KEEP и осиротевшие архивы упавших прогонов |
| `site-backup-retention.sh` | наборы копий баз витрин; никогда не трогает тот, на который указывает `latest` |

Правило, общее для всех четырёх: **существование архива не есть доказательство
восстановления**. Подтверждён только бэкап с записью о проверке.

## Узел витрин `k2-zomro-01` — исполняется НЕ здесь

Файлы с приставкой `k2-` (18 записей, считая юниты и таймеры) и
`letsencrypt-reload-nginx.sh` запускаются на **другом узле**: там живут восемь витрин партии K2. На control-host они лежат
только как источник — доставляются в `/home/k2deploy/stage/` и запускаются там.
Путать узлы дорого: `k2-launch-site.sh`, исполненный здесь, разместил бы
витрину не на том сервере, а проверка путей этого узла ничего не говорит о
другом.

| файл | что делает на узле | права |
|---|---|---|
| `k2-launch-site.sh` | размещение витрины: юнит, конфигурация nginx, upstream | root |
| `k2-enable-tls.sh` | сертификат и блок 443 одной командой: проверяет DNS и путь ACME ДО выпуска, откатывает блок при неудаче `nginx -t`, ставит хук продления, проверяет результат | root |
| `letsencrypt-reload-nginx.sh` | хук продления: `nginx -t` и перезагрузка после обновления сертификата (без него продление не доходит до посетителя) | ставится в `renewal-hooks/deploy/` |
| `k2-accept-site.sh` | приёмка витрины на узле: поверхности, честные ошибки, canonical, номер издателя, запрос к поставщику | k2deploy |
| `k2-catalog-apply.sh` + `.timer`/`.service` | установка доставленного каталога; таймер каждые 15 минут, `Persistent` | root |
| `k2-catalog-deliver.user.{service,timer}` | суточная доставка каталога с control-host (05:20 UTC) | пользовательский юнит `claude` |
| `k2-catalog-state.py` | ревизия, число позиций, свежесть и необработанные комплекты по каждой витрине | k2deploy |
| `k2-make-recovery-copy.sh` | архив комплекта И его распаковка со сверкой SHA-256 — «архив есть» доказательством не считается | k2deploy |
| `k2-verify-payload.sh`, `k2-test-apply-{cycle,install}.sh`, `k2-trial-run.sh` | проверки доставки и установки до боевого применения | k2deploy |
| `k2-measure-{frontend,concurrent}.sh` | отклик витрины и поведение восьми под одновременной нагрузкой | k2deploy |

Таблица выпуска по доменам считается с control-host одной командой —
`python3 automation/local/k2-release-table.py` (DNS, сертификат, служба, номер
издателя, каталог, режим индексации, остаточный блокер).

## Прочее

## Unit'ы: что установлено, а что подготовлено

`systemd/` содержит и работающие на хосте unit'ы, и подготовленные к установке.
Отличить можно так:

```
systemctl list-unit-files 'site-factory*' 'yummy*' 'lords*' --no-pager
```

На 2026-09-03 подготовлены, но **не установлены**: `yummy-site-backup.*`
(расписание копий баз витрин) и `yummy-episode-watcher/watchdog/enrich.service`
в варианте, исполняющем код из образа. Причины и порядок установки —
`docs/runbooks/pending-owner-actions.md`.
