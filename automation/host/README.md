# `automation/host` — автоматизация control-host

Что здесь лежит и в каком отношении к боевому хосту. Подробности каждого файла —
в его собственной шапке; здесь только карта, чтобы не читать шестнадцать
скриптов ради ответа «а где ротация логов».

## Установка

```
sudo bash automation/host/install-units.sh                      # все unit'ы
sudo bash automation/host/install-units.sh ИМЯ.service ИМЯ.timer  # только названные
```

При явном списке timer'ы не включаются: это отдельный, осознанный шаг. Отбор
идёт до проверки root, поэтому опечатку видно без `sudo`.

## Периодические проверки хоста

| файл | что делает | запускается |
|---|---|---|
| `site-factory-health.sh` | диск, иноды, память, TLS, свежесть бэкапа; код выхода = число алертов | `site-factory-health.timer`, 15 мин |
| `site-factory-selfcheck.sh` | схемы, реестры, guardrails, чистота дерева | `site-factory-selfcheck.timer`, сутки |
| `check-unit-provenance.sh` | из артефакта или из рабочего дерева git исполняется служба | вручную |

## Резервное копирование

| файл | что делает |
|---|---|
| `site-factory-backup.sh` | состояние хоста: архив + распаковка + сверка SHA-256; запись `*.verified.json` только после сверки |
| `backup-space-precheck.sh` | политика «хватит ли места» до упаковки; учитывает общую файловую систему |
| `backup-retention.sh` | подтверждённые тройки сверх KEEP и осиротевшие архивы упавших прогонов |
| `site-backup-retention.sh` | наборы копий баз витрин; никогда не трогает тот, на который указывает `latest` |

Правило, общее для всех четырёх: **существование архива не есть доказательство
восстановления**. Подтверждён только бэкап с записью о проверке.

## Контент витрин

| файл | что делает |
|---|---|
| `lords-content-refresh.sh` | обновление каталога Lords с гейтом рендера по контрольной сумме входа |
| `yummy-content-run.sh` | запуск контентного скрипта YummyAnime **внутри боевого образа**, а не из рабочего дерева |

## Прочее

`emit-runtime.py`, `finalize-public-sites.sh`, `lords-staging-apply.sh`,
`remove-lords-basic-auth.sh` — разовые и вспомогательные, запускает человек.

`logrotate/site-factory` — конфиг ротации логов. Внесён в репозиторий после
того, как выяснилось, что он жил только на хосте и не подлежал ни ревью, ни
переносу.

## Unit'ы: что установлено, а что подготовлено

`systemd/` содержит и работающие на хосте unit'ы, и подготовленные к установке.
Отличить можно так:

```
systemctl list-unit-files 'site-factory*' 'yummy*' 'lords*' --no-pager
```

На 2026-09-03 подготовлены, но **не установлены**: `yummy-site-backup.*`
(расписание копий баз витрин) и `yummy-episode-watcher/watchdog/enrich.service`
в варианте, исполняющем код из образа. Причины и порядок установки —
`docs/runbooks/pending-owner-actions.md`.
