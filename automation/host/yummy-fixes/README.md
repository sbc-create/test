# Исправления приложения Yummy, подготовленные архитектором

Патчи прикладываются тем же путём, что патчи B016: сборочный сценарий витрины
(`yummy-b016-release.py`) накладывает их на ЖИВУЮ базу каждого арендатора и
собирает образ. Здесь лежат только патчи и объяснение — ничего не применяется
чтением этого файла.

## `b016-sitemap-index-lastmod.patch`

**Что исправляет.** Индекс карты сайта объявляет каждой вложенной карте одну и
ту же замороженную дату, и обходчик по ней решает, что карты смотреть не нужно.

Измерено 2026-10-15 по пяти витринам (`scratchpad/д91-lastmod.py`, запросы к
публичным доменам):

| витрина | `lastmod` в индексе — всем пяти картам | свежайший `lastmod` внутри `titles.xml` | внутри `images.xml` |
| --- | --- | --- | --- |
| yummyani.biz | `2026-08-21T00:00:00.000Z` | **2026-10-12T07:43:13.000Z** | 2026-10-12T07:43:13.000Z |
| yummyani.org | `2026-08-21T00:00:00.000Z` | **2026-10-12T07:43:13.000Z** | 2026-10-12T07:43:13.000Z |
| yummyani.site | `2026-08-21T00:00:00.000Z` | **2026-10-12T07:43:13.000Z** | 2026-10-12T07:43:13.000Z |
| yummyani7.site | `2026-08-21T00:00:00.000Z` | то же | то же |
| yummyani7.info | `2026-08-21T00:00:00.000Z` | то же | то же |

То есть дата в индексе на 52 суток старше содержимого карты. Для обходчика это
сообщение «ничего не изменилось с 21 августа» — и 329 адресов, добавленных
снятием потолка 15.10, он имеет основание не перезапрашивать. **Снятый потолок
без этой правки до поиска не доезжает.**

Причина в коде: `sitemapLastModified()` возвращает константу
`SEO_CONTENT_UPDATED_AT = "2026-08-21T00:00:00.000Z"` (`src/lib/seo/copy.ts`), и
`sitemapIndexXml` подставляет её каждой карте. Записи ВНУТРИ карт при этом
несут настоящие даты из `updated_at` — расхождение именно в индексе.

**Что делает патч.** Считает дату каждой карты по её собственному содержимому:
максимум `lastModified` среди записей этой карты (`partLastModified`), а старая
константа остаётся запасным значением для карты без дат вовсе. Индекс берёт тот
же инвентарь из SWR-кеша, что и части, — лишней сборки не возникает: на тёплом
кеше это работа в памяти, на холодном SWR отдаёт последний исправный инвентарь.

**Порядок наложения.** Только ПОСЛЕ `b016-sitemap-swr.v2.patch`: патч
пользуется `loadSitemapInventoryWithState` из этого патча. Сухое наложение
проверено на двух базах — `8be8d8b5bdf2` (yummyani.org) и `054c6170519d`
(yummyani.site), обе с уже наложенным B016: код возврата 0 на обеих.

**Чего эта подготовка НЕ доказывает.** Сборка TypeScript здесь не
воспроизводится: зависимости приложения живут в образе, а не в рабочем дереве,
поэтому проверка типов и тестов приложения возможна только в сборочном прогоне.
Значит доказательство правки — сам выпуск и внешнее измерение после него.

**Критерий приёмки (измеряется снаружи, без доступа к контейнеру).** Для каждой
витрины: `lastmod`, объявленный индексом для `titles.xml`, равен свежайшему
`lastmod` внутри `titles.xml`; то же для `images.xml` и `static.xml`; у
`seasons.xml` и `episodes.xml` допускается прежняя константа, пока их записи
несут только её. Проба — тот же `scratchpad/д91-lastmod.py`.

## Наблюдение рядом: закрыто, второго потолка нет

У всех пяти витрин `seasons.xml` содержит 50 адресов, `episodes.xml` — 539 при
8 329 в `titles.xml`. Вопрос «не второй ли это потолок» разобран соседней
сессией 2026-10-15 и закрыт измерением, а не рассуждением:

* `/anime/arion/season/1/episode/1` (в карте нет) → **404**;
* `/anime/vosstavshiy-protiv-neba-2/season/2/episode/2` (в карте есть) → **200**;
* `episodes.xml` покрывает **36** различных заголовков, `seasons.xml` — те же
  36 (50 сезонов), разность множеств ровно ноль.

То есть 539 серий относятся к 36 многосерийным работам, а у остальных 8 293
заголовков страниц серий не существует вовсе — одиночные произведения. Карта
объявляет ровно то, что есть; неохваченной поисковой поверхности здесь нет.

Оговорка той же сессии, важная для чтения вывода: данных по индексации ИМЕННО
страниц серий нет и быть не может — Вебмастер отдаёт одно число страниц в
поиске на хост, без разбивки по разделам. Вывод сделан по составу карт и кодам
ответов.
